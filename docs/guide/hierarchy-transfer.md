# Entityを別のワールド・アイテムへ渡す

Hierarchyで選んだEntityを、子Entityと必要な素材ごと`.xriftstudio`ファイルに書き出せます。受け取る側ではワールドやアイテムを開いたまま、選んだEntityだけを追加できます。

## 選んだ部分を書き出す

1. Hierarchyで渡したいEntityを選びます。親を選ぶと子Entityも一緒に含まれます。複数選択もできます。
2. SceneかHierarchyのEntityを右クリックし、「選択範囲を書き出す」を選びます。
3. 選択範囲、配置、書き出す種類（ワールドまたはアイテム）を確認し、「書き出しを準備」を押します。
4. 含まれるEntity・素材・ファイルの数と注意事項を確認し、「.xriftstudioを保存」を押します。

ブラウザ版ではブラウザの保存先、デスクトップ版では指定した保存先に書き出されます。選択していないEntityや未使用の素材、シーンの空・照明設定、元の公開先情報は含まれません。ただし、Entityとして配置したライトは選択していれば含まれます。

書き出しても元のプロジェクトは変わりません。Scriptを編集中の場合は、編集内容を保存してからコピーされます。

## MToon・VRMモデルを渡す

MToonを使うEntityを書き出すと、マテリアルの色・陰影・輪郭線の設定と参照先のテクスチャも含まれます。VRM 0.xやVRM 1.0を渡す場合は、Model本体を選んでください。元のモデルファイル、取り込んだマテリアルや画像、モデルポーズをまとめて渡せます。

取り込み先でモデルのMaterialsを開くと、[MToonの色や輪郭線](./materials.md#mtoonマンガのような陰影と輪郭線を付ける)を引き続き編集できます。照明や環境光には追加先シーンの設定が使われるため、Playで見た目を確かめてください。

## 今のHierarchyへ追加する

1. 追加先のワールドかアイテムを開きます。ワールドの一部を独立したアイテムにしたい場合は、新しいアイテムを作成して開いてください。
2. 上部の「素材を追加 → .xriftstudioから追加」を選びます。
3. `.xriftstudio`ファイル、または従来の`.zip`ファイルを選びます。ビジュアルプロジェクト全体のファイルもそのまま使えます。
4. シーンが複数ある場合は1つを選び、追加したいEntityにチェックを付けます。
5. 追加先と配置を選び、「追加する内容を確認」を押します。
6. 注意事項を確認して「Hierarchyへ追加」を押します。

追加先は「Scene直下」「操作開始時に選んでいたEntityの子」「そのEntityと同じ階層」から選べます。特定のEntityの子として追加したい場合は、ダイアログを開く前にそのEntityを選んでおいてください。

すでにあるEntityはそのまま残り、新しく追加されたEntityが選択状態になります。プロジェクトの種類、シーン設定、公開先は変わりません。追加したEntityと素材の登録は、Undoでまとめて取り消せ、Redoでやり直せます。

## 配置を選ぶ

| 配置 | 動き |
| --- | --- |
| 元のワールド座標を保つ | 元のシーンでの位置をそのまま再現します。追加先の親の位置・回転・大きさを補正して配置します。 |
| 先頭のEntityを原点へ移す | 最初に選んだEntityを、Sceneまたは追加先の親の原点へ移します。複数選んだ場合も、互いの位置関係は変わりません。 |
| 元のローカル座標を使う | 保存されている位置・回転・大きさをそのまま使います。追加先の親のTransformによって見た目が変わります。 |

アイテムへ読み込むときは、初期設定で「先頭のEntityを原点へ移す」が選ばれています。部分書き出ししたファイルでは、書き出し時点の座標が基準になるため、元の親から切り離す前の座標には戻せません。

親の回転と縦横比の異なる拡大縮小が組み合わさっている場合、位置・回転・大きさだけでは元の形を再現できずエラーになります。その場合は親ごと選ぶか、「元のローカル座標を使う」で追加してから調整してください。

## コピーして別のプロジェクトへ貼り付ける

HierarchyでEntityを選び、Ctrl+C（MacはCmd+C）を押します。「コピーしました」の通知が出てから別のワールドやアイテムを開き、Ctrl+V（MacはCmd+V）を押すと、追加内容の確認画面が開きます。タッチ操作では、選択したHierarchy行の「…」からコピーできます。

同じプロジェクト内での「貼り付け」と「反転して貼り付け」はすぐに反映されます。別のプロジェクトへ貼り付ける場合だけ、素材を含めた確認画面が開きます。

コピーした時点の素材ファイルも一緒に引き継がれます。この操作は同じアプリウィンドウ（または同じブラウザタブ）内でプロジェクトを切り替えた場合にのみ有効で、OSのクリップボードには保存されません。別のウィンドウやタブ、別端末、アプリの再起動後に渡したいときは、`.xriftstudio`ファイルを使ってください。

## 注意事項が出たとき

- **選択外の参照と専用Component**：選択に含まれないEntityを参照するComponentは、参照が外れて無効になります。関連するEntityも一緒に選ぶか、追加後に参照先を設定し直してください。Graphでも不足する参照は外れ、注意事項が表示されます。追加先で使えないワールド専用のComponentは、設定を残したまま無効になります。
- **PrefabとModel**：Prefabは現在の内容に展開され、元のPrefabとの同期は引き継がれません。無効なPrefabは、有効にするか展開してから書き出してください。Model内部のEntityだけを選んだ場合は、Model本体を選び直します。
- **Scriptの扱い**：Scriptのコード自体は変更されません。Edit中にも動くScriptは、渡した先のコピーだけPlay時の実行に切り替わります。Scriptは隔離された環境で動くわけではないため、受け取ったコードや外部URLの内容を確認してからPlayしてください。コード内に直接書かれたEntity IDやAsset IDは自動では変換されません。
- **一度に渡せる上限**：Entityは20,000件、素材ファイルは512件までです。素材の容量は1ファイル128 MB・合計256 MBまでで、ファイル全体と展開後のデータにもそれぞれ256 MBの上限があります。容量超過や参照ファイルの欠落がある場合は追加が中止されるため、選択を分けるか素材を取り込み直してください。

プロジェクト全体の保存と取り込みは[保存して、また開く](./save-and-open.md)、素材の取り込みは[Assetsを使う](./assets.md)を参照してください。

## そのままアイテムとして開く

書き出し画面の「書き出すプロジェクトの種類」で「アイテム」を選ぶと、保存した`.xriftstudio`ファイルを独立したアイテムとして開けます。元のワールドや公開先情報は変わりません。ワールド専用のComponentは設定を残したまま無効になるため、書き出し準備後の注意事項を確認してください。既存のプロジェクトへ追加する場合は、追加先の種類に合わせて取り込まれます。
