# 容量を調べ、必要な画像だけ軽くする

動画：未収録（文章で進められます）

関連動画：[テクスチャの解像度と容量を確認する](./lesson-04-09.md)

## このレッスンでできること

容量の大きい素材を見つけ、画像を一つ選んで変換の前後を見比べます。十分に軽い場合は、確認だけ済ませてそのまま次へ進めます。

## 始める前に

- [公開前のテスト](./course-test-world.md)を終えたワールドを開きます。
- 変換を試す前に、[プロジェクト全体のバックアップ](./course-save-backup.md)を残しておきます。
- 変換を練習する場合は、シーンで使っているPNGやJPGなどのテクスチャを一つ用意します。まだ画像を使っていない場合は、先に[画像を貼って、模様の大きさを変える](./lesson-02-04.md)を試してみてください。
- Play中ならStopで編集に戻り、自動保存や素材の取り込みが終わるまで待ちます。

## 手順

### 1. 読み込み容量とVRAMの目安を分けて見る

ファイルの容量は、ワールドを開くときに読み込むデータ量を表します。一方のVRAMは、画像や3Dモデルを画面に表示するためにGPUが使うメモリー量です。ファイル容量が減っても、描画の重さが同じ割合で軽くなるとは限らないため、両方を分けて確認します。

**デスクトップ版**では「XRiftへ公開」を開き、「読み込み容量・VRAMの目安」の「詳細を見る」を押します。「初回の読み込み」「実行時の全体目安」と、容量の大きい素材の名前を一つメモしておきましょう。ここでは確認だけ行い、まだ送信はしません。

表示される読み込み時間は回線速度から計算した目安であり、実測値ではありません。VRAM使用量もブラウザ・GPU・画面解像度・影の設定などによって変わるため、「余裕あり」と表示されてもすべての端末で快適に動くとは限りません。

**ブラウザ版・iPad**では、Assetsの「並び順」を「ファイルサイズが大きい順」または「VRAM概算が大きい順」に切り替えて、大きい画像の名前と容量をメモします。ブラウザ版にはデスクトップ版のような全体の詳細画面がないため、作品全体をしっかり見積もりたい場合は、`.xriftstudio`ファイルを書き出してデスクトップ版で確認してください。

### 2. 画像を一つ選び、変換前の見た目を覚えておく

編集画面に戻り、Assetsから対象のテクスチャを選びます。Inspectorの「ソース」にある「使用中の解像度」を確認してください。未取得になっている場合は「サイズを確認」を押します。

次に、その画像が貼られている場所を、近くと少し離れた位置の両方から見ておきます。看板の文字、細い線、透明な輪郭など、変換後もくっきり残したい部分を覚えておくと比較しやすくなります。同じ画像を複数の場所で使っている場合は、ほかの使用箇所も確認しておきましょう。

### 3. 必要なときだけ変換の設定を選ぶ

Inspectorの「サイズと圧縮」で、まずはどちらか一方だけ試してみます。

- **解像度を下げる**：「最大解像度」で現在より小さい上限を選び、「変換後」の幅と高さを確認します。この練習では「辺を2のべき乗に揃える」はオフにしておきます。
- **圧縮する**：「最大解像度」を「原寸のまま」にして、「圧縮方式」を選びます。WEBPは通信量を減らす形式で、VRAM使用量は変わりません。KTX2は通信量とVRAM使用量の両方を減らせますが、端末によって見え方が変わることがあります。

縮小や圧縮を行うと、細部や文字がぼやける場合があります。「変換後」のサイズや形式が意図したものと違う場合は、適用する前に設定を見直してください。

なお、初期設定では画像を取り込んでも自動で縮小・圧縮されません。取り込み設定を変更した場合はそれ以降に取り込む画像に適用されるため、すでに取り込み済みの画像には次の手順で適用します。

### 4. 選んだ画像に変換を適用する

「この設定で画像を書き出す」を押し、変換が終わるまで待ちます。完了後に表示される解像度・形式・変換前後の容量を見比べてください。画像の性質によっては、変換しても容量があまり減らないこともあります。

設定を選んだだけではまだ変換されていません。「この設定で画像を書き出す」を押した時点で変換が行われ、変換後の画像が編集画面と公開の両方に使われます。元の画像も保持されるため、見比べたあとで戻すこともできます。

### 5. 同じ場所で見比べ、採用するか決める

編集画面とPlayの両方で、手順2と同じ場所・同じ距離から見た目を確認します。看板の文字が読めるか、模様や輪郭が崩れていないかを見てください。同じ画像を共有しているほかの場所も確認します。

見た目が気になる場合は、Stopで編集に戻り、保持されている原本から「元の画像に戻す」を押して元に戻せます（原本が保持されていない素材では、このボタンは使えません）。

デスクトップ版では公開画面の見積りを開き直し、最初にメモした数値と比べてみてください。ブラウザ版ではAssetsとInspectorで容量を確認します。容量の削減幅が小さい場合や見た目を優先したい場合は、元の画像をそのまま残す判断でも構いません。採用する状態が決まったら、保存完了を確認して終了です。

## できたか確認する

- 読み込み容量とVRAMが別の指標であることを理解できました。
- 確認した画像の名前、変換前後の容量、見た目の変化を説明できます。
- 変換を試した場合は、編集画面とPlayの両方で見た目を見比べられました。
- 見た目を優先して元に戻したり、変換せずに残したりする判断もできるようになりました。

## うまくいかないとき

- **変換ボタンが押せない**：Stopで編集に戻り、自動保存やほかの素材処理が終わるまで待ちます。「変更なし」と表示されている場合は、現在の状態と設定に差がありません。変換に対応していない形式の場合は、画面に表示される理由を確認してください。
- **サイズを取得できない**：元ファイルに問題がないか確認してからやり直してください。解像度が読み取れていない状態では容量の見積りも正確にならないため、取得できてから確認します。
- **文字や模様が崩れた**：元画像が保持されていれば「元の画像に戻す」で戻し、縮小の幅を弱めるか変換を見送ってください。
- **容量は小さくなったのに動作が重い**：影・半透明の重なり・パーティクル・Post Processing・モデル数なども動作に影響します。[容量と描画負荷を減らす](./performance.md)を参考に、一項目ずつ変えて同じ場所から見比べてください。
- **編集画面の品質を下げたら見え方が変わった**：編集用の軽量表示では影やBloomが省略されます。この設定は公開されるワールドの画質には影響しないため、仕上がりの確認は高品質表示とPlayで行ってください。
