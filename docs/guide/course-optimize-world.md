# 容量を調べ、必要な画像だけ軽くする

動画：未収録（文章で進められます）

関連動画：[テクスチャの解像度と容量を確認する](./lesson-04-09.md)

## このレッスンでできること

容量の大きい素材を見つけ、画像を一つ選んで変換前後を比べます。軽くする必要がなければ、確認だけで終えられます。

## 始める前に

- [Playのテスト](./course-test-world.md)を済ませたワールドを開きます。
- 変更前の[プロジェクト全体のバックアップ](./course-save-backup.md)を残します。
- 変換を試す場合は、シーンで使っているPNGやJPGなどのテクスチャを一つ用意します。画像をまだ使っていなければ、[テクスチャのレッスン](./lesson-02-04.md)を先に試せます。
- Play中ならStopで戻り、初回の自動保存と素材の取り込みが終わるまで待ちます。

## 手順

### 1. 読み込み容量と描画負荷を分けて見る

ファイルの容量は、読み込むデータの量です。VRAMは、画像やモデルの表示などに使うGPUのメモリーです。容量が小さくなっても、表示の動作が同じだけ軽くなるとは限りません。

**デスクトップ版**では「XRiftへ公開」を開き、「読み込み容量・VRAMの目安」の「詳細を見る」を押します。「初回の読み込み」「実行時の全体目安」と、容量の大きい素材の名前を一つ控えてください。この段階では内容を確認し、送信には進みません。

読み込み時間は回線速度から計算した目安で、実測値ではありません。VRAMもブラウザ、GPU、画面解像度、影などで変わります。「余裕あり」などの評価も、すべての端末での動作を保証するものではありません。

**ブラウザ版・iPad**では、Assetsの「並び順」を「ファイルサイズが大きい順」または「VRAM概算が大きい順」にします。大きい画像の名前と容量を控えてください。デスクトップ版の公開画面と同じ詳細カードがある前提では進めず、全体の詳しい見積りが必要なら`.xriftstudio`で引き継いで確認します。

### 2. 画像を一つ選び、変更前を確認する

編集画面に戻り、Assetsで対象のテクスチャを選びます。Inspectorの「ソース」で「使用中の解像度」を確認してください。未取得なら「サイズを確認」を押します。

その画像が貼られた場所を、近くと少し離れた位置から見ます。看板の文字、細い線、透明な輪郭など、変換後にも残したい部分を覚えておきます。同じ画像を複数の場所で使っている場合は、使っている場所も確認してください。

### 3. 必要なときだけ、変換の設定を選ぶ

Inspectorの「サイズと圧縮」で、まず一種類の変更を試します。

- **解像度を下げる**：「最大解像度」で現在より小さい上限を選びます。「変換後」の幅と高さを確認してください。この練習では「辺を2のべき乗に揃える」はオフにします
- **圧縮する**：「最大解像度」を「原寸のまま」にし、「圧縮方式」を選びます。WEBPは通信量を減らすための形式で、VRAM使用量は変わりません。KTX2は通信量とVRAM使用量を減らせますが、端末によって見た目が変わります

縮小や圧縮では、細部や文字がぼけることがあります。無劣化になるとは限りません。「変換後」が意図しないサイズや形式なら、適用する前に設定を見直します。

取り込みの初期設定では、画像を自動で縮小・圧縮しません。取り込み時の設定を自分で変えた場合は、以降の取り込みに適用されます。今回すでに取り込んだ画像には、次の操作で明示的に適用します。

### 4. 選んだ画像へ適用する

「この設定で画像を書き出す」を押し、変換が終わるまで待ちます。結果に表示された解像度、形式、変換前後の容量を確認してください。変換しても必ず小さくなるとは限りません。

元画像は保持され、変換後の画像が編集画面と公開に使われます。公開時に未適用の縮小・圧縮が自動で行われるわけではありません。設定を選んだだけでは、この画像の変換は完了していません。

### 5. 同じ場所で見比べ、採用するか決める

編集画面とPlayで、手順2と同じ場所から確認します。看板が読めるか、模様や輪郭が崩れていないかを見てください。画像を共有しているほかの場所も確かめます。

結果がよくなければStopで戻り、保持された原本の「元の画像に戻す」を使います。原本が保持されていない素材では、この操作は使えません。

デスクトップ版では公開画面の見積りを開き直し、控えた数値と比べます。ブラウザ版ではAssetsとInspectorで容量を確認してください。改善が小さい場合や見た目を保てない場合は、元の画像を使う判断でも構いません。採用する状態を決めたら保存完了を確認します。

## できたか確認する

- 読み込み容量とVRAMが別の目安だと分かる
- 確認した画像の名前、変更前後の容量、見た目の結果を説明できる
- 変換した場合は、編集画面とPlayの両方で見比べた
- 見た目を優先して戻す、または変換せずに残す判断もできる

## うまくいかないとき

- **変換ボタンが押せない**：Stopで戻り、自動保存と他の素材処理を待ちます。「変更なし」なら変換する設定差がありません。対応していない形式では、画面の理由を確認してください
- **サイズを取得できない**：元ファイルを確認して再試行します。解像度が不明なまま、数値を正確な見積りとして扱わないでください
- **文字や模様が崩れた**：元画像が保持されていれば「元の画像に戻す」で戻し、縮小を弱めるか変換を見送ります
- **ファイルは小さくなったが動作が重い**：影、半透明の重なり、パーティクル、Post Processing、モデルの数も影響します。[容量と描画負荷](./performance.md)を読み、一つずつ変えて同じ場所から比べます
- **編集画面の品質を下げたら見え方が違う**：編集用の軽量表示では影やBloomが省略されます。この設定は公開作品の品質には反映されないため、仕上げは高品質表示とPlayでも確認してください
