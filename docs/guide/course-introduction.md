# XRiftとXRift Studioでできること

動画：未収録（文章で進められます）

## このレッスンでできること

XRiftとXRift Studioの役割を整理し、自分が作りたいものに合う制作方法を選べるようになります。コードを使う作り方についても、どんな表現ができるのか全体像をつかんでおきましょう。

## 始める前に

このページは、アプリをインストールする前でも読めます。プログラミングの知識も必要ありません。まずは「こんな場所を作ってみたい」というイメージを一つ思い浮かべてみてください。

## 手順

### 1. XRiftとXRift Studioの関係を知る

[XRift](https://xrift.net/)は、ブラウザから3D空間に入って人と交流できるサービスです。パソコン、スマートフォン、対応するVR端末から、公開されているワールドを体験できます。

XRift Studioは、そのXRiftで使うワールドやアイテムを作るためのツールです。有志が開発している非公式ツールで、デスクトップ版とブラウザ版βがあります。素材の配置、色や動きの調整、Playでの動作確認、そしてXRiftへの公開までを行えます。

| 名前 | 役割と使う場面 |
| --- | --- |
| XRift | 公開されたワールドに入って体験する（展示を見に行く、友達と集まるなど） |
| XRift Studio | ワールドやアイテムを制作する（展示会場を組み立てる、押すと音が鳴る仕掛けを作るなど） |

制作は「Studioで作る → Playで試す → XRiftへ公開する → XRiftに入って確かめる」という流れで進めます。Studioで保存しておけば、いつでも続きから編集できます。ほかの人に遊んでもらうには、保存だけでなくXRiftへの公開が必要です。

なお、XRift本体にも、ワールドの中で物を配置してフレンドと一緒に作れる「ワールドビルダー」という機能があります。このコースでは、XRift Studioを使った制作を学びます。それぞれの作り方の違いは、[XRift公式の作り方の紹介](https://xrift.net/creators)でも確認できます。

### 2. ワールドとアイテムの違いを知る

ワールドは、人が中に入って歩き回れる3D空間です。展示会場や友達と集まる部屋、遊べる広場などを作れます。床や開始位置を用意し、訪れた人が何を見たり操作したりするかを考えながら組み立てます。

アイテムは、ワールドの中で使う個別のオブジェクトです。空間全体を作るワールドとは、プロジェクトの種類や公開先が分かれています。このコースでは、まず小さなワールドを作るところから始めます。

### 3. 作り方とコードの種類を知る

最初はビジュアルエディターで物を置き、色や大きさを変えるだけで十分にワールドを作れます。画面上では、シーンに配置した一つひとつの物をEntityと呼びます。

動きやオリジナルの表現を足したくなったら、目的に合わせて次の方法を組み合わせてみてください。

| 作り方 | 使う仕組みとできること |
| --- | --- |
| ビジュアルエディター | 画面上で素材を配置し、部屋・家具・ライトなどを組み立てる |
| Node Graph | きっかけと処理をノードと線でつなぎ、押すと音が鳴るボタンや、少し待ってから動く箱を作る |
| Script | TypeScript／TSXをEntityに付け、展示物を回し続けたり、条件によって音を変えたりする |
| コードエディター | TypeScript／TSXでワールドやアイテム全体を組み立て、計算で物を並べたり独自の3D表示を作ったりする |
| カスタムシェーダー | GLSLで表面の色や模様を描き、時間とともに色が変わる表現や動く模様を作る |

Node Graphなら、コードを書かずに動く仕掛けを作れます。まずは[ノードをつないで箱を動かす](./lesson-03-00.md)レッスンで、きっかけと処理のつなぎ方を試せます。

TypeScriptは物の動きや条件分岐などを書く言語で、TSXはTypeScriptの中に画面や3Dの構成をそのまま書ける形式です（ReactやReact Three Fiberで使われます）。Scriptは配置済みのEntityに動きを付けるときに使い、コードエディターはワールドやアイテム全体の構成を編集するときに使います。同じ言語でも、扱う範囲が異なります。

Scriptを試してみたいときは、[テンプレートでBoxを回転させる](./lesson-03-04.md)レッスンから入ると分かりやすいです。また、ビジュアルエディターで作ったシーンを[コードエディターへ書き出して](./save-and-open.md#コードエディターへ書き出す)続きを作ることもできます。ただし、書き出したコード側で行った変更はビジュアルエディターには自動で戻りません。

GLSLは、物体の表面の色や模様といった見た目を細かく制御する言語です。ボタンの処理やワールド全体の構成はNode GraphやTypeScript／TSXが担当します。独自の見た目をコードで作ってみたいときは、[GLSLの案内](./custom-shaders.md)をご覧ください。

このほか、AIに配置やコードの編集を手伝ってもらう方法もあります。詳しくは[AI連携の案内](./ai-connection.md)にまとめていますが、最初の制作はAIを接続せずに進められます。

### 4. 最初に作るものを決める

最初は「床と展示物がある小さな部屋」を目標にするのがおすすめです。配置、色の変更、保存、Play、公開という一連の流れを無理なく体験できます。コードは「こんな動きを足したい」と思ったタイミングで取り入れれば大丈夫です。

ブラウザ版βでも配置やNode Graphからすぐ始められ、ワールドとアイテムを公開できます。Scriptを含む作品の公開やコードエディターへの書き出しには、デスクトップ版を使います。次のレッスンで、使う環境と保存先を決めましょう。

## できたか確認する

- XRiftで体験し、XRift Studioで制作するという役割の違いが分かりました。
- ワールドとアイテムの違いを説明できます。
- Node Graph・Script・コードエディター・GLSLで何ができるか、それぞれイメージできました。
- 最初に作ってみたいワールドのテーマを一つ決められました。

## うまくいかないとき

- **仕組みや言葉が多くて迷う**：最初からすべてを覚える必要はありません。まずはビジュアルエディターで物を置いて色を変えてみて、動きを付けたくなったらNode Graphへ進んでください。分からない画面名は[用語集](./glossary.md)ですぐ調べられます。
