# GLSLでマテリアルを編集する

色や質感をコードで自由に作り込みたいときは、マテリアルのカスタムシェーダーを使います。アニメ調の陰影や輪郭線を付けたい場合は、コードを書かずに使える[マテリアルの種類からMToonを選ぶ](./materials.md#mtoonマンガのような陰影と輪郭線を付ける)手順を参照してください。

## カスタムシェーダーを作る

Assetsでマテリアルを選び、「Inspector → カスタムシェーダー」を開きます（スマートフォンでは、この項目の折りたたみを展開してください）。「カスタムシェーダーを作成」を押すと、コードの編集を始められます。

「シェーダーコード」の欄で、「頂点シェーダー GLSL」または「フラグメントシェーダー GLSL」の「編集」を押します。頂点シェーダーは頂点の位置や変形を、フラグメントシェーダーは表面の色や模様を計算します。最初は自動生成されたコードを少しずつ書き換え、プレビューで変化を確かめながら進めると分かりやすくなります。

## 編集と保存を確認する

GLSLエディターでの変更は自動で保存されます。状態表示が「保存待ち → 自動保存中 → 保存済み」と切り替わるのを確認してください。もし保存に失敗した場合は、「自動保存を再試行」を押します。

保存した変更は、そのマテリアルを使っているすべての場所に反映されます。特定のEntityだけ見た目を変えたい場合は、あらかじめマテリアルを分けておいてください。割り当てた画像やuniformの値はInspectorで確認できます。

## uniformの種類と入力

Inspectorの「シェーダーの調整値」には、シェーダーで定義されているuniformが一覧で表示されます。基本的な数値・色・ベクトル・テクスチャに加えて、次の種類も編集できます。uniformの追加や種類の変更は、AIクライアントの `update_custom_shader` で行います。

| 表示 | GLSLの宣言 | 入力する内容 |
| --- | --- | --- |
| mat3、mat4 | `mat3`、`mat4` | 9個または16個の数値を、列ごとにカンマ区切りで並べます |
| 12個の数値など | `float`、`vec2`〜`vec4`、`mat3`、`mat4`の配列 | 1〜4096個の数値を並べます（例：`vec3 uPoints[4]` なら12個） |
| 3Dテクスチャ | `sampler3D` | スライスを左から右へ並べた画像と「スライス数」を指定します |
| キューブマップ | `samplerCube` | +X、-X、+Y、-Y、+Z、-Zの各面に使う6枚の画像を指定します |

テクスチャ系のuniformには、次の形式・サイズ条件があります。

- **3Dテクスチャ**：高さがスライス1辺の長さ、幅が「1辺 × スライス数」になる画像を用意します。「スライス数」を空欄にすると、正方形のスライスが並んでいるものとして自動計算されます。1辺の長さとスライス数はそれぞれ256が上限です。GLSLでは、スライス内の横が `x`、縦が `y`（画像の上端が0）、スライス番号が `z` になります。
- **キューブマップ**：6枚すべてを同じサイズの正方形にします。3DテクスチャとキューブマップにはPNGやJPEGなどの8bit画像を選んでください（KTX2へ圧縮したテクスチャやEXRは選べません）。
- **2Dテクスチャ（`sampler2D`）**：EXRも選択できます。EXRは浮動小数の値がそのまま渡されるため、1を超える明るさや位置データなどの数値を読み取れます。精度はファイルに応じて16bitまたは32bitになります。端末によっては32bitの値を滑らかに補間できないため、数値テーブルとして参照するEXRは16bitで保存するか、`update_custom_shader` で `filter` を `nearest` に指定してください。なお、HDR（`.hdr`）は選べません。

## 合成とカリングを設定する

Inspectorの「合成とカリング」では、バリアントごとに描画方法を設定できます。バリアントとは、Meshの名前に応じて切り替える設定の組み合わせです。

| 項目 | 効果 |
| --- | --- |
| Blending | すでに描かれている背景色への重ね方を、Normal（通常）、Additive（加算）、Multiply（乗算）、Subtractive（減算）から選びます |
| Transparent | 不透明なオブジェクトを描いたあとに、奥から手前へ順に描画します。Normal以外のBlendingを使うときは有効にしてください |
| Depth Write | 深度バッファへの書き込みを切り替えます。光や煙のように重ねて見せる表現ではオフにします |
| Frustum Culling | 画面外にあるMeshの描画を省略します。頂点シェーダーでMeshを別の位置へ大きく動かす場合はオフにしてください |

Frustum Cullingをオフにしたマテリアルを割り当てたMeshは、画面外にあるときも描画されます。別のマテリアルへ差し替えると元の設定に戻ります。大量のMeshでオフにすると描画負荷が増えるため、必要なマテリアルだけに限定して使ってください。

## モデルの属性を読む

頂点シェーダーでは、割り当て先のメッシュが持つ頂点属性を `attribute` で宣言して読み取れます。GLBに含まれる独自属性は、すべて小文字の名前で宣言してください（例：`_AMAT` の場合は `attribute float _amat;`）。

同じ形状を複数並べたGLB（`EXT_mesh_gpu_instancing`）でも、インスタンスごとの独自属性を同じ書き方で読めます。このとき値は頂点単位ではなく、インスタンスごとに1つ渡されます。各インスタンスの配置には `instanceMatrix` を使います。

```glsl
attribute vec3 _aoffset;

void main() {
  vec4 local = vec4(position + _aoffset, 1.0);
  #ifdef USE_INSTANCING
    local = instanceMatrix * local;
  #endif
  gl_Position = projectionMatrix * modelViewMatrix * local;
}
```

独自属性はGLBファイルから直接読み込みます。外部ファイルを参照する `.gltf` は取り込み時にGLBへ変換されるため、インスタンスごとの独自属性が失われます。独自属性を使いたい場合は、必要なデータを含んだGLBファイルを取り込んでください。

## 動作中に値を変える

「シェーダーの調整値」に設定した値は、ワールドの実行中は固定のままです。歩く人の位置に合わせて草を倒すなど、動作中に値を変化させたいときはスクリプトを使います。スクリプトから `ctx.materials.setUniform` にuniform名と値を渡してください。正確なuniform名は、「シェーダーの調整値」にある「uniform名」ボタンを押すと確認できます。

渡す値はuniformの型と一致させる必要があります（数値は数値1つ、ベクトルは同じ要素数の数値、色は色、画像はテクスチャ）。型が合わない場合はエラーになって反映されません。原因はスクリプトのConsoleで確認でき、具体的な書き方はスクリプト画面の「APIガイド」に例が載っています。

スクリプトで変更した値は、そのスクリプトを付けたEntityだけに適用されます。同じマテリアルを共有するほかのEntityや、保存されている設定値には影響しません。Stopを押すと元の設定値に戻ります。「時間を受け取る変数名（任意）」に指定した変数をスクリプトから書き換えた場合は、変更している間だけスクリプト側の値が優先されます。

## コンパイルできないときに直す

GLSLに文法ミスなどがあるとシェーダーをコンパイルできず、そのマテリアルを割り当てたメッシュは画面に表示されなくなります。同時に、Inspectorの「カスタムシェーダー」とGLSLエディターに「GLSLをコンパイルできません」と表示されます（メッシュへ割り当てる前のマテリアルでも、Inspectorで開いた時点でチェックされます）。

エラー表示には、次の情報が出ます。

- 頂点シェーダーとフラグメントシェーダーのどちらで起きたか
- 該当する行番号（GLSLエディターの行番号と一致します）
- コンパイラのエラーメッセージ

該当箇所を修正して自動保存されると再チェックが走り、問題が解消すればエラー表示は消えます。

詳しい出力を確認したいときは「コンパイラのログ」を開いてください。ただし、こちらのログはThree.jsが先頭に自動追加するコードも含めて行数を数えるため、GLSLエディターの行番号より大きい番号になります。

また、「頂点とフラグメントの組み合わせ」と表示された場合は、2つのシェーダー間で宣言が一致していません。片方にしかない `varying` 変数などがないか見直してください。

修正前の状態に戻したいときは、「元に戻す」または「初期のシェーダーに戻す」を使えます。

## PBRへ戻す

「PBRへ戻す」を押すと、カスタムシェーダーの割り当てが解除されて標準のPBRマテリアルに戻ります。コードを大きく編集する前に[プロジェクトをバックアップ](./save-and-open.md#バックアップする)しておくと、変更前後の見た目を安全に見比べられます。

空や水の見本を使いたい場合は、[Skybox Shaderと水の使い方](./sky-and-water.md)を参照してください。カスタムGLSL、MToon、標準のPBRマテリアルはそれぞれ描画方式が異なるため、作りたい表現に合わせて使い分けます。
