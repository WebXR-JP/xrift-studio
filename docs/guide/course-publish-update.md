# 同じワールドを更新する

動画：未収録（文章で進められます）

## このレッスンでできること

公開した元のプロジェクトを使って、小さな変更を同じワールドへ反映します。別ワールドの作成や、審査待ちの版を更新済みと間違えることを防ぎます。

## 始める前に

- [審査と一覧への公開](./course-publish-review.md)を確認してください
- 前回公開した元のプロジェクトと、送信結果のワールドIDを用意してください
- 変更前の状態を[.xriftstudioファイルへ書き出して](./save-and-open.md#バックアップする)残してください

## 手順

### 1. 更新元のプロジェクトを開く

1. 前回公開した端末とアプリ、またはブラウザで、プロジェクト一覧を開きます。
2. 前回使った元のプロジェクトを選びます。似た名前の複製を選ばないようにしてください。
3. 「XRiftへ公開」を開き、保存されている公開先を確認します。
4. 前回のワールドIDと一致することを確かめたら、送信せずに編集へ戻ります。

複製や`.xriftstudio`／ZIPから取り込んだプロジェクトは、新しい未公開プロジェクトです。同じ名前を付けても、元のワールドへ自動で結び付きません。ブラウザからデスクトップへ移した場合も、取り込み先を同じ公開先だと思い込まないでください。

### 2. 一つだけ変更してPlayで試す

1. 例として、入口の案内文を一か所だけ直します。ほかには、展示台の色やEntityの位置など、違いを確認しやすい変更でも構いません。
2. 保存が終わるまで待ちます。
3. Playで変更した場所を見て、表示と操作を確認します。
4. Stopで戻り、必要なら説明とサムネイルも更新します。

最初は小さな変更にすると、公開先で新旧の違いを見分けやすくなります。

### 3. 更新先を確認して再公開する

1. 「XRiftへ公開」を開きます。
2. デスクトップ版は「公開先」、ブラウザ版は「更新先」のIDを、前回の記録と見比べます。
3. タイトル・説明・サムネイル、公開チェック、アカウントを確認します。
4. デスクトップ版は「XRiftへ公開」、ブラウザ版は「このワールドを更新」を一度押します。
5. 送信完了画面で、ワールドIDが同じであることと、今回返されたバージョンを確認します。

「新しいワールドとして送信」と出た場合は送信しません。元のプロジェクトが残っているか調べてください。公開先を合わせるために、内部のIDや認証ファイルを手作業で書き換える必要はありません。

### 4. 更新した版が使われているか確認する

1. XRiftで同じワールドを開き、「バージョン履歴」を確認します。
2. 今回送信した版の審査が終わるまで待ちます。
3. その版が「審査通過」「現在使用中」になっているか確認します。
4. ワールドへ入り直して、手順2で変更した箇所を確かめます。開きっぱなしの画面に変更が即時反映されるとは限りません。
5. 確認できたバージョンと変更点を、手元のメモに残します。

番号の増加だけで判断せず、返された結果と公開先の表示を照合してください。

## できたか確認する

- 初回と同じワールドIDへ送信できた
- 今回の版の審査結果と「現在使用中」を確認した
- 実際に入り直し、変更箇所が反映されていた
- 次回も使う元のプロジェクトを残している

## うまくいかないとき

- 別ワールドができそう：送信前に止めて、元のプロジェクトを開き直します
- 公開先の保存が失敗していた：重複防止のため再送を控え、[送信結果が分からない場合](./course-publish-upload.md#送信結果が分からない)を確認します
- 公開先が古いまま：送信した版の審査結果と「現在使用中」を確認します。更新が却下された場合は、以前の通過版が公開されたままになります
- 元のプロジェクトが見つからない：バックアップを保管したまま、[復旧と問い合わせ](./recovery.md)へ進みます。取り込んだ複製を元の公開先だと決めつけて送らないでください

### 前の版へ戻す必要がある場合

XRiftの「バージョン履歴」に残っている審査通過済みの版では、「このバージョンを公開」を選べます。確認画面で対象の番号を読み、全利用者に使われる公開版が変わることを理解してから確定してください。

これはXRift上で使う版を切り替える操作です。Studioの編集中データを自動で以前の状態へ戻す操作ではありません。また、履歴に残る版数には制限があるため、制作データのバックアップも保管してください。
