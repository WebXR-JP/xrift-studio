# 同じワールドを更新する

動画：未収録（文章で進められます）

## このレッスンでできること

前回公開した元のプロジェクトを使って、小さな変更を同じワールドへ反映します。別のワールドを誤って新しく作ってしまったり、審査待ちのバージョンを更新済みと思い込んだりするのを防ぎます。

アイテムを更新するときも考え方は同じです。前回公開した元のプロジェクトを開き、保存されているアイテムIDを確認してから更新します（ブラウザ版では「このアイテムを更新」を使います）。以下の手順に出てくるワールドIDは、アイテムIDに読み替えて進めてください。

## 始める前に

- [審査と一覧への公開を確認する](./course-publish-review.md)を済ませておきます。
- 前回公開した元のプロジェクトと、送信時に控えたワールドIDを用意します。
- 変更を加える前に、現在の状態を[.xriftstudioファイルへ書き出して](./save-and-open.md#バックアップする)バックアップを残しておきます。

## 手順

### 1. 更新元のプロジェクトを開く

1. 前回公開したときと同じ端末・アプリ（または同じブラウザ）でプロジェクト一覧を開きます。
2. 前回公開した元のプロジェクトを選びます。似た名前の複製プロジェクトと間違えないよう気をつけてください。
3. 「XRiftへ公開」を開き、保存されている公開先を確認します。
4. 前回のワールドIDと一致していることを確かめたら、まだ送信せずに編集画面へ戻ります。

複製したプロジェクトや`.xriftstudio`／ZIPから取り込んだプロジェクトは、新しい未公開プロジェクトとして扱われます。同じ作品名を付けても、元のワールドには自動で結び付きません。ブラウザ版からデスクトップ版へ移した場合も同様なので、公開先を必ず確認してください。

### 2. 小さな変更を一つ加えてPlayで確かめる

1. たとえば、入口の案内文を一か所だけ直してみます。展示台の色やEntityの位置など、変化が見分けやすい変更でも構いません。
2. 自動保存が完了するまで待ちます。
3. Playで変更した場所へ行き、見た目や動作を確かめます。
4. Stopで編集画面に戻り、必要があれば説明やサムネイルも更新します。

最初の更新練習では小さな変更にしておくと、公開先で新旧の違いをすぐ確認できて安心です。

### 3. 更新先を確認して再公開する

1. 「XRiftへ公開」を開きます。
2. デスクトップ版は「公開先」、ブラウザ版は「更新先」に表示されているIDを、前回の控えと見比べます。
3. タイトル・説明・サムネイル・公開チェック・アカウントを確認します。
4. デスクトップ版は「XRiftへ公開」、ブラウザ版は「このワールドを更新」を一度だけ押します。
5. 送信完了画面で、ワールドIDが前回と同じであることと、新しく発行されたバージョン番号を確認します。

もし「新しいワールドとして送信」と表示された場合は、いったん送信を止めて、前回公開した元のプロジェクトが残っていないか確認してください。

### 4. 新しいバージョンが使われているか確認する

1. XRiftで同じワールドを開き、「バージョン履歴」を確認します。
2. 今回送信したバージョンの審査が終わるまで待ちます。
3. そのバージョンが「審査通過」かつ「現在使用中」になっていることを確認します。
4. ワールドへ入り直し、手順2で変えた箇所が反映されているか確かめます（開きっぱなしのタブには自動で反映されないことがあるため、入り直して確認します）。
5. 確認できたバージョン番号と変更内容を、手元のメモに残しておきます。

バージョン番号が増えただけで完了と判断せず、送信結果の番号と「現在使用中」が一致しているか確認するのがポイントです。

## できたか確認する

- 初回と同じワールドIDへ新しいバージョンを送信できました。
- 今回のバージョンが「審査通過」「現在使用中」になっていることを確認しました。
- ワールドへ入り直し、変更した箇所が実際に反映されていることを確かめました。
- 次回の更新でも使えるよう、元のプロジェクトをそのまま残しています。

## うまくいかないとき

- **別のワールドとして公開されそう**：送信前に画面を閉じ、前回公開した元のプロジェクトを開き直してください。
- **送信結果の保存に失敗した**：二重送信を防ぐためすぐに再送せず、[送信結果が分からない場合](./course-publish-upload.md#送信結果が分からない)を確認してください。
- **公開先の見た目が古いまま**：「バージョン履歴」で今回送信したバージョンの審査状態と「現在使用中」を確認します。更新版が却下された場合は、以前通過したバージョンがそのまま公開され続けます。
- **元のプロジェクトが見当たらない**：バックアップを保管したまま、[復旧と問い合わせ](./recovery.md)を確認してください。取り込んだ複製を元の公開先と思い込んで送信しないよう気をつけます。

### 前のバージョンへ戻したいとき

XRiftの「バージョン履歴」に残っている審査通過済みのバージョンでは、「このバージョンを公開」を選べます。確認画面で対象バージョンを確かめ、すべての利用者に表示される公開版が切り替わることを理解したうえで確定してください。

なお、これはXRift側で公開するバージョンを切り替える操作であり、Studioの編集データ自体は元に戻りません。また、履歴に残るバージョン数には上限があるため、手元のバックアップもあわせて保管しておきましょう。
