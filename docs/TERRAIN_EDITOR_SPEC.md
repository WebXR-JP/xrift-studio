# Terrain エディター 仕様

Terrain は Studio の中で操作が最も多い機能である。他の Component と同じ Inspector に並べる限り窮屈になる。専用エディターへ切り出すための設計を示す。

この文書は設計である。「実装済み」と書いた部分以外は**未実装**である。

## なぜ専用にするのか

Terrain の編集は「対象を選んで値を変える」作業ではない。「筆を選んで地面を操作し続ける」作業であり、他の Inspector 操作とは性質が異なる。具体的な不都合は 3 つある。

- ブラシの半径・強さ・種類を変えるたびに右パネルへ視線を戻すことになる。このため、地面から目を離すことになる
- 高さ、草、穴、マテリアルが同じ縦長のリストに混ざる。このため、いま何を編集しているのかが画面から読めない
- Terrain を触っている間も他の Entity が選択対象のまま残る。このため、誤って別の物を動かしてしまう

## 全体の形

Terrain を選択して「地形を編集」に入ると、**専用モード**へ遷移する。

- Scene View は Terrain だけを操作対象にする。他の Entity のギズモと選択を止める
- 左下に**ツールバー**（モード切替）を出す。右には**そのモード専用のパネル**だけを出す
- Escape または「編集を終了」で通常の Editor へ戻る。**戻り先は常に画面へ残す**

### ツールバーの見せ方

Unity の Terrain Inspector に合わせる。モードは**アイコンのタブ**として横一列に並べる。選択中のモードだけが押された状態になる。選んだモードの設定だけを下へ出す。使わない設定は出さない。「操作」のドロップダウンから選ぶ形は使わない。いま何が有効なのかが読めないためである。

操作の意味をアイコンだけで示さない。各タブには読めるラベルを添える。`title` も付ける。形モードの中の筆（盛る・削る・ならす・高さを揃える・スタンプ）も同じ扱いにする。アイコン付きのボタン列にする。ドロップダウンでは、いま選んでいる筆が一覧の中に見えないためである。

モードは 4 つである。同時に有効なのは常に 1 つである。いま何を触っているのかを画面が示す。

| モード | 触るもの | 主な操作 |
| --- | --- | --- |
| 形 (Sculpt) | 高さフィールド | 盛る / 削る / 高さを揃える / ならす / スタンプ |
| 穴 (Hole) | セルマスク | 開ける / 塞ぐ |
| 草 (Grass) | 草の層 | 層の追加・削除、密度・高さ帯・傾斜上限の調整、塗り足し / 消し |
| 表面 (Surface) | マテリアル | Terrain マテリアルの割り当てとタイリング |

## 形モード

### ブラシ

既存の `TerrainBrushOperation` をそのまま使う。追加するのは操作の速さだけである。

- 半径と強さは**カーソル上で直接**変える。`[` `]` で半径を変える。`Shift` + ドラッグで強さを変える。数値欄はパネルにも置く。地面から目を離さずに済む経路を主にする
- ブラシ円は Scene View に**常時表示**する。半径と落ち方が見えていないと、どこが変わるか予測できない
- `Ctrl` を押している間は逆操作にする（盛る↔削る、開ける↔塞ぐ）。持ち替えを挟まない

ブラシを押してから離すまでを、Undo の 1 件にまとめる。既存の `handleTerrainStrokeStart` がこの区切りを管理している。専用モードでも同じ扱いにする。

### 高さを揃える

`flatten` は現在「ブラシ中心の高さ」へ揃える。この動作に**基準高さの取得**を足す。`Alt` + クリックでその地点の高さを取得する。以降はその高さへ揃える。道や広場を作るときに、同じ高さを繰り返し狙う必要がなくなる。

## 草モード

草はルール配置で始まる。ただし**塗りは必ず必要になる**。「ここだけ生やしたくない」という指定はルールでは表せないためである。

### マスク

`TerrainGrassLayer` へ任意の `mask` を足す。

```
mask?: number[]   // 0..1、Terrain の resolution と同じ並び
```

- **省略時は一様に 1 である。**既存の層はそのまま動く。塗って初めて配列が生まれる
- 解像度は高さフィールドと**同じにそろえる**。別解像度にすると、彫ったときの対応付けが壊れる
- `serialization.ts` の許可キーへ足す。`generateTerrainGrassInstances` の候補判定へも同時に足す。片方だけでは、保存した時点で Scene が読めなくなる

配置側は `hash(seed, index, 5) < maskAt(localX, localZ)` を候補の採否へ加える。この条件であれば、密度の安定性（増やしても既存が動かない）を保てる。

- ブラシで**足す / 消す**。強さはマスク値の増減量である
- いま編集中の層だけを塗る。複数層を同時に塗ると、何をしたのか後から読めない
- 編集中の層を Scene View で**強調表示**する。他層は薄く出す

### 層のパネル

草は**レイヤー**として扱う。Unity の Terrain Layers と同じく、一覧へ積み上げていく形にする。上から順に並べる。選択中の層は 1 つである。塗りはその層へ入る。

層の一覧表示、追加、削除、並べ替えを用意する。各層は種類・密度・高さ帯・傾斜上限を持つ。選択中の層は一覧の中で見て分かるようにする。塗り・消しはその選択に従う。層ごとにボタンを置く。「どの層を塗っているのか」を毎回選ばせ直さない配置にする。

**実際に置かれた本数と、密度が要求した本数は常に表示する。**上限で丸めたときはその旨を出す。何も出さずに切り捨てない。

### MCP から草を扱う

草は長い間 Inspector からしか操作できなかった。このため、AI が作った Terrain は地面だけの状態で渡されていた。パネルと同じ操作単位で tool を分けている。草の配列をまるごと受け取る tool にはしない。一部だけ間違った要求で、調整済みの層が推測値へ置き換わってしまうためである。

| Tool | 対応する操作 |
| --- | --- |
| `list_terrain_grass_types` | 種類カタログ、preset、密度・傾斜・高さ帯・上限の一覧 |
| `apply_terrain_grass_preset` | 「セットを適用」。層を積むのではなく置き換える |
| `add_terrain_grass_layer` | 「レイヤーを追加」。appearance は同時に渡せる |
| `update_terrain_grass_layer` | 種類・密度・高さ帯・傾斜上限・seed・appearance の変更と、`index` による並べ替え |
| `delete_terrain_grass_layer` | 層の削除 |
| `paint_terrain_grass` | 塗り足し / 消し。層を1つ指定する |

`appearance` の各項目へ `null` を渡すと、その上書きだけが消える。`patch.appearance` 自体へ `null` を渡すと、種類の値へ全部戻る。省略は「今の値をそのまま」である。この 3 つを混同せずに使い分ける。`patch.mask` へ `null` を渡すと、塗りだけを戻す。

`get_terrain` は層ごとに、解決後の色とこの Terrain で実際に置かれる本数を返す。上限で丸めた層は `clampedByInstanceLimit` で分かる。Inspector と同じく、黙って切り捨てない。

## 表面モード

Terrain マテリアルは現在ひとつである。ここへ**高さと傾斜による混合**を入れる。

- 低い所 / 高い所 / 急斜面に別のマテリアルを割り当てる。境界をぼかす
- 実装は Terrain 専用のシェーダーになる。Water と同じく preset 付きのカスタムシェーダーとして配る形にする。既存の公開経路に乗るためである

これは草より重い作業である。**草のマスクを先に済ませてから着手する。**

## 性能

### 距離カリングと LOD

草は現在、全インスタンスを常に描いている。広い Terrain では処理が追いつかなくなる。

- 距離カリング: 既定 40m である。層ごとに設定できるようにする
- LOD: 近距離は交差カードにする。遠距離は 1 枚へ落とす
- 実装は InstancedMesh を距離帯ごとに分ける形にする。1 つの Mesh の中でカードを減らすことはできない

`TERRAIN_GRASS_MAX_INSTANCES` は実装済みである。ただし**まだ UI へ出していない**。草モードのパネルで「上限に達したので丸めた」ことを示す。

## 公開への反映

**未実装である。これが残りで一番大きい。**

`runtime.json` へ載せるのは種類 id、密度、高さ帯、傾斜上限、seed、マスクだけである。GLSL もインスタンス座標も載せない。公開物のサイズは密度に比例しなくなる。

ランタイム側で同じ配置を再生成する必要がある。**Studio 側と生成アルゴリズムが一致していないと、Play と公開後で草の位置がずれる。**

一致のさせ方は 2 案ある。

1. **生成 World へアルゴリズムを直接埋め込む。**出力されたコードがアルゴリズムそのものを含む。このため、二重管理が起きない
2. ランタイムパッケージへ実装を置き、fixture で TS 実装と突き合わせる

1 を選ぶ。2 は「同じものを 2 箇所に書いて、テストで一致を確認する」形になる。ずれる余地が残るためである。1 なら埋め込んだ関数を fixture 内で評価できる。TS 実装と同じ入力から同じ出力が出ることを直接確かめられる。

## 実装順

1. **草のマスク** — データ、配置側の判定、塗り操作。専用モードの土台になる（実装済み）
2. **モード制のパネル** — アイコンタブでの形 / 穴 / 草の切り替えと、草のレイヤー選択。Inspector の中で先に形にする（実装済み）
3. **専用モードの枠** — Scene View 側の Terrain 以外の選択停止、戻り先
4. **形モードの操作改善** — カーソル上での半径・強さ、常時ブラシ円、高さの吸い取り
5. **距離カリングと LOD** — 広い Terrain が実用になる
6. **公開への反映** — 上記の埋め込み方式と fixture（実装済み）
7. **表面モード** — 高さ・傾斜によるマテリアル混合

## 注意

- Scene document のスキーマへ追加するときは、`serialization.ts` の許可キーと MCP の対応ツールを同時に更新する。片方を忘れると、保存した時点で Scene が読めなくなる
- 草の配置に手を入れるときは、密度を上げても既存の blade が動かない性質を壊さない。`terrain-grass.fixture.ts` が固定している
- 専用モードへ入っている間も、Play への遷移と保存は塞がないこと
