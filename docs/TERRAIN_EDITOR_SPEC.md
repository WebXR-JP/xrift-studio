# 地形エディター仕様

地形の編集には多くの操作が伴い、通常のコンポーネントと同じ設定パネルでは扱いにくい。この文書では、地形編集を専用エディターとして切り出す設計をまとめる。

なお、この文書は設計の記録であり、「実装済み」と明記した部分以外は未実装である。

## なぜ専用にするのか

地形はブラシを選び、地面を繰り返し塗りながら編集する。通常の設定パネルのままでは次の問題がある。

- ブラシの半径・強さ・種類を変えるたびに、地面から右パネルへ視線を移さなければならない。
- 高さ、草、穴、マテリアルが同じ縦長のリストに混在し、いま編集している項目が分かりにくい。
- 地形の編集中も他のオブジェクトを選択できてしまい、誤って別の物を動かしてしまうことがある。

## 全体の形

地形を選択して「地形を編集」に入ると、専用モードへ切り替わる。

- シーン上の操作対象を地形だけに限定し、他のオブジェクトのギズモと選択を止める。
- 左下にモード切替用のツールバーを出し、右側には選択中モード専用の設定パネルだけを表示する。
- `Escape` キーまたは「編集を終了」ボタンで通常のエディターへ戻れるようにし、戻り先の操作は常に画面へ残す。

### ツールバーの見せ方

Unity の地形設定にならい、モードはアイコン付きのタブとして横一列に並べる。選択中のモードだけが押された状態になり、そのモードで使う設定だけを下へ表示する。現在どのモードが有効か一目で分かるよう、「操作」のようなドロップダウン選択は使わない。

アイコンだけで操作の意味を表さず、各タブには読めるラベルと `title` 属性を添える。形モード内のブラシ（盛る・削る・ならす・高さを揃える・スタンプ）も同じ方針とし、一覧の中で選択中のブラシが常に見えるアイコン付きのボタン列にする。

モードは次の 4 つで、同時に有効になるのは常に 1 つだけとする。

| モード | 触るもの | 主な操作 |
| --- | --- | --- |
| 形 (Sculpt) | 高さフィールド | 盛る / 削る / 高さを揃える / ならす / スタンプ |
| 穴 (Hole) | セルマスク | 開ける / 塞ぐ |
| 草 (Grass) | 草の層 | 層の追加・削除、密度・高さ帯・傾斜上限の調整、塗り足し / 消し |
| 表面 (Surface) | マテリアル | 地形マテリアルの割り当てと繰り返し |

## 形モード

### ブラシ

既存の `TerrainBrushOperation` をそのまま利用し、操作のしやすさだけを改善する。

- 半径と強さはカーソル上で直接変更できるようにする（`[` `]` で半径を変更、`Shift` + ドラッグで強さを変更）。パネル側にも数値欄を置くが、地面から目を離さずに済む操作を主とする。
- 変更範囲と減衰が予測できるよう、ブラシ円はシーン上に常時表示する。
- `Ctrl` を押している間は逆操作（盛る ↔ 削る、開ける ↔ 塞ぐ）に切り替え、ツールを持ち替えずに修正できるようにする。

ブラシを押してから離すまでの一連の操作は、元に戻す（Undo）の 1 件にまとめる。既存の `handleTerrainStrokeStart` がこの区切りを管理しているため、専用モードでも同じ仕組みを使う。

### 高さを揃える

現在の `flatten` はブラシ中心の高さへ揃える仕様だが、基準高さを取得する操作を追加する。`Alt` + クリックで指定地点の高さを取得し、以降はその高さへ揃えられるようにすることで、道や広場を作るときに同じ高さを毎回狙い直す手間を省く。

## 草モード

草はルールに従って配置するが、特定の場所だけ生やさないといった微調整には、ルール配置に加えて塗り操作が必要になる。

### マスク

`TerrainGrassLayer` に任意の `mask` を追加する。

```
mask?: number[]   // 0..1、Terrain の resolution と同じ並び
```

- 省略時は全サンプルを 1 として扱う。既存の層はそのまま動作し、塗り操作を行ったタイミングで配列を生成する。
- 解像度は高さフィールドと同じにする。解像度が異なると、地形を編集したときに各サンプルを正しく対応付けられない。
- `serialization.ts` の許可キーと `generateTerrainGrassInstances` の候補判定の両方を同時に更新する。片方だけを足すと、保存した時点でシーンが読み込めなくなる。

配置判定には `hash(seed, index, 5) < maskAt(localX, localZ)` を加える。この条件にすれば、密度を増やしても既存の草の位置が動かない性質を維持できる。

- ブラシで塗り足し・消しを行い、ブラシの強さをマスク値の増減量とする。
- 複数層を同時に塗ると変更内容が追いにくくなるため、編集対象は選択中の 1 層だけに限定する。
- シーン上では編集中の層を強調表示し、他の層は薄く表示する。

### 層のパネル

Unity の地形 Layers と同じく、草の層を上から順に並べて表示する。選択できる層は常に 1 つとし、塗り操作はその層だけに適用する。

層の一覧表示・追加・削除・並べ替えを用意し、各層に種類・密度・高さ帯・傾斜上限を持たせる。選択中の層は一覧の中で明確に区別し、層ごとに塗り・消しのボタンを配置することで、「どの層を塗っているか」を毎回選び直さずに済むようにする。

実際に配置された本数と密度から要求された本数は常に表示し、上限で丸めた場合は黙って切り捨てず、その旨を画面に示す。

### MCP から草を扱う

草を設定パネルからしか操作できなかった時期は、AI が草のない地形を作っていた。そこで MCP にもパネルと同じ単位の操作を用意する。草の配列全体を一括で渡す方式では、一部の誤りで調整済みの層まで上書きしてしまうおそれがあるため、層単位のツールに分割する。

| Tool | 対応する操作 |
| --- | --- |
| `list_terrain_grass_types` | 種類カタログ、プリセット、密度・傾斜・高さ帯・上限の一覧 |
| `apply_terrain_grass_preset` | 「セットを適用」。層を積むのではなく置き換える |
| `add_terrain_grass_layer` | 「レイヤーを追加」。appearanceは同時に渡せる |
| `update_terrain_grass_layer` | 種類・密度・高さ帯・傾斜上限・seed・appearanceの変更と、`index`による並べ替え |
| `delete_terrain_grass_layer` | 層の削除 |
| `paint_terrain_grass` | 塗り足し / 消し。層を1つ指定する |

`appearance` の各項目に `null` を渡すとその上書きだけが消え、`patch.appearance` 自体に `null` を渡すと種類の既定値へすべて戻る。項目を省略した場合は現在の値をそのまま残す。これら 3 つの違いを明確に使い分ける。また、`patch.mask` に `null` を渡すと塗りマスクだけをリセットする。

`get_terrain` は層ごとに、解決後の色とその地形で実際に配置される本数を返す。上限によって丸められた層は `clampedByInstanceLimit` で判別でき、設定パネルと同様に黙って切り捨てない。

## 表面モード

現在の地形マテリアルは 1 種類のみだが、高さと傾斜に応じた混合を導入する。

- 低い場所・高い場所・急斜面に別々のマテリアルを割り当て、境界をぼかしてつなぐ。
- 既存の公開経路にそのまま乗せるため、実装は水面と同じくプリセット付きの地形専用カスタムシェーダーとして提供する。

草の実装より規模が大きいため、草のマスクを完了してから着手する。

## 性能

### 距離カリングと LOD

現状の草はすべてのインスタンスを常時描画しているため、広い地形では処理が追いつかなくなる。

- 距離カリング: 既定 40m とし、層ごとに設定できるようにする。
- LOD: 近距離は交差カード、遠距離は 1 枚のカードへ落とす。
- 1 つのメッシュ内でカード枚数を減らすことはできないため、`InstancedMesh` を距離帯ごとに分けて実装する。

`TERRAIN_GRASS_MAX_INSTANCES` 自体は実装済みだが、まだ UI には表示していない。草モードのパネルで上限到達による丸めを明示する。

## 公開への反映

この節は未実装時点の設計を記録したものである。現在の実装状況は、冒頭の「現状（確認済み）」と末尾の「実装順」を参照する。

`runtime.json` には種類 ID、密度、高さ帯、傾斜上限、`seed`、マスクだけを保存し、GLSL やインスタンス座標は含めない。これにより公開物のサイズが密度に比例して肥大するのを防ぐ。

ランタイム側で同じ配置を再生成する際、Studio 側と生成アルゴリズムが異なると、動作確認時と公開後で草の位置がずれてしまう。一致を保証する方法として次の 2 案がある。

1. 生成ワールドへアルゴリズムを直接埋め込む。出力されたコード自体がアルゴリズムを含むため、二重管理が起きない。
2. ランタイムパッケージ側にも実装を置き、フィクスチャテストで TypeScript 実装と突き合わせる。

ここでは 1 を採用する。2 ではアルゴリズムを 2 箇所で保守することになり差分が生じるおそれがあるが、1 であれば埋め込んだ関数をフィクスチャテスト内で直接評価し、TypeScript 実装と同じ入力から同じ出力が得られることを確実に検証できる。

## 実装順

1. 草のマスク — データ構造、配置判定、塗り操作を用意し、専用モードで利用する（実装済み）
2. モード制のパネル — アイコンタブによる形 / 穴 / 草の切り替えと草のレイヤー選択を、まず設定パネル内で形にする（実装済み）
3. 専用モードの枠 — シーン側での地形以外の選択停止と戻り先の確保
4. 形モードの操作改善 — カーソル上での半径・強さ調整、常時ブラシ円表示、高さの取得
5. 距離カリングと LOD — 広い地形を実用的な負荷で描画できるようにする
6. 公開への反映 — 上記の埋め込み方式とフィクスチャテスト（実装済み）
7. 表面モード — 高さ・傾斜によるマテリアル混合

## 注意

- シーンドキュメントのスキーマに項目を追加するときは、`serialization.ts` の許可キーと MCP の対応ツールを同時に更新する。片方を忘れると保存時点でシーンを読み込めなくなる。
- 草の配置処理を変更するときは、密度を上げても既存の草の位置が動かない性質を壊さないようにする（`terrain-grass.fixture.ts` で検証を固定している）。
- 専用モードに入っている間も、Play による動作確認への遷移や保存操作は妨げないようにする。
