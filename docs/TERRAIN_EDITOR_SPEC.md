# Terrain エディター 仕様

Terrain は Studio の中で最も操作が多い機能で、他の Component と同じ Inspector に
並べる限り窮屈になる。専用エディターへ切り出すための設計。

この文書は設計であり、「実装済み」と書いた部分以外は**未実装**である。

## なぜ専用にするのか

Terrain の編集は「対象を選んで値を変える」ではなく「筆を選んで地面を触り続ける」
作業で、他の Inspector 操作と性質が違う。3つの具体的な不都合がある。

- ブラシの半径・強さ・種類を変えるたびに右パネルへ視線を戻すことになり、地面から
  目が離れる
- 高さ、草、穴、マテリアルが同じ縦長のリストに混ざり、いま何を編集しているのかが
  画面から読めない
- Terrain を触っている間も他の Entity が選択対象のままなので、誤って別の物を
  動かせてしまう

## 全体の形

Terrain を選択して「地形を編集」に入ると、**専用モード**へ遷移する。

- Scene View は Terrain だけを操作対象にし、他の Entity のギズモと選択を止める
- 左下に**ツールバー**（モード切替）、右に**そのモード専用のパネル**だけを出す
- Escape または「編集を終了」で通常の Editor へ戻る。**戻り先を常に画面へ残す**

### ツールバーの見せ方

Unity の Terrain Inspector に合わせる。モードは**アイコンのタブ**として横一列に
並べ、選択中のモードだけが押された状態になる。選んだモードの設定だけを下へ出し、
使わない設定は出さない。「操作」のドロップダウンから選ぶ形は、いま何が有効なのか
が読めないので使わない。

アイコンだけに意味を預けない。各タブには読めるラベルを添え、`title` も付ける。
形モードの中の筆（盛る・削る・ならす・高さを揃える・スタンプ）も同じくアイコン
付きのボタン列にする。ドロップダウンでは、いま選んでいる筆が一覧の中に見えない。

モードは4つ。同時に有効なのは常に1つで、いま何を触っているのかを画面が示す。

| モード | 触るもの | 主な操作 |
| --- | --- | --- |
| 形 (Sculpt) | 高さフィールド | 盛る / 削る / 高さを揃える / ならす / スタンプ |
| 穴 (Hole) | セルマスク | 開ける / 塞ぐ |
| 草 (Grass) | 草の層 | 層の追加・削除、密度・高さ帯・傾斜上限の調整、塗り足し / 消し |
| 表面 (Surface) | マテリアル | Terrain マテリアルの割り当てとタイリング |

## 形モード

### ブラシ

既存の `TerrainBrushOperation` をそのまま使う。追加するのは操作の速さだけ。

- 半径と強さは**カーソル上で直接**変える。`[` `]` で半径、`Shift` + ドラッグで強さ。
  数値欄はパネルにも置くが、地面から目を離さずに済む経路を主にする
- ブラシ円は Scene View に**常時表示**する。半径と落ち方が見えていないと、どこが
  変わるか予測できない
- `Ctrl` を押している間は逆操作（盛る↔削る、開ける↔塞ぐ）。持ち替えを挟まない

### 高さを揃える

`flatten` は現在「ブラシ中心の高さ」へ揃える。これに**基準高さの取得**を足す。
`Alt` + クリックでその地点の高さを吸い取り、以降その高さへ揃える。道や広場を
作るときに、同じ高さを繰り返し狙う必要がなくなる。

### アンドゥの単位

1ストロークで1件。押している間の連続適用を1件にまとめる。これは既存の
`handleTerrainStrokeStart` が持っている境界なので、専用モードでも同じ扱いにする。

## 草モード

草はルール配置で始まるが、**塗りは必ず要る**。「ここだけ生やしたくない」は
ルールでは書けない。

### マスク

`TerrainGrassLayer` へ任意の `mask` を足す。

```
mask?: number[]   // 0..1、Terrain の resolution と同じ並び
```

- **省略時は一様に 1**。既存の層はそのまま動き、塗って初めて配列が生まれる
- 解像度は高さフィールドと**同じにそろえる**。別解像度にすると、彫ったときの
  対応付けが壊れる
- `serialization.ts` の許可キーと、`generateTerrainGrassInstances` の候補判定へ
  同時に足すこと。片方だけだと保存した時点で Scene が読めなくなる

配置側は `hash(seed, index, 5) < maskAt(localX, localZ)` を候補の採否へ加える。
これなら密度の安定性（増やしても既存が動かない）を壊さない。

### 塗りの操作

- ブラシで**足す / 消す**。強さはマスク値の増減量
- いま編集中の層だけを塗る。複数層を同時に塗ると、何をしたのか後から読めない
- 編集中の層を Scene View で**強調表示**する。他層は薄く出す

### 層のパネル

草は**レイヤー**として扱う。Unity の Terrain Layers と同じく、一覧へ積み上げて
いく形にする。上から順に並び、選択中の層が1つあり、塗りはその層へ入る。

層の一覧、追加、削除、並べ替え。各層に種類・密度・高さ帯・傾斜上限。
選択中の層は一覧の中で見て分かるようにし、塗り・消しはその選択に従う。層ごとに
ボタンを置いて「どの層を塗っているのか」を毎回選ばせ直さない。

**実際に置かれた本数と、密度が要求した本数を常に表示する。** 上限で丸めたときは
その旨を出す。黙って切り捨てない。

### MCP から草を扱う

草は長い間 Inspector からしか触れず、AI が作った Terrain は地面だけの状態で
渡されていた。パネルと同じ操作単位で tool を分けてある。草の配列をまるごと
受け取る tool にはしない。一部だけ間違った要求で、調整済みの層が推測値へ
置き換わるため。

| Tool | 対応する操作 |
| --- | --- |
| `list_terrain_grass_types` | 種類カタログ、preset、密度・傾斜・高さ帯・上限の一覧 |
| `apply_terrain_grass_preset` | 「セットを適用」。層を積むのではなく置き換える |
| `add_terrain_grass_layer` | 「レイヤーを追加」。appearance は同時に渡せる |
| `update_terrain_grass_layer` | 種類・密度・高さ帯・傾斜上限・seed・appearance の変更と、`index` による並べ替え |
| `delete_terrain_grass_layer` | 層の削除 |
| `paint_terrain_grass` | 塗り足し / 消し。層を1つ指定する |

`appearance` の各項目へ `null` を渡すとその上書きだけが消え、
`patch.appearance` 自体へ `null` を渡すと種類の値へ全部戻る。省略は「今の値を
そのまま」なので、この3つを混同しないこと。`patch.mask` へ `null` を渡すと
塗りだけを戻す。

`get_terrain` は層ごとに、解決後の色とこの Terrain で実際に置かれる本数を返す。
上限で丸めた層は `clampedByInstanceLimit` で分かる。Inspector と同じく、黙って
切り捨てない。

## 表面モード

Terrain マテリアルは現在ひとつ。**高さと傾斜による混合**をここへ入れる。

- 低い所 / 高い所 / 急斜面に別のマテリアルを割り当て、境界をぼかす
- 実装は Terrain 専用のシェーダーになる。Water と同じく preset 付きの
  カスタムシェーダーとして配る形が、既存の公開経路に乗る

これは草より重い。**草のマスクを先に済ませてから着手する。**

## 性能

### 距離カリングと LOD

草は今、全インスタンスを常に描いている。広い Terrain では効かなくなる。

- 距離カリング: 既定 40m。層ごとに設定可能にする
- LOD: 近距離は交差カード、遠距離は1枚へ落とす
- 実装は InstancedMesh を距離帯ごとに分ける形にする。1つの Mesh の中で
  カードを減らすことはできない

### 上限の見せ方

`TERRAIN_GRASS_MAX_INSTANCES` は実装済みだが、**まだ UI へ出していない**。
草モードのパネルで「上限に達したので丸めた」ことを示す。

## 公開への反映

**未実装。これが残りで一番大きい。**

`runtime.json` へ載せるのは種類 id、密度、高さ帯、傾斜上限、seed、マスクだけ。
GLSL もインスタンス座標も載せない。公開物のサイズが密度に比例しなくなる。

ランタイム側で同じ配置を再生成する必要がある。**Studio 側と生成アルゴリズムが
一致していないと、Play と公開後で草の位置がずれる。**

一致のさせ方は2案ある。

1. **生成 World へアルゴリズムを直接埋め込む。** 出力されたコードがアルゴリズム
   そのものを含むので、二重管理が起きない
2. ランタイムパッケージへ実装を置き、fixture で TS 実装と突き合わせる

1 を推す。2 は「同じものを2箇所に書いて、テストで一致を見張る」形になり、
ずれる余地を残す。1 なら埋め込んだ関数を fixture 内で評価して、TS 実装と
同じ入力から同じ出力が出ることを直接確かめられる。

## 実装順

1. **草のマスク** — データ、配置側の判定、塗り操作。専用モードの土台になる（実装済み）
2. **モード制のパネル** — アイコンタブでの形 / 穴 / 草の切り替えと、草のレイヤー
   選択。Inspector の中で先に形にする（実装済み）
3. **専用モードの枠** — Scene View 側の Terrain 以外の選択停止、戻り先
4. **形モードの操作改善** — カーソル上での半径・強さ、常時ブラシ円、高さの吸い取り
5. **距離カリングと LOD** — 広い Terrain が実用になる
6. **公開への反映** — 上記の埋め込み方式と fixture（実装済み）
7. **表面モード** — 高さ・傾斜によるマテリアル混合

## 注意

- Scene document のスキーマへ追加するときは `serialization.ts` の許可キーと MCP の
  対応ツールを同時に更新する。片方を忘れると、保存した時点で Scene が読めなくなる
- 草の配置に手を入れるときは、密度を上げても既存の blade が動かない性質を壊さない。
  `terrain-grass.fixture.ts` が固定している
- 専用モードへ入っている間も、Play への遷移と保存は塞がないこと
