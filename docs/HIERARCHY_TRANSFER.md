# Hierarchyの受け渡し契約

- 基礎実装: 2026-09-14
- 今回の統合: PR #101 相当の UI 調整版
- 対象: ビジュアルプロジェクトの Entity 選択範囲
- 関連資料: 操作手順は[利用者向けガイド](./guide/hierarchy-transfer.md)、画面状態は[F-46](./ux/editor.md#f-46)、検証結果は[検証記録](./AUTHORING_WORKFLOW_VERIFICATION.md)を参照する。

## 目的と境界

ワールド → アイテム、アイテム → ワールド、ワールド → ワールド、アイテム → アイテムの 4 パターンをすべて同じ追加処理で扱う。別プロジェクトとして開く操作と、現在の Hierarchy へ Entity を追加する操作は明確に分離する。なお、公開済みワールドからの抽出や、コードプロジェクトの任意ソース解析は行わない。

追加インポートでは追加先の `projectKind` を維持し、ワールド／アイテムの選択は書き出し時に行えるようにする。種別をまたぐ場合も既存の追加計画と同じ Component 制約を適用する。たとえばワールドの家具をアイテムにしたい場合は、アイテムプロジェクトを作成してその Hierarchy へ家具を追加すれば、以降の編集と公開は既存のアイテム向け経路でそのまま行える。

## .xriftstudioとの互換性

ZIP コンテナー、`.xrift-studio/package-manifest.json` の `formatVersion: 1`、編集ドキュメントの `schemaVersion: 0.1.0` をそのまま維持する。新しい拡張子や、既存データの移行が必須となるスキーマは導入しない。

部分書き出しは、選択範囲を 1 つの通常のビジュアルプロジェクトとして出力する。新しい `projectId` と `sceneId` を採番し、`scenes/hierarchy.scene.json`、`assets/manifest.json`、および参照ファイルを格納するため、独立したプロジェクトとしてそのまま開くこともできる。これに加えて、次の補助情報を `.xrift-studio/hierarchy-transfer.json` に格納する。

```json
{
  "format": "xrift-studio-hierarchy",
  "formatVersion": 1,
  "sourceProjectKind": "world",
  "warnings": []
}
```

この補助情報は既存ドキュメントを置き換えるものではなく、注意事項と形式の識別を補う役割を持つ。読み込み時には未来の形式バージョンや不正な注意事項を拒否する。補助情報を持たない従来のビジュアル `.xriftstudio` / `.zip` も読み込めるが、複数シーンを含むパッケージでは 1 度につき 1 つのシーンを選んで取り込む。

元の `lastPublication`、公開記録の付随ファイル、シーン全体の設定、未使用素材、キャッシュは選択範囲へ持ち込まない。一方で Asset の著作者・提供元など、素材に付随する帰属情報はコピーする。既存のパッケージマニフェストに含まれるファイル一覧と SHA-256 は既存の書き出し処理が生成するものであり、署名や Script の安全性を保証するものではない。

## 選択範囲と依存素材

- 親と子を同時に選んだ場合は祖先を 1 つのルートとして扱い、その子孫をすべて含める。親のチェックから子だけを外した場合は親の選択も解除し、残した子や兄弟をそれぞれ独立したルートにする。Entity が存在しない場合、親子関係が循環している場合、子が重複している場合、参照が欠けている場合は明示的に中止する。
- 参照フィールドから Asset の依存関係をたどり、Model → Material → Texture、Script、Audio、Font、Graph、Shader などの必要な素材と、それらが属する親フォルダーを含める。元の Model への編集履歴リンクはそれだけでは依存素材に含めず、派生サムネイルは再生成対象とする。最適化前のバックアップを参照している場合は、その元ファイルも含める。
- glTF の相対パスのバッファーや画像、OBJ の MTL、MTL が参照するテクスチャは元の相対ディレクトリ構成ごと収集する。外部 HTTP 参照、絶対パス、プロジェクト外へ出るパスは取得しない。オプション付きの MTL については GLB へ変換するよう案内する。任意の Script 本文を解析・評価して依存ファイルを探す処理は行わない。
- Prefab Instance は既存のリゾルバーで現在の Entity へ展開し、元の Prefab とのリンクを切る。無効な親の中にあるなどリゾルバーが展開しない Instance は黙って消さずに中止する。実行時テンプレートの参照は Hierarchy への展開が必要なものとして拒否し、Model 内部の Entity を選ぶ場合は所有する Model を一緒に選ぶ。

## 参照の再割り当て

追加のたびに Entity、Component、Asset、Asset フォルダーの ID を新しく生成する。Component ID は Entity 単位で振られているため、対応表のキーには元の Entity ID と Component ID の両方を含める。ファイルは新しい `assets/imported/hierarchy-<id>/` 配下へ元の相対ディレクトリ構成を維持したまま格納し、同名の Asset・同じ ID・同じファイル名であっても既存の内容は上書きしない。

- 変換対象は、型付きの参照フィールド、Component の `entityReferences` / `assetReferences` で宣言されたプロパティ、Graph の Entity・Component・Asset 設定とする。表示名、文章、コード、URL、シェーダーソースに対する一括文字列置換は行わない。Graph の `scene` / `self` / `player` 用特殊 ID はそのまま残す。
- 選択範囲に含まれない Entity への参照は空にし、その Component を無効化する。Graph 内の参照も空にして未設定状態とし、注意事項を表示する。追加先に偶然一致する ID があっても結び付けない。登録済み Component の `uniqueWithinScene` な文字列も新しく採番するが、コード内に直接書かれた ID や独自の一意キーは制作者側で確認する必要がある。
- 追加先のプロジェクト種別で使えない、または定義が存在しない XRift Component は、設定値を残したまま無効にする。標準の Spawn Point は追加先に応じて `player` または `item-preview` へ切り替える。ただし、すべてのギミックが異なる種別でも同じように動作する保証はない。
- Script の `play-and-edit` は受け渡し用のスナップショット作成時に `play` へ変更し、直接の取り込み計画でも再確認する。元の Script Asset 本文や元プロジェクトの実行設定は変更せず、受け渡し操作から Play を自動開始することもしない。既存の Script ランタイムはサンドボックスではないため、Play 時の安全性はコードの内容に依存する。

## 座標

配置時の座標変換には次の 3 方式を用意する。

- `world`: 選択ルートをワールド座標へ変換する。追加先に親がある場合は、親のワールド行列の逆行列を使ってローカル座標へ変換する。
- `local`: 元のローカル TRS をそのまま使う。
- `origin`: `world` 変換後の先頭ルートの位置を全ルートから引き、親またはシーンの原点へ移す。回転・大きさとルート間の相対配置はそのまま残す。

TRS で行列を再構成できないせん断変形（shear）と、逆変換できない大きさ 0 は拒否し、形状が変わる近似変換は行わない。すでに部分書き出しされたファイルは保存時の TRS を基準とし、切り離した元の親は復元しない。

## 追加とUndo

処理は `createHierarchyTransfer` → `prepareHierarchyTransferFiles` → `planHierarchyImport` → `applyHierarchyImportPlan` の順で進める。計画段階では元のバンドルも追加先のバンドルも変更しない。

素材バイト列を読み終え、既存のコーデックでドキュメントを検証して確認を得たあと、既存の `commitVisualAssetImport` で素材を書き込む。書き込み前後に対象バンドル・`projectPath`・編集状態を確認し、途中で変わっていた場合はドキュメントを追加しない。既存の Entity は参照を維持したまま追加先の親だけをイミュータブルに更新し、更新後のバンドル全体を 1 件の編集履歴に積む。

Undo を行うと Entity と Asset の登録がまとめて元に戻る。Redo に備えて、書き込んだ素材ファイル自体は残す。書き込み後に別操作でリビジョンが変わり追加を中止した場合も、未参照の管理ファイルが残ることがある。ドキュメント・ファイル・永続保存を一括確定する DB トランザクションは追加しておらず、追加後の永続保存には既存の自動保存を用い、保存エラーも既存の UI で扱う。

## UIと入出力

- 同一ウィンドウ・タブ内のモジュール内クリップボードに、素材バイト列付きのスナップショットを保持する。プロジェクトを切り替えても消えないが、OS のクリップボード、別ウィンドウ・別タブ、アプリ再起動、他アプリへの貼り付けには対応しない。長期保存や端末間の受け渡しにはファイルを使う。
- 部分書き出しは Scene / Hierarchy 共通の右クリックメニューから、追加インポートは上部の「素材を追加」から確認ダイアログへ入る。ダイアログにはネイティブ `<dialog>` のモーダル・フォーカス管理を使い、処理中の変更・終了・二重実行を防ぐ。Entity の選択一覧は描画件数を制限して検索に対応し、インポートが完了するまで確認画面を閉じず失敗理由を残す。
- ブラウザ版では準備完了後に利用者がダウンロードリンクを押して保存する（保存開始と保存完了を混同しない）。デスクトップ版では型付き IPC `saveHierarchyPackage` で保存先を明示的に選び、新規の `save_hierarchy_package` でサイズと形式を検証したあと、一時ファイルへ書き出してリネームする方式で保存する。既存の全プロジェクト書き出し機能は置き換えない。

## 制限

| 対象 | 上限・扱い |
| --- | --- |
| 選択Entity | 20,000件 |
| 素材ファイル | 512件、1ファイル128 MB、合計256 MB |
| ZIP | ファイル本体と展開後256 MB、既存リーダーの20,000エントリー上限 |
| 対象 | 編集可能なビジュアルプロジェクトのみ |
| 複数シーン | 入力で選択可能。一度の追加・書き出しは一つのシーン |
| 同期リンク | 元Prefab・元プロジェクトとの継続同期なし |

MCP 向けに選択範囲のインポート／エクスポートを行う新しいツールは追加していない。UI のファイル選択・ダウンロード・セッションクリップボードは人の操作と権限に依存するため公開しない。将来的に独立した機械操作 API を追加する場合は、バイト列の受け渡し・管理パス・リビジョン・実行承認の仕様を別途定める。現在の 147 ツールの成功条件は変更しない。
