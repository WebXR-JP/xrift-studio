# プロジェクトの受け渡し形式

XRift Studio のプロジェクトは、`.xriftstudio` ファイルにまとめて受け渡す。iPad のブラウザ版、デスクトップ版、MCP の `export_project` はすべて同じ拡張子を使う。既存の ZIP 構造とパッケージマニフェストをそのまま利用し、編集用ドキュメントの形式は変更しない。

## 拡張子と互換性

| 項目 | 仕様 |
| --- | --- |
| 書き出すファイル名 | `プロジェクト名.xriftstudio` |
| 取り込める拡張子 | `.xriftstudio`、従来の `.zip` |
| 内部形式 | ZIP。プロジェクト直下、または 1 つのフォルダーの中にプロジェクトを格納する |
| ブラウザの対象 | ビジュアルエディターのプロジェクト |
| デスクトップ・MCP の対象 | ビジュアルエディターとコードエディターのプロジェクト |

拡張子は XRift Studio のプロジェクトを見分けるために使う。取り込み時は ZIP の内容、パス、容量、プロジェクト定義を検証する。パッケージマニフェストのない従来の ZIP も取り込み対象とし、拡張子だけで有効なプロジェクトとは判定しない。

## パッケージの内容

ビジュアルプロジェクトには `xrift-studio.project.json`、全シーン、Assets、プレハブ、取り込んだ素材を含める。コードプロジェクトは `xrift.json` を含む既存のプロジェクト構成を維持する。`node_modules`、`.git`、`dist`、キャッシュ、公開記録のサイドカーファイルは書き出しに含めない。

`.xrift-studio/package-manifest.json` には既存の次の情報を記録する。

| キー | 内容 |
| --- | --- |
| `format` | `xrift-studio-package` |
| `formatVersion` | `1` |
| `files` | 格納ファイルの `path`、バイト数の `size`、`sha256` |
| `studioVersion` | デスクトップ版が記録する Studio のバージョン |

`files` はパッケージマニフェスト自身を除く格納ファイルの一覧であり、信頼性の署名や取り込みの許可条件ではない。書き出すたびに、実際に格納するバイト列から再生成する。

取り込み先では新しい `projectId` を割り当て、`lastPublication` と公開記録を引き継がない。受け取った作品を公開しても、元のワールドが上書きされないようにするためである。

## 操作と容量

デスクトップ版のカードでは「.xriftstudioファイルに書き出す」「ファイルから取り込む」と案内する。ブラウザ版では「プロジェクトを書き出す」で保存し、「開く」から「ファイルを選ぶ」で取り込む。iPad で保存した `.xriftstudio` ファイルを Mac や Windows へ渡し、デスクトップ版から取り込んで公開できる。OS のファイル関連付けや、ダブルクリックによるアプリの起動・取り込みは対象外とする。

ブラウザ版ではファイル本体と展開後のデータを 256 MB 以下、ファイル数をパッケージマニフェスト込みで 20,000 以下に制限する。書き出し時はメモリ負荷を抑えるため ZIP の STORE 方式を使い、取り込み時は従来の Deflate にも対応する。

取り込み処理はデスクトップ版の ZIP64 エントリにも対応し、CRC、実際の展開サイズ、参照素材の存在を確認する。ブラウザの編集セッションでは Web Locks を使って同じ作品の複数タブ編集を防ぎ、自動保存と書き出しを順番に処理する。読み込みに成功してから次回の復帰先を更新し、閉じるときは受け付け済みの保存が完了してからロックを解放する。

利用手順は [iPad の案内](./guide/ipad.md)、画面の状態遷移は [F-44](./ux/app.md#f-44) と [F-45](./ux/publishing.md#f-45)、MCP の仕様は [編集ツール](./MCP_EDITOR_TOOLS.md#project-12) を参照する。

## Hierarchy の一部を受け渡す

選択した Entity とその子孫、必要な素材だけを通常のビジュアルプロジェクトとして書き出す。拡張子は同じく `.xriftstudio` を使う。パッケージマニフェストとドキュメントのバージョンは変えず、任意の補助情報として `.xrift-studio/hierarchy-transfer.json`（`format: "xrift-studio-hierarchy"`、`formatVersion: 1`）を添える。補助情報のない従来の全体パッケージからも、シーンと Entity を選んで追加できる。

「Hierarchy へ追加」では、新規プロジェクトとして開く処理とは異なり、追加先の `projectId`・`projectKind`・公開情報をそのまま残す。受け渡す Entity・Component・アセットの ID とファイル格納先は追加のたびに新しく採番し、シーン設定は移さない。詳しくは [Hierarchy の受け渡し契約](./HIERARCHY_TRANSFER.md) と [操作ガイド](./guide/hierarchy-transfer.md) を参照する。
