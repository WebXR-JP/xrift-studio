## F-08 ビジュアル編集素材の制作・取り込みの状態設計

### Blender の編集元をプロジェクトに保存する

参照: MI-03, MI-05

- デスクトップ版で `.blend` を Assets へ追加すると、導入済み Blender で表示用 GLB を生成し、編集元と一緒に保存する。変換中は既存の取り込み進捗を表示し、成功後はそのモデルを選択する。Blender がない場合や変換に失敗した場合は取り込み失敗を表示し、既存素材を維持する。
- モデルの Inspector に「Blenderの編集元」とプロジェクト内パスを表示する。「Blenderで編集」は起動中の二重操作を防ぎ、失敗時は同じ場所に理由を示す。起動後は Blender で保存してから「Blenderから再取り込み」を実行する案内を残す。
- 再取り込みでは既存のモデル ID・配置・読み込み設定を維持し、既存の影響確認を通す。変換に失敗しても最後に成功した表示用モデルを残す。AI で Blender モデルを生成した場合も `.blend` を同じ保存境界に含める。
- `.blend` はパーツごとに取り込める。外部参照はローカル化し、テクスチャは Blender 内へパックする。シーン・Play・公開は同じ GLB を使い、公開時に Blender 変換を追加しない。
- 既存 GLB への編集元追加は開発用の準備・往復検証・保存の 3 段階で行う。表示用 GLB とシーンを維持し、保存済み編集元は同じ Inspector から開ける。移行ツールが保持したテクスチャ参照のない MToon 設定は再取り込み時に復元し、Blender 上の材質表示との違いは利用ガイドで説明する。

### 外部カタログの続きを表示する

- AI LOWPOLY PROPS は Web 版・デスクトップ版で同じ一覧と取り込み処理を使う。全ページを同じカタログ版で取得し、取得中に版が変わった場合は先頭から一度だけ再取得する。一覧の読み込み中・失敗・再試行は既存の外部カタログ表示にそろえる。
- 日本語・英語の名前、ID、タグ、配布元のキーワードで検索でき、全半角・大文字小文字・かなの違いを吸収する。空白やカンマで区切った語をすべて含むモデルを表示する。
- 追加中は既存のボタン無効化と進捗表示を使い、GLB の容量・配布ハッシュ・詳細の CC0 情報を検証してから通常の素材書き込みへ渡す。成功後は Assets で追加したモデルを選択し、エラー時は保存を成功扱いにしない。
- 外部素材は初回に 120 件を表示し、総件数と表示済み件数を下部に示す。「さらに○件を表示」で次の最大 120 件を追加し、最後まで表示したらボタンを隠す。
  - 検索と種類の絞り込みは全件に適用する。条件変更、配布元切替、再読み込み、ダイアログ開き直しでは表示件数を 120 件へ戻す。表示範囲だけの変更であり、追加ダウンロードやシーン更新は発生しない。
- 音蔵では「すべて / SFX（効果音・環境音） / BGM（音楽）」で分類する。音源カテゴリと `music` タグで判定し、名前や説明から推測しない（BGM には歌入りも含む）。分類と検索は併用でき、分類変更時は表示範囲を先頭へ、配布元変更時は分類を「すべて」へ戻す。

### 操作前

- Assets の左側には実フォルダーの親子関係を常時表示し、右側には選択フォルダーの内容を表示する。3D モデル / glTF、テクスチャ、マテリアル、プレハブ、パーティクルの種類別一覧は実フォルダーと区別し、基本形状は別の追加パレットに置く。マテリアル・3D モデル・テクスチャは生成済みサムネイルを優先し、未生成時は種類アイコンを表示する。
- `sceneSelection` と `assetSelection` は独立して保持し、Inspector がどちらを表示中かを背景・見出し・固定タブで明示する。
- 取り込み前に対応形式、HDR / EXR の取り込み時に空の背景へ設定しつつ元データも残すこと、最大解像度・品質・Mipmap・圧縮の既定値、リソース上限、外部 URI の参照先をローカル依存ファイルに限定する条件を確認できるようにする。
- モデルの Inspector には元データ、最後に成功した解析結果、マテリアル枠、アニメーション、境界ボックス、現在の取り込み設定を表示し、解析済みの値と次回再インポート用の設定を区別する。
- マテリアルスロットは件数付きで初期状態を折りたたみ、閉じている間は行と選択肢を生成しない。展開後は 20 件ずつ表示し、スロット名と ID で検索できる（検索変更時は先頭ページへ、該当なし時は検索語変更を案内）。折りたたみ・再展開時は検索とページを初期化するが、保存済み割当は維持する（MI-117）。モデル設定プレビューは 80px、素材グリッドは最小幅 76px・サムネイル高 40px、フォルダーアイコンは 18px に抑える。

### 操作中

- マテリアル作成ダイアログ内に入力検証結果を表示する。テクスチャ・3D モデル・HDRI の取り込みでは、インポートキューに検証・コピー・デコード・派生データとサムネイル生成・確定の進捗を表示し、処理段階に応じてキャンセル可否を制御する。
- MCP の `import_audio_asset` / `import_texture_asset` も編集中に限り、通常インポートと同じ内容ハッシュコピー、アトミック確定、履歴、自動保存を通す。元データの絶対パスはネイティブ側で通常ファイルであること、symlink / reparse point がないこと、対応拡張子、128 MB 上限、読み取り前後サイズ、音声の MP3 / WAV 識別情報を検証する。応答には外部パス・データ URL・バイト列を返さない。
- パーティクルは素材作成から追加し、Inspector で emission、shape、velocity、lifetime、size、color、テクスチャ、blend を編集する。シーンまたは Hierarchy へドラッグして `Particle Emitter` 付き Entity として配置できる。
- 右クリックメニューでは素材の種類と状態に応じて実行可能な項目だけを有効にし、メニューを開いただけでは選択や編集データを変えない。
- 3D モデルの取り込み倍率、Collider 生成、メッシュ最適化、Animation 取り込みを変更した場合は、取り込み設定だけを未保存として再インポートが必要な項目を Inspector に示す。処理中も既存のシーン参照と直前の正常表示を維持する。
- Assets の複数選択では標準マテリアルだけを対象に種類を一括変更できる。すべて同じ種類なら単体と共通の全設定を表示し、異なる値は「一部異なる」と示す。入力した項目だけを素材ごとに反映し、色の他成分と画像の UV を維持する。モデル・画像・カスタムシェーダー素材は変更しない。

### 成功時

- インポート・マテリアル作成は `AssetManifest` とフォルダー所属を一度だけ確定し、新素材を `assetSelection` にする。HDR / EXR 取り込みだけは同じ履歴でシーン設定の空の背景参照も確定し、それ以外は `sceneSelection` と `SceneDocument` を維持する。
- MCP 音声・テクスチャ取り込みは新素材を `assetSelection` にする。同じ種別と元データハッシュが登録済みなら複製せず既存素材を選択し、結果にはプロジェクト相対パスと形式メタデータだけを残す（外部元データパスは表示しない）。
- パーティクル作成は新素材を `assetSelection` にし、配置または `Particle Emitter` 追加時は参照素材 ID を `SceneDocument` に保存する。
- サムネイルと派生データは、元データ・取り込み設定・処理系・対象のハッシュが一致した場合だけ準備済みとする。同じ元データを再インポートしても素材 ID と参照は維持する。マテリアル一覧は保存済み画像を使い、変更時の生成キュー以外で WebGL コンテキストを増やさない。
- マテリアル変更は共有素材へ一度だけ保存し、同じ ID を参照する全プレビューへ反映する。一括変更は 1 回の履歴と自動保存で確定し、元に戻す・やり直すでも複数選択を保ったまま全対象を復元する。
- 3D モデル再インポートは素材 ID を維持し、スロット識別情報が一致する既存マテリアル割当を保持する。新規スロットは未設定として追加し、消失スロットは診断に残して参照先を修正できるようにする。

### 失敗時

- 拡張子、URI、上限、デコード、マテリアル入力、スロット割当に問題がある場合は、対象素材・入力欄・元データ URI（プロジェクト相対パス）を示し、再インポート・設定変更・参照置換を案内する。
- MCP テクスチャ取り込みで相対パス・symlink・未対応形式・署名不一致・古いリビジョンが検出された場合はマニフェストと履歴を変更せず、エラー詳細にも外部絶対パスを含めない。
- 失敗した処理の一時データは削除し、シーン・素材・フォルダー編集データ、両選択、履歴、元データ、直前の正常な派生データはすべて操作前の状態を維持する。同じ設定で自動再試行を繰り返さない。
- 3D モデルメタデータが非有限値、境界ボックス不正、スロット重複、未対応の外部 URI の場合は新しいマニフェストを確定せず、直前の正常なモデル素材と配置済み Entity を維持する。

### 戻り先

- インポートキューを閉じても素材と Inspector に直前の結果・診断を残す。キャンセル時は直前の `assetSelection`・設定画面・シーンへ戻る。
- Play 中は既存マテリアル・パーティクルのプロパティ変更と MCP 経由の既存テクスチャ取り込み設定変更を許可し、テクスチャ元データの新規インポートは Stop まで無効にする。Stop 後も Play 中に保存した変更と選択状態を維持する。

完了条件: マテリアル / テクスチャ / 3D モデル / glTF / OBJ / VRM / プレハブ / パーティクルを左のフォルダーツリー・種類別一覧・保存済みサムネイル付きで管理できる。GLB / VRM の埋め込みマテリアルとテクスチャを再利用可能な素材へ展開し、マテリアル変更時だけ一時レンダラーでサムネイルを更新する（カード自体は WebGL コンテキストを持たない）。HDR / EXR は正距円筒図法テクスチャとして取り込んで即座にシーンへ設定でき、ソースからサムネイルを自動生成・再生成できる。テクスチャは右クリックからプロジェクトサムネイルへ設定でき、シーン設定で実際の画像を確認できる。元データ保持インポート、上下反転を含む取り込み設定編集、参照を保つ再インポート、古い派生データ診断、GLB / VRM の Node・Bone・メッシュ単位編集、Animation 取り込みモデルの再生設定に対応し、素材編集中も `sceneSelection` を維持する。

## F-15 OBJ / VRM 取り込みと静的モデルポーズの状態設計

### 操作前

- インポート操作に GLB / glTF / OBJ / VRM を同じ 3D モデル形式として並べる。OBJ は単体ジオメトリを取り込み、外部 MTL やテクスチャを自動取得しないこと、必要なマテリアルは XRift Studio 内で割り当てることを示す。
- VRM 0.x / 1.x は 3D モデル素材として取り込み、humanoid ボーンを含む骨格とシェイプキーを最後に正常解析したメタデータとして保持する。Timeline やクリップ編集が静的ポーズ編集とは別機能であることを UI 上で区別する。
- VRM 0.x の MToon は元ファイルを残したまま、旧互換描画設定を持つ派生マテリアルとして取り込む。種類を「MToon 0.x」と表示し、VRM 1.0 と共通の Inspector で影色や輪郭線を編集する。取り込み済みマテリアルを上書きした作品は通常のユーザー編集保護を維持する。
- 配置後は 3D モデル Entity の下に元データの Node、Bone、メッシュ、Skinned メッシュを親子順で展開する。Skin は Node ごとに複製せず、親 3D モデルの共有描画方式でバインドポーズと Animation を維持する。
- ポーズと Node 別マテリアル割当は配置 Entity の Mesh Component に保存し、同じ 3D モデルを使う別の配置には影響させない。

### 操作中

- インポート中は既存インポートキューで形式検証・元データコピー・解析・サムネイル・マニフェスト確定を順に表示し、二重インポートと再インポートを無効にする。
- Hierarchy で Bone または Node を選ぶと、ローカルの位置・回転・大きさを通常の数値入力とギズモで編集でき、共有 3D モデルの元データノードポーズへ即時反映する。従来の Bone 選択 UI とシェイプキーの 0〜1 のウェイトも同じ配置の静的ポーズとして維持する。
- 数値ドラッグとギズモ操作中も同じメッシュ・マテリアル・スケルトンで Skin 変形を描画し、VRM 0.x / 1.0 ともに World / Local 軸とモデルの実際の移動方向をそろえる。長い数値ドラッグ中は保存を待ち、離した時点を 1 件の履歴として確定する。数値の Escape やギズモの touch / pen `pointercancel` では操作前の姿勢へ戻す。
- メッシュ / Skinned メッシュ Node を選ぶと、その元データノードが使うマテリアル枠だけを表示する。同じ元データの material index を共有する別 Node とは `sourceNodeIndex` で上書きを分離する。
- Hierarchy の目アイコンで共有 3D モデルの Node も表示・非表示を切り替えられる。`enabled` と共有メッシュのポーズ（`nodes[i].visible`）を同時に更新し、シーン・公開ワールド・ランタイムでそのサブツリーを一致させる。Node 削除操作は非表示への変更として扱い、Entity 自体は削除せず理由と再表示操作を通知する（MI-117）。
- ポーズ変更は有効な有限値だけを確定する。Play 中は読み取り専用とし、素材再インポート中は編集を無効化して最後に成功した解析結果と現在ポーズを表示し続ける。

### 成功時

- インポート成功後は新しい 3D モデル素材を選択し、形式・Bone 数・シェイプキー数・元データ・サムネイルを Inspector に残す。「配置」で Entity を作成してそのままポーズ編集へ進める。
- Bone / Node の位置・回転・大きさ、ノード別マテリアル、ノード別表示・非表示、シェイプキーウェイトを共有 Mesh Component に保存し、元に戻す・やり直す、プロジェクト再表示、シーン、コード編集 JSX、ランタイムマニフェストで同じ静的状態を復元する。旧版が保存した「無効なのに描画される」Node フラグはプロジェクトを開いた際に実態へそろえ、件数を通知する。
- 「ポーズをリセット」は Bone とシェイプキーだけを初期値へ戻し、Entity の位置・回転・大きさ、Node ごとの位置・回転・大きさ、マテリアル割当、衝突判定、3D モデル素材はそのまま維持する。Bone 回転やシェイプキーの個別変更でも Node の調整値を保つ。

### 失敗時

- 不正な OBJ / VRM、上限超過、読めないジオメトリ、VRM 拡張解析失敗では `AssetManifest` を確定せず、インポートキューに形式と再選択の案内を残す。
- OBJ の外部 MTL / テクスチャ参照は自動取得せず警告とする。3D モデル自体が読める場合に限り確定し、欠けた見た目はマテリアル枠から修正できるようにする。
- 再インポート後にポーズ対象の Bone やシェイプキーが消えた場合は値を別対象へ移さず、残っている対象だけに適用して未適用件数とリセット操作を Inspector に示す。
- 元データ Node 解析や Skin 参照が壊れている場合は部分的な Hierarchy を成功扱いとせず、直前の正常な素材とシーンを維持してインポートキューから再試行できるようにする。

### 戻り先

- インポートキューを閉じても新しい 3D モデル素材と診断を Assets / モデル設定に残す。Entity を選択すると直前のポーズ編集へ戻れる。
- ポーズ編集後に別 Entity や素材を選んでも値を保持し、同じ Entity へ戻ると保存済みポーズを再表示する。Timeline 追加時にこの静的ポーズを初期状態として扱える構造を維持する。

完了条件: OBJ / VRM を 3D モデル素材として配置し、VRM の Node・Bone・Skinned メッシュを Hierarchy から選択して配置 Entity ごとの位置・回転・大きさ、ノード別マテリアル、シェイプキーウェイト、ノード別表示・非表示、ノード単位の衝突判定追加を保存でき、再表示と生成結果で同じ静的状態を復元できる。

## F-16 UnityPackage・シーン・プレハブ取り込みの状態設計

### 操作前

- 通常の素材インポートとドロップで `.unitypackage`、`.unity`、`.prefab` も受け付ける。UnityPackage にはシーンと依存素材が含まれる一方、単体のシーンやプレハブでは外部 GUID の素材を同時取得しないことを区別して説明する。
- 変換対象は GameObject 階層、ローカル位置・回転・大きさ、GLB / glTF / OBJ / VRM、主要テクスチャ、Unity マテリアル、`Mesh Renderer`、ライト、音源設定、衝突判定、Fog / Ambient / Camera 設定とする。FBX など実行時 3D モデルへ変換できない元データも参照先と件数を診断に残す。
- MonoBehaviour の class ID と件数はプレハブの生成元情報として保存し、C# から JavaScript へのコード変換は行わない。

### 操作中

- インポートキューでは読み込み、gzip / tar 展開、`pathname` 安全性検査、Unity YAML オブジェクト / GUID 参照解析、素材派生データ生成、シーン再構築、プレハブ生成、アトミック確定を 1 つの進捗として表示する。処理中は 3D モデル再インポートを含む別の素材変更と Play を無効にする。
- Unity の左手座標系は XRift / Three.js の右手座標系へ変換し（position の Z と quaternion を対応）、親参照の欠落や循環参照はシーン直下へ安全に戻して警告とする。
- 対応する素材元データは既存の内容ハッシュに基づく保存とサムネイル生成を再利用し、同一 SHA は既存素材を選択して再コピーしない。パッケージ内の全バイナリ書き込みが完了するまで `SceneDocument`、`AssetManifest`、プレハブ編集データを画面へ反映しない。

### 成功時

- 変換した GameObject ルートを現在のシーンへ再構築し、Unity シーン・プレハブごとにプレハブ編集データとプレハブを保存する。最後に作成または再利用したプレハブを Assets で選択し、再構築ルートを Hierarchy / シーンで選択する。
- Activity パネルにプレハブ・Entity・素材・要確認の件数を残す。プレハブのインポートメタデータには元データ名、パッケージ内 `pathname`、元データ SHA、Unity class ID 件数、未対応 class ID、C# 変換を行っていない事実を記録する。

### 失敗時

- gzip / tar 破損、安全でない `pathname`、展開上限超過、Unity YAML 不正、変換対象なし、素材確定失敗では、直前の正常な `SceneDocument`、`AssetManifest`、プレハブ一式、両選択状態を維持する。
- 一部の素材や Component が未対応でも変換可能な階層は残し、FBX・外部 glTF・音声クリップ・MonoBehaviour などの不足を Activity パネルの警告で確認できるようにする（すべて変換できたように見せない）。

### 戻り先

- 成功後は「素材を表示」から生成プレハブへ移動でき、Hierarchy / シーンに再構築結果を残す。失敗後は Activity パネルを閉じても元のシーンを編集でき、同じパッケージや修正版を再度ドロップできる。

完了条件: UnityPackage の論理 `pathname` と GUID 参照を安全に復元し、対応素材を抽出してシーン階層を再構築し、再利用可能な XRift プレハブとして保存できる。未対応素材・Component を黙って成功扱いせず診断と生成元記録に残し、C# 変換は行わない。

## F-18 OpenBrush 取り込みとシェーダー描画の状態設計

### 操作前

- 新規ビジュアル編集ワールドでは Blank と OpenBrush の 2 サンプルを表示し、OpenBrush が 48 種類のブラシを含むこと、`three-icosa` とエディター同梱の固定ブラシのリソースを使うことをカードとモデル設定で事前に示す。
- 通常の GLB / glTF インポート操作をそのまま使い、`GOOGLE_tilt_brush_material`、旧 Tilt Brush 書き出し元、OpenBrush のマテリアル名から自動判定する（別形式の指定は求めない）。
- OpenBrush 元データのシェーダーを既定値とし、各ブラシを編集可能な素材一覧へ展開するときも Standard / PBR へ変換せず、`three-icosa` プリセットを参照する専用マテリアルとして扱う。通常の XRift マテリアル割当は明示的なスロット上書きとする。

### 操作中

- インポートキューは既存の検証・コピー・解析・サムネイル・確定を使う。OpenBrush 書き出しに残る古い外部画像 URL は解析時に取得せず埋め込みの仮画像へ置換し、外部バッファー参照は従来どおり停止する。
- OpenBrush の glTF ノードは元 GLB を複製せず、共有 3D モデル素材と `sourceNodeIndex` を持つ Entity 階層へ展開する。親子関係とローカル位置・回転・大きさを維持し、各メッシュ Entity にはそのノードが使うブラシのスロットだけを表示する。
- シーンでは OpenBrush 判定済み 3D モデルだけに `three-icosa` ローダー拡張を登録し、通常の GLB / glTF・OBJ・VRM の挙動は変えない。
- カスタムマテリアルのプレビューアダプターは、シェーダー種別・元 3D モデル・元データの material index から代表ノードを解決する。OpenBrush アダプターは同じ `three-icosa` ローダーを使い、標準球体ではなくブラシ固有の頂点属性を持つ実際のストロークジオメトリで描画する。
- カスタムシェーダー契約では、マテリアル内の編集可能なシェーダーコピーとして頂点 / フラグメント GLSL、uniform 型と値、頂点属性の対応付けを分離する。プリセット GLSL 自体は変更せず、マテリアルコピーだけを編集・リセットできる。
  - 頂点 GLSL の `in` / `attribute` 宣言を解析し、`position`・`normal`・`color`・`uv`・`tangent` へ対応付ける。`color` / `uv` / `tangent` は安全な既定値を生成でき、任意のジオメトリ属性名へ上書き可能とする。解決できない必須属性は PBR 切替理由として表示する。
- OpenBrush マテリアルも通常マテリアルと同じ `Mesh Renderer` スロットへ割り当てられ、組み込み基本形状では元 GLB に依存せずブラシプリセット・uniform・テクスチャを独立ロードする。
- プレビュー用 GLSL とブラシテクスチャは固定コピーを同梱し、ネットワークや外部 CDN に依存せず参照できるようにする（安定版テンプレートのリソースを優先し、`three-icosa` 本体固有のリソースを補う）。
- `three-icosa` が知らないブラシプリセット、公開リソースのないプリセット、GLSL / テクスチャ読み込み失敗時は、該当プリミティブだけ GLTFLoader の PBR マテリアルを維持して他ブラシを含むモデル全体のインポートを失敗させない。プレビューとマテリアル設定に代替表示種別・ブラシ名・失敗理由を表示する。
  - この PBR 代替表示は既存の互換挙動であり、制作時の見た目を再現できた状態とは扱わない。今後の修正は [編集・Play・公開の描画契約](../AGENT_IMPLEMENTATION.md#rendering-parity) に従い、元素材と描画処理を共有して原因を解消する。
- 公開変換ではコンパイラー管理下の一時作業フォルダーに固定バージョンの `three-icosa` だけを許可リスト付きで追加し、編集中プロジェクトのマニフェストや任意パスへは追加しない。

### 成功時

- モデル設定に OpenBrush / `three-icosa`、ブラシ数、書き出し元、レンダラーバージョンを記録し、各 OpenBrush マテリアル設定にブラシ名・GUID・元データの material index を表示する。対応マテリアルを各メッシュ Entity のスロットへ初期設定し、通常 XRift マテリアルへ差し替えたスロットだけ PBR へ置換する。
- マテリアル設定のリアルタイムプレビューでは、適用マテリアル種類、GLSL ソース、uniform 一覧、解決済みブラシテクスチャを表示し、見た目と内部シェーダーの両面から初期割当を確認できる。
- OpenBrush スターターは検証済み GLB と Apache-2.0 ライセンスをプロジェクト相対パスへコピーし、48 ブラシメッシュを Gallery ルート配下の個別 Entity として展開したプレハブを含む新規プロジェクトを開く。プレハブ設定にも同じツリーを表示し、元データ Entity へ移動できる。
- プレハブ元データの階層を編集して「プレハブに反映」すると、既存プレハブ ID と元データ Entity の対応を保ったままプレハブ編集データを再生成し、元に戻す・やり直しと通常保存の対象にする。
- コンパイラー出力は GLTFLoader へ `three-icosa` 拡張と固定ブラシ基準 URL を登録し、一時作業フォルダーの依存計画へ固定パッケージ仕様を記録する。

### 失敗時

- 不正 glTF、外部バッファー、ジオメトリ解析失敗、コピー・ハッシュ不一致では `AssetManifest` とシーンを変更せず、インポートキューまたは新規作成へ戻す（OpenBrush 判定だけを理由に不完全な素材を確定しない）。
- ブラシライブラリの通信・CORS・シェーダー読み込み失敗はその 3D モデルの表示エラーとして扱い、エディター全体・他 Entity・保存済み元データを維持して再試行またはモデル設定へ戻れるようにする。
- マテリアルの元 3D モデル・代表ノード・ブラシのリソースを解決できない場合は固定画像を成功表示せず、プレビュー内に原因と再試行を残す。
- 一時作業フォルダーへの `three-icosa` インストール失敗時は検査・アップロードへ進まず、編集中プロジェクトを保持したまま公開モーダルに失敗理由を示す。

### 戻り先

- インポート成功後は新しい 3D モデル素材を選択して OpenBrush 情報とスロットを確認でき、シーン配置後は同じ Entity を選択して通常の Transform・衝突判定・プレハブ・元に戻す / やり直しを使える。
- スターター作成後は OpenBrush 3D モデルが見えるシーンを開き、Blank へ戻って作り直す場合も失敗プロジェクトを一覧に残さない。

完了条件: OpenBrush / Tilt Brush 形式の glTF を通常の 3D モデル素材として取り込み、`three-icosa` 専用シェーダーでシーンと生成ワールドを再現できる。OpenBrush サンプルは外部アセットストアの Open Brush 提供元から追加でき、Apache-2.0 ライセンスを検証付きで保存できる。

## F-21 外部アセットストアと環境テクスチャの状態設計

### パーティクルテンプレートと追加前の調整

参照: MI-03, MI-05, MI-09, MI-15, MI-16

- **操作前**: 25 種類を名前・説明・カテゴリで検索し、詳細の「追加前に設定を調整」で Inspector と共通の設定を使って色・放出量・寿命・形状・動き・Burst を変更できる。見本は保存する値を共通パーティクルランタイムへ渡して描画し、1 回放出の見本には再生し直す操作を用意する。
- **操作中**: プリセットごとの調整値を保持し、選択を戻しても編集を続けられる。追加中は検索・カテゴリ・選択・設定・配置指定・再追加を無効にする（MI-03）。「テンプレートの設定に戻す」は選択中の調整だけを初期値へ戻す。
- **成功時**: 調整値で通常のパーティクル素材を作成し、既存の追加・配置履歴と選択に反映する（MI-05, MI-15）。25 種類に用途別の透明 PNG を自動割当し、同梱 11 画像のうち見本で使用した画像をプロジェクトへ保存して、テクスチャとパーティクルを 1 つの履歴で確定する。同じ `sourceHash` と取り込み設定を持つテクスチャは再利用する。編集・Play・公開は同じ PNG と設定を使い、Assets または Hierarchy から Inspector で編集を続けられる。
- **失敗時・戻り先**: 値と選択を保ったままエラーを表示し、同じ追加を再試行できる（MI-09）。画像読み込み・ハッシュ検証・保存に失敗した場合はテクスチャ・パーティクル・Entity を確定しない。見本画像の読み込み失敗は明示し、未指定の四角い粒子を完成見本として表示しない。ストアを閉じるまでの調整は作品を変更しない。テクスチャ差替やマテリアル参照は追加後の Inspector で行い、既存パーティクルは一括変更しない。

### 操作前

- Assets ヘッダーの「アセットストア」から開始し、左サイドバーに登録済み提供元を並べる。提供元を選ぶと中央カタログと権利表記が切り替わり、選択中の提供元と対応種別が最初から分かるようにする。
  - Poly Haven: 空の背景 / HDRI、マテリアル / テクスチャ、3D モデルをインストール可能。
  - ambientCG: 空の背景 / HDRI、マテリアル / テクスチャをインストール可能。3D モデルは非 glTF 形式のため一覧表示に留める。
  - Open Brush: Poly Haven の下位絞り込みにはせずサイドバーの同階層に配置し、検証済み 48 マテリアルを名前・カテゴリ・タグで選べる。一覧と右詳細は固定 `all_brushes.glb` の代表ストロークノードを `three-icosa` で事前描画した保存済み WebP を GUID 単位で共有し、ストアを開くだけでは Canvas を作らない。右詳細にはブラシ GUID、レンダラーバージョン、カタログリビジョン、ストローク向けマテリアルである互換性説明を表示する（解像度・ファイル形式・ダウンロード容量は出さない）。
  - XRift 公式コンポーネント: 同じ提供元サイドバーに配置し、公開パッケージバージョン、公式元データ、コンポーネント名、カテゴリを表示する。全配置可能コンポーネントはパッケージ本体を事前描画したバージョン付き保存済み WebP を一覧と詳細で共有し、選択コンポーネントだけを 1 件のシーン履歴として追加する。
  - 素材庫: 配信中の GLB・PNG を一覧表示し、未指定ライセンスを明示して通常・アニメーションファイルを選択できる。カタログを 5 分キャッシュし、追加時は詳細と配信ファイルを再取得する。デスクトップ版・ブラウザ版とも既存の追加中・成功・失敗状態を使い、元ファイルをアトミック保存する（PNG・マスクはテクスチャとして Assets で選択）。
- 各素材にはサムネイル、説明、作者、ライセンス、配布ページ、解像度、HDR / EXR 形式、ダウンロード容量を表示する。プロジェクト未保存・Play 中・別素材処理中は理由を示してインストールを無効にする。ローカルの `.hdr` / `.exr` も通常インポートから選べることをファイル選択画面に示す。

### 操作中

- カタログとファイル情報は XRift Studio 固有の User-Agent で取得する。インストール要求に任意 URL を含めず、提供元 ID・素材 ID・解像度からネイティブ側でファイル情報を再取得し、許可済み HTTPS ドメインだけをプロジェクト管理下へ保存する。
- 種別ごとの取り込み処理は次のとおりとする。
  - マテリアル: 基準 color・normal・ARM をテクスチャとして保存し、それらを参照するマテリアルを 1 つ作る（ambientCG では色と NormalGL を保存）。
  - HDRI: 選択した HDR または EXR だけを取得し、形式と正距円筒図法用途を保持したテクスチャにする。ローカルファイル取り込みでも HDR / EXR シグネチャを検証し、HTML 代替ページなど不正内容は確定しない。
  - 3D モデル: Poly Haven API の glTF 一式を取得し、glTF 2.x・依存 URI・安全な相対パス・許可ドメイン・容量を検証したうえで、バッファーと画像をデータ URI に埋め込んだ自己完結 glTF にする。ambientCG の 3D モデルは非 glTF のためインストールを開始しない。
  - ダウンロード中はダイアログを閉じる操作と二重実行を止める。
- Open Brush は任意 URL や GLSL を要求データに含めず、提供元 ID・ブラシ GUID・固定カタログリビジョンを提供元側で照合する。追加中は主操作を「追加中」にし、提供元切替・マテリアル切替・閉じる操作・二重実行を止め、1 件の履歴トランザクションで作成する（途中失敗では `AssetManifest` を変えない）。
- 環境テクスチャ保存後は HDR / EXR を一時 WebGL レンダラーでトーンマッピングし、`assets/.derived/thumbnails/` へ一覧用 PNG を保存する。未生成・古い状態・旧レンダラー版・上下反転変更後はプロジェクトを開いたときに自動再生成し、カードと Inspector を同じ画像へ更新する。

### 成功時

- インストールしたマテリアル・環境テクスチャ・3D モデルを Assets で選択し、提供元・作者・ライセンス・配布ページを保持する。3D モデルは通常素材と同じ配置導線を使い、外部取得だけを理由に自動配置しない。HDRI で「インストール後に空の背景へ設定」が有効なら同じ履歴でシーン設定へ反映し、ローカル HDR / EXR 取り込み時も同様にシーン設定へ反映する。
- Open Brush は `External/Open Brush` フォルダーへブラシ名・GUID・レンダラーバージョン・元データの material index・権利表記を持つマテリアルを追加し、新マテリアルを `assetSelection` にする（シーンやメッシュへは自動割当しない）。同じ GUID とレンダラーバージョンが既にあれば複製せず既存マテリアルを選択し、成功画面に「Assetsで開く」と「続けて追加」を残す。
- 環境テクスチャをシーンまたはシーン設定のドロップ領域へドラッグすると、Entity を作らずシーン全体の背景と IBL を既定で有効にする（以後はシーン設定で片方だけ無効化可能）。上下反転はテクスチャ設定、回転・露出・追加反転はシーン設定から調整を続けられる。

### 失敗時

- カタログ取得失敗時は選択中の提供元と検索条件を維持し、同じ一覧から再試行できる。ファイル取得・ダウンロード・保存・素材作成失敗時は既存の `AssetManifest` とシーンを変更せず、提供元・素材・解像度・形式を保持して再試行できるようにする。
- 提供元未対応、許可外ドメイン、保存先の異なる内容、HDRI・必須基準 color・glTF 本体・glTF 依存ファイルの欠落ではインストールを完了扱いにしない。
- Open Brush の保存済みサムネイル欠落・破損はインストール失敗と区別し、カード内にブラシアイコンと「プレビューを利用できません」を即時表示する（「準備中」のままにしない）。マテリアル追加は固定カタログの GUID 検証で判定し、GUID・プリセット・レンダラーバージョンの不一致では完了扱いにせず同じ選択から再試行できるようにする。

### 戻り先

- ダイアログを閉じると同じビジュアルエディター・シーン・選択・カメラへ戻る。成功後は選択済み素材の Inspector へ移れ、空の背景はシーンドロップまたはシーン設定から変更できる。
- Open Brush 追加後の「Assetsで開く」はダイアログを閉じて実プレビューと権利表記を表示し、取消では追加前の素材選択を復元する。
- 提供元を追加する場合も共通カタログ・ダウンロード選択肢・権利表記・インストール結果を再利用し、素材側に提供元固有の保存構造やライセンス文言を散在させない。

完了条件: 提供元・作者・ライセンス・HDR / EXR 形式を確認して外部マテリアル、テクスチャ、HDRI、3D モデル、XRift 公式コンポーネントを追加できる。Poly Haven 3D モデルは依存検証済みの自己完結 glTF、ambientCG は公式 v3 API の ZIP から色 / NormalGL または EXR を検証保存し、UI と MCP で同じ境界を使う（ambientCG の非 glTF 3D モデルは一覧表示のみ）。Open Brush と XRift 公式コンポーネントも同列の提供元から実描画のプレビューで確認して追加できる。ローカル・外部の HDR / EXR は正距円筒図法テクスチャとして上下反転等を編集し、直後適用またはシーンドロップでシーン全体へ設定できる。

## F-23 公式 XRift コンポーネントカタログとコード編集・TSX 変換の状態設計

### 操作前

- 公式カタログは Assets の「アセットストア」内「ギミック・機能」区分の「XRift公式コンポーネント」提供元から開く。プロジェクト種別で配置可能な全コンポーネントを並べ、カードにコンポーネント名・カテゴリ・パッケージ本体を事前描画した保存済みサムネイルを表示する（一覧と詳細を開くだけでは WebGL コンテキストを作らない）。`DevEnvironment` はシーン用ではなく開発エントリー用ラッパーである旨を別注記する。
- 選択中コンポーネントには公開パッケージバージョン、公式元データ、実際に生成する名前付きインポートと JSX 例を表示する。
- 右上の「読み込む」に 3D モデル / 3D 素材と R3F / コード編集変換を置く。R3F / コード編集変換には TSX 貼り付け欄、「コード編集プロジェクトを選択」、HTTPS / git SSH のリポジトリ URL 入力を並べ、フォルダー・リポジトリ読み込みがデスクトップ機能であること、パッケージ名・エントリーファイル・パスまたは URL・読み込みモジュール数を表示する。
  - 確定前に追加予定の Entity、3D モデル、テクスチャ、音声、空の背景、カスタムマテリアル、衝突判定部位、診断を確認できる。
  - コード編集プロジェクトの素材はこの確認画面へ入る時点で書き込みなしの通常インポート準備まで行い、原本容量、テクスチャ解像度と RGBA / mipmap 展開量、3D モデル原寸・取り込み倍率・親を含む配置サイズ・配置後寸法・中心補正・反転、同倍率で復元する名前指定衝突判定を表示する（この段階ではシーン・`AssetManifest`・プロジェクトファイルは変更しない）。

### 処理中

- 公式サンプルや貼り付け TSX は JavaScript として実行せず、インポート別名、JSX タグ、文字列・真偽値・数値・配列・オブジェクトリテラル、`Math.PI` を含む有限数式だけを静的解析する。
- 主な要素変換規則は次のとおりとする。
  - Drei 基本形状 → Studio 基本形状とマテリアル、R3F ライト → ライト、Rapier `RigidBody` → 親 Entity の独立した `Rigid Body` Component、`Billboard` → `BillboardY`、`Reflector` → `Mirror`、`Sky` / `Environment` → `Skybox`。
  - `RigidBody` の `fixed` / `dynamic` / `kinematicPosition` / `kinematicVelocity`、一般設定、`colliders` 生成方式を保持し、親原点へ仮直方体衝突判定を作らない。動的コールバックと未対応コンポーネントだけを診断に残す。
  - 定数配列の `.map()` と `Array.from({ length })` で対象と件数が静的に決まる繰り返しは要素ごとに個別 Entity へ展開し、要素値やインデックスを使う位置・色・名前もリテラル置換する（入れ子も外側から順に展開）。props など静的に決まらない場合は展開せず従来どおり 1 件のテンプレート構造と診断を残す。
  - `THREE.Shape` の `moveTo` / `lineTo` 輪郭とリテラル深さを持つ `extrudeGeometry` / Drei `Extrude` は押し出しメッシュへ変換し、編集・Play・公開で同じ輪郭から `ExtrudeGeometry` を生成する（ベベル未再現は診断に残し、曲線輪郭は変換しない）。
- コード編集フォルダーまたは浅いクローン済みリポジトリでは、`package.json`、`xrift.json`、`src/World.tsx` または `src/Item.tsx` を検査し、ファイル数・総容量・symlink をネイティブ側で制限する。
  - `src` 内の TypeScript / JavaScript モジュールを上限付きで読み、エントリーから相対インポートを再帰解決する。ローカルコンポーネントはインスタンス境界を Entity として残し、静的に確認できる return JSX を子へ展開する。
  - 参照されるローカルの 3D モデル・テクスチャ・MP3 / WAV は `baseUrl`・先頭 `/`・`public/` を同じプロジェクト相対パスへ正規化して重複除去し、通常の素材トランザクションへ渡す。リポジトリ URL では作業ツリー全体から解決し、指定パス欠落時も `public` 内で同名ファイルが一意なら復旧する。
  - sphere / BackSide 背景画像は無限遠投影のシーン背景へ変換し、`new Audio` のループ音源は `Audio Source` として復元する。カスタムコード、Hook、コールバック、条件分岐、動的配列は実行しない。
- `THREE.ShaderMaterial` は頂点 / フラグメント GLSL、リテラル uniform、テクスチャサンプラー、メッシュ名に対する define バリアントだけを宣言的カスタムマテリアルへ保存し、元 3D モデルのマテリアル枠へ適用する（シーン・Play・JSX コンパイラーで同じシェーダーと時間 uniform を使用）。OBJ 内で明示選択された衝突判定メッシュ名は名前付きサブメッシュとして復元し、非表示衝突グループをモデル全体の代替 Box に変換しない。
- `group`、`RigidBody`、Drei / XRift ラッパーは独立 Entity として残し、ローカル Transform と親子順を維持する。定数参照を含むローカルコンポーネントのサイズと位置を静的復元し、3D モデル取り込み倍率・中心オフセット・X 反転を同一単位系で合成する。名前指定 OBJ 衝突判定はルート 3D モデル描画を通らないため、取り込み倍率を衝突判定 Entity 自身へ適用して可視モデル・衝突判定・物理形状の寸法を一致させる。
- シーン・`AssetManifest`・選択は「追加」確定まで変更しない。

### 成功時

- 追加 Entity、3D モデル・テクスチャ・音声・マテリアル、空の背景、ライト、衝突判定、公式 XRift コンポーネントを 1 件の元に戻す履歴へ確定し、最後の Entity を選択して Inspector で編集できるようにする。「インポート後、そのまま動作確認で確認」が有効なら確定したデータの分離コピーで即座に Play を開始する。
- コンパイラーは `@xrift/world-components` から公式名をインポートし、`Portal` など実行時 Context が必要なコンポーネントは編集・Play でも公式本体を描画して外部通信や遷移だけを Studio の Provider 連携で止める（生成結果では公式ランタイムを使用）。

### 失敗時

- フォルダー選択取消時は入力を変更しない。パッケージ / XRift マニフェストや同種エントリーの欠落、JSX なし、対応要素なし、プロジェクト種別不一致、Entity / マテリアル / Component 作成失敗では成功表示しない。個別素材の欠落・未対応形式・変換失敗は対象パスを警告に残し、該当素材だけスキップして残りを 1 履歴で確定する。
- 入力コードと元モジュールのパス・行番号付き診断をダイアログに保持し、リテラル修正・未対応要素除去・別コンポーネント選択へ戻れるようにする。

### 戻り先

- キャンセルと Escape はシーンを変更せず元のエディターへ戻る。成功後はシーン・Hierarchy・Inspector が追加 Entity へ同期し、元に戻すで追加前の両選択と編集データ一式へ戻せる。

完了条件: 外部アセットストアで公開パッケージバージョンと公式元データを確認しながら全配置可能コンポーネントをサムネイル付きで選べる。右上の「読み込む」から Drei / React Three Fiber の基本形状・ライト、Rapier `RigidBody`、公式 XRift JSX、および既存コードプロジェクトの検査済みエントリーを安全なシーンデータへ変換でき、未対応コードや素材を完全変換と誤表示しない。

## F-24 glTF マテリアル制御と Behavior 連携の状態設計

### 操作前

- マテリアル設定の各テクスチャスロットでは、テクスチャ選択、UV セット、繰り返し・補間参照、繰り返し / UV 変換を同じ画面に配置し、繰り返しを隠し機能にしない。glTF 既定値（ずらす量 0、回転 0°、繰り返し 1）を明示する。
- Animation 設定では 3D モデルクリップ再生とマテリアルアニメーションを分け、マテリアルアニメーションは Node Graph 素材の `pointer/interpolate` を開く導線として表示する（独自タイムラインがあるようには見せない）。
- ノードグラフの `pointer/get`、`pointer/set`、`pointer/interpolate` では対象マテリアルを選択式にし、手書き JSON Pointer を前提にしない。設定前は対象マテリアルと項目が未選択であることを示す。

### 操作中

- テクスチャスロットのずらす量・繰り返し・回転・UV セットの変更は `MaterialTextureInfo` へ保存し、コンパイラーとランタイムマニフェスト変換で `KHR_texture_transform` 仕様を維持する。繰り返しが 1 以外でテクスチャ側の繰り返し設定が「繰り返す」でない場合は、マテリアル値を勝手に戻さずテクスチャ設定への修正案を表示する。
- マテリアルのポインタープリセットは、選択マテリアルの安定した順序インデックス、正規ポインター、KHR 型インデックス、`material` インライン接続口、設定または補間する `value` 接続口を 1 操作で更新する。テクスチャ Transform プリセットは `KHR_texture_transform` のオフセット・スケール・回転だけを対象にする。
- MCP は `get_material_asset`、`update_material_asset`、`set_material_texture_transform`、`configure_interactivity_material_pointer` を公開し、プロジェクト ID・シーン ID・想定リビジョン・編集 / インポート状態を通常操作と同じ境界で検査する。

### 成功時

- マテリアル変更は同じマテリアルを参照するシーン・サムネイル・ランタイムマニフェストへ反映し、対象マテリアルを選択状態にする。ランタイムローダーはテクスチャをマテリアルごとに複製して UV チャンネル・offset・repeat・rotation を適用し、別マテリアルのテクスチャ状態を変えない。
- ノードグラフは正規形式の `KHR_interactivity` JSON として保存し、ノード設定と MCP 取得結果にポインター・種類・マテリアルインデックスを残す。Animation 設定から開いた場合も同じグラフエディターと入力検証を使う。

### 失敗時

- テクスチャ未設定スロット、存在しないマテリアル、非ポインターノード、不明プリセット、不正ベクトル、Play / インポート中、古いリビジョンでは `AssetManifest`・Node Graph 素材・履歴を変更せず、MCP は原因コードと対象 ID を返す。
- ランタイムでテクスチャを読み込めない場合はマテリアル全体を消さず、該当マップの診断を残して係数（factor）値で描画を継続する。

### 戻り先

- マテリアル編集後は同じ素材設定へ、Animation から Graph を開いた後は同じ Node Graph 素材へ戻れる。シーン選択は維持し、素材タブを閉じると元の Entity 設定へ戻る。
- Entity から開いた素材設定では見出し下のパンくずに「<オブジェクト名>へ戻る」ボタンと現在素材名を表示し、押すと選択を変えずに元の Entity 設定へ戻れる。
- マテリアルと Graph の変更取消は通常の元に戻すを使い、MCP 変更も同じ履歴と自動保存から復元する。

完了条件: マテリアルテクスチャの繰り返し・ずらす量・回転・UV セットを glTF 互換値として編集でき、MCP・Animation 導線・`KHR_interactivity` ポインターノードから同じマテリアル設定を操作でき、ランタイムマニフェストでもテクスチャ Transform と繰り返しサンプラーを維持できる。

### F-24 MToon 0.x・1.0 と Outline（2026-09-29）

参照: MI-03, MI-09, MI-15, MI-25

- **操作前**: 標準マテリアルの Inspector に「Shading → マテリアルの種類」を置き、`Standard (PBR)`、`MToon 0.x`、`MToon 1.0` から選べる（VRM 0.x 由来の旧互換設定も `MToon 0.x` として表示）。MToon では Shade Color、陰影の境界、Outline の方式・幅・色、Shading Shift Map、Matcap、Rim Lighting、UV Animation、描画順を表示し、`Base Color`、`Alpha`、`Normal Map`、`Emissive`、`Double Sided` は共通編集とする。
- **操作中**: MToon への切替は同じマテリアルを 1 回更新する。初回は `Base Color` の RGB を 0.8 倍した Shade Color と `Base Color Map` を引き継ぎ、黒い Outline・World 幅 0.003 m を調整の出発点とする（MToon 仕様の省略時既定値とは区別）。使わない PBR の反射・透過・Occlusion 設定は非表示にしつつ値を保持する。Play 中など編集禁止状態では切替と入力を無効化する。
- **バージョン切替と PBR 往復**: `0.x` と `1.0` の切替では旧互換陰影設定だけを変更し、色・陰影値・輪郭線・テクスチャ・追加設定を保つ。保存は glTF の MToon 1.0 形式を維持し、旧互換は `extras.xriftVrm0CompatShade` で区別する（glTF マテリアル見本にも 0.x / 1.0 比較セットを配置）。PBR へ戻しても MToon 固有設定を非表示データとして保持して再選択時に復元し、画像参照を使用箇所として維持する。
- **一括編集**: Assets 複数選択の「マテリアルの一括変更」にも同じ種類選択を置く。混在選択ではマテリアルだけを対象とし、カスタムシェーダー素材は対象外件数を示す。対象がすべて同種なら単体と共通の全設定を表示し、値が異なる項目は空欄・「一部異なる」・チェックボックス一部選択状態で示す（先頭素材の値を全体値として出さない）。操作した入力欄だけを 1 履歴で反映し、RGB / UV の 1 成分変更時は他成分を、画像のみ変更時は各素材の UV を保持し、画像未割当素材へ UV 編集で新規参照を作らない。
- **素材プレビュー**: MToon 0.x / 1.0 は斜めの Directional Light と弱い環境光で明面と Shade Color を区別し、同じ照明を見本カードにも使う。描画処理バージョン変更で旧サムネイルを再生成し、素材色やシーンライト設定は維持する。
- **成功時**: 使用中の全スロットと素材プレビューへ同じ MToon 設定を反映し、同じ素材設定に留まる。Outline Width Mode が `None` なら幅・色入力を無効化し、`Screen` は画面高に対する割合、`World` は m を表示する（一括編集で方式混在時は入力可能）。`Transparent With ZWrite` は `Alpha Mode` が `Blend` かつ `Depth Write` が自動の素材で有効になり、混在選択でも保存値を一括変更できる（既存の明示的な Blending・Depth Write 設定は保持して Rendering で確認可能）。
- **失敗時・戻り先**: 不正値や保存競合は通常マテリアル更新で拒否して前回値と選択を維持する。テクスチャ読込失敗は該当スロットに表示して開き直し導線を残す。`Standard (PBR)` へ戻せば保持済み PBR 設定を再表示し、変更は通常の元に戻す・やり直しと自動保存、戻りは既存パンくずを使う。

## F-29 カスタムシェーダーの編集とマテリアル適用の状態設計

参照: MI-03, MI-05, MI-09, MI-15, MI-16, MI-19, MI-25, MI-48

### 水面シェーダーカタログ

- **操作前**: Assets → アセットストア → 水面シェーダーで 24 種類を検索・分類し、一覧の実際に描画した静止画と詳細のアニメーションで比較できる。調整項目は「波・さざ波」「反射・透明感」「泡」「演出」「色」にまとめる。
  - 川のプリセットは流れが風と独立して進むため、シーンの風が停止中でも警告にせず、流れは動くことと風を有効にするとさざ波が加わることを案内する。メッシュ中心線に沿ってまっすぐ流れ、曲がった川・岩・地形には合わせない旨を詳細に明記し、一覧・詳細とも川幅に応じた岸からの構図で描く。
- **処理中（MI-03）**: 追加中は検索・カテゴリ・選択・パラメータ編集・再追加を無効にする。詳細の試し風はシーンを変更しない。
- **成功時（MI-05）**: 追加・更新したマテリアル名と割当方法をパネルに残し、Assets から設定へ進める。既存マテリアル更新は同じプリセットを再追加した場合に限る。
- **失敗時・戻り先（MI-09）**: 選択と値を保ってエラーを表示し、同じ追加を再試行できる。検索 0 件は空状態を表示し、条件解除で一覧へ戻る。一覧は共有レンダラーの静止画、詳細だけ動画とし、非表示・一時停止・動きを減らす設定ではアニメーションを止める。`list_material_presets` と `create_material_from_preset` で全種類とパラメータを扱う。

### 操作前

- マテリアル設定に「カスタムシェーダーを作成」を置き、標準 PBR から切り替えると初期 GLSL・uniform・既定バリアントを同じマテリアルへ作成する（シーンの割当は変えず選択を維持）。
- カスタムシェーダーはマテリアル内の編集可能なシェーダー契約として頂点 / フラグメント GLSL、uniform 値、バリアント、時間 uniform を持ち、既存 3D モデル由来シェーダーを直接壊さずマテリアル単位コピーとして編集する。
- MCP は `create_custom_shader`、`get_custom_shader`、`update_custom_shader` を公開し、`get_editor_context` のプロジェクト ID・シーン ID・リビジョンを要求して同じ `AssetManifest` 境界で扱う。
- 「シェーダーの調整値」では行列（`mat3`・`mat4`）、数値配列、3D テクスチャ（横並び画像とスライス数）、キューブマップ（6 枚画像）の uniform も編集できる。数値列は入力途中の文字を保ち個数が一致したときだけ保存し、不一致の間は「保存していません」と条件を示す。「合成とカリング」はバリアントごとに Blending、Transparent、Depth Write、Frustum Culling を持ち、Normal 以外の Blending で Transparent 無効時は注意を表示する。選べないテクスチャを指す uniform は原因を欄の下に示す。
- 「シェーダーの調整値」では、空・水・Terrain の表面・草木などの同梱シェーダーにカタログの項目名と説明を表示する。それ以外は uniform 名から表示名を作る。時刻、風、主光源、環境光など、シーンが設定する項目には「自動」と表示する。手入力した値は次の描画で上書きされるため、編集できる項目と区別する。

### 処理中

- GLSL ソース・uniform・バリアント編集中は `assetSelection` と参照 Entity を維持し、連続入力を 1 つの素材更新へまとめる。保存と MCP 更新は同じリビジョンを消費し、古い MCP 要求は `STALE_REVISION` で止める。
- シーンでは実際の `ShaderMaterial` としてメッシュへ適用し、基本形状と 3D モデルのスロットで同じ uniform・属性・時間 uniform 契約を使う（テクスチャ uniform は明示されたテクスチャだけを読み込む）。
- 3D モデルへ割り当てたカスタムシェーダーはメッシュ属性を名前で参照し、glTF 独自属性は小文字名になる。`EXT_mesh_gpu_instancing` の独自属性はインスタンスごとの値として渡され、glTF 名・小文字名のどちらでも参照できる。編集・Play・公開は同じ読み込み処理を使う（仕様は [3Dモデルの読み込み仕様](../MODEL_IMPORT_CONTRACT.md#インスタンスごとの属性) を参照）。
- MCP 更新は `void main()`、uniform 型、バリアント、ソース長を検証してから確定する。設定の途中入力は診断対象として保持し、コンパイル・Play では該当マテリアルだけを PBR 代替表示または公開停止診断へ分離する。

### 成功時

- マテリアル設定にプレビュー、GLSL、uniform、バリアント情報を残し、同じマテリアルを参照する全メッシュと生成ワールドへ反映する（必要なら `set_material` で任意スロットへ割当可能）。
- `.glsl` / `.vert` / `.frag` / `.vs` / `.fs` を通常インポートからシェーダー素材として登録できる。素材のダブルクリックやマテリアル設定の「編集」からスクリプトと同じドック型エディターを開き、頂点 / フラグメントごとにマテリアル内コードまたはシェーダー素材を選べる。
- MCP の作成・更新結果にはマテリアル ID、シェーダー内容、`revisionAfter`、Scene View のコンパイル結果（`compile`）を返し、元に戻す・自動保存・Play 中の影響 Entity 再同期は通常マテリアル変更と同じ扱いとする。

### 失敗時

- シェーダー形式不正、必須 `main` 欠落、uniform テクスチャ欠落、バリアント不正、古いリビジョン、Play / インポート競合ではマテリアル・シーン割当・履歴を部分更新せず、原因コード・入力欄・マテリアル ID を MCP と設定に残す。
- WebGL のコンパイル・リンク失敗ではエディター全体を止めず、Scene View レンダラーのコンパイラログをマテリアルごとに保持し、Inspector ではプレビュー下、GLSL エディターではコード上に `role="alert"` で失敗段階・作者 GLSL 行・コンパイラメッセージ・次の修正箇所を表示する（「PBRへ戻す」も同じ位置に残す）。未割当マテリアルも Inspector で開いた時点でコンパイル確認し、GLSL 書き換えで表示を消して最新結果へ更新する（確認中表示は出さない）。MCP の不正更新は前回正常マテリアルを維持する（MI-09）。
- 形式検証を通った GLSL はコンパイルエラーがあっても書きかけコード保護のため保存し、その間は割当済みメッシュを描画しない。MCP には `compile` と `get_editor_context` の `customShaderErrors` で同じ内容を返す。公開ワールドには UI 表示を追加せず、マテリアル名と行をコンソールへ出力する。

### 戻り先

- 成功後は同じマテリアル設定に留まって参照メッシュを確認でき、MCP 作成後も `assetSelection` を新マテリアルへ更新する。
- 取消、「PBRへ戻す」、失敗時再試行では元のマテリアル・両選択を維持し、通常の元に戻すでカスタムシェーダー設定前へ戻せる。

完了条件: マテリアル設定または MCP から GLSL・uniform・バリアント・時間 uniform を作成・編集してメッシュスロットへ割り当て、シーン・Play・生成ワールドへ反映できる。無効シェーダーは診断と PBR 復帰を残し、成功後は対象マテリアルへ戻れる。

## F-37 テクスチャ解像度変更・圧縮の適用の状態設計

参照: MI-03, MI-05, MI-09, MI-15, MI-16, MI-25, MI-67

### 編集負荷の調整と再変換

- MI-03 / MI-05 / MI-67: 複数テクスチャの最大解像度・形式を共通指定でき、実行前に各画像の対象・変更不要・非対応理由を表示する。変換中は設定と実行を無効化し、失敗時は元参照を保って同じ選択から再試行できる。
- 変換済み画像は保持している原画像から再変換できる。現在使用中の画像と変換元を区別し、KTX2 自体を再圧縮できるようには見せない。
- インポート最大解像度は編集用画像にも適用しつつ元ファイルを残し、再インポート時は保護された個別設定を優先する。
- シーンに描画解像度 50%・25% の編集用品質を用意し、Play と公開物には適用しない。

### 操作前

- テクスチャ設定の最大解像度と圧縮（方式・Quality）は設定として保持するだけで原本画像ファイル自体は変わらない。「この設定で画像を書き出す」で適用すると編集・公開で使用する画像が切り替わる（公開時に未適用設定は実行しない）。「画像の書き出し」に現在の解像度・形式・容量と、変換後の解像度・形式・Quality を並べて表示する。
- 設定が原本と一致して変換不要な場合は理由を示して実行を無効にする。環境テクスチャ（HDRI）、KTX2 / SVG など書き戻せない形式、外部・組み込み元データ、解析結果のない素材では実行操作を出さず非対応理由を表示する。
- 未適用設定があるときは、明示的に書き出すと編集・公開画像が変わることと元画像が残ることを事前に示し、適用後はシーンと Play で見た目を確認するよう案内する。
- Play 中、および素材インポート・3D モデル再インポート・別テクスチャ変換中は実行不可とし、理由と完了後に同じ設定から実行できる旨を示す。

### 処理中

- ボタンを「変換中」にして無効化し、対象テクスチャの設定変更も止める。読み込み・変換・保存の段階を文言で示して二重実行を防ぐ。
- 書き出しファイルは `assets/.optimized/` へハッシュ名で新規保存し、原本は上書きしない。保存失敗時は `AssetManifest` を変更せず表示中テクスチャも維持する。

### 成功時

- 変換後の解像度・形式・変換前後容量を Inspector と通知に残し、素材の元データとインポートメタデータを書き出しファイルへ切り替える。保存上は未反映設定をリセットするが、設定・一括編集では適用済み設定を表示・編集基準として保持し、既存の最適化結果も実形式と寸法から補って KTX2 が意図せず JPEG へ戻らないようにする。
- 1 件の元に戻す履歴として確定して自動保存へ引き継ぎ、生成済みサムネイルは古い状態にして再生成対象とする。元に戻すで変換前素材へ戻せる。

### 失敗時

- 失敗理由を Inspector と通知の両方に残し、原本と設定を維持する。変換中に同じテクスチャの設定が変わった場合は書き出し画像を採用せず取消として表示する。
- 未保存プロジェクトでは実行せず、初回自動保存後に実行できる旨を示す。

### 戻り先

- 成否にかかわらず同じテクスチャ設定に留まり、設定変更後の再実行や公開前確認の容量見積もりへ進める（公開前確認の一括最適化と同じ保存先を使用）。書き出さずに公開へ進んだ場合は F-40 に従い現在使用中の画像をそのまま公開する。

完了条件: テクスチャの最大解像度・圧縮設定を原本を残したまま明示適用でき、変換前後の解像度・形式・容量を同じ場所で比較し、編集画面で確認した画像をそのまま公開できる。環境テクスチャや書き戻せない形式は理由を示して実行させない。

## F-40 公開画像の保持と取り込み時の最大解像度の状態設計

参照: MI-03, MI-05, MI-09, MI-15, MI-16, MI-25, MI-67, MI-100

### 操作前

- 公開・アップロード・コード編集書き出し・CLI 書き出しは、編集画面で使用中のテクスチャを同じ形式・解像度でそのまま配布する。未適用の最大解像度・2 のべき乗・圧縮設定を公開時に自動実行しない。アップロード確認画面には現在使用中の画像をそのまま公開する旨を短く表示する。
- 画像を変更したい場合は F-37 の「この設定で画像を書き出す」または容量詳細画面の最適化を明示適用し、シーンと Play で見た目を確認してから公開する。
- 歯車から開く設定パネルに「取り込むテクスチャのサイズと圧縮」を配置する（読み込むメニューには置かない）。未設定時は最大 1024px・KTX2 圧縮とし、シーン配置前に変換を完了する。保存済み設定と MCP 明示設定を優先し、単体・モデル内蔵の対応画像へ同じ上限で編集用画像を生成しつつ元ファイルを残す。選択既定値はエディター状態としてブラウザに保存し、モデル再インポートでも個別保護設定を優先する。

### 処理中

- 公開時は現在画像ファイルをコピーするだけで画像変換 Worker を起動せず、公開直前に画像を変える処理を入れない。
- 取り込み時や Inspector からの明示変換では必要な画像を順番に処理する。KTX2 圧縮は専用 Worker で 1 枚ずつ実行して画面スレッドを占有せず、完了・失敗時に Worker を終了してメモリを解放する。120 秒で完了しない場合も終了し、最大解像度を下げるか WebP で再試行するよう案内する。変換失敗時は新マニフェストを採用せず元参照を維持する。glTF サンプラー由来設定は取り込み既定より優先し、HDRI・SVG・元画像のない KTX2 は変換しない。

### 成功時

- 公開テクスチャのバイト列・形式・解像度は現在元データと一致する（適用済み KTX2 は KTX2、未変換 PNG は PNG として読み込み）。
- 公開によって制作データ・元画像・読み込み設定は変更せず、明示加工で保持した元画像も残す。容量と VRAM は現在使用中の画像の形式・解像度から見積もり、未適用設定は含めない。

### 失敗時

- 公開用コピーの読み込み・保存に失敗した場合は対象を示して公開を止め、制作データは変更しない。
- 明示的な画像変換失敗はその操作画面に理由を残し、現在画像を維持して同じ設定から再試行できるようにする。

### 戻り先

- 公開画面を閉じると元の編集画面へ戻る。画像を変えたい場合は Inspector で適用・確認してから公開画面を開き直す。

完了条件: 公開だけでテクスチャのバイト列・形式・解像度が変わらない。明示加工と取り込み時変換はシーンと Play で確認でき、元ファイルを常に保持する。

### F-24 頂点カラーと不透明度マップ（2026-09-08）

### F-43 glTF マテリアル・ギミック各 50 種類への拡充（2026-09-08）

参照: MI-03, MI-04, MI-05, MI-09, MI-11

- 従来の追加処理、角丸、白・グレー配色、主操作色を維持しつつ、文字とプレビューを拡大して視認性を高める。
- **操作前**: 総数と該当件数、用途別分類、英語名と日本語説明を表示し、Emissive 専用ボタンと「テクスチャ付き」で絞り込める。選択中項目が絞り込みから外れたら表示中候補へ切り替える。見本の比較条件は 3D 内ラベルに加えて詳細ペインにも表示する。回転・拡大は見え方確認用であり、ギミック操作は追加後の Play で行う。
- **処理中**: 検索・分類・選択・追加を無効化し、素材・画像・音・グラフの取り込み完了まで「追加中」とする。取り込み中にプロジェクトや編集内容が切り替わった場合は古い内容を上書きせず失敗理由を表示する。

### F-21 同梱の透過画像（MI-03 / MI-04 / MI-05 / MI-06）

- 操作前は透過画像 30 点を「動物」「花と葉」「空と演出」「飾りと小物」で検索でき、一覧はチェッカー背景、詳細は透過・明るい・暗い背景から選べる。PNG 保存と Assets への追加は別操作とする。

- 同じ素材を再追加しても作者が編集したテクスチャやマテリアルを上書きしない。取得・SHA-256 照合・保存に失敗した場合はマニフェストと履歴を変更せず、その場で理由と再試行を案内する。ブラウザとデスクトップで同じプロジェクト保存処理を使う。
