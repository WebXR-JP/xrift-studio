## F-07 ビジュアルエディターの状態設計

### 操作前

- スマホでは戻る・Undo・Redo・追加・ファイルを1行にまとめる。ファイル名と保存状況はファイルメニュー内に表示し、保存エラーはメニューを閉じていても示す。編集パネルの切り替えは次の行に残す。

- 新規作成ではアイテムのコード編集、ワールドのコード編集、アイテムのビジュアル編集、ワールドのビジュアル編集の四つのカードを同じ画面で選ぶ。内部では成果物の種別と制作方法の組み合わせとして扱う。二段階UIにしない。
- コード編集は`package.json` / `xrift.json` / `src/`を編集するコードプロジェクト、ビジュアルは専用のmanifest、シーン、素材の編集データを編集するプロジェクトと説明する。同じプロジェクトの表示切替や自動相互変換とは表示しない。
- ビジュアル編集では専用の保存形式を使うことを、選択前に説明する。保存、動作確認、変換、検査、アップロードまで同じエディターから操作できることも示す。
- 開いた直後は成果物種別、プロジェクトの種類、既定シーン、独立した`sceneSelection` / `assetSelection`、編集、位置・回転・大きさのツール、未保存状態を表示する。
- 起動時は保存済みのパネル配置をウィンドウサイズと保存形式に合わせて復元する。不正または画面外の配置は安全な初期配置に補正する。
- ワールドにはワールド用の動作確認モード、アイテムにはアイテム用のプレビューモードを使うことを示す。ワールド動作確認は`@xrift/world-components`の公式プレイヤーを起動する。開始位置から一人称で歩く。ワールドの操作制御 / 物理演算 / 開始位置の処理をアイテムへ適用しない。利用可能な入力操作を動作確認前に示す。
- Node.js / XRift CLIがなくても編集と同じ画面での動作確認を利用できる。Vite、CLI、開発サーバー、別ブラウザの起動を制作操作として置かない。
- コード編集を選んだ場合は既存の名前入力、作成、一覧更新、コードエディターへの流れを変えない。
- コード編集のファイル選択では、最後に選んだファイルの読み込み結果だけを反映する。既定ファイルの探索中に手動でファイルを選んだ場合は、その選択を優先する。読み込み中は本文の編集と保存を無効にする。

### 操作中

- コード編集の保存はMI-03に従い「保存中…」と無効な保存ボタンで示す。クリックと保存ショートカットが続けて届いても書き込みは一度だけ行う。成功時は書き込んだ内容を保存済みにし、保存中に加えた変更は未保存のまま残す。別ファイルへ切り替えた後に保存が完了しても、切り替え先の保存状態を変えない。失敗時は編集内容を維持し、同じ保存操作から再試行できる。
- 素材を一度クリックすると、`assetSelection`を更新し、Inspectorにその素材を表示する。`sceneSelection`は維持する。3Dモデルやプレハブは、シーンへドラッグするか「配置」を実行したときにだけオブジェクトとして追加する。
- HierarchyとAssetsはShiftの範囲選択、Ctrl・Cmdの追加／解除を受け付ける。複数選択時はInspectorで対象数を表示する。全対象が持つMesh Renderer / ライトまたはマテリアルの共通プロパティだけを表示する。
- Entityの新規作成と既存Entityの編集メニューを分ける。シーンの右クリックはコピー・貼り付けなどの編集操作、Hierarchyの空白の右クリックは共通カタログからの新規作成に使う。取り込み済み素材の配置はAssetsにまとめる。
- Hierarchyの行D&Dは上端と下端を兄弟順の挿入位置、中央を親子化として扱う。親行の矢印は子孫行だけを折り畳む。シーンなどから折り畳まれた子を選んだ時は祖先を自動展開する。検索は名前、種類、コンポーネント、有効状態を対象にする。直下の用途を示すアイコンではメッシュ、ライト、衝突判定、音声、パーティクル、Animation、Spawn、XRiftのコンポーネントを複数選択できる。種類同士はOR、文字検索とはANDで絞り込む。一致オブジェクトと祖先を表示する。クリア後は元の折り畳み状態へ戻す。行の目アイコンと単一／複数Entityの設定の有効はオブジェクト自身の状態を切り替える。単一設定の先頭は有効チェック、名前、必要時だけ継承状態アイコンの順に並べる。プレハブ元データは名前と更新アイコンだけを置く。説明は常設しない。ツールチップと読み上げ名へ移す。
- 子オブジェクトの位置・回転・大きさはローカル値として保持する。シーン、動作確認、生成ワールドのすべてで親の位置 / 回転 / 大きさを継承する。
- マテリアルドラッグ中はシーンメッシュまたはEntityの設定スロットだけをドロップ対象とする。スロットが複数なら選択画面を表示する。テクスチャドラッグは右のマテリアル設定の対応するスロットだけを対象にする。
- 素材のドラッグ中はシーンだけを配置可能領域として示す。ドロップ前にはオブジェクトを増やさない。
- ギズモ操作中はカメラ操作を競合させない。シーンと設定の位置・回転・大きさ値を同期する。設定の軸ラベルをスクラブする時もローカル位置・回転・大きさを即時同期する。大きさの比率固定中は操作軸の倍率で不均等比率を保つ。
- Inspectorとシーン設定の数値欄は、欄を左右へドラッグして値を変える。上下のスピナーは表示しない。通常のドラッグは微調整に使い、Ctrl / Altを押している間は変化量を大きくする。動かさずに離すと数値入力を開始し、入力した値はキーごとに反映する。一回のドラッグを一件の履歴として確定し、Escapeでは操作前の値へ戻す。
- ギズモとそのドラッグ平面は、親子関係に関わらず対象オブジェクトのワールド位置に置く。ギズモをオブジェクトの祖先の下に描かない。祖先の位置・回転・大きさを二重に適用しない。ドラッグ開始時はカメラの慣性を先に止める。操作中の見え方と移動量を一致させる。
- オブジェクト選択中のFは、そのオブジェクトサブツリーの描画境界ボックスへカメラとOrbit中心を合わせる。境界ボックスは表示中のメッシュだけから測る。コライダー枠、ライトの向き矢印、選択輪郭などの編集用補助表示と、無効化された子は含めない。フォーカス中に別オブジェクトを選択しただけでは追従しない。Fを押した時だけ対象を切り替える。
- モデルを選択したら、選択したノードのメッシュ表面を紫色で強調する。離れた部品を一つの箱で囲わず、部品の間の空間は強調しない。ドリルダウン時は選択先に表示を切り替え、選択解除時に消す。強調表示はクリック判定、フォーカス範囲、保存・公開データに含めない。
- 待機中のギズモと選択補助線はニュートラルカラーで控えめにする。操作中の軸と素材ドロップ対象だけを明るく示す。「ライトなし」「ワイヤー」「コライダー編集」は、既定のグレーマテリアルが背景に埋もれない暗いニュートラルな背景を使う。シーン設定や公開結果は変更しない。
- パネルのサイズを変えるときやドッキングするときは、配置先のプレビューと最小サイズを示す。編集データと選択は変更しない。
- シーンとAssetsのヘッダーは、パネルが狭くなっても一行に収める。シーンでは名前を先に省略し、次にスナップと「表示」をアイコンだけにする。カメラの投影方式、表示モード、診断、録画は「表示」のポップオーバーにまとめる。録画パネルはシーン右上の「録画」から開く。Assetsでは検索欄を縮め、パンくずを折り畳み、「外部から追加」とインポートをアイコンだけにする。動作確認と停止は常に同じ行に残し、ほかの操作と重ならないようにする。
- マテリアルのcolor、metalness、roughness、テクスチャ参照は編集と動作確認の設定から変更できる。同じ素材IDを参照する全オブジェクトのプレビューと同期する。動作確認では参照オブジェクトだけを再起動する。オブジェクト固有マテリアル値へ複製しない。
- 外部のGLB / GLTFをドロップすると、インポートキューで検証、元データのコピー、派生データとサムネイルの生成、manifestの確定まで処理する。Assetsへのドロップでは素材の追加まで行う。シーンへドロップした場合は、取り込みが成功した後に同じ操作の続きとして配置する。
- 動作確認準備中は二重開始を防ぐ。成功するまで編集データを変更しない。ワールドでは有効な開始位置をHierarchy順に解決する。親子位置・回転・大きさと開始位置自身の位置を合成した位置からキャラクターを開始する。動作確認開始後は実行コピーを`Play Window`へ表示する。Hierarchyと設定は編集データへ接続したままにする。オブジェクト / コンポーネント構成、位置・回転・大きさ、衝突判定、Animation、既存マテリアル / パーティクルのプロパティとMCP経由のシーン設定は通常の履歴と自動保存で変更できる。シーン設定は共有シーンへ即時反映する。オブジェクト / 素材変更は影響するオブジェクトだけへ反映する。テクスチャ / 3Dモデル設定、設定のマテリアル割り当て、シーンの位置・回転・大きさギズモ、素材ドロップは停止まで無効にする。
- ワールドプレビューは使える入力操作と操作方法を示し、アイテムプレビューにはワールド用のアバターと操作制御を出さない。
- 動作確認中の入力、操作制御、カメラ、物理演算などはPlaySessionにだけ保持する。
- 動作確認中は停止を常に見える位置に置き、別画面や別ブラウザへ移動させない。
- ヘッダーの「ビジュアル」、未保存、コンパイル結果の更新状態、アップロードと審査の状態は操作中も消さない。

### 成功時

- 素材の配置成功では素材IDを参照するルートオブジェクトを一つ追加する。GLB / VRMに元データのNodeメタデータがある場合だけ同じトランザクションで編集用Nodeオブジェクトツリーを子へ展開する。Hierarchy、シーン、Entityの設定はルートを選択する。元に戻すではルートと展開したNode、選択を配置前へ戻す。
- 基本形状の作成成功では`CreatePrimitiveCommand`一件でオブジェクトと組み込み形状への参照を追加する。マテリアルドロップ成功では`AssignMaterialCommand`一件で既存メッシュの割り当て枠だけを更新する。
- 位置・回転・大きさの変更では、ギズモや軸ラベルを押してから離すまでを一件の履歴として確定する。選択とカメラは維持する。
- フォーカス成功では対象名とF / Escape / 解除ボタンをシーン端に残す。同じオブジェクトでFを押すか解除操作を行うと開始前のカメラ位置、向き、Orbit中心、ズームへ戻す。
- パネル配置の操作成功では正規化したサイズ、ドッキング領域、並び順をエディターの設定に保存する。再起動後も復元する。
- マテリアル操作成功では有効値がAssetManifestの一つのマテリアルに残る。共有する全オブジェクトの表示を更新する。SceneDocumentとオブジェクト固有値は変更しない。
- 動作確認開始成功では中央の動作確認画面でプロジェクトの種別に対応する動作確認モードを確認できる。ワールドのキャラクターは有効な開始位置のワールド位置から開始する。実行環境の位置、速度、アニメーション時刻はPlaySessionにだけ残る。
- 動作確認中の許可されたオブジェクト変更は編集データへ残る。そのオブジェクトだけ実行環境リビジョンを進めてAnimationと物理演算を先頭から再実行する。ほかのオブジェクトと操作制御の実行環境状態は維持する。
- 停止成功ではPlaySessionを破棄する。動作確認中に許可された調整を含む最新SceneDocumentとAssetManifest、選択、編集カメラへ戻る。実行環境の位置や速度、`ctx.materials` / `ctx.particles` 上書きを編集データへの変更として扱わない。
- GLB / GLTFのインポート成功は元データ / 派生データ / サムネイル / manifest確定の完了と新しい素材カードを表示する。シーン配置はシーンドロップまたは後続の「配置」が成功した時だけ別結果として示す。
- 同期操作の結果はトーストだけにせず、追加オブジェクト、Inspector、参照オブジェクトの表示、インポートキューの項目として画面へ残す。

### 失敗時

- 非対応ファイルは拡張子と対応形式を示し、SceneDocument、AssetManifest、選択、履歴を変更しない。
- 位置・回転・大きさに有限でない値や不正な大きさが入った場合、または軸スクラブをEscape / pointerキャンセルで終えた場合は操作前へ戻す。対象項目の近くに修正方法を示す。
- 選択オブジェクトに描画境界ボックスがない場合はワールド座標の位置をフォーカス中心にする。オブジェクト自体を選べない場合や動作確認中、入力中はカメラを変更しない。
- マテリアルに不正なcolor、有限でない値、`0..1`の範囲外、欠落テクスチャ参照が入った場合は確定しない。Inspectorの対象入力欄近くに形式または範囲を示す。
- 欠落素材参照ではオブジェクトを消さず、欠落ID、参照元オブジェクト、素材の再インポートまたは置換を示す。
- 基本形状の作成位置、親オブジェクト、マテリアル / テクスチャスロットを解決できない場合はCommandを確定しない。対象を選び直す操作を示す。
- 動作確認の初期化に失敗した場合は編集と編集データを維持する。シーン内に動作確認モード、原因、再試行を示す。回避策としてCLIや別ブラウザの手動起動を要求しない。
- 動作確認中に実行環境エラーが発生した場合はPlaySessionを破棄して編集へ安全に戻す。SceneDocumentとAssetManifestが変更されていないことを保つ。
- シーンを初期化できない場合はMI-09のエラー画面を表示する。ライブラリへ戻る操作と再読み込みを用意する。
- パネル配置の設定を保存できない場合は現在のパネル配置を保つ。編集を止めない。再試行と「レイアウトをリセット」を示す。
- 保存、変換、検査、アップロードに失敗した場合は、失敗した段階と原因を表示する。原因からは機密情報を除く。成功通知は表示せず、再試行するか対象の入力欄へ戻れるようにする。

### 戻り先

- ヘッダーにライブラリへ戻る操作を置く。未保存変更がある場合は保存、破棄、取消を同じ画面内で選べる。
- 動作確認中にライブラリへ戻る場合は、先に停止と同じ解放を実行してPlaySessionを破棄する。実行環境状態を編集データへ保存しない。
- 戻った後はプロジェクトライブラリを表示し、新規作成の操作を先頭に保つ。
- Escapeで未確定ドッキング / サイズ変更を操作前のパネル配置へ戻す。「レイアウトをリセット」で左Hierarchy、中央シーン、Inspector、下のAssetsへ戻す。
- フォーカス中のEscape、解除ボタン、動作確認開始は保存した編集カメラへ戻す。選択とSceneDocumentは変更しない。
- 作成または保存トランザクションが確定したプロジェクトだけを一覧へ追加する。
- 永続化を接続した後は、シーン / プレハブ / 素材 / フォルダーを含む保存対象のいずれかが未保存なら保存、破棄、戻るの取り消しを選べる確認へ置き換える。

完了条件: 四つの作成カード、Hierarchy、シーン、Inspector、下のAssetsを使う。独立選択、シーンを含む複数選択と共通プロパティ編集、復元可能なオブジェクトフォーカス、目的別のシーン表示、Empty / 基本形状 / XRiftのコンポーネント作成、素材 / マテリアル / パーティクル / XRiftプレハブD&D、Hierarchyの文字検索・種類フィルター・折り畳み・並び替え・親子化・有効、親子位置・回転・大きさ、軸スクラブと大きさ比率固定、コンポーネントごとの有効、視覚的なマテリアル選択、マテリアル / テクスチャ / パーティクル編集、マテリアルテクスチャの繰り返し、Animation / ノードグラフからのマテリアル操作、配置オブジェクトごとの静的なモデルポーズ、GLB / VRMのNode・Bone・メッシュ別編集、GLB / glTF Animationの動作確認時自動再生、動的サムネイル、テクスチャから設定できるプロジェクトのサムネイル、動作確認とシーン全体の環境設定、右上の3Dモデル / R3F / コード編集からのインポートを扱える。下部のユーティリティレールからAI接続、シーン設定へ到達でき、録画はシーン右上から開ける。ヘルプと報告、パネル配置の初期化はシーン設定の先頭から開ける。パネル配置はサイズ変更 / ドッキング後も復元される。エディターの描画 / モジュールの読み込み失敗はApp全体へ伝播させない。再試行、再読み込み、一覧への復帰を選べる。

## F-09 Command / Shortcut / プレハブの状態設計

### シーンの右クリックメニュー（MI-11）

- 通常はコピー、貼り付け、反転して貼り付け、複製、名前を変更、フォーカス、削除を表示する。Sceneの空白では貼り付け、Hierarchyの空白ではEntity作成カテゴリと貼り付けを表示する。選択中の複数Entityの上で右クリックしても選択を一件に戻さない。選択外を右クリックした場合はそのEntityを対象にする。
- コピー前の貼り付けは無効にし、理由をツールチップへ表示する。取り込み中は変更する操作を無効にする。動作確認・録画ビュー・アセットプレビューではシーン編集メニューを出さない。
- 「反転して貼り付け」を押したときだけX・Y・Zの選択を同じメニュー内に開く。通常の貼り付けは一回で実行する。専用のCtrl+Mや常設の反転ボタンは追加しない。Hierarchyの貼り付けも同じ部品とコマンドを使う。
- 上下キーで項目を移動し、右キーで軸選択を開く。軸選択のEscape・左キーは一段戻り、親メニューのEscapeはシーンへフォーカスを戻す。外側クリックではクリック先の操作を妨げずに閉じる。右ドラッグのカメラ操作ではメニューを開かない。
- メニューは既存UIの白・slate・violetの配色に合わせ、行間を抑えて表示する。画面端では位置を補正し、軸選択を開いた後も画面内に収める。パネルの境界で切れないようにする。
- 反転はコピーされた各ルートのローカルScaleの一軸だけに適用する。位置・回転・子のローカルTransformを変更しない。比率固定の状態に左右されない。鏡面を挟んだ自動配置は行わない。親子の重複選択は一つのサブツリーとして扱う。
- 成功時は新しいルートをすべて選択し、元データとクリップボードを保つ。編集データ、選択、保存対象の変更を一件の履歴へ積み、Undo / Redoで同じIDと選択を復元する。反転専用の保存形式やフラグは設けない。
- 単独の共有モデルNodeはコピーできない理由と、モデル全体を選ぶ操作を案内する。無効な貼り付け先や反転データでは編集データと履歴を変更しない。

### 操作前

- ツールバー、右クリックメニュー、ツールチップ、Shortcut設定は同じ操作名、用途に合うLucideアイコン、OSごとのキー割り当て、有効・無効の理由を中央Registryから表示する。
- HierarchyからAssetsへドラッグする時はプレハブを作成する操作になる。作成先フォルダー、サブツリー / 依存ファイル件数をドロップ前に示す。

### 操作中

- コピーはバージョン付きのバッファーだけを更新する。Paste / 複製 / 削除 / プレハブ作成は操作前後の編集データと`sceneSelection` / `assetSelection`を一つのトランザクションに保持する。
- テキスト入力欄、contenteditable、数値入力欄、IMEの変換がフォーカス中はW / E / R / X / F / 矢印 / PageUp / PageDown / 削除 / Copy / Paste / 複製のエディターのコマンドを実行しない。Shiftによるスナップの反転も同じ条件で止める。ショートカットの競合はどちらも実行しない。
- スナップの入切と間隔は`editor.gizmo`のscene設定として保存する。元に戻す履歴には積まない。矢印 / PageUp / PageDownの1ステップはgizmoドラッグと同じ一件の履歴として確定する。

### 成功時

- Paste / 複製は決定済みの新ID、プレハブ作成はプレハブ / 編集データ / フォルダーの所属 / インスタンス メタデータを一度だけ確定する。両選択を仕様どおり更新する。
- 元に戻す / やり直すは同じID、依存ファイルの参照、プレハブ上書き、前後の両選択を復元する。ツールバー、メニュー、キーボードの操作の場所によって履歴の結果を変えない。

### 失敗時

- コピー用バッファーが古い場合、リビジョンが競合した場合、プレハブが循環参照する場合、依存ファイルがない場合は、編集データを変更しない。参照中の素材も削除しない。対象IDと修正するための操作を示す。
- 複数の編集データにまたがるプレハブ操作に失敗した場合は、途中の結果を残さない。一時的なプレハブの編集データと新しく発行したIDを破棄し、シーン、Assets、フォルダーを操作前のリビジョンへ戻す。

### 戻り先

- Escapeは未確定ドラッグ / メニュー / ダイアログを閉じる。操作前の両選択とフォーカスがある操作面へ戻る。確定後の戻りは元に戻すを使う。
- ショートカットの上書きはエディターの設定に残す。プロジェクトを切り替えても同じ割り当てを使う。「既定へ戻す」でRegistryの既定値へ戻せる。

完了条件: ツールバー、メニュー、キーボード、HierarchyD&Dが同じCommand / Shortcut Registryを使う。Copy / Paste / 複製 / 削除 / Reparent、オブジェクトフォーカスの切替と解除、Empty / コンポーネント作成、Hierarchyからのプレハブ化、XRift組み込みプレハブ配置、元に戻す / やり直すがIDsと両選択を復元する。

## F-11 衝突判定 authoring / export の状態設計

Mesh Rendererの「歩行・当たり判定」から追加、解除、シーン全体を選択メッシュだけへ置換できる（MI-03）。置換対象はTriggerを含む衝突判定と物理挙動の自動生成。操作前に範囲を常設し、処理は一件の元に戻すへまとめ、成功後も選択と設定一覧を残す。動作確認中と無効な階層では操作できない。親の自動Box / 球をメッシュへ変換する必要がある場合は形状を勝手に変えず、設定元を示して変更を拒否する。親の独立したBox形状は「これを外す」の対象外で、設定一覧から開ける。

共有3DモデルNodeと通常のMesh Rendererとして展開された3Dモデルノードの両方にDecimationを表示する。当たり判定用の軽量化は表示用のメッシュを変更しない。


### 操作前

- 新規インポートした3Dモデルは`generateColliders`を既定で有効にする。シーンへ初回配置した時に同じオブジェクトへ既定`Static (Fixed)`の`Mesh Collider`を追加する。既存Assetsで明示的に無効化された設定は移行で上書きしない。
- 組み込みの基本形状は`Box Collider`を同時作成する。Floor / Planeは薄いローカル 境界ボックス、その他は基本形状の境界ボックスを初期各軸の半幅とする。オブジェクト大きさは値へ焼き込まない。位置・回転・大きさで追従させる。
- Physicsのコンポーネントを追加に`Rigid Body`を一オブジェクト一件で表示する。追加した親オブジェクトは自身と子孫の衝突判定 / メッシュを一つの物理Bodyへまとめる。ネストした別Rigid Bodyを持つオブジェクトから先は別Bodyとして扱う。

### 操作中

- Colliderのカードでは、Boxの中心と各軸の半幅、自動フィット、Mesh Colliderの形状を編集する。Mesh Colliderはメッシュと同じ形か、凹みを省いた外形を選べる。有効、Trigger、摩擦、跳ね返りも同じカードに表示する。
- Rigid Bodyのカードで`Static (Fixed)` / `Dynamic` / `Kinematic Position` / `Kinematic Velocity`、重力の倍率、Linear / 回転の減衰、静止中は計算を休止する、高速移動時の衝突判定、位置 / 回転Lockを編集する。衝突判定生成は`子孫のCollider Component`、`Auto Cuboid`、`Auto Ball`、`Auto Convex Hull`、`Auto Trimesh`から選ぶ。対象となる子孫衝突判定 / メッシュ件数を同じカードに表示する。
- Rigid Body Componentがない旧編集データでは衝突判定内のBody設定を互換読み込みする。`Static (Fixed)`を既定にする。旧コード編集importerが子を持つ空オブジェクトの原点へ作った既定サイズBoxは、名前またはBody / 操作面設定のインポート時の識別情報を確認できる場合だけ親のRigid Body Componentへ読み込み時に移行する。原点Boxを残さない。親または自身にRigid Body Componentがある衝突判定は、Body設定の編集先をその親オブジェクト名で示す。Colliderのカードでは形状と接触設定だけを編集する。
- Boxの再フィットは同じオブジェクトのメッシュ境界ボックスだけを使用する。3Dモデルはインポートのメタデータの境界ボックスと取り込み時の倍率を用いる。絶対パスや生のglTFデータをシーンの編集データへ保存しない。
- シーンの「コライダー編集」はメッシュを抑えて衝突判定形状だけを確認する。選択オブジェクトの診断件数と、MCPと同じ安全な最適化操作を表示する。`inspect_colliders`は`entityIds`を省略すればシーン全体を扱う。`optimize_colliders`は`projectId`、`sceneId`、`expectedRevision`を使って同じ結果を一回のエディターのリビジョンへ反映する。

### 成功時

- Box / メッシュの衝突判定の変更、追加、削除は一つのシーン履歴として確定するトランザクションになる。選択を維持する。選択中の直方体の衝突判定はシーンにワイヤーフレームで表示する。
- 動作確認とコンパイラーはRigid Bodyを持つオブジェクトのローカル位置・回転・大きさをBody原点にする。そのサブツリーを一つのRapier `RigidBody`で包む。子孫のBoxは各オブジェクトのローカル階層を保った`CuboidCollider`、メッシュの衝突判定は`MeshCollider`として同じBodyへ含める。親原点へ代替Boxを追加しない。ネストした物理挙動は新しいBodyの所属を開始する。
- Auto衝突判定を選んだ場合はRapierの自動生成をサブツリーメッシュへ適用する。物理演算で動かす / Kinematicの明示メッシュと同じ形はRapier互換の凹みを省いた外形へ自動変換する。コンパイラー診断にも残す。
- 最適化では物理演算で動かす / Kinematicのメッシュの衝突判定を保存データ上も凹みを省いた外形へ揃える。移動体の高速移動時の衝突判定を有効化する。出力時に先頭へ畳まれる重複メッシュの衝突判定を無効化する。自動衝突判定と明示メッシュの衝突判定の併用、メッシュなし、無効オブジェクトは自動で無効化しない。診断へ残す。

### 失敗時

- メッシュのないオブジェクトへメッシュの衝突判定を追加しない。必要なMesh Rendererを示す。自動フィット境界ボックスがない時は既存値とシーンを変更しない。
- 非有限中央、0以下の各軸の半幅、負の摩擦、`0..1`外の跳ね返りは確定しない。アップロード前入力検証でも公開を止める診断にする。
- 物理挙動のサブツリーに明示衝突判定がなく、Auto衝突判定対象のメッシュもない場合はBodyを消さない。設定とコンパイラー診断へ「物理形状がありません」と示す。

### 戻り先

- 衝突判定または物理挙動削除後もメッシュ、マテリアル、位置・回転・大きさ、オブジェクト選択を維持する。元に戻すで同じコンポーネントID、Bodyの所属、設定を復元する。

完了条件: インポートした3Dモデルと組み込みの基本形状へ既定衝突判定が付く。形状、中央 / 各軸の半幅、自動フィット、物理挙動の物理設定を設定から編集できる。シーンの「コライダー」表示、動作確認、生成ワールドが同じ物理表現を使う。

## F-12 シーン environment settings の状態設計

### 操作前

- 左下の歯車「シーン設定」を押すと、右のInspectorをシーン設定へ切り替える。オブジェクトと素材の選択は維持する。シーン全体を設定する画面として扱い、Hierarchyには追加しない。
- 空の背景、Fog、環境光はシーンのプレビューと生成するワールドの両方に反映する。空の背景は素材のequirectangular環境テクスチャまたは通常の画像テクスチャを選択・ドロップで設定する。背景表示とIBLライティングを独立して切り替える。回転と露出を共有する。HDR / EXRを直接インポートした場合は新しい環境テクスチャを同じシーンへ設定する。背景とIBLを既定で有効にする。手前 / 奥、FOV、背景、グリッド、ギズモ、スナップは編集ビューの設定として明示する。
- シーン固有の不透明な地面は追加しない。空の背景有効時は地平線の下側まで空の背景を見せる。その上へ編集用グリッドだけを重ねる。
- サムネイルは保存済みプロジェクトでだけ編集可能にする。未保存プロジェクトでは保存後に設定できる理由をボタン文言で示す。

### 操作中

- 色、トグル、数値の変更は対象の節内で即時にプレビューへ反映する。数値入力はEnterまたはフォーカスを外した時に確定する。不正値は直前の有効値へ戻す。空の背景画像は環境テクスチャまたは通常の画像テクスチャだけを受け付ける。画像がない時はIBLトグルを無効にする。テクスチャ設定の上下反転を基本値とする。シーン設定の追加反転はシーン固有の上書きとして合成する。
- Fogの終了距離は開始距離より大きく、Camera奥は手前より大きく保つ。動作確認中は編集データを変えない。各入力欄を読み取り専用にする。
- ギズモのスナップは移動、回転、拡縮に同じ設定を適用する。移動スナップまたはグリッドサイズを変えたら、グリッドのサイズと分割数を調整して各マスを移動スナップの整数倍に揃える。分割数は手動で上書きできる。グリッドの表示を切ってもオブジェクトやSceneDocumentの構造は変えない。

### 成功時

- 確定したシーン設定は元に戻す / やり直すの一件として残る。保存後にシーンJSONへ書き込まれる。コンパイラーは空の背景画像の背景とIBLを独立した設定として、Fog、環境光とともに生成したワールドのソースに出力する。
- サムネイルを保存した後はシーン設定へ戻る。公開前確認が同じ画像を再取得できる状態を保つ。

### 失敗時

- 読み取り専用、未保存プロジェクト、範囲外の数値、無効な色、使用できない空の背景画像ではSceneDocumentと選択を変えない。同じ場所で理由または復帰方法を示す。生成対象にできない画像はグラデーションへフォールバックする。コンパイル診断に残す。
- サムネイルの読み書きに失敗した時は既存画像を維持する。サムネイル編集画面内で再試行できる。

### 戻り先

- ヘッダーの戻る、オブジェクト / 素材の選択はシーン設定だけを閉じる。直前のシーンと選択、編集位置へ戻る。確定済みの変更は保存または元に戻すで扱う。

完了条件: 左下の歯車から右のシーン設定へ切り替える。ワールド名またはアイテム名、説明、サムネイル、空の背景の背景表示・IBLライティング、無限遠・ボックス・地面付きドーム投影、画像・回転・明るさ・有限メッシュ位置・回転・大きさ・投影中心、Fog、環境光、Near/Far、FOV、背景、グリッド、ギズモ、スナップを一か所で設定する。公開情報、シーン、生成ワールドへ一貫して反映する。

## F-13 XRiftのコンポーネント editor preview の状態設計

### 操作前

- Hierarchy、追加、設定、AssetsはコンポーネントRegistryの公式名、説明、用途を示すアイコンを使用する。シーンは保存済みPropsとオブジェクト位置・回転・大きさを`@xrift/world-components`本体へ渡す。編集と動作確認で同じ公式描画方式を使用する。

- 設定でPortalの`instanceId` / `disabled`、TagBoardの`title` / `columns` / `tags` / `scale`を変更する。同じ公式コンポーネントへPropsを即時反映する。通信、ユーザー状態の生成、シーン履歴以外の副作用は起こさない。

### 戻り先

- 選択解除、オブジェクト削除、元に戻す / やり直すでは補助表示だけを同じシーンの編集データへ追従させる。Camera、選択、実行環境状態を追加で変更しない。

## F-14 Basic コンポーネント menu / 音源の状態設計

### 操作前

- Entity作成メニューは、選択中のEntityの有無にかかわらず、新しいEntityを作る。すべての配置候補をカテゴリにまとめる。先頭のEntityには空のEntity、続く基本形状にはCube、Plane、Sphere、Cylinder、Cone、ワールドにはSpawnPointを入れる。「床」のような用途名を基本形状の名前にしない。光るCubeなどの装飾プリセットは追加候補から外す。
- Light、Text、Image、Audio Source、Particle Emitterは配置候補として残す。Rigid Body、Collider、Script、Interaction Trigger、Windなど、既存Entityへ付ける機能はInspectorから追加する。「Component付きEntity」という分類を作らない。
- Skybox、TagBoard、EntryLogBoard、PortalはEntityの配置候補に含めない。既存のEntityとInspectorのComponent設定は維持する。
- 複数選択のEntity上で右クリックした場合は名前変更、コピー、複製、削除などの操作だけを出し、Entity作成とComponent追加は表示しない。削除は選択全体に適用する。選択外のEntityを右クリックすると、そのEntityを選択して単体用メニューへ切り替える。上部の「素材を追加」とHierarchyの空白からは、複数選択中でもシーン直下へ新しいEntityを追加できる。
- XRiftの配置候補は一つの一覧にし、同じ保存形式のPrefabがある場合は設定済みのPrefabを使う。Prefabと生のComponentを二つの配置候補として並べない。配置前に必要な設定がある場合は案内を残す。Entityの作成は上部の「素材を追加 → Entityを作成」から行う。
- デスクトップではUndo / Redo / 追加だけの独立したツール行を置かない。Undo / Redoはプロジェクト見出しと同じ上部ヘッダーへ置き、Entityの追加は上部の「素材を追加」とHierarchyの空白、選択Entityの操作はScene / HierarchyのEntity上の右クリックへ分ける。タッチ端末ではHierarchy見出しの「追加」から同じ新規作成カタログを開き、選択中でもシーン直下へ作成する。選択行の「…」は編集メニューを開く。シーン表示の縦幅をこのためだけに消費しない。
- Inspectorの「Componentを追加」は、対象Entityへの追加操作とする。HierarchyのEntity上の右クリックは対象の編集・再利用、空白の右クリックは新規Entityの作成に使う。Transformは必須なので候補に出さず、Spawn Pointの旧追加口も出さない。SpawnPointは公式の一つに揃える。
- Hierarchyの右クリックメニューは他パネルの上へ表示し、画面内に収まる位置と最大高さを使う。空白からのEntity追加は、検索欄を置かず、Entity・基本形状・ワールド・ライト・UI・音声・エフェクト・XRiftの分類から選ぶ。外側のクリックまたはEscapeで閉じる（MI-11）。Scriptエディターより上、モーダルダイアログより下に表示する。
- 名前、カテゴリ順、重複規則、Mesh Colliderの前提条件は共通定義を参照する。候補に追加できない理由を表示する。Inspectorの検索中は一致するカテゴリを開き、空のカテゴリを表示しない。基本Componentと公式XRift Componentは英語名を使う。
- Audio Sourceは追加直後も既存オブジェクト選択を維持する。設定で取り込み済み音声素材を選択できる。直接URLは新規設定に使わない。既定では自動再生しない。編集画面を開いただけで音を鳴らさない。

### 操作中

- 節の開閉とInspectorの検索文字の入力・クリアはSceneDocumentと履歴を変更しない。検索中は一致する節を開く。候補がない場合は同じメニューで伝える。項目を選んだ時だけコンポーネント追加を一件確定する。メニューを閉じる。追加したコンポーネントの設定を表示する。
- Audio Sourceは有効、音声素材、音量、繰り返す、自動で再生する、Spatial、音量を保つ距離、音の減衰率、最大距離を型と範囲を保って編集する。音声素材がない時は同じ設定からMP3 / WAVを取り込む操作を確認できる。編集表示では音声取得を開始しない。動作確認中はvolume / loop /距離プロパティを既存プレイヤーへ更新する。素材、spatial、enabled、構成変更は対象オブジェクトだけを再同期する。

### 成功時

- 動作確認とコンパイラーは参照されたMP3 / WAVを管理下元データから読み込む。同じ音源実行環境で通常音声 / PositionalAudioへ変換する。カメラへAudioListenerを接続する。コンポーネントを無効化した時とオブジェクトを破棄した時は再生、リスナー、バッファー参照を解放する。
- ライト、パーティクル、Audio Sourceは追加、Hierarchy、設定のどの操作から追加しても同じコンポーネントID、初期値、重複規則、生成結果になる。

### 失敗時

- 未設定音声素材や読み込み失敗でシーン全体を停止させない。未設定はコンパイル 警告として出力を省略し、参照切れ・MP3 / WAV以外の元データはコンパイルを停止する。実行環境読み込み失敗は該当コンポーネントの音声だけを停止する。自動再生ポリシーで拒否された時は再生が拒否された状態を保持する。操作後のスクリプトまたは通常操作から再試行できる。
- 非有限値、範囲外の音量、0以下の距離、負の音の減衰率は確定しない。直前のSceneDocumentと選択を維持する。

### 戻り先

- コンポーネントを追加を閉じると同じEntityの設定へ戻る。追加後は同じオブジェクトを選択したままにする。元に戻すでコンポーネント追加前へ戻る。やり直すで同じコンポーネントIDと設定へ戻れる。

完了条件: Entity作成とComponent追加の対象が明確で、共通Registryから用途に合う候補を表示する。折りたたみを開いて一件追加し、設定へ到達できる。Audio Sourceは取り込み済み音声素材を選ぶ。編集画面を開いただけでは音を鳴らさない。

## F-31 地形 authoring / MCP の状態設計

参照: MI-03, MI-05, MI-09, MI-13, MI-16, MI-76, MI-87

### 操作前

- 上部の「素材を追加 → Entityを作成 → ワールド → Terrain」から、16 × 16m・33 × 33の高さサンプル・平坦な地形を作成できる。地形には常に静的なメッシュと同じ形の衝突判定を付け、マテリアル枠は一つだけにする。
- 選択中の地形の設定には大きさ、Resolution、現在の高さの範囲と、Raise / Lower / Flatten / Smoothのブラシを表示する。中心X/Z、radius、strength、Flattenの対象の高さを指定して一回のスタンプを適用する。
- 「草」では層の一覧、密度、傾斜の上限に加えて、選択中の層だけに色と大きさを開く。値は種類の既定から始まり、動かした項目だけが層の上書きになるので、既定のまま使う層は何も持たない。

### 処理中

- 作成と各ブラシスタンプは編集中だけ有効にし、動作確認中または素材インポート中は無効化して理由を残す。ブラシ処理中に別の編集データ操作を重ねない。
- MCPでは`get_terrain`で対象の範囲を確認し、`create_terrain`または`sculpt_terrain`へprojectId、sceneId、expectedRevisionを渡す。UIとMCPは同じ高さサンプルの計算を使う。

### 成功時

- 地形を選択したままシーン、Hierarchy、設定を更新し、各スタンプを一件の元に戻す履歴と自動保存対象として確定する。シーン、動作確認、コンパイル、実行環境manifestは同じ高さサンプルを使う。
- 静的なメッシュと同じ形の衝突判定の範囲は地形の幅、奥行き、高さの範囲に追従する。マテリアル枠から地形の見た目を続けて調整できる。
- 草の色と大きさの変更も同じ一件のシーン更新として確定し、シーン、動作確認、生成ワールドは同じ解決済みの値で描く。「種類の既定に戻す」で層は上書きを持たない状態へ戻る。層が本数の上限に達している場合は「本数を確認」に、密度どおりに生えないことと下げ方を示す。

### 失敗時

- 範囲外、空の対象、古いリビジョン、地形以外のオブジェクトへの適用は編集データと履歴を変更しない。設定の入力と選択を保ち、対象またはリビジョンを確認して同じ操作からやり直せる。

### 戻り先

- 作成・ブラシ適用後は地形設定に留まる。元に戻す / やり直すで直前の地形の高さサンプルを戻し、必要ならマテリアルまたは衝突判定診断へ進める。

完了条件: 上部の「素材を追加 → Entityを作成 → ワールド → Terrain」から静的な地形を追加する。設定とMCPの同じRaise / Lower / Flatten / Smoothブラシで高さサンプルを編集する。各スタンプは一件の元に戻す履歴として保存される。シーン、動作確認、生成コード、メッシュと同じ形の衝突判定へ同じ地形を反映する。

## F-32 シーン post effects の状態設計

### 戻り先

- 設定変更後はシーンへ留まり、動作確認、Compile、公開レビューの順に進める。失敗時はシーン設定または変換manifestの診断へ戻る。

完了条件: シーン設定でHDR / AO / Bloom / 露出を編集する。シーン、動作確認、生成ワールドの同じレンダリング設定へ反映する。設定は保存・再読込・公開レビューまで同じシーンの契約で扱う。

## F-33 風コンポーネントの状態設計

参照: MI-03, MI-05, MI-09, MI-11, MI-13, MI-14, MI-15, MI-16, MI-81

### 操作前

- 風コンポーネントはEntityの設定のコンポーネントを追加からRenderingカテゴリーに置く。コンポーネント検索でも同じ項目に到達できる。
- コンポーネントカードは「風」「オブジェクトコンポーネント」を見出しにし、対象がこのオブジェクトと子メッシュであること、風の強さ・速度・突風はシーン設定のグローバル設定を使うこと、メッシュ名からは判定しないことを本文で示す。カード内の操作は有効だけにし、同じ値をコンポーネントとシーン設定の二か所で編集させない。
- シーン設定の「風（グローバル）」に、風の有効化、風の強さ、風の速度、突風の強さ、風向き（度）を置く。シーンの風は常に一つであることを同じ場所に書く。
- 風に反応するシェーダーマテリアルは、`uWindDirection`、`uWindSpeed`、`uWindTurbulence`を宣言したものだけが対象になる。宣言していないシェーダーへ値を渡さず、対応しているように見せない。

### 操作中

- コンポーネントの追加と有効の切り替えは一件のシーン更新として履歴と自動保存へ入り、シーンへ即時反映する。設定とMCPは同じリビジョン検査を通る。
- グローバル設定の変更はシーンの対象オブジェクトと風対応マテリアルへ同時に反映する。水面が北へ、草が東へ流れるような食い違いを作らない。
- 向きはグローバルのままとし、オブジェクト側では上書きしない。一つのシーンに二つの風向きを持たせない。

### 成功時

- エディタープレビュー、動作確認、生成ワールド、Runtime manifestが同じコンポーネントとシーン値を読み、同じ揺れを描く。
- グローバル風を無効にした場合、またはオブジェクトのコンポーネントを無効にした場合は完全な静止に戻す。マテリアルが独自に動き続けない。

### 失敗時

- 対象オブジェクトに描画対象のメッシュがない場合もコンポーネント自体は保存し、対象が空であることを示す。名前や見た目からの推測で別のオブジェクトを対象にしない。
- シーン設定に風の設定がない古いシーンは互換既定値で読み込み、シーンを開けなくしない。

### 戻り先

- 追加・変更後はEntityの設定に留まり、グローバル値の調整はシーン設定へ一操作で移動できる。確認は動作確認で行う。

完了条件: Entityの設定またはMCPから風コンポーネントを明示的に追加する。対象オブジェクトと子メッシュだけへシーン設定のグローバル風設定を適用する。エディタープレビュー、動作確認、生成ワールド、Runtime manifestは同じコンポーネントとシーン値を使う。名前・メッシュ分類・言語に依存した対象推測を行わない。

## F-34 空の背景シェーダー（手続き的な空）の状態設計

### 33種類への拡充

- 操作前: 11カテゴリ・名前・説明・タグで絞り込み、選択が検索結果から外れたら先頭へ移す。0件は空状態を表示する。一覧は本体と同じThree.jsマテリアル生成処理で描いた静止画、詳細だけはR3Fで描画する。

- 失敗・戻り先（MI-09）: 選択と設定を保持して再試行できる。詳細はドラッグ・矢印キー・再生停止・視点リセットに対応し、非表示中は連続描画を止める。
- MCP: `list_material_presets`で品質ごとのvariantを取得し、`create_material_from_preset`と`update_custom_shader`で同じ品質を設定する。既存の編集操作で扱えるため専用ツールは増やさない。プレビュー視点と停止はストアだけの状態で、シーンへの保存や表示側の上書きの対象ではない。

### 操作前

- 「外部から追加」の左一覧に「Skybox Shader」を公式カタログとして置く。見出しには件数と「GLSLで空を描くマテリアルです」という説明を表示する。
- カードは実際のGLSLをWebGLで描画する。SVGやCSSの疑似サムネイルを使わず、カードで見えているものと追加後の空を一致させる。11カテゴリー（昼、夕暮れ、朝焼け、夜空、オーロラ、宇宙、天候、幻想、スタイル、抽象、水中）で絞り込める。
- 詳細では、そのプリセットが何を描くかと負荷の目安を文章で示し、調整できる値を名前・値・説明・uniform名付きのスライダーとして並べる。変更はプレビューへ即時反映し、「既定値へ戻す」でプリセットの値に戻せる。
- 追加ボタンは「Skyboxに設定」とし、「追加後にSkyboxへ設定」を既定で有効にする。チェックを外した場合はマテリアルだけを追加することを、同じ場所に書く。
- シーン設定のSkyboxには「空の背景シェーダー（カスタムシェーダーマテリアル）」の選択肢を置き、割り当て中は空の背景画像とグラデーションより優先して空を描くことを示す。

### 操作中

- 追加は通常の素材インポート トランザクションを通り、マテリアルの作成とシーンのskybox設定を同じ履歴へ確定する。
- 割り当て中は上空の色、地平線の色、オフセット、グラデーションを無効表示にする。水平回転と明るさはシェーダーのuniformへ渡すため有効なまま残す。
- Skybox Shaderは編集中のシーンにも表示する。表示モードや品質の設定で表示が変わる場合は、その条件をUIで示す。動作確認でも同じシェーダーを使って見え方を確認できる。

### 成功時

- 追加後はマテリアルとして残り、星の数や色を設定の調整できる値から何度でも変更できる。カタログからの調整と設定での再調整は同じマテリアルを指す。
- 動作確認、生成ワールド、Runtime manifestが同じGLSLと同じuniform値を使う。
- 同じプリセットをもう一度追加した場合はマテリアルをプリセットの値で上書きし、二つ目の同名マテリアルを増やさない。

### 失敗時

- 割り当てたマテリアルが欠落または不正な場合は理由を示してグラデーションの空へ戻す。背景を空にしない。
- 重いプリセットは計算ステップ数をvariantのdefineとして残し、下げられる状態にする。負荷を隠さない。

### 戻り先

- 追加後はシーン設定の空の背景シェーダー欄へ戻り、「〇〇のUniformを編集」からマテリアル設定へ移動できる。カタログを閉じた場合もシーンと選択は変わらない。

完了条件: 空を描くカスタムシェーダーマテリアルとして昼・夕暮れ・朝焼け・夜空・オーロラ・星雲の空を追加できる。星の数、太陽と月の位置、月の満ち欠け、雲、地平線の遠景をuniformで調整できる。レイマーチする厚みのある雲も選べる。外部リソース集での調整と設定での再調整が同じマテリアルを指す。シーン、動作確認、生成ワールドが同じGLSLを描く。マテリアルが欠落した場合はグラデーションへ戻す。警告診断を残す。重いプリセットは計算ステップ数をvariantのdefineとして残す。下げられる状態にする。

参照: MI-05, MI-09, MI-81, MI-90

### 操作前

- 追加、Hierarchy右クリック、設定のコンポーネントを追加のRenderingに「テキスト」「テキスト看板」「作品キャプション」を並べる。三つは同じテキストコンポーネントで、初期の書体、揃え、背景の板だけが異なる。看板とキャプションは追加した時点で板と書体が入っており、美術館の解説や壁のラベルをそのまま置ける。
- 設定は文字（内容、書体、太さ、色、大きさ、折り返し幅、揃え、行間、字間、基準点、縁取り）と背景（なし・色・画像、色味、不透明度、板の大きさ、余白または幅高さ、文字との奥行き、裏からの見え方）を一つのカードに順に並べる。
- 書体は「自動」を既定にする。自動は同梱の標準書体（日本語のサブセットのため欧文も含む）で表示するので、日本語と欧文が混ざっていても設定なしで表示できる。
- 手持ちの書体を使う場合は、TTF、OTF、WOFFのファイルを素材へ取り込み、同じ書体の選択欄の「プロジェクトのフォント」から選ぶ。WOFF2は表示に使えないため取り込みの時点で理由を示して断る。取り込んだフォントは太さを選べないので、太さの操作は同梱書体のときだけ意味を持つ。

### 処理中

- 書体を選ぶと、その書体の同梱ファイルを初回だけ取得し、取得が終わってから一度だけ組版する。取得の間は文字を描かず、背景の板だけを先に置く。取得済みの書体はキャッシュから即座に使う。自動の書体で先に組んでから差し替えないのは、その組版が文字種ごとの代替フォント取得を伴い、代替フォントの配布元へ到達できない環境では以後の組版ごと止まってしまうため。
- 背景の画像は素材のテクスチャから選ぶ。編集中はプロジェクトの画像をそのまま読み、シーンと動作確認で同じ板を描く。
- 板の大きさが「文字に合わせる」のときは、組版が終わるたびに実測した文字の範囲へ余白を足して板を組み直す。実測が終わるまでは板を出さないので、途中の大きさで一瞬ちらつかない。

### 成功時

- シーン、動作確認、生成したコード編集元データ、公開したワールドは同じテキストコンポーネントの値から同じ描画経路で文字と板を描く。Studioが独自に別の見た目を作ることはない。
- 「自動」も同梱の書体として解決する。文字種ごとに配布元から代替フォントを取得する経路は使わない。公開したワールドはそこへ到達できず文字が表示されないうえ、Studioと公開先で字形が食い違うため。書体のファイルはワールドへ同梱し、Runtime JSON出力ではmanifestがその置き場所を示す。
- 書体は`fontId`だけを編集データへ保存し、ファイルのURLはカタログで一元管理する。その書体に含まれない太さを選んだ場合は、配布されている太さへ丸めて保存する。
- 背景に選んだテクスチャは公開時の同梱対象になり、Runtime manifestにも参照が残る。

### 失敗時

- 取り込んだフォントの参照先が見つからない、または公開用にコピーできない場合は、同梱の書体で出力し、コンパイルで警告を残す。文字が消えることはない。
- 書体のファイルを読めなかった場合はtroika既定の字形で表示を続ける。文字が消えることはなく、設定に取得できない可能性を文言で残す。
- 背景を「画像」にしたまま画像が未設定、または参照先が公開できないテクスチャのときは、コンパイルで警告を出して色だけの板として出力する。文字は必ず出力する。
- カタログにない書体ID、範囲外の太さ・行間・不透明度・余白・幅高さはSceneDocument、選択、履歴を変更しない。MCPからの`update_component`も同じ境界で拒否し、背景の画像はテクスチャを指しているときだけ受け付ける。

### 戻り先

- 変更は一件のシーン更新として保存し、元に戻すで直前の書体・背景へ戻る。追加や編集の後も同じEntityの設定に留まり、プレビュー / Compile / 動作確認へ進める。

完了条件: テキスト、テキスト看板、作品キャプションを同じコンポーネントRegistryから追加する。同梱書体または取り込んだフォント、色、太さ、揃え、行間と、色または画像の背景板をInspectorで設定できる。板は文字の実測値に合わせて組み立てる。シーン、動作確認、書き出したコード、公開ワールドが同じ描画経路で同じ見た目になる。取得できない書体は自動の書体へ戻す。出力できない背景画像は色だけの板へ切り替える。文字は必ず表示する。

## F-44 画像コンポーネント（画像の板）の状態設計

参照: MI-05, MI-09, MI-11, MI-15, MI-118

### 操作前

- 追加、Hierarchy右クリック、設定のコンポーネントを追加のRenderingに「画像」を並べる。テクスチャを1枚の板として置くコンポーネントで、美術館の展示、ポスター、時計の文字盤のように「画像そのものを貼る」用途に使う。文字を添えるときは同じオブジェクトの子にテキストを置く。
- 素材のテクスチャをシーンまたはHierarchyへドラッグする、右クリックの「シーンへ配置」を選ぶ、MCPの`place_asset`へテクスチャを渡すと、そのテクスチャを貼った画像オブジェクトができる。幅1mで、高さは画像の縦横比から決まる。環境テクスチャ（HDRI）は空の背景の落とし先のままにし、画像にはしない。
- コンポーネントを追加で画像を足すとき、Assetsで画像テクスチャを選択中ならその画像を貼った状態で始める。選択がなければ画像は未設定で、設定に画像の選択欄と取り込みの案内を出す。
- 設定は画像（サムネイル、選択欄、テクスチャ設定を開くボタン）、幅、高さ（画像に合わせる・サイズを指定）、基準点、色味、不透明度、透明部分の扱い（切り抜く・なめらかに重ねる）、裏からの見え方、ライトの影響を一つのカードに並べる。既定はライトの影響を受けない表示で、部屋の明るさに関わらず画像そのままの色になる。

### 処理中

- 画像はプロジェクトのテクスチャをそのまま読み、シーンと動作確認で同じ板を描く。画像を選んでいて読み込みが終わるまでは板を出さず、途中の大きさで一瞬ちらつかない。画像が未設定のときだけ、色味と不透明度どおりの正方形の板を置いて選べる状態にする。
- 高さが「画像に合わせる」のときは、読み込んだ画像のピクセル寸法から縦横比を取り、幅から高さを決める。取り込み時に寸法が分かっているテクスチャでは、設定に決まる高さを先に示す。

### 成功時

- シーン、動作確認、生成したコード編集元データ、公開したワールドは同じ画像コンポーネントの値から同じ描画経路で板を描く。Studioが独自に別の見た目を作ることはない。
- 貼ったテクスチャは公開時の同梱対象になり、Runtime manifestにも参照が残る。通常のテクスチャと同じく、編集画面で使用中の画像をそのまま公開する。
- ノードグラフの「Set Property」では、画像の表示、色味、不透明度を変えられる。不透明度に時間をかけるとフェードになる。画像の差し替えは対象にしない。理由は[KHR_INTERACTIVITY_EDITOR.md](../KHR_INTERACTIVITY_EDITOR.md)の「What a trigger can write」にある。

### 失敗時

- 画像が未設定、または参照先が公開できないテクスチャのときは、コンパイルで警告を出して色だけの板として出力する。板が消えることはなく、エディターで見えていた枠がそのまま公開先に出る。
- 0以下の幅・高さ、範囲外の不透明度、未知の基準点・透明の扱いはSceneDocument、選択、履歴を変更しない。MCPの`update_component`も同じ境界で拒否し、`textureAssetId`は画像のテクスチャを指すときだけ受け付ける。空文字で画像を外し、`height: null`で画像の縦横比へ戻す。
- テクスチャを削除するときは、Image Componentも参照元として数える。「参照を外す」ではテクスチャの参照だけを外し、Image Componentは残す。

### 戻り先

- 追加、配置、編集は一件のシーン更新として保存し、元に戻すで直前の状態へ戻る。配置後は新しいオブジェクトを選択し、位置・回転・大きさ、幅、画像の差し替えへ進める。編集の後も同じEntityの設定に留まり、プレビュー / Compile / 動作確認へ進める。

完了条件: 画像コンポーネントを同じコンポーネントRegistryから追加し、テクスチャのドラッグ・配置・MCPの`place_asset`で画像オブジェクトを作れる。幅と縦横比、基準点、色味、不透明度、透明部分の扱い、両面、ライトの影響をInspectorで設定できる。シーン、動作確認、書き出したコード、公開ワールドが同じ描画経路で同じ見た目になる。画像を出力できないときは色だけの板へ落とし、警告を残す。Graphから表示、色味、不透明度を変えられる。

Assetsの左側は、ルートの「Assets/」とフォルダー階層、その下に種類の絞り込みを表示する。素材一覧には実際のフォルダーと素材だけを表示し、Modelsなどの種類をフォルダー風の項目として並べない。左側の種類を選ぶと該当する素材だけを表示する。空のワールドの初期Assetsは床が使うMaterialだけにし、テスト用Material、サンプルPrefab、Starter Libraryフォルダーは生成しない。

Assetsの背景はフォルダー、絞り込み、一覧を白で揃える。Assetsカードはプレビューと素材名を中心に高さを抑える。プレビューを表示できない場合は種類アイコンを中央に表示し、準備中などの文言をカードごとに並べない。素材自体の異常は警告アイコンで示す。

Assetsのリストでは編集データ・ファイルパス・通常時の準備済み表示を省く。リストとグリッドの配置ボタンは除き、右クリックの「シーンへ配置」から操作する。

## 編集画面の最終調整（MI-03、MI-09、MI-11）

- デスクトップの元に戻す・やり直すは上部の操作列にまとめ、32px四方にする。同じ列の追加・書き出し・公開ボタンも高さ32pxにそろえる。履歴なし・取り込み中・Play中の無効化は維持し、タッチ操作の44pxの当たり領域も維持する。
- デスクトップのHierarchy見出しに「操作 / 追加」は置かない。タッチ端末では見出しの「追加」からHierarchyの空白の右クリックと同じ作成カタログを開く。上部の「素材を追加 → Entityを作成」も利用でき、「外部から追加」は上部から一回で開ける。選択対象への編集操作は右クリックまたは選択行の「…」に残す。追加中・Play中は変更操作を無効にする。
- Scaleの比率固定は初期状態でOFF。数値入力・軸スクラブとも操作軸だけを変更する。固定をONにした場合だけ既存の比率変更を使う。保存済みScaleや反転して貼り付けの挙動は変えない。
- アイテムの編集表示はUnlit、ワールドはシーンを初期状態にする。プロジェクトを開き直した際の初期表示に使い、通常の編集・UndoやPlay/Stopでは選んだ表示を保つ。Play・録画のクリーン表示・サムネイルは従来どおりシーンを使う。素材や保存形式へ表示モードを書き込まない。
- デスクトップのAI接続・シーン設定は、ワークスペース外の下部ステータスバーへ固定する。録画はシーン右上から設定パネルを開く。Assetsのログ・進捗を同じバーへ移し、重複表示しない。パネルを隠してもログは残す。詳細を開いたときだけ上へ展開し、画面内でスクロールできる。Escape・閉じるで起点へフォーカスを戻し、外側クリックはクリック先の操作を妨げない。タブレット・スマートフォンの既存配置は維持する。


## F-46 Hierarchyの部分書き出し・追加・コピー

SceneとHierarchyは同じ右クリックメニューとコマンド処理を使用する。Sceneの空白は貼り付け、Hierarchyの空白は共通カタログからの新規作成と貼り付け、Entity上は選択を保って編集操作を表示する。既存EntityのComponent追加はInspectorに残す。無効な操作は理由を表示する（MI-11）。タッチ操作の親子移動はHierarchy行のメニュー内に残す。

選択範囲を書き出す際は、子孫・必要素材・配置・出力するプロジェクトの種別・注意事項を確認してから保存する。既存の全体ファイルからの追加はScene/Entityを選んで確認後に実行する。元の公開情報や追加先のScene設定を置き換えない。ファイル先行書き込みに成功し、リビジョンとprojectPathが変わっていない場合だけ編集データと選択を一件の履歴へ入れる。ファイル失敗・キャンセル・編集中の変更では編集データを追加しない（MI-03、MI-07）。

元コードや表示文字列を一括置換せず、宣言された参照を新IDへ変換する。ScriptのEdit実行はコピーで無効化する。同期リンクや任意Scriptの安全性を保証しない。保存開始と保存完了を区別する。操作・制約は[受け渡し契約](../HIERARCHY_TRANSFER.md)を正とする。

## F-47 編集導線と制作データ確認

「素材を追加」は共有カタログをカテゴリ表示し、入力中は該当カテゴリを開いて横断検索する。検索はメモリ内の照合だけとし、履歴・識別子・計測を保存しない。検索結果なしの理由と別語での検索を提示する。Entity作成とInspectorのComponent追加を分ける。World/Itemは同じ候補を見せ、個別のプロジェクトの種別による制約・重複・依存条件を実行時にも維持する。

Inspectorは編集対象（Entity / Asset / 複数 / Scene設定）を見出しに表示し、Assetsの選択をEntity複数選択で覆い隠さない。Transformを先頭に保ち、Component検索は正式名と日本語カテゴリで探せる。右クリックメニューは共通の順番と名称にする。


オプトイン、KPI、イベント送信、分析SDK、識別子、使用回数の永続化は導入しない。ローカルの制作データ検査は利用状況の収集ではない。
