## F-07 ビジュアルエディターの状態設計

### 操作前

- コードエディターのワールド設定では、配置する Item ID を 1 行ずつ編集できる。UUID の誤りや 50 種類を超える登録は入力欄で示して保存を止め、重複 ID は保存時にまとめる。公開先や独自の JSON 設定は引き継ぎ、配置コード・Placement ID・`xriftDev` の手順へヘルプから移動できる。
- ワールドのアイテム配置では Item ID と Placement ID を分けて表示する。Placement ID は配置時に固定し、複製時に別の値へ変える。公開用アイテム一覧はシーンから生成する。読み込みに失敗しても設定は保持し、Inspector の「Itemを再読み込み」から現在の認証状態で再試行できる。ブラウザ版のプレビュー用 API キーは作品へ保存しない。
- スマートフォンでは戻る・Undo・Redo・追加・ファイルを 1 行にまとめ、ファイル名と保存状況はファイルメニュー内へ表示する（保存エラーはメニューを閉じていても表示）。編集パネルの切り替えは次の行に残す。
- 新規作成ではアイテム / ワールドとコード編集 / ビジュアル編集の 4 カードを同じ画面で選び（二段階 UI にしない）、内部で成果物種別と制作方法の組み合わせとして扱う。
  - コード編集は `package.json` / `xrift.json` / `src/` を編集するコードプロジェクト、ビジュアル編集は専用マニフェスト・シーン・素材編集データを編集するプロジェクトであることを説明し、同一プロジェクトの表示切替や自動相互変換とは誤解させない。
  - ビジュアル編集では専用保存形式を使うことと、保存・Play・変換・検査・アップロードまで同じエディターから操作できることを選択前に示す。
  - コード編集を選んだ場合は既存の名前入力・作成・一覧更新・コードエディターへの流れを維持する。
- コードエディターのファイル選択では最後に選んだファイルの読み込み結果だけを反映する。既定ファイル探索中に手動選択した場合は手動選択を優先し、読み込み中は本文編集と保存を無効にする。
- ビジュアルエディターを開いた直後は、成果物種別、プロジェクト種別、既定シーン、独立した `sceneSelection` / `assetSelection`、編集状態、位置・回転・大きさツール、未保存状態を表示する。保存済みパネル配置はウィンドウサイズと保存形式に合わせて復元し、不正や画面外の配置は安全な初期配置へ補正する。
- ワールドにはワールド用 Play モード、アイテムにはアイテム用プレビューモードを使うことを示す。ワールドの Play は `@xrift/world-components` の公式プレイヤーを開始位置から一人称で起動し、ワールドの操作制御・物理演算・開始位置処理はアイテムへ適用しない。利用可能な入力操作は Play 前に示す。
- Node.js や XRift CLI がなくても編集と同じ画面で Play を利用できる。Vite・CLI・開発サーバー・別ブラウザの手動起動を制作操作として求めない。

### 操作中

- **コード編集の保存**: MI-03 に従い「保存中…」と無効な保存ボタンで示し、クリックとショートカットが連続しても書き込みは 1 回だけ行う。成功時は書き込んだ内容を保存済みにし、保存中に加えた変更は未保存のまま残す。別ファイル切替後に保存完了しても切替先の保存状態は変えず、失敗時は編集内容を維持して再試行できるようにする。
- **選択と配置**:
  - 素材を 1 回クリックすると `assetSelection` を更新して Inspector に表示し、`sceneSelection` は維持する。3D モデルやプレハブはシーンへのドラッグまたは「配置」の実行時だけ Entity として追加する。
  - Hierarchy と Assets は Shift による範囲選択と Ctrl / Cmd による追加・解除を受け付ける。複数選択時は Inspector に件数を表示し、全対象に共通する `Mesh Renderer` / ライト / マテリアルのプロパティだけを表示する。
  - Entity の新規作成と既存 Entity の編集メニューを分離する。シーン右クリックはコピー・貼り付け等の編集操作、Hierarchy 空白の右クリックは共通カタログからの新規作成に使い、取り込み済み素材の配置は Assets にまとめる。
  - マテリアルドラッグ中はシーンメッシュまたは Entity 設定スロットだけをドロップ対象とし（複数スロットなら選択画面を表示）、テクスチャドラッグは右マテリアル設定の対応スロットだけを対象にする。素材ドラッグ中はシーンだけを配置可能領域として示し、ドロップ前に Entity を増やさない。
- **Hierarchy の操作**:
  - 行のドラッグ＆ドロップは上端・下端を兄弟順の挿入位置、中央を親子化として扱い、ドラッグ中の案内とシーン直下ドロップ先は各行の位置を変えずに表示する。
  - 親行の矢印は子孫行だけを折りたたみ、シーン等から折りたたまれた子を選んだときは祖先を自動展開する。
  - 検索は名前・種類・コンポーネント・有効状態を対象とする。検索欄直下のアイコンでメッシュ、ライト、衝突判定、音声、パーティクル、Animation、Spawn、XRift コンポーネントを複数選択でき、種類同士は OR・文字検索とは AND で絞り込んで一致 Entity と祖先を表示する（クリア後は元の折りたたみ状態へ戻す）。
  - 行の目アイコンと単一 / 複数 Entity の有効チェックは Entity 自身の状態を切り替える。単一 Inspector の先頭は有効チェック・名前・必要時のみ継承状態アイコンの順に並べ、プレハブ元データは名前と更新アイコンだけを置く（説明は常設せずツールチップと読み上げ名へ移す）。
  - 子 Entity の位置・回転・大きさはローカル値として保持し、シーン・Play・生成ワールドのすべてで親の Transform を継承する。
- **ギズモ・数値入力・フォーカス・強調表示**:
  - ギズモ操作中はカメラ操作を競合させず、シーンと Inspector の Transform 値を即時同期する。軸ラベルのスクラブ時も同様に同期し、大きさの比率固定中は操作軸の倍率で不均等比率を維持する。
  - Inspector とシーン設定の数値欄は上下スピナーを置かず、左右ドラッグで値を変更する（通常ドラッグは微調整、Ctrl / Alt で変化量を拡大）。動かさずに離すと数値入力を開始してキーごとに反映する。1 回のドラッグを 1 件の履歴として確定し、Escape で操作前の値へ戻す。
  - ギズモとそのドラッグ平面は親子関係にかかわらず対象 Entity のワールド位置に描き、祖先の Transform を二重適用しない。ドラッグ開始時はカメラ慣性を先に止め、見え方と移動量を一致させる。
  - Entity 選択中に `F` を押すと、そのサブツリーの表示中メッシュだけから測った描画境界ボックスへカメラと Orbit 中心を合わせる（コライダー枠・ライト矢印・選択輪郭などの補助表示や無効な子は除外）。フォーカス中に別 Entity を選んだだけでは追従せず、`F` を押したときだけ対象を切り替える。
  - モデル選択時は選択ノードのメッシュ表面を紫色で強調し、離れた部品を 1 つの箱で囲わない（部品間の空間は強調しない）。ドリルダウン時は選択先へ切り替え、選択解除で消す。強調表示はクリック判定・フォーカス範囲・保存・公開データに含めない。
  - 待機中ギズモと選択補助線はニュートラルカラーで控えめにし、操作中の軸と素材ドロップ対象だけを明るく示す。「ライトなし」「ワイヤー」「コライダー編集」では既定グレーマテリアルが埋もれない暗いニュートラル背景を使い、シーン設定や公開結果は変えない。
- **レイアウトと狭いパネル**:
  - パネルのサイズ変更やドッキング中は配置先プレビューと最小サイズを示し、編集データと選択は変えない。
  - シーンと Assets のヘッダーは幅が狭くなっても 1 行に収める。シーンでは名前省略 → スナップと「表示」のアイコン化の順で縮め、カメラ投影方式・表示モード・診断・録画は「表示」ポップオーバーにまとめる（録画パネルはシーン右上の「録画」から開く）。Assets では検索欄縮小 → パンくず折りたたみ → 「アセットストア」とインポートのアイコン化を行う。Play / Stop は常に同じ行に残し、他操作と重ねない。
- **素材変更・外部ドロップ・Play 中の編集**:
  - マテリアルの色・Metallic・Roughness・テクスチャ参照は編集・Play のどちらからも変更でき、同じ素材 ID を参照する全プレビューへ同期する（Play 中は参照 Entity だけを再起動し、Entity 固有値へ複製しない）。
  - 外部 GLB / glTF のドロップはインポートキューで検証・コピー・派生データとサムネイル生成・マニフェスト確定まで行う。Assets ドロップは素材追加まで、シーンドロップは取り込み成功後に続けて配置する。
  - Play 準備中は二重開始を防ぎ、成功まで編集データを変更しない。ワールドでは有効な開始位置を Hierarchy 順に解決し、親子 Transform と合成した位置から開始する。
  - Play 開始後は実行コピーを `Play Window` に表示し、Hierarchy と Inspector は編集データへ接続したままにする。Entity / Component 構成、Transform、衝突判定、Animation、既存マテリアル・パーティクルのプロパティ、MCP 経由のシーン設定は通常履歴と自動保存で変更でき、シーン設定は共有シーンへ即時反映、Entity / 素材変更は影響 Entity だけへ反映する。テクスチャ / 3D モデル設定、Inspector のマテリアル割当、ギズモ、素材ドロップは Stop まで無効にする。
  - ワールドプレビューは使える入力操作を示し、アイテムプレビューにはワールド用アバターや操作制御を出さない。Play 中の入力・操作制御・カメラ・物理演算は `PlaySession` にだけ保持する。Stop は常に見える位置に置き、ヘッダーの「ビジュアル」・未保存・コンパイル状態・アップロード / 審査状態も消さない。

### 成功時

- 素材配置では素材 ID を参照するルート Entity を 1 つ追加する。GLB / VRM に元データの Node メタデータがある場合だけ同じトランザクションで編集用 Node ツリーを子へ展開し、ルートを選択する（元に戻すでルート・展開 Node・選択をまとめて戻す）。
- 基本形状作成は `CreatePrimitiveCommand` 1 件で Entity と組み込み形状参照を追加し、マテリアルドロップは `AssignMaterialCommand` 1 件で既存メッシュの割当枠だけを更新する。
- Transform 変更はギズモや軸ラベルを押してから離すまでを 1 件の履歴として確定し、選択とカメラを維持する。
- フォーカス成功時は対象名と `F` / Escape / 解除ボタンをシーン端に残し、同 Entity での再 `F` または解除で開始前のカメラ位置・向き・Orbit 中心・ズームへ戻す。
- パネル配置変更後は正規化したサイズ・ドッキング領域・並び順をエディター設定へ保存し、再起動後も復元する。
- マテリアル変更後は有効値を `AssetManifest` の 1 マテリアルへ保存し、共有する全 Entity 表示を更新する（`SceneDocument` や Entity 固有値は変えない）。
- Play 開始時は中央の `Play Window` で種別に応じたモードを確認でき、実行時の位置・速度・アニメーション時刻は `PlaySession` にだけ保持する。Play 中の許可済み変更は編集データへ残し、該当 Entity だけ実行リビジョンを進めて Animation と物理演算を先頭から再実行する（他 Entity や操作制御は維持）。
- Stop 時は `PlaySession` を破棄し、Play 中の許可済み調整を含む最新の `SceneDocument`・`AssetManifest`・選択・編集カメラへ戻る（実行時の位置・速度や `ctx.materials` / `ctx.particles` 上書きは編集データ変更としない）。
- GLB / glTF 取り込み成功は元データ・派生データ・サムネイル・マニフェスト確定と新素材カードで示し、シーン配置はシーンドロップまたは後続「配置」成功時だけ別結果として示す。同期操作の結果はトーストだけに留めず、追加 Entity・Inspector・参照表示・インポートキューとして画面に残す。

### 失敗時

- 非対応ファイルは拡張子と対応形式を示し、`SceneDocument`、`AssetManifest`、選択、履歴を変更しない。
- Transform に非有限値や不正サイズが入った場合、または軸スクラブを Escape / ポインターキャンセルで終えた場合は操作前へ戻し、対象欄の近くに修正方法を示す。
- 選択 Entity に描画境界ボックスがない場合はワールド座標をフォーカス中心にし、Entity を選べない場合や Play 中・入力中はカメラを変更しない。
- マテリアルに不正色、非有限値、`0..1` 範囲外、欠落テクスチャ参照が入った場合は確定せず、入力欄近くに形式や範囲を示す。
- 欠落素材参照では Entity を消さず、欠落 ID・参照元 Entity・再インポートまたは置換の案内を表示する。
- 基本形状の作成位置・親 Entity・マテリアル / テクスチャスロットを解決できない場合はコマンドを確定せず、選び直しを促す。
- Play 初期化失敗時は編集画面とデータを維持し、シーン内にモード・原因・再試行を表示する（CLI や別ブラウザの手動起動を回避策として求めない）。Play 中の実行時エラーでは `PlaySession` を破棄して安全に編集へ戻り、`SceneDocument` と `AssetManifest` を壊さない。
- シーン初期化失敗時は MI-09 のエラー画面を表示し、ライブラリへ戻る操作と再読み込みを用意する。
- パネル配置設定を保存できない場合も現在の配置を維持して編集を止めず、再試行と「レイアウトをリセット」を示す。
- 保存・変換・検査・アップロード失敗時は、機密情報を除いた段階と原因を表示して成功通知は出さず、再試行または対象入力欄へ戻れるようにする。

### 戻り先

- ヘッダーにライブラリへ戻る操作を置き、未保存変更がある場合は保存・破棄・取消を同じ画面内で選べる（永続化接続後はシーン・プレハブ・素材・フォルダーのいずれかが未保存の場合にこの確認を出す）。
- Play 中にライブラリへ戻るときは先に Stop と同じ解放を実行して `PlaySession` を破棄し、実行時状態を編集データへ保存しない。
- ライブラリへ戻ると新規作成カードを先頭に維持する。一覧には作成または保存トランザクションが確定したプロジェクトだけを追加する。
- Escape で未確定のドッキング・サイズ変更を操作前へ戻し、「レイアウトをリセット」で左 Hierarchy・中央シーン・右 Inspector・下 Assets へ戻す。
- フォーカス中の Escape・解除ボタン・Play 開始は保存した編集カメラへ戻し、選択と `SceneDocument` は変更しない。

完了条件: 4 作成カードと Hierarchy・シーン・Inspector・Assets を使い、独立選択、複数選択と共通プロパティ編集、復元可能なフォーカス、目的別表示モード、Empty / 基本形状 / XRift コンポーネント作成、素材 / マテリアル / パーティクル / プレハブの D&D、Hierarchy の検索・種類フィルター・折りたたみ・並び替え・親子化・有効切替、親子 Transform、軸スクラブと比率固定、コンポーネント有効切替、マテリアル・テクスチャ・パーティクル編集、テクスチャ繰り返し、ノードグラフからのマテリアル操作、配置ごとの静的モデルポーズ、GLB / VRM の Node・Bone・メッシュ別編集、Animation 自動再生、動的サムネイル、テクスチャからのプロジェクトサムネイル設定、Play とシーン環境設定、右上の 3D モデル / R3F / コード編集取り込みを一貫して扱える。下部ユーティリティレールから ChatGPT とシーン設定、設定画面から MCP 接続、シーン右上から録画、シーン設定先頭からヘルプと報告・レイアウト初期化へ進める。パネル配置は再起動後も復元され、描画やモジュール読み込み失敗はアプリ全体へ伝播させず再試行・再読み込み・一覧復帰を選べる。

## F-09 コマンド・ショートカット・プレハブの状態設計

### シーンの右クリックメニュー（MI-11）

- 通常はコピー、貼り付け、反転して貼り付け、複製、名前を変更、フォーカス、削除を表示する。シーン空白では貼り付け、Hierarchy 空白では Entity 作成カテゴリと貼り付けを表示する。複数選択中の Entity 上で右クリックしても選択を 1 件に戻さず、選択外を右クリックしたときだけその Entity を対象にする。
- コピー前の貼り付けは無効化して理由をツールチップに表示し、取り込み中は変更操作を無効にする。Play 中・録画ビュー・アセットプレビューではシーン編集メニューを出さない。
- 「反転して貼り付け」を押したときだけ X・Y・Z の選択を同じメニュー内に開く（通常貼り付けは 1 回で実行し、専用の Ctrl+M や常設反転ボタンは追加しない）。Hierarchy の貼り付けも同じ部品とコマンドを使う。
- 上下キーで項目移動、右キーで軸選択を開き、軸選択の Escape・左キーで 1 段戻り、親メニューの Escape でシーンへフォーカスを戻す。外側クリックではクリック先操作を妨げずに閉じ、右ドラッグのカメラ操作ではメニューを開かない。
- 既存 UI の白・slate・violet 配色に合わせて行間を抑え、画面端や軸選択展開後も画面内へ収めてパネル境界で切れないようにする。
- 反転はコピーされた各ルートのローカル Scale の 1 軸だけに適用し、位置・回転・子のローカル Transform は変えない（比率固定状態に左右されず、鏡面自動配置も行わない）。親子の重複選択は 1 サブツリーとして扱う。
- 成功時は新しいルートをすべて選択し、元データとクリップボードを維持する。編集データ・選択・保存対象変更を 1 件の履歴に積み、Undo / Redo で同じ ID と選択を復元する（反転専用保存形式やフラグは設けない）。
- 単独の共有モデル Node はコピー不可の理由とモデル全体を選ぶ操作を案内し、無効な貼り付け先や反転データでは編集データと履歴を変更しない。

### 操作前

- ツールバー、右クリックメニュー、ツールチップ、ショートカット設定は、共通レジストリーから同じ操作名、用途に合う Lucide アイコン、OS 別キー割り当て、有効・無効理由を表示する。
- Hierarchy から Assets へドラッグするとプレハブ作成となり、ドロップ前に作成先フォルダーとサブツリー / 依存ファイル件数を示す。

### 操作中

- コピーはバージョン付きバッファーだけを更新し、Paste / 複製 / 削除 / プレハブ作成は操作前後の編集データと `sceneSelection` / `assetSelection` を 1 トランザクションにまとめる。
- テキスト入力欄、`contenteditable`、数値入力欄、IME 変換中のフォーカス時は、`W` / `E` / `R` / `X` / `F` / 矢印 / PageUp / PageDown / 削除 / Copy / Paste / 複製のエディターコマンドと Shift スナップ反転を実行しない。ショートカット競合時はどちらも実行しない。
- スナップの入切と間隔は `editor.gizmo` のシーン設定として保存し、元に戻す履歴には積まない。矢印 / PageUp / PageDown の 1 ステップはギズモドラッグと同じ 1 件の履歴として確定する。

### 成功時

- Paste / 複製は決定済みの新 ID を、プレハブ作成はプレハブ・編集データ・フォルダー所属・インスタンスメタデータを一度だけ確定し、両選択を仕様どおり更新する。
- 元に戻す / やり直しは同じ ID・依存ファイル参照・プレハブ上書き・前後両選択を復元し、ツールバー・メニュー・キーボードのどこから実行しても同じ履歴結果にする。

### 失敗時

- コピーバッファーが古い場合、リビジョン競合、プレハブ循環参照、依存ファイル欠落では編集データを変更しない。参照中素材も削除せず、対象 ID と修正操作を示す。
- 複数文書にまたがるプレハブ操作が失敗した場合は途中結果を残さず、一時プレハブデータと新規 ID を破棄してシーン・Assets・フォルダーを操作前リビジョンへ戻す。

### 戻り先

- Escape は未確定ドラッグ・メニュー・ダイアログを閉じ、操作前の両選択とフォーカス面へ戻る（確定後は元に戻すを使用）。
- ショートカット上書きはエディター設定に保存してプロジェクト切替後も引き継ぎ、「既定へ戻す」でレジストリー既定値へ戻せる。

完了条件: ツールバー・メニュー・キーボード・Hierarchy D&D が共通のコマンド / ショートカットレジストリーを使い、Copy / Paste / 複製 / 削除 / Reparent、フォーカス切替・解除、Empty / Component 作成、プレハブ化、組み込みプレハブ配置、元に戻す / やり直しで ID と両選択を正確に復元できる。

## F-11 衝突判定の編集・書き出しの状態設計

`Mesh Renderer` の「歩行・当たり判定」から追加・解除・シーン全体を選択メッシュだけへ置換できる（MI-03）。置換対象は Trigger を含む衝突判定と物理挙動の自動生成であり、操作前に範囲を常時示して 1 件の元に戻す履歴へまとめ、成功後も選択と設定一覧を維持する。Play 中と無効階層では操作不可とする。親の自動 Box / 球をメッシュへ変換する必要がある場合は形状を勝手に変えず、設定元を示して変更を拒否する。親の独立 Box 形状は「これを外す」の対象外とし、設定一覧から開けるようにする。

共有 3D モデル Node と通常の `Mesh Renderer` として展開された 3D モデルノードの両方に Decimation を表示し、当たり判定用の軽量化では表示用メッシュを変更しない。

### 操作前

- 新規インポートした 3D モデルは `generateColliders` を既定で有効にし、シーンへ初回配置した際に同じ Entity へ既定 `Static (Fixed)` の `Mesh Collider` を追加する（既存素材で明示無効化された設定は移行で上書きしない）。
- 組み込み基本形状は `Box Collider` を同時作成する（Floor / Plane は薄いローカル境界ボックス、その他は基本形状の境界ボックスを初期半幅とし、Entity の大きさは値へ焼き込まず Transform に追従させる）。
- Physics の Component 追加に `Rigid Body` を 1 Entity 1 件で表示する。追加した親 Entity は自身と子孫の衝突判定・メッシュを 1 つの物理ボディへまとめ、ネストした別 `Rigid Body` 以降は別ボディとして扱う。

### 操作中

- Collider カードでは Box の中心・各軸の半幅・自動フィット、`Mesh Collider` の形状（メッシュと同じ形 / 凹みを省いた外形）、有効、Trigger、摩擦、跳ね返りを編集する。
- `Rigid Body` カードでは `Static (Fixed)` / `Dynamic` / `Kinematic Position` / `Kinematic Velocity`、重力倍率、Linear / 回転減衰、静止中休止、高速移動時衝突判定、位置 / 回転 Lock を編集する。衝突判定生成方式は「子孫のCollider Component」`Auto Cuboid` `Auto Ball` `Auto Convex Hull` `Auto Trimesh` から選び、対象の子孫衝突判定・メッシュ件数を同じカードに表示する。
- `Rigid Body` Component がない旧データでは衝突判定内のボディ設定を互換読み込みする（既定 `Static (Fixed)`）。旧コード編集インポーターが子を持つ空 Entity 原点に作った既定サイズ Box は、名前またはインポート識別情報を確認できる場合だけ読み込み時に親 `Rigid Body` へ移行して原点 Box を残さない。親または自身に `Rigid Body` がある衝突判定ではボディ設定の編集先を親 Entity 名で示し、Collider カードでは形状と接触設定だけを編集する。
- Box 再フィットは同一 Entity のメッシュ境界ボックスだけを使い（3D モデルはインポートメタデータの境界ボックスと取り込み倍率を使用）、絶対パスや生 glTF データをシーンデータへ保存しない。
- シーンの「コライダー編集」はメッシュを抑えて衝突判定形状だけを確認でき、選択 Entity の診断件数と MCP 共通の安全な最適化操作を表示する。`inspect_colliders` は `entityIds` 省略時にシーン全体を対象とし、`optimize_colliders` は `projectId`・`sceneId`・`expectedRevision` で 1 回のリビジョンへ反映する。

### 成功時

- Box / Mesh 衝突判定の追加・変更・削除は 1 シーン履歴トランザクションとして確定し、選択を維持する。選択中の直方体衝突判定はワイヤーフレーム表示する。
- Play とコンパイラーは `Rigid Body` を持つ Entity のローカル Transform をボディ原点としてサブツリーを 1 つの Rapier `RigidBody` で包み、子孫 Box は各ローカル階層を保った `CuboidCollider`、メッシュ衝突判定は `MeshCollider` として含める（親原点へ代替 Box を足さず、ネストした `Rigid Body` で新ボディを開始）。
- Auto 衝突判定では Rapier 自動生成をサブツリーメッシュへ適用する。Dynamic / Kinematic の明示メッシュ一致形状は Rapier 互換の凹みを省いた外形へ自動変換し、コンパイラー診断にも残す。
- 最適化では Dynamic / Kinematic のメッシュ衝突判定を保存データ上も凹みを省いた外形へそろえ、移動体の高速移動時衝突判定を有効化し、出力時に先頭へ畳まれる重複メッシュ衝突判定を無効化する。自動衝突判定と明示メッシュ衝突判定の併用・メッシュなし・無効 Entity は自動無効化せず診断に残す。

### 失敗時

- メッシュのない Entity へ `Mesh Collider` を追加せず、必要な `Mesh Renderer` を示す。自動フィット境界ボックスがないときは既存値とシーンを変更しない。
- 非有限中心、0 以下の半幅、負の摩擦、`0..1` 外の跳ね返りは確定せず、アップロード前検証でも公開を止める診断にする。
- 物理挙動サブツリーに明示衝突判定も Auto 対象メッシュもない場合はボディを消さず、Inspector とコンパイラー診断へ「物理形状がありません」と示す。

### 戻り先

- 衝突判定や `Rigid Body` 削除後もメッシュ・マテリアル・Transform・選択を維持し、元に戻すで同じ Component ID・ボディ所属・設定を復元する。

完了条件: インポートした 3D モデルと組み込み基本形状へ既定衝突判定が付き、形状・中心 / 半幅・自動フィット・物理設定を Inspector で編集でき、「コライダー」表示・Play・生成ワールドが同じ物理表現を使う。

## F-12 シーン環境設定の状態設計

### 操作前

- 左下の歯車「シーン設定」を押すと、選択状態を維持したまま右の Inspector をシーン設定へ切り替える（シーン全体設定として扱い、Hierarchy には追加しない）。
- Skybox、Fog、Ambient Light はシーンプレビューと生成ワールドの両方に反映する。Skybox は素材の正距円筒図法環境テクスチャまたは通常画像テクスチャを選択・ドロップで設定し、背景表示と IBL ライティングを独立切替しつつ回転と露出を共有する。HDR / EXR の直接取り込み時は新環境テクスチャを同じシーンへ設定し、背景と IBL を既定で有効にする。Near / Far、FOV、編集背景、グリッド、ギズモ、スナップは編集ビュー設定として明示する。
- シーン固有の不透明地面は追加せず、Skybox 有効時は地平線の下側まで Skybox を見せて編集用グリッドだけを重ねる。
- サムネイルは保存済みプロジェクトでのみ編集可能とし、未保存時は保存後に設定できる理由をボタン文言で示す。

### 操作中

- 色・トグル・数値の変更は対象セクション内で即座にプレビューへ反映する。数値入力は Enter またはフォーカスアウト時に確定し、不正値は直前の有効値へ戻す。Skybox 画像は環境テクスチャまたは通常画像テクスチャだけを受け付け、画像がないときは IBL トグルを無効にする。テクスチャ設定の上下反転を基準値とし、シーン設定の追加反転をシーン固有上書きとして合成する。
- Fog の終了距離は開始距離より大きく、カメラの Far は Near より大きく保つ。Play 中は編集データを変えず各入力欄を読み取り専用にする。
- ギズモのスナップは移動・回転・拡縮に共通適用する。移動スナップまたはグリッドサイズを変えたら、各マスが移動スナップの整数倍になるようグリッドサイズと分割数を調整する（分割数は手動上書き可能）。グリッド表示を切っても Entity や `SceneDocument` 構造は変えない。

### 成功時

- 確定したシーン設定は 1 件の元に戻す / やり直し履歴として残り、保存後にシーン JSON へ書き込む。コンパイラーは Skybox の背景表示と IBL を独立設定として、Fog・Ambient Light とともに生成ワールドへ出力する。
- サムネイル保存後はシーン設定へ戻り、公開前確認で同じ画像を再取得できる状態を維持する。

### 失敗時

- 読み取り専用、未保存プロジェクト、範囲外数値、無効色、使用不可 Skybox 画像では `SceneDocument` と選択を変えず、同じ場所で理由または復帰方法を示す。生成対象にできない画像はグラデーションへフォールバックしてコンパイル診断に残す。
- サムネイル読み書き失敗時は既存画像を維持し、同じ編集画面内で再試行できるようにする。

### 戻り先

- ヘッダーの戻る操作や Entity / 素材選択でシーン設定だけを閉じ、直前のシーン・選択・編集位置へ戻る（確定済み変更は保存または元に戻すで管理）。

完了条件: 左下歯車からシーン設定を開き、ワールド / アイテム名、説明、サムネイル、Skybox（背景表示・IBL・無限遠 / ボックス / 地面付きドーム投影・画像・回転・明るさ・有限メッシュ位置 / 回転 / 大きさ / 投影中心）、Fog、Ambient Light、Near / Far、FOV、背景、グリッド、ギズモ、スナップを一元設定し、公開情報・シーン・生成ワールドへ一貫して反映できる。

## F-13 XRift コンポーネントのエディタープレビューの状態設計

### 操作前

- Hierarchy、追加メニュー、Inspector、Assets はコンポーネントレジストリーの公式名・説明・アイコンを使用する。シーンは保存済み Props と Entity の Transform を `@xrift/world-components` 本体へ渡し、編集と Play で同じ公式描画処理を使う。
- `XRiftProvider`、Physics、各実行環境 Context は Studio の Provider 連携で供給し、インスタンス取得・遷移・ユーザー・画面共有など外部サービスの副作用は起こさない。公式コンポーネントの React / Three 実装自体は差し替えない。

### 操作中

- Inspector で `Portal` の `instanceId` / `disabled`、`TagBoard` の `title` / `columns` / `tags` / `scale` を変更すると同じ公式コンポーネントへ Props を即時反映し、通信・ユーザー状態生成・シーン履歴以外の副作用を起こさない。
- `Interactable`、`Grabbable`、`Seat`、`TextInput`、`BillboardY` は同じ Entity の子要素を公式ラッパーで包み、独自外観を追加しない。

### 成功時

- `Portal`、`TagBoard`、`EntryLogBoard`、鏡、Video 系を含む全公式コンポーネントをパッケージ実装どおりに表示し、Studio 独自の旧ポータルシェーダー・HTML ボード・簡易画面へ分岐しない。
- カタログサムネイルは同じ Provider 連携と公式描画を固定生成処理で事前描画した保存済み WebP として一覧・詳細で共有し、コンポーネント名と公式表示を画像へ焼き込む（SVG・CSS 図形・DOM 疑似サムネイルは使わない）。

### 失敗時

- 欠落または不正 Props はレジストリー既定値または公式空状態へフォールバックしてシーン全体を止めない。公式描画を安全に起動できない場合は架空の代替外観を作らず、コンポーネント名と未対応理由をエディター診断に残す。

### 戻り先

- 選択解除・Entity 削除・元に戻す / やり直しでは補助表示だけを同じシーンデータへ追従させ、カメラ・選択・実行時状態を追加変更しない。

完了条件: 編集と Play で公式パッケージ本体と同じ描画方式を使い、`Portal` や `TagBoard` の実際の見た目を独自デザインへ置換せず確認でき、外部実行環境機能だけを副作用のない Provider 連携へ差し替えられる。

## F-14 基本コンポーネントメニュー・音源の状態設計

### 操作前

- **Entity 作成メニュー**: 選択中 Entity の有無にかかわらず新しい Entity を作成し、全配置候補をカテゴリにまとめる。
  - 先頭の Entity に空の Entity、基本形状に Cube・Plane・Sphere・Cylinder・Cone、ワールドに `SpawnPoint` を配置する（「床」などの用途名を基本形状名にせず、光る Cube 等の装飾プリセットは外す）。
  - Light、Text、Image、`Audio Source`、`Particle Emitter` は配置候補として残す。`Rigid Body`、Collider、Script、Interaction Trigger、Wind など既存 Entity へ付ける機能は Inspector から追加し、「Component付きEntity」分類は作らない。
  - `Skybox`、`TagBoard`、`EntryLogBoard`、`Portal` は Entity 配置候補に含めない（既存 Entity と Inspector の設定は維持）。
  - XRift 配置候補は 1 一覧にまとめ、同じ保存形式のプレハブがあれば設定済みプレハブを使う（プレハブと生 Component を二重に並べず、必要設定の案内を残す）。Entity 作成は上部「素材を追加 → Entityを作成」から行う。
- **右クリックとツールバー配置**:
  - 複数選択 Entity 上での右クリックは名前変更・コピー・複製・削除だけを表示し、Entity 作成と Component 追加は出さない（削除は選択全体に適用）。選択外 Entity の右クリックはその Entity を選んで単体メニューへ切り替える。上部「素材を追加」と Hierarchy 空白からは複数選択中でもシーン直下へ新規 Entity を追加できる。
  - デスクトップでは Undo / Redo / 追加だけの独立ツール行を置かず、Undo / Redo は上部ヘッダー、Entity 追加は上部「素材を追加」と Hierarchy 空白、選択 Entity 操作は Scene / Hierarchy 右クリックへ分ける。タッチ端末では Hierarchy 見出しの「追加」から共通カタログを開き、選択行の「…」から編集メニューを開く。
  - Inspector の「Componentを追加」は対象 Entity への追加操作とし、必須の `Transform` と旧 Spawn Point 追加口は出さない（`SpawnPoint` は公式 1 つに統一）。
  - Hierarchy 右クリックメニューは他パネルの上・モーダルダイアログの下（Script エディターより上）に画面内へ収まる位置と最大高さで表示する。空白からの Entity 追加には検索欄を置かず、Entity・基本形状・ワールド・ライト・UI・音声・エフェクト・XRift の分類から選び、外側クリックまたは Escape で閉じる（MI-11）。
- 名前・カテゴリ順・重複規則・`Mesh Collider` の前提条件は共通定義を参照し、追加できない候補には理由を表示する。Inspector 検索中は一致カテゴリを開いて空カテゴリを隠し、基本 Component と公式 XRift Component には英語名を使う。
- `Audio Source` は追加直後も既存 Entity 選択を維持し、Inspector で取り込み済み音声素材を選ぶ（直接 URL は新規設定に使わない）。既定では自動再生せず、編集画面を開いただけでは音を鳴らさない。

### 操作中

- カテゴリの開閉や Inspector 検索文字の入力・クリアは `SceneDocument` と履歴を変更しない。検索中は一致カテゴリを開き、候補がなければ同じメニュー内に伝える。項目選択時だけ Component 追加を 1 件確定してメニューを閉じ、追加した Component 設定を表示する。
- `Audio Source` は有効、音声素材、音量、繰り返す、自動で再生する、Spatial、音量を保つ距離、音の減衰率、最大距離を型と範囲を守って編集する。音声素材がない場合は同じ設定から MP3 / WAV を取り込める。編集表示では音声取得を開始せず、Play 中は volume / loop / 距離プロパティを既存プレイヤーへ更新し、素材・spatial・enabled・構成変更時は対象 Entity だけを再同期する。

### 成功時

- Play とコンパイラーは参照 MP3 / WAV を管理下元データから読み込み、同じ音源ランタイムで通常音声 / `PositionalAudio` へ変換し、カメラへ `AudioListener` を接続する。Component 無効化や Entity 破棄時は再生・リスナー・バッファー参照を解放する。
- ライト、パーティクル、`Audio Source` はどの入口から追加しても同じ Component ID・初期値・重複規則・生成結果になる。

### 失敗時

- 未設定音声素材や読み込み失敗でシーン全体を止めない。未設定はコンパイル警告として出力を省略し、参照切れや MP3 / WAV 以外の元データはコンパイルを止める。実行時読み込み失敗は該当 Component の音声だけを止め、自動再生ポリシー拒否時は拒否状態を保持して操作後スクリプトや通常操作から再試行できるようにする。
- 非有限値、範囲外音量、0 以下の距離、負の減衰率は確定せず、直前の `SceneDocument` と選択を維持する。

### 戻り先

- Component 追加メニューを閉じると同じ Entity の Inspector へ戻り、追加後も選択を維持する。元に戻すで追加前へ、やり直すで同じ Component ID と設定へ戻せる。

## F-33 風コンポーネントの状態設計

参照: MI-03, MI-05, MI-09, MI-11, MI-13, MI-14, MI-15, MI-16, MI-81

### 操作前

- 風コンポーネントは Entity の「Componentを追加」の Rendering カテゴリに配置し、コンポーネント検索からも見つけられるようにする。
- カード見出しは「風」「オブジェクトコンポーネント」とし、対象がその Entity と子メッシュであること、強さ・速度・突風はシーン設定のグローバル設定を使うこと、メッシュ名からは推測しないことを本文に書く。カード内操作は有効切替だけとし、同じ値を 2 か所で編集させない。
- シーン設定の「風（グローバル）」に有効化、強さ、速度、突風の強さ、風向き（度）を配置し、シーンの風は常に 1 つであることを同じ場所に明記する。
- 風に反応するシェーダーマテリアルは `uWindDirection`・`uWindSpeed`・`uWindTurbulence` を宣言したものに限定し、未宣言シェーダーへ値を渡したり対応しているように見せたりしない。

### 操作中

- Component の追加と有効切替は 1 件のシーン更新として履歴と自動保存へ入れ、シーンへ即時反映する（設定と MCP は同じリビジョン検査を使用）。
- グローバル設定変更はシーンの対象 Entity と風対応マテリアルへ同時反映し、水面と草で風向きが食い違う状態を作らない。向きはグローバル単一とし Entity 側では上書きしない。

### 成功時

- エディタープレビュー、Play、生成ワールド、ランタイムマニフェストが同じ Component とシーン値を読んで同じ揺れを描く。
- グローバル風または Entity の Component を無効にした場合は完全な静止へ戻し、マテリアルが独自に動き続けないようにする。

### 失敗時

- 対象 Entity に描画対象メッシュがない場合も Component 自体は保存して対象が空であることを示し、名前や見た目から別 Entity を推測対象にしない。
- 風設定のない古いシーンは互換既定値で読み込み、シーンを開けなくしない。

### 戻り先

- 追加・変更後は Entity の Inspector に留まり、グローバル調整のため 1 操作でシーン設定へ移動できる。動作は Play で確認する。

完了条件: Entity の Inspector または MCP から風コンポーネントを明示追加し、対象 Entity と子メッシュだけにシーンのグローバル風設定を適用できる。編集・Play・生成ワールド・ランタイムマニフェストで同じ設定を使い、名前や言語による対象推測を行わない。

## F-39 テキストコンポーネント（書体・背景）の状態設計

参照: MI-05, MI-09, MI-81, MI-90

### 操作前

- 追加メニュー、Hierarchy 右クリック、Inspector の「Componentを追加」の Rendering に「テキスト」「テキスト看板」「作品キャプション」を並べる。3 つは同じテキストコンポーネントで初期の書体・揃え・背景板だけが異なり、看板とキャプションは美術館解説や壁ラベルとしてそのまま置ける。
- Inspector は文字（内容、書体、太さ、色、大きさ、折り返し幅、揃え、行間、字間、基準点、縁取り）と背景（なし・色・画像、色味、不透明度、板の大きさ、余白または幅高さ、文字との奥行き、裏からの見え方）を 1 カードに順に並べる。
- 書体は既定を「自動」（欧文も含む同梱の標準書体）とし、日本語と欧文が混ざっても設定なしで表示できるようにする。
- 手持ちのフォントを使う場合は TTF / OTF / WOFF を素材へ取り込み、書体選択の「プロジェクトのフォント」から選ぶ。WOFF2 は表示に使えないため取り込み時点で理由を示して断る。取り込みフォントは太さ変更不可のため、太さ操作は同梱書体のときだけ有効とする。

### 処理中

- 書体を選ぶと初回だけ同梱ファイルを取得し、取得完了後に一度だけ組版する（取得中は文字を描かず背景板だけを先に置き、取得済み書体はキャッシュから即表示）。自動書体で仮組版して差し替える方式は採らない（代替フォント配信元へ到達できない環境で組版全体が止まるのを防ぐため）。
- 背景画像は素材のテクスチャから選び、編集中もプロジェクト画像をそのまま読んでシーンと Play で同じ板を描く。
- 板の大きさが「文字に合わせる」のときは、組版ごとに実測した文字範囲へ余白を足して組み直す。実測完了まで板を出さないため、途中サイズでちらつかない。

### 成功時

- シーン、Play、生成したコード編集元データ、公開ワールドはすべて同じテキストコンポーネント値と描画経路で文字と板を描く。
- 「自動」も同梱書体として解決し、文字種別の外部代替フォント取得経路は使わない（公開先での未表示や字形差を防ぐため）。書体ファイルはワールドへ同梱し、Runtime JSON 出力ではマニフェストに配置先を記録する。
- 書体は `fontId` だけを編集データへ保存してファイル URL をカタログで一元管理し、未対応の太さは配布されている太さへ丸めて保存する。背景テクスチャも公開時の同梱対象とし、ランタイムマニフェストに参照を残す。

### 失敗時

- 取り込みフォントの参照先が見つからない、または公開用コピーができない場合は同梱書体で出力し、コンパイル警告を残して文字が消えないようにする。
- 書体ファイルを読めなかった場合は troika 既定の字形で表示を続け、取得できない可能性を Inspector に表示する。
- 背景を「画像」にしたまま未設定または公開不可テクスチャの場合は、コンパイル警告を出して色だけの板として出力し、文字は必ず表示する。
- カタログ外の書体 ID や範囲外の太さ・行間・不透明度・余白・幅高さは `SceneDocument`・選択・履歴を変更しない。MCP の `update_component` も同じ境界で拒否し、背景画像はテクスチャを指す場合だけ受け付ける。

### 戻り先

- 変更は 1 件のシーン更新として保存し、元に戻すで直前の書体・背景へ戻れる。追加・編集後も同じ Entity の Inspector に留まり、プレビュー・コンパイル・Play へ進める。

完了条件: テキスト・テキスト看板・作品キャプションを共通レジストリーから追加し、同梱書体や取り込みフォントと背景板を Inspector で設定でき、文字実測値に合わせた板と同一描画経路でシーン・Play・書き出しコード・公開ワールドの表示を一致させられる。取得不可書体は自動書体へ、出力不可背景画像は色板へ安全にフォールバックし、文字は常に表示する。

## F-44 画像コンポーネント（画像の板）の状態設計

参照: MI-05, MI-09, MI-11, MI-15, MI-118

### 操作前

- 追加メニュー、Hierarchy 右クリック、Inspector の「Componentを追加」の Rendering に「画像」を並べる。美術館展示・ポスター・文字盤のようにテクスチャを 1 枚の板として貼る用途に使い、文字を添える場合は同じ Entity の子にテキストを置く。
- 素材テクスチャをシーンや Hierarchy へドラッグする、右クリックの「シーンへ配置」を選ぶ、または MCP の `place_asset` へテクスチャを渡すと、幅 1 m・高さは縦横比準拠の画像 Entity を作成する（環境テクスチャ HDRI は Skybox のままにし、画像にはしない）。
- Component 追加で画像を足す際、Assets で画像テクスチャを選択中ならその画像を貼った状態で開始し、未選択時は未設定として選択欄と取り込み案内を表示する。
- Inspector には画像（サムネイル・選択欄・テクスチャ設定を開くボタン）、幅、高さ（画像に合わせる・サイズ指定）、基準点、色味、不透明度、透明部分の扱い（切り抜く・なめらかに重ねる）、裏からの見え方、ライトの影響を 1 カードに並べる（既定はライト影響なし）。

### 処理中

- 画像はプロジェクトテクスチャをそのまま読み、シーンと Play で同じ板を描く。画像選択時は読み込み完了まで板を出さずちらつきを防ぎ、未設定時だけ色味と不透明度どおりの正方形の板を置いて選択可能にする。
- 高さが「画像に合わせる」のときは読み込み画像のピクセル寸法から縦横比を算出し、取り込み時に寸法が判明しているテクスチャでは決まる高さを設定欄に先に示す。

### 成功時

- シーン、Play、生成したコード編集元データ、公開ワールドは同じ画像コンポーネント値と描画経路で板を描く。
- 貼ったテクスチャは公開時の同梱対象となりランタイムマニフェストに参照が残り、編集画面で使用中の画像をそのまま公開する。
- ノードグラフの「Set Property」では表示・色味・不透明度を変更でき（不透明度に時間をかけるとフェードになる）、画像の差し替えは対象外とする（理由は [KHR_INTERACTIVITY_EDITOR.md](../KHR_INTERACTIVITY_EDITOR.md) の「What a trigger can write」を参照）。

### 失敗時

- 画像未設定または公開不可テクスチャの場合は、コンパイル警告を出して色だけの板として出力し、エディターで見えていた枠を公開先へ残す。
- 0 以下の幅・高さ、範囲外不透明度、未知の基準点・透明設定では `SceneDocument`・選択・履歴を変更しない。MCP の `update_component` も同様に拒否し、`textureAssetId` は画像テクスチャのみ受け付け、空文字で解除、`height: null` で縦横比基準へ戻す。
- テクスチャ削除時は Image Component も参照元として数え、「参照を外す」では参照だけを外して Component を残す。

### 戻り先

- 追加・配置・編集は 1 件のシーン更新として保存し、元に戻すで直前へ戻せる。配置後は新 Entity を選択し、編集後も同じ Entity の Inspector に留まる。

完了条件: 画像コンポーネントを共通レジストリーまたはテクスチャ D&D・配置・`place_asset` で追加し、幅・縦横比・基準点・色味・不透明度・透明処理・両面・ライト影響を Inspector で設定でき、シーン・Play・書き出しコード・公開ワールドで同じ見た目を再現できる。出力不可画像は警告付きで色板へフォールバックし、Node Graph から表示・色味・不透明度を制御できる。

### Assets パネルの表示整理

- Assets 左側にはルートの「Assets/」とフォルダー階層、その下に種類の絞り込みを配置する。素材一覧には実フォルダーと素材だけを表示し、Models などの種類をフォルダー風項目として並べない。左側で種類を選ぶと該当素材だけを表示する。空のワールドの初期 Assets は床マテリアルだけとし、テスト用マテリアル・サンプルプレハブ・Starter Library フォルダーは作らない。
- Assets の背景はフォルダー・絞り込み・一覧を白で統一する。カードはプレビューと素材名を中心に高さを抑え、プレビュー不可時は種類アイコンを中央に表示する（「準備中」等の文言はカードごとに並べず、素材自体の異常だけ警告アイコンで示す）。
- リスト表示では編集データ・ファイルパス・通常時の準備済み表示を省き、リスト / グリッドの配置ボタンも除いて右クリックの「シーンへ配置」へ集約する。

## 編集画面の最終調整（MI-03、MI-09、MI-11）

- **上部操作列**: デスクトップの元に戻す・やり直しは上部操作列にまとめて 32px 四方とし、追加・書き出し・公開ボタンも高さ 32px にそろえる（履歴なし・取り込み中・Play 中の無効化と、タッチ操作の 44px 当たり領域は維持）。
- **Hierarchy と作成導線**: デスクトップの Hierarchy 見出しには「操作 / 追加」を置かない。タッチ端末では見出しの「追加」から Hierarchy 空白右クリックと同じ作成カタログを開く。上部「素材を追加 → Entityを作成」と「アセットストア」1 回起動を利用でき、選択対象の編集操作は右クリックまたは選択行の「…」に残す（追加中・Play 中は変更操作を無効化）。
- **既定値**: Scale の比率固定は初期状態で OFF とし、ON にしたときだけ比率変更を使う（保存済み Scale や反転貼り付けの挙動は変えない）。編集表示の初期状態はアイテムが Unlit、ワールドがシーンとし、通常編集・Undo・Play / Stop では選択中の表示を維持する（Play・録画クリーン表示・サムネイルは常にシーンを使い、表示モードは保存データへ書き込まない）。
- **下部ステータスバーと制作チャット**:
  - 下部ステータスバーの ChatGPT から Scene View・Script の隣に制作チャットタブを開く（初期非表示、切替・閉じる・再表示でも入力と処理状態を保持）。MCP 接続は「設定」内で開き、ChatGPT タブや選択を変えない。
  - ChatGPT は Scene View の横にチャットを表示し、作成プラン・実行工程・配置結果を確認できる。通常は現在シーンへ 1 つずつ調整・追加して保存し、Plan モードでは変更前に確認して反映または破棄を選べる（停止後も保存済み変更を残す）。
  - シーン設定は下部ステータスバーから Inspector で、録画はシーン右上から設定パネルを開く。Assets のログ・進捗も下部バーへ移して重複表示を避け、詳細を開いたときだけ上へ展開して画面内スクロール可能にする。Escape・閉じるで起点へフォーカスを戻し、外側クリックはクリック先操作を妨げない。タブレット・スマートフォンでも同じ下部操作から開ける。

## F-46 Hierarchy の部分書き出し・追加・コピー

- Scene と Hierarchy は同じ右クリックメニューとコマンド処理を使う。シーン空白は貼り付け、Hierarchy 空白は共通カタログからの新規作成と貼り付け、Entity 上は選択を保って編集操作を表示する。既存 Entity への Component 追加は Inspector に残し、無効操作は理由を表示する（MI-11）。タッチ操作の親子移動は Hierarchy 行メニュー内に残す。
- 選択範囲の書き出し時は、子孫・必要素材・配置・出力先プロジェクト種別・注意事項を確認してから保存する。既存全体ファイルからの追加はシーン / Entity を選んで確認後に実行し、元の公開情報や追加先シーン設定は上書きしない。ファイル先行書き込みに成功し、リビジョンと `projectPath` が変わっていない場合だけ編集データと選択を 1 履歴へ確定する（ファイル失敗・キャンセル・編集中変更時は追加しない、MI-03・MI-07）。
- 元コードや表示文字列を一括置換せず、宣言された参照を新 ID へ変換する。Script の Edit 実行はコピー時に無効化し、同期リンクや任意 Script の安全性は保証しない。保存開始と保存完了を区別する。操作と制約は [受け渡し契約](../HIERARCHY_TRANSFER.md) に従う。

## F-47 編集導線と制作データ確認

- 「素材を追加」には入力欄を置かず、「Entityを作成」やファイル読み込み方法から選ぶ。開いた際のフォーカスはメニューへ移し、スマートフォンのソフトウェアキーボードを出さない。矢印キーで移動し、Escape で閉じて元のボタンへ戻る（MI-11）。Entity 作成と Inspector の Component 追加を分け、ワールド / アイテムで同じ候補を見せつつ個別 Component の種別制約・重複・依存条件を実行時にも維持する。
- Inspector は編集対象（Entity / Asset / 複数 / Scene設定）を見出しに表示し、Assets 選択を Entity 複数選択で覆い隠さない。`Transform` を先頭に保ち、Component 検索は正式名と日本語カテゴリの両方で探せる。右クリックメニューは共通の順序と名称にそろえる。
- オプトイン、KPI、イベント送信、分析 SDK、識別子、使用回数の永続化は導入しない。ローカルの制作データ検査は利用状況の収集ではない。

## F-48 ライトベイク

参照: MI-03, MI-05, MI-09, MI-10

作者は動かないメッシュを対象に選んでベイクし、やわらかい影と跳ね返った光を焼いたライトマップをシーンへ適用できる。編集・Play・公開で同じ素材を使い、仕組みは [ライトベイクの仕組み](../LIGHT_BAKE.md) に従う。

入口はエディター左下の電球ボタンとする。押すと Inspector の位置にライトベイクパネルが開き、見出しの「戻る」で元の Inspector へ戻る（シーン設定とは同時に開かない）。

| 状態 | 画面が示すこと | 主操作 | 戻り先 |
| --- | --- | --- | --- |
| 未ベイク | 「まだベイクしていません」、焼かれる内容の一文、対象数 | ベイク | 対象が 0 件または未保存のときは無効とし、理由をボタン下に出す |
| 対象を選ぶ | 対象メッシュ一覧とチェック、動く見込みメッシュの印。「Scene Viewでクリックして選ぶ」の間は対象メッシュに色を重ね、ギズモを隠す | クリックまたはチェックで切替 | もう一度押すと通常選択へ戻る。切替は 1 件ずつ履歴へ記録する |
| 処理中 | 段階名（UV の生成、光の計算と割合、仕上げ）、進捗バー、編集継続可能な旨 | 中止 | 中止するとシーンを変えず元の状態へ戻る（MI-03） |
| ベイク済み | 画像の大きさと容量、細かさ、対象数、日時と所要時間 | 焼き直す | 「Assetsで表示」でライトマップ素材へ移動、「外す」で陰影を外す |
| 要焼き直し | 「Sceneが変わりました」、焼き直すと今のシーンに合う旨 | 焼き直す | 焼いた陰影はそのまま表示し続ける |
| 失敗 | 原因と次の対処（対象を選ぶ、表示を「シーン」にするなど） | ベイク | 設定と対象は維持する（MI-09） |

- 完了通知にはライトマップの大きさと、Assets へ保存してシーンに適用した旨を記載し（MI-05）、結果を Scene View へ即時反映する。
- ベイクと「外す」はそれぞれ 1 件の履歴として「元に戻す」で取り消せる。計算中に進めた編集は残し、その上にライトマップだけを適用する。
- 対象から外したメッシュは焼き直しを待たずに陰影を外し、「リアルタイム」へ戻したライトは即座に描画へ戻す。外した対象に古い陰影を残さない。
- 「ベイク」にしたライトが対象外メッシュとアバターに届かなくなる旨はライト欄に常時明記する。取り返しのつく設定のため確認ダイアログは挟まない。
- 対象選択中に重ねる色は編集補助であり、作品のマテリアルを変更しない。Play・撮影・公開には出力しない。
