## F-07 ビジュアルエディターの状態設計

### 操作前

- 新規作成では item classic、world classic、item visual、world visual の四カードを同じ画面で選ぶ。内部では成果物と project type の二軸で扱う。二段階 UI にしない。
- コード編集は `package.json` / `xrift.json` / `src/` を編集する code project、ビジュアルは専用 manifest / シーン / 素材 document を編集する project と説明する。同じ project の表示切替や自動相互変換とは表示しない。
- ビジュアルを選ぶ前に専用 format を作成する。保存、動作確認、変換、check、upload まで同じ Editor flow で扱うことを示す。
- 開いた直後は成果物種別、project type、既定シーン、独立した `sceneSelection` / `assetSelection`、編集、位置・回転・大きさ tool、未保存状態を表示する。
- 起動時は saved panel layout を window size と schema に合わせて復元する。不正または画面外の配置は safe default に補正する。
- ワールドにはワールド動作確認 Profile、アイテムにはアイテムプレビュー Profile を使うことを示す。ワールド動作確認は`@xrift/world-components`の公式プレイヤーを起動する。開始位置から一人称で歩く。ワールドの controller / physics / spawn adapter をアイテムへ適用しない。利用可能な input capability を動作確認前に示す。
- Node.js / XRift CLI がなくても authoring と同一画面の動作確認 shell を利用できる。Vite、CLI、開発サーバー、別ブラウザの起動を制作操作として置かない。
- コード編集を選んだ場合は既存の名前入力、作成、一覧更新、コードエディターへの流れを変えない。
- コード編集のファイル選択では、最後に選んだファイルの読み込み結果だけを反映する。既定ファイルの探索中に手動でファイルを選んだ場合は、その選択を優先する。読み込み中は本文の編集と保存を無効にする。

### 操作中

- コード編集の保存はMI-03に従い「保存中…」と無効な保存ボタンで示す。クリックと保存ショートカットが続けて届いても書き込みは一度だけ行う。成功時は書き込んだ内容を保存済みにし、保存中に加えた変更は未保存のまま残す。別ファイルへ切り替えた後に保存が完了しても、切り替え先の保存状態を変えない。失敗時は編集内容を維持し、同じ保存操作から再試行できる。
- 素材の一回クリックは `assetSelection` と右設定の素材 context を更新する。`sceneSelection` を維持する。3Dモデル / プレハブをシーンへ drag するか「配置」を実行するまでオブジェクトを増やさない。
- オブジェクト一覧と素材は Shift の範囲選択、Ctrl・Cmd の追加／解除を受け付ける。複数選択時は右設定で対象数を表示する。全対象が持つメッシュの描画 / ライトまたはマテリアルの共通プロパティだけを表示する。
- オブジェクト一覧 / シーンの右クリック追加は selected parent / click point を menu header に示す。primitive 選択前にはオブジェクトを増やさない。
- オブジェクト一覧の行D&Dは上端と下端を兄弟順の挿入位置、中央を親子化として扱う。親行の矢印は子孫行だけを折り畳む。シーンなどから折り畳まれた子を選んだ時は祖先を自動展開する。検索は名前、種類、コンポーネント、有効状態を対象にする。直下のsemantic iconではメッシュ、ライト、衝突判定、音声、パーティクル、Animation、Spawn、XRiftのコンポーネントを複数選択できる。種類同士はOR、文字検索とはANDで絞り込む。一致オブジェクトと祖先を表示する。クリア後は元の折り畳み状態へ戻す。行の目アイコンと単一／複数オブジェクト設定の有効はオブジェクト自身の状態を切り替える。単一設定の先頭は有効チェック、名前、必要時だけ継承状態アイコンの順に並べる。プレハブ元データは名前と更新アイコンだけを置く。説明は常設しない。tooltipと読み上げ名へ移す。
- 子オブジェクトの位置・回転・大きさはlocal値として保持する。シーン、動作確認、生成ワールドのすべてで親の位置 / 回転 / 大きさを継承する。
- マテリアル drag 中はシーンメッシュまたはオブジェクト設定 slot だけをここに移動 target とする。slot が複数なら chooser を表示する。テクスチャ drag は右マテリアル設定の compatible slot だけを target にする。
- 素材のドラッグ中はシーンだけを配置可能領域として示す。ここに移動前にはオブジェクトを増やさない。
- ギズモ操作中はカメラ操作を競合させない。シーンと設定の位置・回転・大きさ値を同期する。設定の軸ラベルをスクラブする時も local 位置・回転・大きさを即時同期する。大きさの比率固定中は操作軸の倍率で不均等比率を保つ。
- 設定とシーン設定の数値欄は上下スピナーを出さない。欄そのものを左右へ引いて値を動かす。修飾キーなしのドラッグは微調整だ。Ctrl / Alt を押している間だけ大きく動かす。動かさずに離した時はクリックとして数値入力へ入る。打った値はキーごとに反映する。ドラッグ一回は一件の履歴として確定する。Escape では引き始める前へ戻す。
- ギズモとそのドラッグ平面は、親子関係に関わらず対象オブジェクトのworld位置に置く。ギズモをオブジェクトの祖先の下に描かない。祖先の位置・回転・大きさを二重に適用しない。ドラッグ開始時はカメラの慣性を先に止める。操作中の見え方と移動量を一致させる。
- オブジェクト選択中のFは、そのオブジェクト subtreeの描画boundsへカメラとOrbit中心を合わせる。boundsは表示中のメッシュだけから測る。コライダー枠、ライトの向き矢印、選択輪郭などの編集用補助表示と、無効化された子は含めない。フォーカス中に別オブジェクトを選択しただけでは追従しない。Fを押した時だけ対象を切り替える。
- モデルを選択したら、選択したノードのメッシュ表面を紫色で強調する。離れた部品を一つの箱で囲わず、部品の間の空間は強調しない。ドリルダウン時は選択先に表示を切り替え、選択解除時に消す。強調表示はクリック判定、フォーカス範囲、保存・公開データに含めない。
- 待機中のギズモと選択補助線はニュートラルカラーで控えめにする。操作中の軸と素材ここに移動 targetだけを明るく示す。「ライトなし」「ワイヤー」「コライダー編集」は、既定のグレーマテリアルが背景に埋もれない暗いneutral背景を使う。シーン settingsや公開結果は変更しない。
- panel resize / dock 中はここに移動 preview と minimum size を示す。authoring Command や selection を変更しない。
- シーンと素材のheaderは、panelが狭くなっても一行を保つ。シーンは名前を先に切る。次にスナップと「表示」のラベルをアイコンへ落とす。カメラ投影方式・表示モード・診断・録画を「表示」ポップオーバーへまとめる。素材は検索欄を縮める。breadcrumbを畳む。外部から追加とインポートをアイコンへ落とす。動作確認 / 停止は常に一行の中に残す。他の操作へ重ねない。
- マテリアルの color、metalness、roughness、texture 参照は編集と動作確認の設定から変更できる。同じ素材 ID を参照する全オブジェクトの preview と同期する。動作確認では参照オブジェクトだけを再起動する。オブジェクト固有マテリアル値へ複製しない。
- 外部 GLB / GLTF のここに移動は読み込む Queue で validate、元データ copy、derive、dynamic thumbnail、manifest commit まで処理する。素材へのここに移動はシーン配置へ進めない。シーンへの明示ここに移動だけが import 成功後の配置を同じ transaction intent で続ける。
- 動作確認準備中は二重開始を防ぐ。成功するまでauthoring documentを変更しない。ワールドでは有効な開始位置をオブジェクト一覧順に解決する。親子位置・回転・大きさと開始位置自身の位置を合成した位置からキャラクターを開始する。動作確認開始後は実行コピーを`Play Window`へ表示する。オブジェクト一覧と設定は編集データへ接続したままにする。オブジェクト / コンポーネント構成、位置・回転・大きさ、衝突判定、Animation、既存マテリアル / パーティクルのpropertyとMCP経由のシーン settingsは通常の履歴と自動保存で変更できる。シーン settingsは共有シーンへ即時反映する。オブジェクト / 素材変更は影響するオブジェクトだけへ反映する。テクスチャ / 3Dモデル設定、設定のマテリアル割り当て、シーンの位置・回転・大きさギズモ、素材ここに移動は停止まで無効にする。
- ワールドプレビューは有効な input と controller 操作方法を示し、アイテムプレビューにはワールド用 avatar / controller を出さない。
- 動作確認中の input、controller、camera、physics などは PlaySession にだけ保持する。
- 動作確認中は停止を常に見える位置に置き、別画面や別ブラウザへ移動させない。
- ヘッダーの「ビジュアル」、未保存、compile freshness、upload / 審査状態は操作中も消さない。

### 成功時

- 素材の配置成功では素材 ID を参照するroot オブジェクトを一つ追加する。GLB / VRMに元データ Node metadataがある場合だけ同じtransactionで編集用Node オブジェクト treeを子へ展開する。オブジェクト一覧、シーン、オブジェクト設定はrootを選択する。元に戻すではrootと展開Node、selectionを配置前へ戻す。
- primitive 作成成功では `CreatePrimitiveCommand` 一件でオブジェクトと builtin geometry reference を追加する。マテリアルここに移動成功では `AssignMaterialCommand` 一件で既存メッシュの割り当て枠だけを更新する。
- 位置・回転・大きさ操作成功ではギズモまたは軸ラベルの pointer down から pointer up までを一件として確定する。選択とカメラを維持する。
- フォーカス成功では対象名とF / Escape / 解除ボタンをシーン端に残す。同じオブジェクトでFを押すか解除操作を行うと開始前のカメラ位置、向き、Orbit中心、ズームへ戻す。
- layout 操作成功では normalized size、dock zone、order を Editor Preferences に保存する。再起動後も復元する。
- マテリアル操作成功では有効値が AssetManifest の一つのマテリアルに残る。共有する全オブジェクトの表示を更新する。SceneDocument とオブジェクト固有値は変更しない。
- 動作確認開始成功では中央の動作確認の画面でproject kindに対応するprofileを確認できる。ワールドのキャラクターは有効な開始位置のworld位置から開始する。実行環境の位置、速度、animation時刻はPlaySessionにだけ残る。
- 動作確認中の許可されたオブジェクト変更は編集データへ残る。そのオブジェクトだけ実行環境 revisionを進めてAnimationとphysicsを先頭から再実行する。他オブジェクトとcontrollerの実行環境 stateは維持する。
- 停止成功ではPlaySessionを破棄する。動作確認中に許可された調整を含む最新SceneDocumentとAssetManifest、selection、編集 cameraへ戻る。実行環境の位置や速度、`ctx.materials` / `ctx.particles` overrideをauthoring変更として扱わない。
- GLB / GLTF の import 成功は元データ / derived / thumbnail / manifest commit の完了と新素材 card を表示する。シーン配置はシーンここに移動または後続の「配置」が成功した時だけ別結果として示す。
- 同期操作の結果はトーストだけにせず、追加オブジェクト、右設定、参照オブジェクトの表示、読み込む Queue の項目として画面へ残す。

### 失敗時

- 非対応ファイルは拡張子と対応形式を示し、SceneDocument、AssetManifest、selection、history を変更しない。
- 位置・回転・大きさに有限でない値や不正な scale が入った場合、または軸スクラブを Escape / pointer cancel で終えた場合は操作前へ戻す。対象項目の近くに修正方法を示す。
- 選択オブジェクトに描画boundsがない場合はworld 位置・回転・大きさ位置をフォーカス中心にする。オブジェクト自体を選べない場合や動作確認中、入力中はカメラを変更しない。
- マテリアルに不正な color、有限でない値、`0..1` の範囲外、欠落 texture 参照が入った場合は確定しない。右設定の対象 field 近くに形式または範囲を示す。
- 欠落素材参照ではオブジェクトを消さず、欠落 ID、参照元オブジェクト、素材の再 import または置換を示す。
- primitive create point、parent、マテリアル / テクスチャ slot を解決できない場合は Command を確定しない。対象を選び直す操作を示す。
- 動作確認の初期化に失敗した場合は編集と authoring document を維持する。シーン内に profile、原因、再試行を示す。回避策として CLI や別ブラウザの手動起動を要求しない。
- 動作確認中に実行環境 error が発生した場合は PlaySession を dispose して編集へ安全に戻す。SceneDocument と AssetManifest が変更されていないことを保つ。
- シーンを初期化できない場合は MI-09 の面を表示する。ライブラリへ戻る操作と再読み込みを用意する。
- layout Preferences を保存できない場合は session layout を保つ。authoring を止めない。再試行と「レイアウトをリセット」を示す。
- 保存、変換、check、upload の失敗は実 stage と sanitized cause を表示する。成功通知へ進めない。retry または対象 field へ戻る操作を置く。

### 戻り先

- ヘッダーにライブラリへ戻る操作を置く。未保存変更がある場合は保存、破棄、取消を同じ画面内で選べる。
- 動作確認中にライブラリへ戻る場合は、先に停止と同じ cleanup を実行して PlaySession を破棄する。実行環境 state を authoring document へ保存しない。
- 戻った後はプロジェクトライブラリを表示し、新規作成入口を先頭に保つ。
- Escape で未確定 dock / resize を開始前 layout へ戻す。「レイアウトをリセット」で左オブジェクト一覧、中央シーン、右設定、下素材へ戻す。
- フォーカス中のEscape、解除ボタン、動作確認開始は保存した編集 cameraへ戻す。selectionとSceneDocumentは変更しない。
- 作成または保存 transaction が commit した project だけを一覧へ追加する。
- 永続化を接続した後は、シーン / プレハブ / 素材 / folder を含む save set のいずれかが未保存なら保存、破棄、戻るの取り消しを選べる確認へ置き換える。

完了条件: 四カードの入口、オブジェクト一覧、シーン、右設定、下素材を使う。独立 selection、シーンを含む複数選択と共通プロパティ編集、復元可能なオブジェクトフォーカス、目的別のシーン表示、Empty / primitive / XRiftのコンポーネント作成、素材 / マテリアル / パーティクル / XRift プレハブ D&D、オブジェクト一覧の文字検索・種類フィルター・折り畳み・並び替え・親子化・有効、親子位置・回転・大きさ、軸スクラブと大きさ比率固定、コンポーネントごとの有効、視覚的なマテリアル選択、マテリアル / テクスチャ / パーティクル編集、マテリアルテクスチャの繰り返し、Animation / ノードグラフからのマテリアル操作、配置オブジェクトごとの静的なモデルポーズ、GLB / VRMのNode・Bone・メッシュ別編集、GLB / glTF Animationの動作確認時自動再生、動的 thumbnail、テクスチャから設定できるproject thumbnail、動作確認とシーン全体の環境設定、右上の3Dモデル / R3F / コード編集読み込むを扱える。左下のユーティリティレールからヘルプ、ショートカット、シーン設定へ迷わず到達できる。panel layout は resize / dock 後も復元される。Editor render / module load failure は App 全体へ伝播させない。再試行、再読み込み、一覧への復帰を選べる。

## F-09 Command / Shortcut / プレハブの状態設計

### 操作前

- toolbar、context menu、tooltip、Shortcut 設定は同じ command label、semantic Lucide icon、platform binding、enabled reason を中央 Registry から表示する。
- 左下のキーボードから現在有効なShortcut一覧を分類表示する。操作を探すために各toolbarを巡回させない。
- オブジェクト一覧から素材へ drag する時は reparent ではなくプレハブ作成になる。作成先 folder、subtree / dependency 件数をここに移動前に示す。

### 操作中

- Copy は versioned buffer だけを更新する。Paste / 複製 / 削除 / プレハブ作成は before / after documents と `sceneSelection` / `assetSelection` を一 transaction に保持する。
- text input、contenteditable、数値 field、IME composition が focus 中は W / E / R / X / F / 矢印 / PageUp / PageDown / 削除 / Copy / Paste / 複製の editor command を実行しない。Shift による snap の反転も同じ条件で止める。shortcut conflict はどちらも実行しない。
- snap の入切と間隔は `editor.gizmo` の scene 設定として保存する。元に戻す履歴には積まない。矢印 / PageUp / PageDown の 1 ステップは gizmo drag と同じ一件の履歴として確定する。

### 成功時

- Paste / 複製は決定済みの新 ID、プレハブ作成はプレハブ / document / folder membership / instance metadata を一度だけ確定する。両 selection を仕様どおり更新する。
- 元に戻す / やり直すは同じ IDs、dependency references、プレハブ overrides、前後の両 selection を復元する。toolbar、menu、keyboard の入口によって履歴結果を変えない。

### 失敗時

- stale copy buffer、revision conflict、プレハブ cycle、missing dependency、参照中素材 delete は document を変えない。対象 ID と修正操作を示す。
- cross-document プレハブ transaction の一部だけを残さない。temporary プレハブ document と払い出し ID を破棄する。元のシーン / 素材 / folder revision へ戻す。

### 戻り先

- Escape は未確定 drag / menu / dialog を閉じる。操作前の両 selection と focus surface へ戻る。確定後の戻りは元に戻すを使う。
- shortcut の override は Editor Preferences に残す。project を切り替えても同じ binding を使う。「既定へ戻す」で Registry default へ戻せる。

完了条件: toolbar、menu、keyboard、オブジェクト一覧 D&D と左下の一覧が同じ Command / Shortcut Registry を使う。Copy / Paste / 複製 / 削除 / Reparent、オブジェクトフォーカスの切替と解除、Empty / コンポーネント作成、オブジェクト一覧からのプレハブ化、XRift built-in プレハブ配置、元に戻す / やり直すが IDs と両 selection を復元する。

## F-11 衝突判定 authoring / export の状態設計

メッシュの描画の「歩行・当たり判定」から追加、解除、シーン全体を選択メッシュだけへ置換できる（MI-03）。置換対象はTriggerを含む衝突判定と物理挙動の自動生成。操作前に範囲を常設し、処理は一件の元に戻すへまとめ、成功後も選択と設定一覧を残す。動作確認中と無効な階層では操作できない。親の自動Box / 球をメッシュへ変換する必要がある場合は形状を勝手に変えず、設定元を示して変更を拒否する。親の独立したBox形状は「これを外す」の対象外で、設定一覧から開ける。

共有3Dモデル Nodeと通常のメッシュの描画として展開された3Dモデルノードの両方にDecimationを表示する。当たり判定用の軽量化は表示用のメッシュを変更しない。


### 操作前

- 新規 import した 3Dモデルは `generateColliders` を既定で有効にする。シーンへ初回配置した時に同じオブジェクトへ既定`Static (Fixed)`の`Mesh Collider`を追加する。既存素材で明示的に無効化された設定は移行で上書きしない。
- built-in primitive は `Box Collider` を同時作成する。Floor / Plane は薄い local bounds、その他は primitive bounds を初期各軸の半幅とする。オブジェクト大きさは値へ焼き込まない。位置・回転・大きさで追従させる。
- Physicsのコンポーネントを追加に`Rigid Body`を一オブジェクト一件で表示する。追加した親オブジェクトは自身と子孫の衝突判定 / メッシュを一つの物理Bodyへまとめる。ネストした別物理挙動オブジェクトから先は別Bodyとして扱う。

### 操作中

- 設定は Box の中央、各軸の半幅、自動フィット、メッシュのメッシュと同じ形 / 凹みを省いた外形、共通の有効、Trigger、摩擦、跳ね返りを同じコンポーネント cardで編集する。
- 物理挙動 cardで`Static (Fixed)` / `Dynamic` / `Kinematic Position` / `Kinematic Velocity`、重力の倍率、Linear / 回転の減衰、静止中は計算を休止する、高速移動時の衝突判定、位置 / 回転 Lockを編集する。衝突判定生成は`子孫のCollider Component`、`Auto Cuboid`、`Auto Ball`、`Auto Convex Hull`、`Auto Trimesh`から選ぶ。対象となる子孫衝突判定 / メッシュ件数を同じcardに表示する。
- 物理挙動コンポーネントがない旧documentでは衝突判定内のBody設定を互換読み込みする。`Static (Fixed)`を既定にする。旧コード編集 importerが子を持つ空オブジェクトの原点へ作った既定サイズBoxは、名前またはBody / surface設定のimport signatureを確認できる場合だけ親物理挙動コンポーネントへ読み込みmigrationする。原点Boxを残さない。親または自身に物理挙動コンポーネントがある衝突判定は、Body設定の編集先をその親オブジェクト名で示す。衝突判定 cardでは形状と接触設定だけを編集する。
- Boxの再フィットは同じオブジェクトのメッシュ boundsだけを使用する。3Dモデルはimport metadataのboundsとimport scaleを用いる。absolute pathや生のglTFデータをシーン documentへ保存しない。
- シーンの「コライダー編集」はメッシュを抑えて衝突判定形状だけを確認する。選択オブジェクトの診断件数と、MCPと同じ安全な最適化操作を表示する。`inspect_colliders`は`entityIds`を省略すればシーン全体を扱う。`optimize_colliders`は`projectId`、`sceneId`、`expectedRevision`を使って同じ結果を一回のEditor revisionへ反映する。

### 成功時

- Box / メッシュの衝突判定の変更、追加、削除は一つのシーン history transactionになる。選択を維持する。選択中の直方体の衝突判定はシーンにwireframeで表示する。
- 動作確認とcompilerは物理挙動オブジェクトのlocal 位置・回転・大きさをBody原点にする。そのsubtreeを一つのRapier `RigidBody`で包む。子孫のBoxは各オブジェクトのlocal階層を保った`CuboidCollider`、メッシュの衝突判定は`MeshCollider`として同じBodyへ含める。親原点へ代替Boxを追加しない。ネストした物理挙動は新しいBody ownershipを開始する。
- Auto 衝突判定を選んだ場合はRapierの自動生成をsubtree メッシュへ適用する。物理演算で動かす / Kinematicの明示メッシュと同じ形はRapier互換の凹みを省いた外形へ自動変換する。compiler診断にも残す。
- 最適化では物理演算で動かす / Kinematicのメッシュの衝突判定を保存データ上も凹みを省いた外形へ揃える。移動体の高速移動時の衝突判定を有効化する。出力時に先頭へ畳まれる重複メッシュの衝突判定を無効化する。自動衝突判定と明示メッシュの衝突判定の併用、メッシュなし、無効オブジェクトは自動で無効化しない。診断へ残す。

### 失敗時

- メッシュのないオブジェクトへメッシュの衝突判定を追加しない。必要なメッシュの描画を示す。自動フィットboundsがない時は既存値とシーンを変更しない。
- 非有限中央、0以下の各軸の半幅、負の摩擦、`0..1`外の跳ね返りは確定しない。upload前validationでもblocking diagnosticにする。
- 物理挙動のsubtreeに明示衝突判定がなく、Auto 衝突判定対象のメッシュもない場合はBodyを消さない。設定とcompiler診断へ「物理形状がありません」と示す。

### 戻り先

- 衝突判定または物理挙動削除後もメッシュ、マテリアル、位置・回転・大きさ、オブジェクト selectionを維持する。元に戻すで同じコンポーネント ID、Body ownership、設定を復元する。

完了条件: importした3Dモデルとbuilt-in primitiveへ既定衝突判定が付く。形状、中央 / 各軸の半幅、自動フィット、物理挙動の物理設定を設定から編集できる。シーンの「コライダー」表示、動作確認、生成ワールドが同じ物理表現を使う。

## F-14 Basic コンポーネント menu / 音源の状態設計

### 操作前

- Entity作成メニューは、選択中のEntityの有無にかかわらず、新しいEntityを作る。空のEntity、Cube、Planeを先頭に置き、Sphere、Cylinder、Cone、SpawnPointを続ける。「床」のような用途名を基本形状の名前にしない。光るCubeなどの装飾プリセットは追加候補から外す。

- Hierarchyの右クリックメニューは他パネルの上へ表示し、画面内に収まる位置と最大高さを使う。追加カテゴリは通常は折りたたみ、検索中は一致する項目を開く。外側のクリックで閉じ、Escapeは検索を解除してからメニューを閉じる（MI-11）。
- 名前、カテゴリ順、重複規則、Mesh Colliderの前提条件は共通定義を参照する。候補に追加できない理由を表示する。検索中は一致するカテゴリを開き、空のカテゴリを表示しない。基本Componentと公式XRift Componentは英語名を使う。
- 音源は追加直後も既存オブジェクト selectionを維持する。設定で読み込む済み音声素材を選択できる。直接URLは新規設定に使わない。既定では自動再生しない。編集画面を開いただけで音を鳴らさない。

### 操作中

- sectionの開閉と検索文字の入力・クリアはSceneDocumentと履歴を変更しない。検索中は一致するsectionを開く。候補がない場合は同じメニューで伝える。項目を選んだ時だけコンポーネント追加を一件確定する。メニューを閉じる。追加したコンポーネントの設定を表示する。
- 音源は有効、音声素材、音量、繰り返す、自動で再生する、Spatial、音量を保つ距離、音の減衰率、最大距離を型と範囲を保って編集する。音声素材がない時は同じ設定からMP3 / WAV 読み込むの入口を理解できる。編集表示では音声取得を開始しない。動作確認中はvolume / loop /距離propertyを既存playerへ更新する。素材、spatial、enabled、構成変更は対象オブジェクトだけを再同期する。

### 成功時

- 動作確認とcompilerは参照されたMP3 / WAVを管理下元データから読み込む。同じ音源実行環境で通常音声 / PositionalAudioへ変換する。cameraへAudioListenerを接続する。コンポーネントを無効化した時とオブジェクトを破棄した時は再生、listener、buffer参照をcleanupする。
- ライト、パーティクル、音源は追加、オブジェクト一覧、設定のどの入口から追加しても同じコンポーネント ID、初期値、重複規則、生成結果になる。

### 失敗時

- 未設定音声素材やload失敗でシーン全体を停止させない。未設定はcompile warningとして出力を省略し、参照切れ・MP3 / WAV以外の元データはcompileをblockする。実行環境 load失敗は該当コンポーネントの音声だけを停止する。自動再生policyで拒否された時はblocked状態を保持する。操作後のスクリプトまたは通常操作から再試行できる。
- 非有限値、範囲外の音量、0以下の距離、負の音の減衰率は確定しない。直前のSceneDocumentとselectionを維持する。

### 戻り先

- コンポーネントを追加を閉じると同じオブジェクト設定へ戻る。追加後は同じオブジェクトを選択したままにする。元に戻すでコンポーネント追加前へ戻る。やり直すで同じコンポーネント IDと設定へ戻れる。

完了条件: Entity作成とComponent追加の対象が明確で、共通Registryから用途に合う候補を表示する。検索から一件追加する。設定へ到達できる。音源は読み込む済み音声素材を選ぶ。編集画面を開いただけでは音を鳴らさない。

## F-31 地形 authoring / MCP の状態設計

参照: MI-03, MI-05, MI-09, MI-13, MI-16, MI-76, MI-87

### 操作前

- 追加メニューの「地形」から、16 × 16m・33 × 33 sample・平坦な地形を作成できる。地形には常にstatic メッシュと同じ形衝突判定を付け、マテリアル枠は一つだけにする。
- 選択中地形の設定には大きさ、Resolution、現在の高さ rangeと、Raise / Lower / Flatten / Smoothのブラシを表示する。中心X/Z、radius、strength、Flattenのtarget heightを指定して一回のスタンプを適用する。
- 「草」では層の一覧、密度、傾斜の上限に加えて、選択中の層だけに色と大きさを開く。値は種類の既定から始まり、動かした項目だけが層の上書きになるので、既定のまま使う層は何も持たない。

### 処理中

- 作成と各ブラシスタンプは編集中だけ有効にし、動作確認中または素材 import中は無効化して理由を残す。ブラシ処理中に別のdocument操作を重ねない。
- MCPでは`get_terrain`で対象の範囲を確認し、`create_terrain`または`sculpt_terrain`へprojectId、sceneId、expectedRevisionを渡す。UIとMCPは同じheight sample計算を使う。

### 成功時

- 地形を選択したままシーン、オブジェクト一覧、設定を更新し、各スタンプを一件の元に戻す履歴と自動保存対象として確定する。シーン、動作確認、compile、実行環境 manifestは同じheight samplesを使う。
- static メッシュと同じ形衝突判定の範囲は地形の幅、奥行き、高さrangeに追従する。マテリアル枠から地形の見た目を続けて調整できる。
- 草の色と大きさの変更も同じ一件のシーン更新として確定し、シーン、動作確認、生成ワールドは同じ解決済みの値で描く。「種類の既定に戻す」で層は上書きを持たない状態へ戻る。層が本数の上限に達している場合は「本数を確認」に、密度どおりに生えないことと下げ方を示す。

### 失敗時

- 範囲外、空の対象、古いrevision、地形以外のオブジェクトへの適用はdocumentとhistoryを変更しない。設定の入力と選択を保ち、対象またはrevisionを確認して同じ操作からやり直せる。

### 戻り先

- 作成・ブラシ適用後は地形設定に留まる。元に戻す / やり直すで直前の地形 samplesを戻し、必要ならマテリアルまたは衝突判定診断へ進める。

完了条件: 追加メニューからstatic 地形を追加する。設定とMCPの同じRaise / Lower / Flatten / Smoothブラシで高さサンプルを編集する。各スタンプは一件の元に戻す履歴として保存される。シーン、動作確認、生成コード、メッシュと同じ形衝突判定へ同じ地形を反映する。

## F-33 風コンポーネントの状態設計

参照: MI-03, MI-05, MI-09, MI-11, MI-13, MI-14, MI-15, MI-16, MI-81

### 操作前

- 風コンポーネントはオブジェクト設定のコンポーネントを追加からRenderingカテゴリーに置く。コンポーネント検索でも同じ項目に到達できる。
- コンポーネントカードは「風」「オブジェクトコンポーネント」を見出しにし、対象がこのオブジェクトと子メッシュであること、風の強さ・速度・突風はシーン Settingsのグローバル設定を使うこと、メッシュ名からは判定しないことを本文で示す。カード内の操作は有効だけにし、同じ値をコンポーネントとシーン Settingsの二か所で編集させない。
- シーン Settingsの「風（グローバル）」に、風の有効化、風の強さ、風の速度、突風の強さ、風向き（度）を置く。シーンの風は常に一つであることを同じ場所に書く。
- 風に反応するシェーダーマテリアルは、`uWindDirection`、`uWindSpeed`、`uWindTurbulence`を宣言したものだけが対象になる。宣言していないシェーダーへ値を渡さず、対応しているように見せない。

### 操作中

- コンポーネントの追加と有効の切り替えは一件のシーン更新として履歴と自動保存へ入り、シーンへ即時反映する。設定とMCPは同じrevision検査を通る。
- グローバル設定の変更はシーンの対象オブジェクトと風対応マテリアルへ同時に反映する。水面が北へ、草が東へ流れるような食い違いを作らない。
- 向きはグローバルのままとし、オブジェクト側では上書きしない。一つのシーンに二つの風向きを持たせない。

### 成功時

- Editor プレビュー、動作確認、生成ワールド、Runtime manifestが同じコンポーネントとシーン値を読み、同じ揺れを描く。
- グローバル風を無効にした場合、またはオブジェクトのコンポーネントを無効にした場合は完全な静止に戻す。マテリアルが独自に動き続けない。

### 失敗時

- 対象オブジェクトに描画対象のメッシュがない場合もコンポーネント自体は保存し、対象が空であることを示す。名前や見た目からの推測で別のオブジェクトを対象にしない。
- シーン Settingsに風の設定がない古いシーンは互換既定値で読み込み、シーンを開けなくしない。

### 戻り先

- 追加・変更後はオブジェクト設定に留まり、グローバル値の調整はシーン Settingsへ一操作で移動できる。確認は動作確認で行う。

完了条件: オブジェクト設定またはMCPから風コンポーネントを明示的に追加する。対象オブジェクトと子メッシュだけへシーン Settingsのグローバル風設定を適用する。Editor プレビュー、動作確認、生成ワールド、Runtime manifestは同じコンポーネントとシーン値を使う。名前・メッシュ分類・言語に依存した対象推測を行わない。

## F-34 空の背景シェーダー（手続き的な空）の状態設計

参照: MI-03, MI-05, MI-09, MI-15, MI-16, MI-19, MI-25, MI-82, MI-83

### 33種類への拡充

- 操作前: 11カテゴリ・名前・説明・タグで絞り込み、選択が検索結果から外れたら先頭へ移す。0件は空状態を表示する。一覧は本体と同じThree.js マテリアル生成処理で描いた静止画、詳細だけはR3Fで描画する。
- 操作中（MI-03）: 軽量・標準・高精細とUniformを詳細に反映する。追加中は検索・カテゴリ・カード選択・品質・Uniform・再追加を無効にする。
- 成功（MI-05）: 選んだ品質のdefinesをマテリアルへ保存し、シーンへの適用結果を残す。既存マテリアルは同じプリセットを追加し直した場合だけ更新する。
- 失敗・戻り先（MI-09）: 選択と設定を保持して再試行できる。詳細はドラッグ・矢印キー・再生停止・視点リセットに対応し、非表示中は連続描画を止める。
- MCP: `list_material_presets`で品質別variantsを取得し、`create_material_from_preset`と`update_custom_shader`で同じ品質を設定する。既存の編集操作で扱えるため専用toolは増やさない。プレビュー視点と停止はストアだけの状態で、シーンへの保存やviewer overrideの対象ではない。

### 操作前

- 「外部から追加」の左一覧に「Skybox Shader」を公式カタログとして置き、「画像ではなくGLSLで空を描くマテリアルです」と件数を見出しに示す。
- カードは実際のGLSLをWebGLで描画する。SVGやCSSの疑似サムネイルを使わず、カードで見えているものと追加後の空を一致させる。11カテゴリー（昼、夕暮れ、朝焼け、夜空、オーロラ、宇宙、天候、幻想、スタイル、抽象、水中）で絞り込める。
- 詳細では、そのプリセットが何を描くかと負荷の目安を文章で示し、調整できる値を名前・値・説明・uniform名付きのsliderとして並べる。変更はプレビューへ即時反映し、「既定値へ戻す」でプリセットの値に戻せる。
- 追加ボタンは「〇〇を空へ設定」とし、「追加後にシーンの空へ設定」を既定で有効にする。外した場合はマテリアルだけを追加することを同じ場所に書く。
- シーン Settingsのスカイボックスには「空の背景シェーダー（カスタムシェーダーマテリアル）」の選択肢を置き、割り当て中は空の背景画像とグラデーションより優先して空を描くことを示す。

### 操作中

- 追加は通常の素材 import transactionを通り、マテリアルの作成とシーンのskybox設定を同じ履歴へ確定する。
- 割り当て中は上空の色、地平線の色、オフセット、グラデーションを無効表示にする。水平回転と明るさはシェーダーのuniformへ渡すため有効なまま残す。
- シーンは空の背景シェーダーを描画しない。編集中の背景は単色のままで、見え方は動作確認で確認する。この違いをUIで示し、描画に失敗したと誤解させない。

### 成功時

- 追加後はマテリアルとして残り、星の数や色を設定の調整できる値から何度でも変更できる。カタログからの調整と設定での再調整は同じマテリアルを指す。
- 動作確認、生成ワールド、Runtime manifestが同じGLSLと同じuniform値を使う。
- 同じプリセットをもう一度追加した場合はマテリアルをプリセットの値で上書きし、二つ目の同名マテリアルを増やさない。

### 失敗時

- 割り当てたマテリアルが欠落または不正な場合は理由を示してグラデーションの空へ戻す。背景を空にしない。
- 重いプリセットはstep数をvariant defineとして残し、下げられる状態にする。負荷を隠さない。

### 戻り先

- 追加後はシーン Settingsの空の背景シェーダー欄へ戻り、「〇〇のUniformを編集」からマテリアル設定へ移動できる。カタログを閉じた場合もシーンとselectionは変わらない。

完了条件: 画像空の背景ではなく、カスタムシェーダーマテリアルとして昼・夕暮れ・朝焼け・夜空・オーロラ・星雲の空を追加できる。星の数、太陽と月の位置、月の満ち欠け、雲、地平線の遠景をuniformで調整できる。レイマーチする厚みのある雲も選べる。外部リソース集での調整と設定での再調整が同じマテリアルを指す。シーン、動作確認、生成ワールドが同じGLSLを描く。マテリアルが欠落した場合はグラデーションへ戻す。警告診断を残す。重いプリセットはstep数をvariant defineとして残す。下げられる状態にする。

## F-39 テキストコンポーネント（書体・背景）の状態設計

参照: MI-05, MI-09, MI-81, MI-90

### 操作前

- 追加、オブジェクト一覧右クリック、設定のコンポーネントを追加のRenderingに「テキスト」「テキスト看板」「作品キャプション」を並べる。三つは同じテキストコンポーネントで、初期の書体、揃え、背景の板だけが異なる。看板とキャプションは追加した時点で板と書体が入っており、美術館の解説や壁のラベルをそのまま置ける。
- 設定は文字（内容、書体、太さ、色、大きさ、折り返し幅、揃え、行間、字間、基準点、縁取り）と背景（なし・色・画像、色味、不透明度、板の大きさ、余白または幅高さ、文字との奥行き、裏からの見え方）を一つのカードに順に並べる。
- 書体は「自動」を既定にする。自動は同梱の標準書体（日本語subsetのため欧文も含む）で表示するので、日本語と欧文が混ざっていても設定なしで表示できる。
- 手持ちの書体を使う場合は、TTF、OTF、WOFFのファイルを素材へ取り込み、同じ書体の選択欄の「プロジェクトのフォント」から選ぶ。WOFF2は表示に使えないため取り込みの時点で理由を示して断る。取り込んだフォントは太さを選べないので、太さの操作は同梱書体のときだけ意味を持つ。

### 処理中

- 書体を選ぶと、その書体の同梱ファイルを初回だけ取得し、取得が終わってから一度だけ組版する。取得の間は文字を描かず、背景の板だけを先に置く。取得済みの書体はキャッシュから即座に使う。自動の書体で先に組んでから差し替えないのは、その組版が文字種ごとの代替フォント取得を伴い、代替フォントの配布元へ到達できない環境では以後の組版ごと止まってしまうため。
- 背景の画像は素材のテクスチャから選ぶ。編集中はプロジェクトの画像をそのまま読み、シーンと動作確認で同じ板を描く。
- 板の大きさが「文字に合わせる」のときは、組版が終わるたびに実測した文字の範囲へ余白を足して板を組み直す。実測が終わるまでは板を出さないので、途中の大きさで一瞬ちらつかない。

### 成功時

- シーン、動作確認、生成したコード編集元データ、公開したワールドは同じテキストコンポーネントの値から同じ描画経路で文字と板を描く。Studioが独自に別の見た目を作ることはない。
- 「自動」も同梱の書体として解決する。文字種ごとに配布元から代替フォントを取得する経路は使わない。公開したワールドはそこへ到達できず文字が表示されないうえ、Studioと公開先で字形が食い違うため。書体のファイルはワールドへ同梱し、Runtime JSON出力ではmanifestがその置き場所を示す。
- 書体は`fontId`だけをドキュメントへ保存し、ファイルのURLはカタログが一箇所で決める。家族が持たない太さを選んだ場合は、実際に配布されている太さへ丸めて保存する。
- 背景に選んだテクスチャは公開時の同梱対象になり、Runtime manifestにも参照が残る。

### 失敗時

- 取り込んだフォントの参照先が見つからない、または公開用にコピーできない場合は、同梱の書体で出力し、compileで警告を残す。文字が消えることはない。
- 書体のファイルを読めなかった場合はtroika既定の字形で表示を続ける。文字が消えることはなく、設定に取得できない可能性を文言で残す。
- 背景を「画像」にしたまま画像が未設定、または参照先が公開できないテクスチャのときは、compileで警告を出して色だけの板として出力する。文字は必ず出力する。
- カタログにない書体ID、範囲外の太さ・行間・不透明度・余白・幅高さはSceneDocument、selection、historyを変更しない。MCPからの`update_component`も同じ境界で拒否し、背景の画像はテクスチャを指しているときだけ受け付ける。

### 戻り先

- 変更は一件のシーン更新として保存し、元に戻すで直前の書体・背景へ戻る。追加や編集の後も同じオブジェクト設定に留まり、プレビュー / Compile / 動作確認へ進める。

完了条件: テキスト、テキスト看板、作品キャプションを同じコンポーネント Registryから追加する。同梱書体または取り込んだフォント、色、太さ、揃え、行間と、色または画像の背景板をInspectorで設定できる。板は文字の実測値に合わせて組み立てる。シーン、動作確認、書き出したコード、公開ワールドが同じ描画経路で同じ見た目になる。取得できない書体は自動の書体へ落とす。出力できない背景画像は色だけの板へ落とす。文字は必ず表示する。

## F-44 画像コンポーネント（画像の板）の状態設計

参照: MI-05, MI-09, MI-11, MI-15, MI-118

### 操作前

- 追加、オブジェクト一覧右クリック、設定のコンポーネントを追加のRenderingに「画像」を並べる。テクスチャを1枚の板として置くコンポーネントで、美術館の展示、ポスター、時計の文字盤のように「画像そのものを貼る」用途に使う。文字を添えるときは同じオブジェクトの子にテキストを置く。
- 素材のテクスチャをシーンまたはオブジェクト一覧へドラッグする、右クリックの「シーンへ配置」を選ぶ、MCPの`place_asset`へテクスチャを渡すと、そのテクスチャを貼った画像オブジェクトができる。幅1mで、高さは画像の縦横比から決まる。環境テクスチャ（HDRI）は空の背景の落とし先のままにし、画像にはしない。
- コンポーネントを追加で画像を足すとき、素材で画像テクスチャを選択中ならその画像を貼った状態で始める。選択がなければ画像は未設定で、設定に画像の選択欄と取り込みの案内を出す。
- 設定は画像（サムネイル、選択欄、テクスチャ設定を開くボタン）、幅、高さ（画像に合わせる・サイズを指定）、基準点、色味、不透明度、透明部分の扱い（切り抜く・なめらかに重ねる）、裏からの見え方、ライトの影響を一つのカードに並べる。既定はライトの影響を受けない表示で、部屋の明るさに関わらず画像そのままの色になる。

### 処理中

- 画像はプロジェクトのテクスチャをそのまま読み、シーンと動作確認で同じ板を描く。画像を選んでいて読み込みが終わるまでは板を出さず、途中の大きさで一瞬ちらつかない。画像が未設定のときだけ、色味と不透明度どおりの正方形の板を置いて選べる状態にする。
- 高さが「画像に合わせる」のときは、読み込んだ画像のピクセル寸法から縦横比を取り、幅から高さを決める。取り込み時に寸法が分かっているテクスチャでは、設定に決まる高さを先に示す。

### 成功時

- シーン、動作確認、生成したコード編集元データ、公開したワールドは同じ画像コンポーネントの値から同じ描画経路で板を描く。Studioが独自に別の見た目を作ることはない。
- 貼ったテクスチャは公開時の同梱対象になり、Runtime manifestにも参照が残る。公開時のKTX2変換も通常のテクスチャと同じに扱う。
- ノードグラフの「プロパティを変える」では、画像の表示、色味、不透明度を変えられる。不透明度に時間をかけるとフェードになる。画像の差し替えは対象にしない。理由は[KHR_INTERACTIVITY_EDITOR.md](../KHR_INTERACTIVITY_EDITOR.md)の「What a trigger can write」にある。

### 失敗時

- 画像が未設定、または参照先が公開できないテクスチャのときは、compileで警告を出して色だけの板として出力する。板が消えることはなく、Editorで見えていた枠がそのまま公開先に出る。
- 0以下の幅・高さ、範囲外の不透明度、未知の基準点・透明の扱いはSceneDocument、selection、historyを変更しない。MCPの`update_component`も同じ境界で拒否し、`textureAssetId`は画像のテクスチャを指すときだけ受け付ける。空文字で画像を外し、`height: null`で画像の縦横比へ戻す。
- テクスチャを削除するときは参照元として画像を数え、「参照を外す」で画像だけを外して画像は残す。

### 戻り先

- 追加、配置、編集は一件のシーン更新として保存し、元に戻すで直前の状態へ戻る。配置後は新しいオブジェクトを選択し、位置・回転・大きさ、幅、画像の差し替えへ進める。編集の後も同じオブジェクト設定に留まり、プレビュー / Compile / 動作確認へ進める。

完了条件: 画像コンポーネントを同じコンポーネント Registryから追加し、テクスチャのドラッグ・配置・MCPの`place_asset`で画像オブジェクトを作れる。幅と縦横比、基準点、色味、不透明度、透明部分の扱い、両面、ライトの影響をInspectorで設定できる。シーン、動作確認、書き出したコード、公開ワールドが同じ描画経路で同じ見た目になる。画像を出力できないときは色だけの板へ落とし、警告を残す。Graphから表示、色味、不透明度を変えられる。
