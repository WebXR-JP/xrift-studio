## F-01 CLI 更新の状態設計

参照: MI-03, MI-04, MI-05

### 操作前

- 起動後、アプリが管理する `@xrift/cli` の現在版と最新版を確認する。更新がある場合はダイアログを表示し、設定画面を探さなくてもそのまま更新できるようにする。
- ダイアログには「@xrift/cliアップデート」「新しいバージョンが公開されました」と表示し、現在版と最新版を左右に並べて更新内容も併記する。
- 主ボタンは「アップデート」とし、「後で」と閉じる操作を用意して更新を延期できるようにする。

### 処理中

- 実行中は「アップデート中…」と表示し、「後で」と閉じる操作を無効化して二重実行を防ぐ。
- 更新対象はアプリ管理下の CLI に限定し、システム側にインストールされた Node.js や CLI は変更しない。

### 成功時

- 更新後はランタイムの状態と実際に導入された CLI のバージョンを再取得し、利用可能かつ案内した版以上になっていることを確認してから成功を通知する。
- 確認中にさらに新しい版が公開された場合でも、通知には実際に導入した版を表示し、設定画面やバージョン情報と同じ値にそろえる。
- 更新後も開いていたプロジェクトを維持し、そのまま作業を続けられるようにする。

### 失敗時

- インストールや更新後の確認に失敗した場合は原因を表示し、ダイアログを開いたまま再試行できるようにする。未確認の版を更新結果として表示しない。
- ネットワークが利用できない場合は更新ダイアログを繰り返し表示せず、後から確認できる場所を案内する。

### 戻り先

- 「後で」または閉じる操作でプロジェクト一覧に戻る。更新の有無にかかわらず制作を続けられる。

完了条件: 現在版と最新版を確認して更新または延期を選べ、更新後の状態を再取得できる。

## F-02 プロジェクトライブラリの状態設計

参照: MI-01, MI-02, MI-03, MI-04, MI-05, MI-06, MI-09, MI-45, MI-74

### 操作前

- セットアップ完了後はプロジェクトライブラリを開き、見出しの下に件数と実際の保存先パスを表示する。
- 一覧の先頭に「新規プロジェクト」を固定し、作品がない状態でもすぐ作成できるようにする。
- 各カードにはサムネイル、種別（ワールド / アイテム）、制作方法（ビジュアル編集 / コード編集）、タイトル、プロジェクト名、説明、更新日時、公開状態を表示する。サムネイルがない場合は「表紙なし」と表示し、カード自体は表示を続ける。
- 検索欄、公開状態の絞り込み、並び順（最近更新した順 / 更新が古い順 / 最近公開した順 / 名前順）を同じ行に配置し、現在の並び順を一覧の上に明記する。
- 表紙の設定と削除は控えめなアイコンで表示し、作品を開く操作から離して配置する。

### 処理中

- 読み込み中・0 件・取得失敗を明確に区別して表示し、0 件をエラーのように見せない。
- 削除は対象と影響を確認ダイアログで示してから実行し、確認前に一覧から消さない。

### 成功時

- カードを選択すると、制作方法に応じたエディター（ビジュアルエディターまたはコードエディター）で開く。
- 新規作成・公開・サムネイル更新の後は一覧を再取得し、対象カードを最新の状態で表示する。

### 失敗時

- ビジュアル編集用マニフェストが不正な場合は、対象と修復方法を表示する。コード編集プロジェクトと推測して開かない。
- 一覧の取得に失敗した場合でも、新規作成と再試行を選べる状態を維持する。

### 戻り先

- 各エディターの「ライブラリ」からいつでも戻れる。未保存の変更がある場合は、保存・破棄・取消を選べる。

完了条件: 成果物種別、制作方法（コード編集 / ビジュアル編集）、更新日時、公開状態を一目で区別できる。検索・並び替え・絞り込み・安全な削除と、新規作成・再開の操作が常に見つかる。不正なビジュアル編集用マニフェストをコード編集と推測して開かない。「ヘルプと報告」から環境情報のコピー、画面保存、GitHub での報告や ChatGPT への相談へ進める。

## F-44 プロジェクトの複製・ファイル書き出し・ファイル / Git 取り込みの状態設計

参照: MI-05, MI-06, MI-45, MI-123

### 操作前

- 各カードの表紙編集と削除の間に「複製」「.xriftstudioファイルに書き出す」を配置し、作品を開く操作と離す。「ファイルから取り込む」は「新規プロジェクト」の横に常設し、作品がなくても使えるようにする。
- 複製ダイアログではフォルダー名を編集できる。初期値は `元の名前-copy` とし、同名のフォルダーがある場合は連番を付ける。
  - ビジュアル編集では、初期値「元のタイトルのコピー」のタイトルも編集できる。
  - 使用できない文字や重複名がある場合は入力欄の下に理由を示し、「複製する」を無効にする。
  - コード編集では、`xrift.json` のタイトルを引き継ぐ旨を説明する。
- 書き出しでは OS の保存ダイアログで `名前.xriftstudio` の保存先を選ぶ。結果画面には `node_modules`、`.git`、`dist`、キャッシュ、公開記録を含めないことを明記する。内部構成は既存の ZIP とパッケージマニフェストの仕様（[プロジェクトの受け渡し形式](../PROJECT_PACKAGE.md)）に従う。
- 「Gitから取り込む」ダイアログでは、HTTPS または git SSH のリポジトリ URL とフォルダー名を入力する（フォルダー名の初期値はリポジトリ名）。浅いクローン（shallow clone）で取得して `.git` は持ち込まないこと、非公開リポジトリの取得にはこの PC の git で認証できる必要があることを説明する。
- ファイル取り込みでは OS のファイル選択で `.xriftstudio` または従来の `.zip` を選び、中身（ワールド / アイテム、ビジュアル編集 / コード編集、タイトル、ファイル数、展開後サイズ）を確認してからフォルダー名を決める。ZIP 直下または 1 階層のフォルダー内に `xrift-studio.project.json` か `xrift.json` がない場合は、理由を通知して取り込みを開始しない。
- OS 上で `.xriftstudio` を XRift Studio に関連付ける。ファイルをダブルクリックした場合もプロジェクト一覧へ移動して同じ内容確認ダイアログを開き、起動済みなら既存ウィンドウを前面に出す。

### 処理中

- 複製・書き出し・取り込みの実行中は、一覧上の他操作と新規作成を無効にし、ボタン表示を「複製中…」「取り込み中…」「ファイルを確認中…」「取得中…」へ切り替える。
- 各処理では保存先ルート直下の一時フォルダーにデータを構築し、完了後に正式な名前へ切り替える。失敗時は一時データを削除し、不完全なプロジェクトを残さない。

### 成功時

- 複製・取り込み完了後は一覧を再取得し、追加したプロジェクトを名前付きで通知する。複製・取り込みされたプロジェクトには新しい `projectId` を発行し、`lastPublication` や `.xrift/*.json` の公開記録を持たない未公開プロジェクトとして扱う。公開しても元のワールドは上書きしない。
- 書き出し完了後は結果ダイアログに `.xriftstudio` のファイル名・ファイル数・容量を表示し、「保存先のフォルダーを開く」からすぐ確認できるようにする。

### 失敗時

- 複製・取り込みに失敗した場合はダイアログを閉じずに原因を表示し、名前を修正して再実行できるようにする。書き出しに失敗した場合は理由を通知し、一覧に留まる。
- 同名フォルダーがすでにある場合は上書きも統合も行わない。

### 戻り先

- キャンセルや失敗時はプロジェクト一覧に戻る。成功後も一覧に留まり、追加されたプロジェクトをそのまま開ける。

完了条件: 一覧または OS から開いた `.xriftstudio` の取り込み、一覧からの複製、`.xriftstudio` 書き出し、従来の `.zip` 取り込み、Git リポジトリからの取り込みが行える。複製・取り込みしたプロジェクトは未公開の独立したプロジェクトとして一覧に追加される。コード編集プロジェクトも同じ手順で扱え、`node_modules` を含まないため取り込み後の初回起動前に依存関係のインストールが必要である旨を画面に明記する。

## F-03 プロジェクト作成の状態設計

参照: MI-03, MI-04, MI-05, MI-06, MI-13, MI-18, MI-35, MI-55, MI-68

### 操作前

- 「新しいプロジェクトを作る」では、次の 4 種類のカードを同じ画面に並べ、成果物と制作方法を一度に選べるようにする。
  - ワールドをコードで作る / アイテムをコードで作る
  - ワールドをビジュアルで作る / アイテムをビジュアルで作る
- 各カードには、何が作られるかを一文で書き、「コード編集」または「ビジュアル」のラベルを添える。
- ビジュアル編集を選んだ次の画面では「最初のシーンと素材」を選ぶ。シーンと Assets は専用 JSON に保存されること、作成後も自由に編集できることを明記する。
- ワールドの選択肢では「空のワールド」（床・メインライト 1 灯・開始位置だけの最小構成）を既定の選択とし、「おすすめ」などの強調表示は付けない。「XRift公式サンプル」および既存 XRift コードプロジェクトからの静的インポートも同じ並びに配置する。アイテムは原点・プレビュー基準点・編集可能なマテリアルを持つ最小構成から始める。
- プロジェクト名の入力欄を同じ画面に配置し、名前が空の間は作成ボタンを無効にする。押せるのに必ず失敗する操作は出さない。
- 「作り方を選び直す」で 4 カードの選択画面へ戻れるようにし、選び直すためにダイアログを閉じ直す必要をなくす。

### 処理中

- 作成中は進捗を表示して二重実行を防ぐ。同梱データのコピー、ハッシュ検証、編集データの保存を一連の処理として実行する。

### 成功時

- 作成したプロジェクトを一覧へ追加し、そのままエディターで開く。通知だけで終わらせない。
- コード編集では既存のコードプロジェクト作成と同じ構成を生成し、ビジュアル編集では専用の編集データをプロジェクトルートへ保存する。

### 失敗時

- コピー、ハッシュ検証、編集データ保存のいずれかに失敗した場合は一時フォルダーを削除し、不完全なプロジェクトを一覧に残さない。
- 失敗理由とともに、戻り先（4 カード選択または名前入力）を示す。

### 戻り先

- キャンセルまたは作成失敗時はプロジェクト一覧に戻る。同じ画面に留まっている間は、入力済みの選択内容とプロジェクト名をそのまま保持する。

完了条件: 4 カードからワールド / アイテムとコード編集 / ビジュアル編集の組み合わせを一度に選べる。コード編集はコードプロジェクトとして、ビジュアル編集は専用編集データを持つプロジェクトとして開く。ビジュアル編集では次の画面で最初のシーンと素材を選べ、ワールドでは「空のワールド」を既定とし、「XRift公式サンプル」（床・壁・Skybox・開始位置を含む公式テンプレート）や既存 XRift コードプロジェクトからの静的インポートも同じ並びから選べる。ローカルフォルダーまたはリポジトリ URL のコードプロジェクトは空のビジュアル編集シーンへ変換し、読み込み元にない床・ライト・開始位置は追加しない。ビジュアル編集アイテムも基本スターターまたは同種のコードプロジェクトから開始できる。

## F-04 ローカル実行の状態設計

参照: MI-03, MI-05, MI-08

### 操作前

- コードエディターのヘッダーに「実行」を配置し、ローカルで開発サーバーを起動してブラウザでプレビューする操作であることをツールチップで示す。同じ並びにサムネイル、ターミナル、VS Code、アップロードを配置する。
- 実行前は開発サーバーが停止していることが分かる状態にし、起動中の URL は表示しない。
- 外部ツールはプロジェクトフォルダーを開く。VS Code の `code` コマンドや対応ターミナルが見つからない場合は起動成功扱いにせず、必要な設定を通知で案内する（詳細は [保存と外部ツールの案内](../guide/save-and-open.md#vs-codeやターミナルが開かない) を参照）。

### 処理中

- 「実行」を押した直後にラベルを「起動中…」へ変えて再実行を防ぎ、ログペインを自動で開いて起動出力をそのまま表示する。
- プレビュー URL を検出したらヘッダーに点滅インジケーターと URL チップを表示し、ブラウザを開く。ブラウザを開けなかった場合も URL チップは残し、クリックで開き直せるようにする。
- 起動中はボタンを「停止」へ切り替え、実行中表示と停止操作を同じ位置にまとめる。

### 成功時

- 起動中の URL はヘッダーに常時表示し、クリックでいつでも開き直せるようにする。ログも同じ画面で確認できる。
- 公開済みプロジェクトでは「XRiftで開く」を並べて表示し、ローカルプレビューと公開先を取り違えない位置に配置する。

### 失敗時

- 起動に失敗した場合は理由をログへ出力し、ボタンを「実行」へ戻して URL チップを消す。
- 停止に失敗した場合も理由をログへ出力し、状態表示を実際のプロセス状態と一致させる。

### 戻り先

- 「停止」で開発サーバーを終了し、URL 表示を消す。ライブラリへ戻る操作はヘッダー左端に常設する。

完了条件: 実行中かどうかが一目で分かり、プレビュー URL をいつでも開ける。

## F-06 アイテム検査の状態設計

参照: MI-03, MI-05, MI-09

### 操作前

- 「チェック」はアイテムのコード編集プロジェクトにだけ表示し、ビルドを含むセキュリティチェックを実行することをツールチップで説明する。ワールドには表示しない。
- 実行中および公開情報の確認中は押せない状態にする。

### 処理中

- 実行と同時にログペインを開き、ビルドと検査の出力をそのまま流す。進行状況を要約だけで隠さない。

### 成功時

- 検査通過を通知し、そのままアップロードへ進めるようにする。ログは確認用に残す。

### 失敗時

- 失敗した事実と、ログを確認して修正する必要がある旨を通知する。ログペインを開いたままにし、原因をすぐ確認できるようにする。
- 検査失敗状態でアップロードを既定の次操作として案内しない。

### 戻り先

- 検査結果にかかわらずエディターへ戻り、同じヘッダーからファイル編集・再実行・アップロードを選べる。

完了条件: ビルドを含むセキュリティチェックを実行でき、成功時は公開へ、失敗時はログ確認と編集へ進める。

## F-20 XRift Studio 本体の更新の状態設計

### 操作前

- 起動後、GitHub Releases の署名済み更新情報をバックグラウンドで確認する。最新版であればダイアログを出さず、About に「最新版です」と表示する。
- 更新がある場合は現在版、最新版、リリースノート、「更新して再起動」「後で」を同じダイアログに表示する。延期後もライブラリヘッダーと About から同じダイアログを再度開ける。

### 処理中

- ダウンロード中は取得済みバイト数と（取得できれば）進捗率を表示し、インストール中は再起動の準備状態を示す。処理中はダイアログを閉じられないようにし、更新や確認の二重実行を防ぐ。
- インストール直前に同じ更新情報の URL を再確認し、署名検証に成功した成果物だけを適用する。アプリ管理外のプロジェクト、Node.js、XRift CLI には触れない。

### 成功時

- インストール完了後にアプリを自動で再起動する。再起動後のバージョンが更新対象と一致した場合にだけ完了通知を表示し、About に新しい現在版と「最新版です」を表示する。

### 失敗時

- 自動確認の失敗は制作作業を妨げず、About に再確認操作を残す。
- ダウンロード・署名検証・インストールの失敗時はダイアログに原因と「再試行」を表示し、現在のアプリをそのまま使い続けられるようにする。

### 戻り先

- 「後で」または確認失敗時は現在の画面に留まる。更新成功時は再起動後の通常起動画面へ戻り、プロジェクト一覧とアプリバージョンを再取得する。

完了条件: 起動時または About から署名済み更新を確認し、現在版・最新版・更新内容を見て延期またはインストールを選べる。進捗を確認しながら再起動し、更新後の確認または失敗時の再試行を行える。

## F-26 アプリデータのリセットの状態設計

参照: MI-03, MI-04, MI-05, MI-09, MI-66

### 操作前

- About の「データの削除とリセット」では、「ランタイムのみ」はプロジェクトを残し、完全リセットはプロジェクトも削除することを明記する。
- `@xrift/cli` のバージョン確認中は、実行中の Node.js と削除処理が競合しないようリセットを開始できないようにする。

### 処理中

- 確認ダイアログの主操作を「実行中」へ変えて無効化し、背景クリック・Escape・閉じる操作を止める。
- 通常のパスから直接削除できない場合は、同じアプリデータ領域内の別名パスへ退避し、次回起動時に旧データが参照されないようにする。

### 成功時

- 削除完了後にアプリ本体を再起動し、ランタイムのみのリセットならセットアップへ、完全リセットならセットアップ後の空のプロジェクト一覧へ進む。確認ボタンは対象に応じて「リセットして再起動」または「すべて削除して再起動」と表示する。
- 退避した旧データは次回起動時にバックグラウンドで削除し、新しい制作作業を妨げない。

### 失敗時

- 退避にも失敗した対象と OS のエラーを確認ダイアログ内に表示し、実行中のターミナルやエディターを閉じる案内を添える。
- ダイアログを閉じず同じ主操作から再試行でき、取消で About へ戻れる。

### 戻り先

- 成功時は再起動後のセットアップまたはプロジェクト一覧へ進む。失敗・取消時は About の「データの削除とリセット」へ戻る。

完了条件: 実行中 CLI との競合や一時的なファイルロックで中途半端な状態を残さず、ランタイムのみまたは全データを次回起動から確実に分離できる。失敗時は対象と再試行方法を確認したまま復帰できる。

## F-41 紹介ページのダウンロード導線の状態設計

参照: MI-01, MI-09, MI-119

ガイドから `#download` 付きで開いた場合は、React の初回描画後にダウンロード欄へスクロールする。

### 操作前

- 主ボタンには「Windows版を無料ダウンロード」のように OS 名を表示し、直下にバージョン・拡張子・形式の読み・容量を常時表示する。
- ダウンロード欄にはファイル名、容量、SHA-256、公開日、リリースノートへのリンクを並べ、配布元が GitHub Releases であることとリリースページへのリンクを明記する。
- OS を判別できない場合やスマートフォンでは、保存を開始するボタンを出さず、パソコン対応であることと全 OS のファイル一覧を示す。
- ヘッダーの常設ボタンはダウンロードを開始せず、ダウンロード節への移動に留める。記事を読んでいる途中で数十 MB の保存が始まらないようにする。
- 表示するリリースはビルド時に埋め込んだ公開済みリリースを初期値とし、表示後に GitHub 公開 API で最新を確認する。確認中もバージョンとファイル一覧を空欄にしない。

### 処理中

- 最新版の確認中も埋め込み済みのリリース情報を表示し続け、ダウンロード操作を無効化しない。
- API 確認は 1 回のページ読み込みにつき 1 回だけ実行し、ページ内の全ダウンロード導線で同じ結果を共有する。

### 成功時

- ダウンロードボタンを押した直後に「ダウンロードを開始しました」と表示し、保存後の手順へ進むリンクを残す。
- インストール後に OS が出す警告（Windows の SmartScreen、macOS の開発元確認）について、コード署名がない理由と対処手順を事前に示し、警告を見て中断しないようにする。
- 選択中 OS の別形式や他 OS のファイルも、同じ節内から 1 操作で選べるようにする。

### 失敗時

- 最新版を確認できなかった場合は、ページ生成時点のリリースを表示している旨を明記し、再確認操作とダウンロード操作の両方を利用できる状態にする。
- 公開 API が返したリリースにインストーラーが 1 つも含まれない場合はその結果を採用せず、埋め込み済みのリリースを表示し続けて空の一覧を出さない。

### 戻り先

- ダウンロード欄からリリースノート、GitHub のリリースページ、ブラウザで試せるエディターのデモへ移動できる。

完了条件: 紹介ページが最新リリースを取得し、閲覧中 OS に合うインストーラーを直接ダウンロードできる。ファイル名・容量・SHA-256・OS 警告への対処と他 OS / 別形式の選択肢を同じ画面にまとめ、リリースの手順を変えずに公開済みリリースへ追従できる。

## 初回セットアップ・制作ツールの更新と読み込み失敗からの復帰

参照: MI-03, MI-05

- 初回起動時はセットアップ開始操作を最初から表示する。デスクトップ版で制作を始める操作は、セットアップ完了後のプロジェクト一覧に配置する。
  - 処理中は開始ボタンを無効にして進捗を表示し、失敗時は同じ画面で再試行または「ヘルプと報告」を開けるようにする。
  - インストール先は必要なときに展開して確認できる。
- 起動時に CLI の導入状態とバージョンを確認し、必要な版より古い場合や Node.js が不足する場合は「制作ツールの更新が必要です」と表示する。
  - 初回起動時の歓迎画面とは明確に区別し、古い CLI については現在版から推奨版への変更を示す。Node.js と初回導入する CLI のバージョンにはアプリから受け取った値を表示する。
  - 「制作ツールを更新」を押すと準備を開始し、処理中は「制作ツールを更新中…」にして二重実行を防ぐ。アプリ専用ツールが利用可能になったことを確認してからプロジェクト一覧へ進む。すでに推奨版より新しい CLI が入っている場合はその版を維持する。
  - 失敗時や準備未完了時は同じ画面に留まり、「更新を再試行」と「ヘルプと報告」を表示する。
- ビジュアルエディターの読み込み失敗画面では画面名を重複させず、通信切断を原因と断定しない。再読み込み後にプロジェクトを開き直す手順と、保存済みデータと未保存変更の区別を示す。戻るボタンのラベルはランタイム準備状態に応じて「セットアップに戻る」または「プロジェクト一覧に戻る」とする。

## 編集内容の自動保存（MI-03・MI-05）

- シーン、Script、GLSL、コードエディターのテキストは変更後に自動保存する。保存待ち・自動保存中・保存済みの状態を表示し、通常の編集で手動の保存操作を求めない。
- 保存中に加えた追加入力はそのまま保持し、次の自動保存へ引き継ぐ。保存失敗時は編集内容を保持したまま再試行操作を表示し、ファイル切り替えや終了時にも未保存の内容を捨てない。
- `Vehicle` と `Seat` は「アセットストア」の XRift 公式コンポーネント欄から追加する。Assets に再利用可能なプレハブと実装 Script を保持し、プレハブの「シーンへ配置」で配置する。
