## F-45 iPad 編集とブラウザプロジェクトの受け渡し

参照: MI-03, MI-04, MI-05, MI-09, MI-10

### 画面構成と狭い画面での操作

- **操作前**: PC のシーン、Hierarchy、Assets、Inspector を共通化し、タブレットではパネルを切り替えて画面幅に応じシーンの横または下に表示する。パネル選択・視点だけ操作・複数選択はその場で切り替え、保存データや PC のパネル幅は変更しない。
  - iPhone でもエディターを直接表示し、読み込み後に短い操作ガイドモーダルを重ねる。閉じればそのまま編集でき、同じページ内では繰り返し表示しない。
  - スマートフォンでは初期状態でパネルを閉じ、シーン操作ボタン群を開閉できるようにする。選んだパネルは作業領域全体に表示し、「シーン」で戻る。Canvas と各パネルの状態は維持する。
- **狭い画面の表示**: スマートフォンとタブレットの上部はプロジェクト名・保存状態と「ファイル」メニューへ集約する。素材追加・プロジェクト切替・書き出し・シーン設定・ガイドをメニュー内へ移し、下部の常設ユーティリティレールを外す。
  - スマートフォンの Assets は一覧まで一続きにスクロールでき、種類・フォルダー・並び順は必要なときだけ開く。長い素材名は折り返し、マテリアル概要は設定欄を圧迫しない大きさに抑える。
- **素材の追加**: 上部の「ファイル → 素材を追加」に「アセットストア」と「3Dモデル / 3Dアセット」を配置する。Hierarchy では選択行の「…」からコピー・複製・移動などの操作を開く。
  - 外部カタログは幅 1023px 以下でカテゴリ選択・一覧・詳細を切り替え、素材を選ぶと詳細へ、一覧へ戻ると選択中カードへ戻る。PC の 3 列表示は維持する。
  - 取り込みモーダルと素材追加メニューは Safari の表示領域に合わせ、入力・追加・閉じる操作が画面内に収まるようにする。
- **パネル切り替え**: 入力中の値や選択状態を維持しつつ、非表示の Inspector ではカスタムマテリアルの描画を止め、非表示の Assets ではサムネイル生成を止める。「視点だけ操作」「複数選択」は Apple Pencil や接続マウスにも適用し、ピンチ操作の途中で指がキャンセルされても残りの指で選択を再開しない。
- **iPad の入口と入力**: 紹介ページでは制作開始と保存済みプロジェクトを開く操作を優先する。新規作成は名前を入力して開き、一覧では更新日時と編集中のプロジェクトを見分けられるようにする。Assets はフォルダーを維持したまま種類を絞り込める。
  - タッチ用数値欄は選択して打ち替えられ、負号や小数点など入力途中の文字も保持する。画面サイズの監視は共有し、数値欄の端末判定はタッチ対応の有無が変わったときだけ更新する。

### プロジェクト選択と保存・受け渡し

- **プロジェクト選択（MI-02, MI-09）**: 「新しく作る」「このブラウザから開く」「ファイルから開く」を同じ見出し・余白で並べ、共通の白いカードとフォーカス表示にそろえる。新規作成は種別を押すと名前入力へ進み、「一覧へ戻る」で作成せず選択画面へ戻れる。保存済み一覧の読み込み中・空状態も同じセクション内に表示し、ファイル選択を戻る操作と並べない。
- **ファイル操作**: 「素材を追加」は編集中プロジェクトへの素材追加、「プロジェクトを開く」はブラウザ保存済み一覧と「ファイルから開く」の統合入口とし、切り替え前に現在の保存を完了させる。「プロジェクトを書き出す」は素材を含めて 1 つのファイルにまとめる。
- **保存**: 共通の文書エンコード・デコード処理を使い、ブラウザのプロジェクトと素材を IndexedDB へ保存する。「ブラウザに保存済み」をファイルへの書き出し完了と混同させない。直近のプロジェクトを自動復元し、「プロジェクトを開く」から保存済み一覧・新規作成・「ファイルから開く」を選べる。別プロジェクトを開く前に現在の保存完了を待つ。
- **処理中**: 書き出し前に Node Graph で編集中の値を確定し、保存待ちの内容を書き終える。Play 中や素材処理中の転送は防ぎ、ファイル準備中はダイアログを閉じられないようにする。取り込み時はパス・容量・文書を検証して別プロジェクトとして保存し、一式の保存がすべて完了してから確定する。成功するまで現在の編集内容は置き換えない。
- **成功時**: `.xriftstudio` ファイルの準備が完了したら、ファイル名・容量・「ファイルに保存」・利用可能なら「共有する」を同じ画面に表示する。非同期処理の完了後に自動クリックでダウンロードせず、Safari で利用者が明示的に押せるリンクにする。Blob URL はダイアログを閉じた直後に破棄しない。保存先はブラウザ側で確認するよう案内し、ダウンロード開始を「保存済み」と断定しない。
- **ダイアログ**: 本文だけをスクロールし、閉じる・作成・保存ボタンは下部に固定する。iPad ではソフトウェアキーボード表示後の画面高にも収める。PC への引き継ぎ説明は折りたたみにし、ダウンロード開始後は確認先を案内する。
- **引き継ぎ**: 書き出し拡張子は `.xriftstudio` とし、従来の `.zip` も取り込める。内部 ZIP 構成（`xrift-studio.project.json`、全シーン、Assets、プレハブ、素材ファイル、パッケージマニフェスト）は [プロジェクトの受け渡し形式](../PROJECT_PACKAGE.md) に従う。Mac / Windows 版の「ファイルから取り込む」へ案内し、公開記録を引き継がない未公開プロジェクトとして開く。スクリプトを含む作品は、この受け渡しを経てデスクトップ版から公開する。
- **容量制限**: ブラウザ転送は ZIP・展開後データともに 256 MB 以下、ファイル一覧を含めて 20,000 ファイル以下に制限する。大きな素材の圧縮で二重のメモリ消費を起こさないよう、書き出し ZIP は `STORE` 方式を使う。取り込みは既存の `Deflate` にも対応する。

### ブラウザからの公開と失敗時の復帰

- **ブラウザからの公開**: パソコン・iPad・スマートフォンでワールドとアイテムの「XRiftへ公開」を同じ公開画面へ通す。タイトル・説明・サムネイルと、新規公開か既存作品の更新かを送信前に確認する。
  - ワールドの `write:worlds`、アイテムの `write:items` 権限付き API キーは公開画面のメモリ上にだけ保持し、閉じたら破棄する。
  - 対応ブラウザでは送信完了後に本人の選択でパスワード管理機能へ保存できる。「APIキーをブラウザに保存」を押した直後には読み戻さず、ブラウザの保存承諾を案内する文と「保存済みキーを確認」を表示する（MI-03, MI-05）。利用者が確認を押し、今回のキーと一致する保存済みキーを読み戻せた場合だけ保存済みと表示する。確認の取消・別キー選択・読み取り失敗では今回のキーを保持し、確認と保存依頼を再試行できるようにする（MI-09）。
  - 準備・送信・結果を明確に分け、送信結果が不明な場合は重複公開を防ぐため直ちに新規送信させない。正式な公開 URL が返った場合だけその URL を表示する。
- **失敗と復帰**: 保存やファイル準備の失敗時は編集内容を保持し、原因と再試行操作を残す。
  - ブラウザ公開では外部送信前に「送信保留」を保存し、結果が不明な場合は画面を閉じても再読み込みしても新規送信を止める。作成された公開先 ID を表示し、XRift 上で公開されていないことを確認した利用者だけが保留を解除できるようにする。公開先作成後やファイル送信開始後の 401 / 403 も保留扱いとする。
  - ファイル取り込みに失敗した場合は別ファイルを選び直せ、保存済みプロジェクトの読み込み失敗時はプロジェクト選択や新規作成へ戻れる。転送ダイアログを閉じると元の編集画面へ戻る。

検証範囲: TypeScript の静的検査と、Node 上での ZIP 往復・複数シーン・プレハブ・素材バイト列・不正パス・欠落ファイル・容量制限を確認済み。ブラウザのアイテム公開は、実 SDK の送信先を隔離した E2E で新規送信・再読み込み後の更新・401 / 403・Script 拒否を確認し、送信シェルのアイテム描画と共有ランタイムの表示を比較済み。実際のアイテムの外部公開・審査・利用および iPad 実機での公開は未確認。

## F-05 公開準備とアップロードの状態設計

参照: MI-03, MI-04, MI-05, MI-07, MI-08, MI-09, MI-17, MI-27

### 操作前

- 「アップロード」は未ログインの間は無効にし、ツールチップでログインが必要なことを伝える。押せるのに必ず失敗する操作は出さない。
- 押すとまず公開情報を確認し、確認中はラベルを「公開情報を確認中…」へ切り替える。
- タイトル・説明・サムネイルがテンプレートのままの場合は「公開前の確認」を開き、そのまま公開すると初期ワールド（または初期アイテム）のように表示される可能性がある旨を伝える。主操作は情報の編集またはサムネイル設定とする。
- ビジュアル編集プロジェクトでは、公開情報、サムネイル、XRift アカウント、公開先、公開データ、公開チェック、ロード容量・VRAM の目安を確認項目として並べ、各状態を 1 行で表示する（[F-27](#f-27-公開前パフォーマンス概算と素材最適化の状態設計)）。
- テクスチャは編集画面で使用中の画像をそのまま公開する。未適用の縮小・圧縮設定を公開時に自動実行しない。変更は Inspector で明示的に適用し、編集画面と Play で確認できるようにする。

### 処理中

- ビジュアル編集の公開画面は検査完了を待たずに開き、「公開データを確認中…」を表示して最新編集内容の検査が終わるまで公開ボタンを無効にする。
  - 検査中も公開情報の編集と「戻る」を操作できる。
  - 編集し直した場合は古い検査結果を採用せず、画面を閉じた場合は検査を終了する。検査を開始できなかった場合は閉じて開き直すよう案内する。
- ビジュアル編集の公開は保存 → 変換 → 検査 → 送信の順に進み、現在の段階と取り消し可否を表示する。
- 送信前の段階では取り消してもリモートを変更しない。送信開始後は、取り消しを試みても完了を保証できないことを明記する。

### 成功時

- 送信後は `worldId` / `itemId`、`versionId`、`versionNumber`、内容のハッシュを表示する。審査中を公開済みとして表示しない。
- 公式の結果に URL が含まれる場合だけページを開く導線を表示し、ID から URL を推測して組み立てない。
- 公開済みプロジェクトでは、以後エディターのヘッダーから公開先を開けるようにする。

### 失敗時

- 失敗した段階、要約したエラー、リモートを変更したかどうかを表示し、該当段階から再試行できるようにする。
- 検査で止まった場合は、修正に必要なログを同じ画面で読める状態にする。
- 結果が不明な送信を再試行するときは、既知の公開先 ID と入力ハッシュを照合し、新しい公開先を重複作成しない。

### 戻り先

- 編集を促された場合は対象の編集画面（`xrift.json` またはサムネイル）へ移り、保存後に同じ確認画面へ戻る。ダイアログを閉じた場合はエディターへ戻り、制作データとリモートは変更しない。

完了条件: 初期値のまま公開する誤操作を防ぎ、必要なツールが不足しても制作データを失わない。公開前確認から送信結果・審査状態の確認まで一連で進められ、正式な結果に含まれない公開 URL を推測表示しない。

## F-10 ビジュアル編集の保存・コンパイル・プレビュー・公開の状態設計

参照: MI-03, MI-04, MI-05

同名の glTF マテリアルは、公開データ生成時に元モデル内のマテリアル番号で自動的に区別する。既存プロジェクトも同じ処理を通るため、名前変更や再取り込みは不要で、ノードごとの割り当てと各マテリアルの見た目を維持できる。この処理は通常の公開前検査に含め、成功後はそのまま公開へ進める。元の番号がない古いデータは名前で照合し、一意に決まらない割り当てを勝手に統合しない。画面・MCP・コード書き出しで共通のコンパイラーを使い、追加の修正操作は設けない。

### 操作前

- 編集操作前は直前のリビジョンを自動保存済みとして表示する。コンパイルとプレビューでは、対象と入力が最新かどうかを示す。公開前にはタイトル・説明・サムネイル・認証・診断結果・既存の公開先 ID を表示する。
- エディターでの直接プレビュー、生成したステージングのプレビュー、XRift への公開と審査を明確に区別して表示する。公式仕様にない hosted / CLI / XFT のプレビューは選択肢に出さない。

### 操作中

- 編集操作の確定から 250ms 待ったのち、最新リビジョンの検証 → 一時書き込み → 確定の順で自動保存する。保存中に次の変更が確定しても並列書き込みは行わず、実行中の保存完了を待ってから最新リビジョンを保存する。
  - まだ書き込みを始めていない古いリビジョンは保存待ちから省き、新しいリビジョンが要求されたら古いリビジョンの再試行待ちを解除して最新へ進む。
- コンパイルは素材準備 → 生成 → ハッシュ計算と生成元の記録へ進む。必須の `public/thumbnail.png` をステージングへコピーし、SHA-256 の一致を検証する。
- 公開ダイアログでは `auth-check`、`saving`、`compiling`、`checking`、`uploading`、`processing` の各段階を表示する。公開前確認から現在のシーンを描画して撮影するか、画像ファイルを選んで `public/thumbnail.png` を更新できる。
- 取り消しボタンは安全に中断できる段階だけ有効にする。リモート送信開始後は取り消しの完了を保証できないことを明示し、送信結果が不明なまま新規公開を再開させない。

### 成功時

- 自動保存は保存完了マーカーと全ハッシュの一致を確認してから対象リビジョンを保存済みにする。保存中に新しいリビジョンが生じた場合は「自動保存中」または「自動保存待ち」を維持し、後続の保存完了後に「自動保存済み」へ切り替える。
- コンパイルと検査では最新入力の内容ハッシュに対応する結果と生成元の記録へのリンクを残し、サムネイルには「公開用ステージングへコピー済み」と検証済み SHA を表示する。
- 公開後は正式結果の `worldId` / `itemId`、`versionId`、`versionNumber`、`contentHash`、審査状態を表示し、正式な URL 欄がある場合だけ URL を表示する。サムネイルを更新した場合は、保存済み画像・公開チェック・再コンパイル要否を同じ確認画面に反映する。
- 公開に成功したら、CLI が `.xrift/world.json` または `.xrift/item.json` に記録した公開先 ID を制作プロジェクトへ保存し、次回ステージング生成時に復元する。`xrift.json` は公開先 ID の保存先にしない。

### 失敗時

- 自動保存が一時的に失敗した場合は、最新リビジョンだけを最大 3 回再試行する。上限後も失敗した場合は最後に保存が確定した文書一式と未保存のエディター状態を維持し、ヘッダーに「自動保存エラー」と再試行を表示する。新しい操作が確定したら古いリビジョンの再試行を打ち切り、同じ内容を無限に再試行しない。
- コンパイル失敗時は最後に成功したステージングを残す。公開失敗時はリモートで変更が確定したかどうか、失敗段階、機密情報を除いた原因、再試行先を表示する。
- 古い入力、`REJECT`、未編集のメタデータ、認証失敗、サムネイルの欠落・コピー失敗・SHA 不一致は成功扱いとせず、該当する Entity・素材・入力欄または公開前確認へ戻す。
  - 確認画面での撮影・画像変換・保存に失敗した場合は既存サムネイルを保持し、同じ画面から再試行できるようにする。
  - サムネイル変更後は再コンパイルを必須とし、ステージングを作り直すまで送信を始めない。トークン、絶対パス、標準エラー出力の原文は画面に表示しない。
- 保存済みの公開先 ID を一意に復元できない場合、およびマニフェスト・CLI 付属ファイル・公開結果の ID が一致しない場合は、新規公開と再試行を止めて公開先の確認を求める。

### 戻り先

- ダイアログやプレビューを閉じると同じビジュアルプロジェクトの編集へ戻り、Play 前のカメラ・`sceneSelection`・`assetSelection`・自動保存状態を復元する。
- ライブラリへ戻るときは待機中・保存中の最新リビジョンの保存完了を待ち、失敗した場合はエディターに留まって再試行を表示する。
- 自動テストや通常の UI 検証ではテスト用バックエンドとフィクスチャで公開状態を再現し、実際の XRift へは送信しない。

完了条件: 編集ごとの直列自動保存、ジャーナル付きの確定処理、同じ入力から同じ出力を作るコンパイラー、生成元の記録、入力の鮮度検査を一連のエディター操作で扱える。プレビュー種別を区別して既存の XRift 検査・公開へ進め、失敗や取消後も最後に保存確定したデータと戻り先を維持できる。公開前確認から現在シーンのサムネイルを保存し、新規公開・更新の両方で再確認できる。

## F-19 ビジュアル編集からコード編集への書き出しの状態設計

### 操作前

- ビジュアルエディターのヘッダーにある「コード編集へ書き出す」から開始し、現在のビジュアルプロジェクトは閉じない。書き出しは一方向で自動同期しないこと、コード編集から戻す場合は F-23 の静的取り込みを別途行うこと、一部情報は再現できないことを最初に説明する。
- OS のフォルダー選択で、同じ種別（ワールド / アイテム）のコードプロジェクトを選ぶ。`package.json`、`xrift.json`、`src/World.tsx` または `src/Item.tsx`、パッケージマネージャーを検査してから書き込みを有効にする。
- 既定は既存エントリーファイルを変更しない「コンポーネントとして追加」とする。「エントリーを切り替える」を選んだ場合は既存ファイルをバックアップして置き換えることを説明し、明示的な確認を求める。

### 操作中

- 先にビジュアル編集の最新文書を保存し、公開と同じ `classic-jsx` コンパイルモードでシーンのソース、素材コピー計画、デコーダーとフォントの同梱計画、診断結果、生成元の記録を生成する。公開を止める診断がある場合はコードプロジェクトへ書き込まない。
- 生成した `src/` 一式は相対インポートを維持したまま `src/xrift-studio/<project-id>/` へ配置し、`Scene.tsx` から `XriftStudioScene` として読み込めるようにする。
  - 素材・デコーダー・フォントは公開ワールドの配信仕様に合わせ `public/` 直下へ配置する。
  - 生成元の記録と書き出しマニフェストは `.xrift-studio/exports/<project-id>/` へ配置する。
  - 既存の `xrift.json` とサムネイルは上書きせず、`permissions` の追加が必要な場合は完了画面に必要項目を示す。
- 依存パッケージはコンパイル計画から決定する。`@xrift/world-components` は既存バージョン範囲で要件を満たせない場合だけ固定し、テキスト用の `troika-three-text` と Open Brush 用の `three-icosa` は必要な場合だけ追加する。
  - npm プロジェクトでは固定許可リスト内のパッケージを自動インストールできる。`package.json` の記載と導入済みバージョンを確認し、不足があれば再試行時にもインストールする（不足がなければ実行しない）。
  - pnpm / Yarn / Bun のプロジェクトでは別のロックファイルを作らず、`package.json` への依存記録と既存パッケージマネージャーでのインストール案内に留める。

### 成功時

- シーンのソース、実行環境モジュール、素材、デコーダーとフォント、接続用コンポーネント、生成元の記録、書き出しマニフェストを出力する。前回の書き出しに記録されていて今回不要になったファイルだけを削除し、手書きファイルやバックアップには触れない。
- エントリー切替時は内容ごとにバックアップを保存してパスをマニフェストに記録し、再実行しても初回内容や途中の修正を失わないようにする（生成済みエントリーファイルのバックアップは増やさない）。
- 完了ダイアログに「フォルダーを開く」「VS Codeで開く」「ターミナルを開く」を並べ、「コンポーネントとして追加」の場合はエントリーファイルへ貼る import と JSX のコードをコピーできるようにする。

### 失敗時

- フォルダー検査・ビジュアル編集の保存・コンパイルに失敗した場合はコードプロジェクトを変更しない。不足ファイル、プロジェクト種別（`kind`）の不一致、処理を止める診断を同じダイアログに表示し、修正や選び直しができるようにする。
- パッケージのインストールに失敗した場合も生成ファイルと依存記録は保持し、公開済みパッケージまたは既存パッケージマネージャーで再実行できる旨を案内する（成功扱いにしない）。

### 戻り先

- 取消または完了後にダイアログを閉じると、元のビジュアルエディター、シーン、選択状態、カメラ、保存状態へ戻る。コード側の編集は自動同期せず、取り込む場合は F-23 から検査と診断を伴う別トランザクションを実行する。

完了条件: ビジュアルエディターから同種のコードプロジェクトを選んで検査し、シーンのソース・素材・接続コンポーネント・固定依存パッケージを手書き領域と分離して追加できる。完了後にフォルダー・VS Code・ターミナル・接続コードへすぐアクセスできる。

## F-27 公開前パフォーマンス概算と素材最適化の状態設計

公開時の不要データ除去と変換キャッシュは [ダウンロード容量削減](../PUBLISH_DOWNLOAD_OPTIMIZATION.md) に従う。通常の Play には変換待ちを追加せず、公開用コピーだけに適用する。公開ログで GLB の変換前後サイズを確認できる。

参照: MI-04, MI-07, MI-27, MI-67

### 操作前

- 公開前確認項目の末尾に「ロード容量・VRAMの目安」を置き、ロード容量、VRAM の推定範囲、優先度の高い改善候補の有無を 1 行で表示する。「詳細を見る」から「ワールドの容量・パフォーマンス目安」を開く。
- 詳細画面には「素材VRAM」「初回素材ロード」「実行時の全体目安」「スマートフォン目安」を並べ、各数値の下に内訳（テクスチャ数・3D モデル数、回線速度と所要秒数、加算した描画バッファ量、余裕ありと判定する Studio 基準の閾値）を併記する。デスクトップ判定・メッシュ配置数・高速回線での所要秒数も補助情報として同じ行に添える。
- 「VRAM使用量が多い順」と「ロード容量が多い順」を寄与量の大きい順に並べ、見出しの下に前提条件を書く。
  - VRAM 順: 同じ素材の複数配置は GPU リソースを共有する。
  - ロード容量順: 公開時にコピーされる元素材ファイルの合計であり、アプリ本体と通信オーバーヘッドを含まない。
- 概算対象となる素材がないシーンでは「0 件」と空状態の文を表示し、合計値だけを出して内訳取得失敗のように見せない。
- 画面末尾に次の注記を明記する。
  - 実測値ではないこと
  - ロード時間計算に含まれない要素（キャッシュ、CDN、アプリ本体、HTTP 処理）
  - VRAM が変動する条件（ブラウザ、GPU、画面解像度、影、ポストエフェクト、KTX2 の転送先形式）
  - PNG / JPEG / WebP を GPU 上の RGBA 展開として算出し、mipmap 有効時は約 33% を加算していること

### 操作中

- 改善候補には対象素材名と現在値を添え、テクスチャは最大 2048px への縮小と KTX2 変換、3D モデルは Draco 圧縮を候補として、優先度「推奨」「検討」に分けて並べる。
- 候補は個別にチェックでき、チェックした分だけを適用する。適用中は進捗と対象を表示し、同じ候補の二重実行を防ぐ。
- 公開前確認を開いた時点で公開対象シーンと展開済みプレハブを解析して概算し、エディターの選択・シーン・素材は変更しない。

### 成功時

- 適用した候補を対象素材の読み込み設定または派生素材へ反映し、概算を再計算して同じ画面の数値と内訳を更新する。変化を確認してから次の操作を選べる。
- 重複メッシュの候補には同じ元データメッシュを参照する部品数を表示し、モデル全体の配置数と区別する。
  - 選択して適用するとモデルの「重複メッシュをインスタンス化」が有効になり、Play と公開先で共通処理を使う。
  - 同じ形状・マテリアルの不透明な静的部品を 64m 単位でまとめ、元モデルと衝突判定は保持する。動的な親、アニメーション、スキン、モーフ、反転部品、スクリプトやグラフ実行があるシーンでは通常描画を維持する。
  - 適用済み候補は一覧から外れ、モデルの設定から解除できる。ファイル容量の削減としては表示しない。
- 「公開前の確認へ戻る」で公開前確認へ戻り、更新後の 1 行サマリーを確認してから公開へ進める。

### 失敗時

- 変換に失敗した候補は対象素材を変更せず、対象名と理由を残す。同時に選んだ他候補の成功結果は取り消さない。
- 概算できない素材は概算対象外として明示し、0 や不明を「余裕あり」に含めない。

### 戻り先

- 「公開前の確認へ戻る」で公開前確認へ戻り、ダイアログを閉じるとエディターへ戻る。いずれの場合もエディターの編集状態・選択・Inspector の対象は変えない。

完了条件: ワールド / アイテムの更新前に、初回ロード容量と回線別所要時間、素材・実行時 VRAM の推定範囲、端末別 Studio 基準、寄与順の内訳と最適化候補を確認できる。縮小・KTX2 変換・Draco 圧縮を個別選択して適用でき、再計算結果を確認してから公開前確認へ戻れる。
