## F-17 AI editor integration / MCP の状態設計

### 制作チャットの実行・履歴分岐

参照: MI-03, MI-05, MI-09。
制作は一つのPiセッションで直接進める。管理役のセッションや通常の実装・検証ごとの承認工程は設けず、重要な未決定事項だけを確認する。
制作中は応答途中の文章、再試行、会話の要約、実行中の正式ツールと制作・配置・保存の進行状況を表示する。内部思考は表示しない。「この依頼の実行情報」で実際のモデル応答・ツール実行とトークン使用量を確認できる。表示する回数を制作の停止上限には使わない。
制作中は「今の制作に反映」と「終了後に実行」を選べる。現在の応答・操作後に追加する場合と、現在の制作終了後に同じ会話で続ける場合を区別する。追加指示には添付を保持し、対象Scene・チャット・依頼をnativeで照合する。受信確認後にだけ入力欄を空にし、送信エラーや送信中の追記は残す。未反映の追加指示は会話に残し、入力欄へ戻せる。
通常の応答が終了しただけの場合は「応答済み」と表示する。保存・画像・完成条件の検証が済んだこととは分け、検証の呼び出しがないだけで失敗にはしない。モデルやツールの実際のエラーは残す。画面文言にはPiなどの内部実装名を出さない。
成功後は実際のSceneと作業記録を残す。モデル配置の結果には作成済みIDと寸法を返す。
失敗時は部分成果を保持し、現在のSceneへ戻って修正できる。
制作途中に重要な確認が必要になった場合は、現在のSceneを明示保存して回答を待つ。保存済みの件数を表示し、回答後も件数・使用量・Revertの控えを引き継ぐ。「この依頼を終了」で追加の制作を止め、保存済みの結果を保持する。
「履歴ツリー」の完了した応答から「ここから分岐」で別案のチャットを選択する。Sceneを復元しないことを操作前に表示する。

Studioはワールド内に制作目標を保存する。再接続後も、MCPの`get_world_authoring`で設計図、画像、未確認の条件、次の操作を取得できる。完了確認には最新の両画像と、各条件の合格が必要になる。編集したら画像を確認し直す。Scriptの実行に追加承認は求めず、ログインと公開の判断は共通ガイドに従う。外部のNode.jsランナーやリポジトリのクローンは不要。

### 操作前

- MCP接続パネルでは、対応するAIクライアントをXRift Studio MCPへワンクリックで登録できることを説明する。会話から現在のシーンを読み取り・編集でき、AIの変更も通常の「元に戻す」と自動保存の対象になる。登録前にこれらの説明を読める位置へ置く。
- MCP接続パネルに、Codex、Claude Code、Claude Desktop / Cowork、OpenCode、Cursorの検出結果、登録範囲、XRift Studio MCPサーバーの状態を表示する。Codexは現在の`PATH`に加え、公式インストーラー、Codexアプリに付属するCLI、npm、pnpm、WinGet、Homebrew、単体インストーラーの標準配置から検出する。起動時の環境変数が古くても、再起動せずに検出できる。ネイティブAPIを利用できないブラウザでは「デスクトップ版で利用できます」と示し、登録済みと表示しない。Claude Desktop / Coworkはローカルセッションだけを対象にする。リモートのCoworkではローカルMCPを起動できないことを登録前に示す。
- MCPの接続対象は、現在開いているビジュアルプロジェクトだけにする。接続したクライアントへプロジェクトID、シーンID、セッションのリビジョンを返す。接続だけでSceneDocument、AssetManifest、選択、履歴を変更しない。
- AIの書き込みは、認可済みプロジェクトの編集と、Play中の差分同期に対応したツールだけに許可する。読み込み中、プロジェクトの切り替え中、Play中に使えない操作では、理由を示して読み取り専用にする。公開を依頼された場合は`publish_project`を使う。プロジェクトの削除、形式を限定しない任意のファイル読み書き、任意のシェル操作は提供しない。素材削除は参照を検査する専用ツールに限る。
- ローカルの音声・テクスチャ・3Dモデル・Skybox・シェーダーは、専用の取り込み操作で追加できる。対応形式、通常ファイルであること、symlinkやreparse pointを含まないこと、容量上限、シグネチャまたはUTF-8を検査する。取り込みはプロジェクトの管理領域へのコピーに限る。Entityの削除は、シーン構造を変更して保存する操作として扱う。

### 操作中

- CodexとClaude Codeの登録では、検出した実行ファイルを直接起動する。クライアントごとに固定した`mcp add`の引数だけを渡す。Claude Desktop / CoworkとCursorは既存設定をバックアップし、`mcpServers.xrift-studio`だけを追加・更新する。OpenCodeも既存設定をバックアップし、`mcp.xrift-studio`へ公式のローカルサーバー形式で追加する。登録するMCPサーバーは、内容のハッシュを付けてアプリのデータ領域へコピーする。Cargoの開発出力をクライアントから直接起動しない。シェル文字列の連結、任意のコマンド実行、プロジェクト文書へのトークン保存は行わない。
- MCPの書き込みでは、入力のプロジェクトID、シーンID、expected revisionを現在のセッションと照合する。副作用のないEditorツールで全入力を検証してから、1件の履歴へ確定する。
- `update_scene_settings`はSkybox、Fog、Ambient Light、Camera、Editorの背景、grid・gizmo・snapの設定を部分更新する。Skyboxの画像は、プロジェクト内に元データがあるテクスチャだけを受け付ける。Play中もシーン設定を共有シーンへ即時反映する。
- `import_audio_asset` / `import_texture_asset` / `import_model_asset` / `import_skybox_asset` / `import_shader_asset`はEdit中だけ使える。検証済みのローカル素材をプロジェクトの管理領域へ追加する。読み取り結果は、管理下のメタデータに限る。外部パスや不要なバイナリを含めない。
- `get_model_asset` / `update_model_asset`、`reimport_model_asset`、`get_shader_asset` / `update_shader_asset`では、既存素材の編集用元データと派生メタデータを同じリビジョン単位で扱う。`create_prefab`はEntityの階層を、再利用できるプレハブ素材と文書として保存する。`set_project_thumbnail`は既存テクスチャから保存用サムネイルを更新する。
- 音声素材の`place_asset`は音源Entityを作る。`core.audio-source`の追加・更新・削除は既存Entityへ保存する。`update_texture_asset`はPlay中も既存テクスチャの設定を保存する。ComponentとEntityの変更は影響するEntityだけを再同期する。マテリアル・テクスチャ・パーティクルの変更は、参照するEntityだけを実行環境へ再同期する。
- 同じMCPブローカーへの書き込みは順に処理する。複数のAIクライアントが同時に操作し、要求の待機が短いqueue timeoutを超えた場合は`EDITOR_BUSY`で終了する。最新の状態を再取得して再試行するよう案内する。Editorの準備状態は定期的なheartbeatで更新し、WebViewの再読み込みや異常終了後に自動失効させる。接続数、最初のメッセージの読み込み時間、メッセージのサイズも制限する。停止したクライアントが他のクライアントを長時間待たせないようにする。成功結果には変更前後のリビジョン、対象のEntityと素材、Commandの概要、自動保存の状態を含める。

### 成功時

- MCP接続を開くたびにクライアントを再検出し、登録済みで更新が必要なサーバーだけを、現在のアプリに同梱された内容のハッシュが付いた版へ自動更新する。検出から更新まで同時実行を共有し、設定の開閉や再表示で登録を重複させない。未登録のクライアントと明示的に無効にした接続は自動登録・有効化しない。既存の他のサーバー、XRift項目の環境変数やタイムアウトも保つ。自動更新に失敗した場合は原因と手動の「更新」を残す。登録先の更新と実行中の接続は区別し、成功後もAIクライアントの再起動またはMCPの再読み込みが必要なことを表示する。接続後はクライアント名、対象のプロジェクトとシーン、最後の操作を表示する。
- シーン設定の変更は、全セクションをまとめて1件の更新として扱う。シーンとシーン設定パネルへ同期し、Play中のMCP変更も保存してStop後に残す。素材の配置では新しいEntityを作り、Hierarchy、シーン、Inspectorで同じEntityを選択する。設定変更と素材配置のどちらも、通常の「元に戻す」「やり直す」と自動保存を使う。
- AIの変更後は、対象のEntity、シーン設定、追加・更新した音声やテクスチャへ移動できるようにする。パネルから通常の「元に戻す」も実行できる。結果をトーストだけで済ませない。

### 失敗時

- クライアント未検出、登録コマンドの失敗、サーバー未起動、Editor未接続、未認可プロジェクト、シーン不一致では、文書と履歴を変更しない。リビジョンの不一致、Editorの処理中、読み込み中、Play中に使えない操作、入力検証の失敗も同じ扱いにする。
- 失敗時は、クライアントの再検出、登録の再試行、Editorへ戻る操作、最新状態の再取得のいずれかを案内する。テクスチャの取り込み元を含む絶対パス、接続トークン、コマンド出力の原文を画面へ表示しない。

### 戻り先

- パネルを閉じても、同じEditor、シーン、シーンと素材の選択、接続状態、直近の操作を維持する。別のプロジェクトを開いた場合は、前のプロジェクトへの書き込み認可を引き継がない。新しい状態を取得するまで変更を拒否する。
- AIの変更は通常の「元に戻す」で取り消す。同じCommand履歴からシーン、素材、両方の選択を復元する。登録解除ではクライアントの設定だけを外し、プロジェクト文書とEditorの履歴を変更しない。

### Editor内のChatGPTワールド生成

参照: MI-126。入力欄で`/goal 目標`を送ると、同じ依頼の中で制作と見直しを続ける。入力中は継続制作になることを示し、空の目標は送信しない。実行中はGoal・見直し回数・進捗・保存件数と停止操作を表示する。変更の保存後も最新Sceneを確認し、必要な改善がなくなったら完了する。判断が必要な質問は回答を待ち、回答後もGoalを続ける。停止とエラーでは保存済みの成果を残し、後のQueueも保留する。固定の継続回数や制作時間の上限は設けず、Piが完成条件を確認する。Sceneを離れた場合やStudioの再起動後には自動で再開しない。

最初のPlanで制作範囲・細かさ・焦点・完了条件・1〜6回の上限を決め、同じ依頼の中では保持する。家1軒では主役の構造、街全体では区画・道・大きさ・配置と素材の再利用を重視する。通常送信でも環境やワールド全体の制作は、保存と必要な継続を上限の中で進める。個々の背景素材への細かな画像修正を繰り返さず、最後に全体を2方向から描画して確認する。未完了なら具体的な項目だけを次の計画へ渡し、条件を満たしたら完了する。上限に達した場合は残りの項目を表示して停止し、完了済みとは表示しない。質問待ちでは継続せず、回答後も上限をリセットしない。

会話と送信待ちを同じスクロール領域に置く。会話の高さを確保し、短いウィンドウではチャット全体もスクロールできるようにする。確認待ちや送信待ちが重なっても、Planの反映・破棄、入力、停止、Queueの再開へ到達できる状態を保つ。Goalには未確定の達成率を表示せず、見直し回数と実際に保存した件数を示す。

公式XRift Componentは既存の定義から設定項目をAIへ渡し、通常の追加・更新処理で保存する。Entityの削除は配下の件数と対象名を変更内容に表示し、手動編集との競合を検査する。削除も「変更を戻す」の対象にする。

参照: MI-128, MI-129。全体一括の依頼では全体へ使う候補を一度だけ確認し、1回の保存でScene内の有効なMesh Rendererの全スロットへ適用する。Entityごとの選択を要求せず、32件を超えても依頼を分割しない。形状・配置・元の共有Materialを保ち、依頼単位で取り消せる。Materialの比較依頼では6〜12候補を対象の用途・色・照明に合う順で表示する。Entityの単体・明示した一部・依頼された全体を区別し、複数対象は別々の候補を選べる。回答までは変更せず、Entityへの割り当てでは元の共有Materialを保持する。AssetsのMaterial自体を編集する依頼は参照先にも反映されることを説明する。範囲が不明なら対象の公開名で確認する。

参照: MI-03, MI-05, MI-09。重要な希望・対象を確認する必要がある場合は、文章だけなら各3択、素材なら最大12候補と「その他（自由入力）」を最大3ページで表示する。Skyboxは十分な素材がある場合6〜12候補を依頼とSceneに合う順に並べる。前後のページへ戻っても回答を保持し、最後の「回答して進める」で送信する。回答がそろうまではSceneを変更せず、未回答での変更の反映も拒否する。回答中にSceneや作品を移った場合は元の対象でのみ再開できる。回答後は同じ依頼・モデル・添付を引き継いで編集を進める。MCP/APIで反映前の確認を指定した依頼は、回答後も確認待ちにする。回答は会話とコピー可能な作業履歴へ残す。

参照: MI-119, MI-120。Enterは送信、Shift+Enterは改行とし、IME変換の確定では送信しない。受け付けた依頼は入力欄から消し、処理中も次の入力を受け付ける。送信できない依頼は理由とともにQueueへ保持し、送信順と各依頼のモデル・思考量・添付・制作方法を保つ。チャットからの依頼は直接編集に統一し、以前のPlan設定が残る送信待ちも送信時にはbuildで実行する。未接続時にQueueが増えても、接続操作へ到達できる高さを確保する。

Queueは現在の作品・Scene・チャットに限って使い、送信直前に最新Sceneを読む。質問への回答や変更内容の確認待ちは次の送信を待ち、停止・失敗・変更の破棄ではQueueも保留する。「再開」「再試行」と依頼ごとの取り消しを表示する。チャットを閉じてもQueueと下書きを保ち、作品・Scene・チャットを移った場合は元の対象へ戻って明示的に再開する。Studioを終了すると未送信Queueは消える。

「制作方法」は「AIにおまかせ」「素材ストア中心」「Blenderで制作」から選ぶ。自動では既存のAssets、外部素材、コード、UIKit、Blenderを用途に合わせて組み合わせる。Blenderが未導入・確認中でも自動で制作できる。「素材ストア中心」はAssetsと素材ストアを使い、静的な形状のコード組み立てとBlenderでの制作を行わない。Blenderの状態と再確認操作を表示し、コード制作を妨げない。R3Fの原本を保存し、手動編集を保って同じEntityを更新する。複製・受け渡し後の原本もコピー先へ対応させる。制作後は実Sceneを2方向から有限回で見直す。Blenderの独立したモデルは最大2件並行で制作し、完成順に実GLBの取り込み・配置・保存へ進める。同じ対象への連続操作とほかの操作との順番を保つ。保存済みの結果はHierarchy・Inspectorから編集できる。計画の公開説明を受信した段階で「制作予定」と表示し、未検証の計画を反映済みと扱わない。内部の推論内容や形状JSONは表示しない。

モデルの制作では、対応するモデルの思考量を「高（じっくり）」に初期設定する。利用者が選んだ値と「モデルの既定」は保持する。形状には安定したパーツIDを付け、輪郭の押し出しと部品の繰り返しも使える。初回の依頼、今回の依頼、制作指示、形状の原本はGLBと同じ処理で保存する。続きの依頼では現在の原本から対象部分を修正し、各版のAssetを残す。Hierarchyの書き出しと追加でも原本とモデルの対応を保つ。

モデル単体の制作では、反映・保存後にStudioの実際の描画を3方向から取得し、依頼と形状を照合する。「実際の形を3方向から確認」「輪郭・寸法・構造・材質を見直し」「修正して保存」を実際の工程に合わせて表示する。画像の確認は最大3回、修正は最大2回とし、修正した版も再確認する。環境やワールド全体では、上記の全体確認を使う。上限、同じ修正の繰り返し、取得や推論の失敗では理由と最後の保存結果を残して停止する。原本やGLBが一致しない場合も、古い形状で上書きしない。対象への手動編集を保ち、結果の確認と次の依頼へ戻れる状態を保つ。画像確認に成功したことを、実アカウントでの推論品質の評価と混同しない。

参照: MI-03, MI-05。下部ステータスバーのChatGPTから、Scene View・Scriptの隣に制作チャットのタブを開く。初期状態ではタブを表示せず、閉じる・切り替え・再表示でも入力と接続状態を保持する。Scene Viewの横、Inspectorの上に表示し、チャットのヘッダーにも「閉じる」を置く。タブとヘッダーの閉じる操作は同じ処理を使い、入力、会話履歴、実行中の制作を保持してScene Viewへ戻る。再び開くと変更内容と実行の結果を読める。制作チャットの入力欄下の「MCP接続」から外部クライアントを登録する。左下の歯車はシーン設定を開閉し、アプリのバージョン情報はプロジェクトライブラリの「設定」から確認する。ChatGPTのタブや選択は変えず、設定を閉じた後に制作を続けられる。MCPのタブは作らない。タブレット・スマートフォンでも同じ下部のChatGPT操作から開ける。

- 操作前: 未接続時は会話中央の接続カードに「ChatGPTに接続」を表示し、接続後はヘッダーのアカウントアイコンから詳細と解除へ進める。ChatGPTプランの利用許可、モデル、思考量、依頼入力、MCP接続、送信操作を表示し、送信した内容で編集を進める。思考量はモデルの対応情報から候補を作り、「モデルの既定」なら明示指定を送らない。モデル変更で非対応になる選択は既定へ戻し、情報がないモデルにも対応値を推測して付けない。外部素材は3Dモデル・マテリアル・音声を必要に応じて使い、種類ごとのチェックボックスは表示しない。Node.jsや外部CLIの準備は求めない。
- 処理中: ログインはブラウザでの完了を案内。接続中・復元中の状態と失敗・再接続を会話中央の同じ位置に示す。接続状態とエラーはネイティブ側に保持し、タブ切り替えで処理や入力を消さない。通常は変更内容の検証後に現在の作品とコードの下書きを保存し、現在のSceneでEntityを一つずつ調整・追加して保存する。推論中に手動編集が入った場合は、最新のSceneと素材から内容を考え直す。反映中は無関係なEntity・設定・Prefabへの編集を保持し、同じ対象が変わった場合だけ再計画する。保存済みの作業を会話へ渡し、未完了の作業だけを続ける。自動再計画は同じ依頼で最大2回とし、チャットに状況を表示する。MCP/APIからmode=planを指定した場合はSceneとファイルを変更せず「変更を反映」か「変更を破棄」を待つ。確認済みの対象が変わっていた場合は、新しい変更内容を表示して再確認を待つ。モデルと思考量は維持する。チャットには実行中の工程、保存済みの累計件数、直近の結果を残し、Scene ViewとInspectorで結果のEntityを確認できる。二重実行を拒否し、Playと素材読み込み中は生成できない。停止操作は現在の工程を安全に終えてから止まり、保存済みの変更を残す。
- 成功: 現在のワールドに文書と素材が保存され、変更内容と結果をチャットで確認できる。Scene View、Hierarchy、Inspectorから通常の編集へ進み、Playで動作を確認する。
- 失敗: チャットと通知に工程と理由を残す。認証・推論・変更内容の検証の失敗では現在作品を変更しない。途中の失敗では配置済みのEntityと取り込んだ素材を保持し、確認先と再試行を案内する。手動編集が続いて再計画の上限に達した場合は、変更を保持して停止し、編集が落ち着いたら次の依頼で最新のSceneから再開できることを案内する。
- 戻り先: 制作中に作品やSceneが切り替わった場合は適用を停止。接続解除はリフレッシュトークンを失効させてStudioとOSの保存先から接続を消し、作品は保持する。遠隔の解除に失敗してもローカルの接続は消し、確認先を表示する。更新用の接続情報はOSの安全な保存先に保管し、起動時に復元する。復元中は実際の送信を保留し、期限切れなどの失敗は再接続を案内する。
- MCP: 接続開始と生成開始は直ちに返す。接続状態はget_chatgpt_connection、Planと工程・進行件数・結果はget_chatgpt_generationで確認する。list_chatgpt_modelsは対応する思考量と既定値の情報も返す。generate_chatgpt_worldは既定で現在のSceneへ反映し、MCP/APIからmode=planを指定すると反映前のPlanだけを作る。Studioチャットには制作モードの切り替えを置かない。reasoningEffortは選択モデルの対応値を任意指定し、省略時はAPI既定を保つ。apply_chatgpt_planは最新のprojectId・sceneId・revisionを要求する。cancel_chatgpt_generationはPlanの破棄と制作の停止に使う。target=newを指定した場合だけ元の下書きを保存して別のワールドを作る。開始済みを完了と扱わない。

制作チャットは現在の素材と内蔵カタログを先に使い、外部素材が必要な場合だけPoly Haven・ambientCG・AI LOWPOLY PROPS・音蔵の対応する種類を検索する。既存Entityの名前・配置を保ったモデル追加・差し替え、Material・Skybox・Audio Source・Colliderの設定に対応する。処理中は実際の取り込み・反映・保存を表示し、失敗時も保存済みの結果を残す。

参照: MI-03, MI-05, MI-09。チャット上部に履歴選択と新規チャットを置き、詳細操作に名前変更・全文コピー・履歴削除をまとめる。制作中は会話の切り替えと削除を無効にする。履歴削除はSceneを変更しない。履歴は端末に保存し、再起動時に失われた確認待ちや実行中処理を再開済みと表示しない。保存できない場合はエラーとコピーの案内を出す。

ヘッダーの「出力をコピー」は制作中も使える。会話、変更項目と作業記録、エラー、案内、操作名をまとめてコピーし、未送信の入力とアカウント情報は含めない。成功・失敗は出力欄の外に表示する。失敗時も文字を選択してコピーできる。出力欄のCtrl+A / Command+Aは出力の文字を選択し、Entityの選択や他のScene操作を実行しない。タッチ操作でも出力と操作名の文字選択を許可する。

参照: MI-03, MI-05, MI-09。Hierarchyの複数選択を保ったままEntityをチャットへドロップし、入力欄の上に添付名と解除操作を表示する。互換用のドラッグJSONは入力本文へ挿入しない。添付の根と配下を送信直前のSceneから優先して要約し、親子関係をモデルへ渡す。送信量の上限は維持し、大きな階層が一部の参照になることを示す。添付はチャットごとの下書き、Queueの依頼、送信後の会話に対応付ける。送信後は入力欄の添付を空にし、Queueと会話には対象名を残す。削除された添付は送信前に理由を示して保留し、別の対象へ自動で置き換えない。「続ける」は表示せず、次の依頼は入力欄から送る。取り消せる保存済みの変更には保存件数の横に「この依頼の変更を戻す」を表示する。依頼内の変更をまとめて戻す操作であり、個別行の取り消しに見せない。

チャットには今回の変更と残りの作業を表示する。次の依頼は手動編集を含む現在のSceneと会話を引き継ぎ、完了済みの作業を重ねない。過去の会話と未実行のPlanをSceneの正本として扱わない。内部の件数制限やJSON修正を利用者へ要求しない。「この依頼の変更を戻す」は実行時の控えがある場合だけ表示し、手動編集など後の変更を上書きする場合は停止する。成功後は保存結果、失敗後は理由を残す。控えは起動中のみ有効で、再起動後は戻すボタンを表示しない。戻した後は保存件数と結果行を取り消し済みの表示へ切り替える。

参照: MI-03, MI-05, MI-125。接続済みで入力欄が空のとき、入力欄に候補を1件だけ表示する。会話の末尾に3択や長い操作説明は置かない。直前の完了結果と現在添付中のEntity・Materialから端末上で候補を作り、追加の推論API通信は行わない。処理中、送信待ちあり、未接続、質問や変更内容の確認待ち、失敗・停止・取り消し後は表示しない。

候補を表示してもフォーカスを動かさない。空の入力欄で修飾キーなしのTabを押すと、1件の依頼文と対象の添付IDを入力する。挿入だけでは送信せず、利用者が文面や添付を編集し、Enterで通常の送信を行う。候補横の閉じるボタンか入力欄のEscapeで候補を閉じ、入力欄へフォーカスを戻す。同じ結果・添付のままなら閉じた状態を保持する。↑・↓、Shift+Tab、IME変換中、入力途中は通常の操作を保つ。最大3ページの質問フォームは独立して扱い、質問中はTabで項目へ移動し、Spaceで回答を選ぶ既存の操作を維持する。

参照: MI-124。制作チャット上部の「Sceneを広く」「チャットを広く」で表示を即時に切り替える。チャットを広くするとScene Viewを小さくし、右側のチャットを画面の高さまで広げる。HierarchyとInspectorは隠す。Scene・チャット・Inspectorは再マウントせず、入力、添付、会話、選択、制作中の処理を保持する。元の表示へ戻すとInspectorと調整済みのパネル幅を復元する。閉じて開き直しても同じ表示を使い、レイアウトのリセットではSceneを広くする。スマートフォン幅は既存の全面表示を使う。

- 操作前: HierarchyとScene ViewのEntityメニューに「チャットに送る」を表示する。モデル内の参照ノードを除き、「AIで作り替える…」も表示する。Textや空のEntityも対象にする。複数選択・Play・取り込み中などの無効状態には理由を示す。

## F-35 ビジュアル編集 QA診断と短時間録画の状態設計

制作チャットのBlender途中画像はF-17、MI-03・MI-05・MI-09に従う。対象の制作依頼だけに実際の形状の撮影画像を追加し、直近4枚とパーツ数・撮影時刻を表示する。最初と最後、長い制作では約10秒経過後のパーツ完成時に更新する。停止後や別の依頼に遅れて届いた画像は反映しない。画像は会話の保存対象にせず、撮影の失敗時はモデル制作を継続して状態を案内する。

参照: MI-03, MI-05, MI-14, MI-26, MI-80

### 操作前

- シーンのツールバーに「診断」を置き、EditとPlayの両方で使えるようにする。Play中は実行中のレンダラーを測る。短い診断動画はMCPの要求で取得する。
- 「診断」はオン・オフを切り替える操作にする。オンの間だけ右上へ計測パネルを重ねる。パネルはpointer eventsを受けず、その下にあるシーンの操作を妨げない。
- パネルにFPS、フレーム時間、draw calls、triangles、可視メッシュ数、総メッシュ数、geometry数、texture数、カメラ位置、Far（描画する最長距離）の値を表示する。計測中の`LIVE`と録画中の`REC`は同じ位置に出す。
- 形状とテクスチャのVRAM概算、合計値をMiBで表示する。実シーンが参照する頂点・インデックス・インスタンス属性、Material/Uniform、背景・環境テクスチャを集計し、同じ参照の重複を除く。テクスチャは実際の形式とmipmapを考慮する。未読み込みや非対応形式は算定できなかった件数として示し、ゼロと断定しない。影、描画バッファ、内部で生成する領域は対象外と明記する。最初の計測後に値を表示し、診断を閉じたら計測を止める。MCPの`capture_scene_debug`にも同じ値を返す。
- テクスチャのVRAMは、GPU圧縮済みと非圧縮を分けて算定済み件数とMiBを表示する。両方の容量の合計をテクスチャ全体の容量に一致させ、未算定の件数は別に数える。判定には実行中のテクスチャのGPU形式を使う。JPEG/WEBPやKTX2のRGBAへの代替読み込みを、GPU圧縮済みと表示しない。

### 操作中

- 0.5秒ごとにThree.jsレンダラーの実測値を取得して表示を更新する。Reactの状態から推定した値を表示しない。
- MCPが診断動画を要求したら、シーンのCanvasを最大15秒のWebMとして記録する。録画中であることと上限秒数を通知に表示する。
- 上限に達したら自動停止し、保存中の表示に切り替える。保存中は録画の開始も停止も受け付けない。
- 診断表示と録画では、SceneDocument、AssetManifest、「元に戻す」の履歴、コンパイル結果を変更しない。サムネイルを撮るときはパネルを隠し、画像へ写り込ませない。

### 成功時

- 停止または自動停止後、デスクトップ版では保存先を選んでWebMを保存する。保存したパスを通知に残す。ブラウザではファイルをダウンロードする。
- MCPへは計測結果、または保存したパスと録画時間を返す。計測処理はUIと共通にする。
- 保存後はシーンへ戻り、診断表示の状態を維持する。

### 失敗時

- WebViewがCanvas録画に対応していない場合、利用できるWebM形式がない場合、録画フレームが0件の場合は、それぞれの理由を通知する。録画状態を解除し、シーンは変更しない。
- 保存を取り消したら、そのことを表示する。保存に失敗した場合は理由を残し、診断表示と最後の計測値を維持する。
- 別の録画を保存中に要求が来た場合は、完了後の再試行を案内する。二重に保存を始めない。

### 戻り先

- もう一度「診断」を押すと表示を閉じる。録画の成否にかかわらずシーンとPlayの状態を保ち、選択とカメラを維持する。

完了条件: EditとPlayで、実行中のレンダラーのFPS、フレーム時間、draw calls、triangles、可視メッシュ数、カメラのFarを確認できる。最大15秒のWebMを保存し、問題の発生前後を確認できる。診断と録画はSceneDocument、AssetManifest、「元に戻す」の履歴を変更しない。停止、保存失敗、WebM非対応の後も同じシーンへ戻れる。

## F-42 ワールド制作の録画の状態設計

参照: MI-03, MI-05, MI-09, MI-122

### 操作前

- シーン右上の「録画」からパネルを開く。状態、フレームのアスペクト比・短辺・fps・画素数、録画ビューの設定、録画用カメラ、保存先を1画面にまとめる。開始前に、保存される内容と大きさを確認できるようにする。
- 「録画ビューを表示」で投稿先の比率に合うフレームを先に表示する。編集画面の比率で撮ってから切り抜く手順にはしない。
- 録画用カメラは「全体」「斜め」「正面」「真上」から選び、フレーム内をドラッグして調整する。MCPの`set_recording_camera`でも同じ姿勢を設定できる。
- 保存済みワールドでは保存先に`<ワールド>/Recording`を表示し、動画とJSONを置く。外部フォルダーを選ぶ操作は出さない。未保存のプレビューでは従来の既定先とフォルダーダイアログを使う。AIは保存先のパスを指定できない。

### 処理中

- 「録画を開始」を押すと録画ビューを表示し、ボタンを「録画を停止」へ変える。開始中と停止中はボタンを無効にし、二重操作を防ぐ（MI-03）。
- フレーム左上とシーンヘッダーに`REC`と経過時間を表示する。パネルには経過時間と書き込んだ容量を出す。RECの表示は動画に含めない。
- プロジェクトの再読み込みや別タブへの移動でシーンが表示されなくなったら、「シーンが表示されていません」と示す。録画は最後のフレームで続ける。
- プロファイルは録画中も変更できる。「次の録画から反映されます」と表示する。
- MCPから始めた録画は「<client名>が録画を開始しました」と通知し、利用者が開始を確認できるようにする。

### 成功時

- 停止後もパネルに「保存済み」、録画時間、容量、パスを残す。「フォルダーを開く」で保存先へ移動できるようにする（MI-05）。トーストにもパスを表示する。
- 動画の隣に付属のJSONファイルを保存する。プロジェクト、シーン、クライアント、構図を記録し、後から録画内容を確認できるようにする。
- MCPへはパス、録画時間、bytes、付属ファイルのパスを返す。

### 失敗時

- WebViewが録画に対応していない場合、ファイルを作れない場合、書き込みに失敗した場合は、「失敗」と理由を1文で表示する（MI-09）。途中で失敗した場合は部分ファイルのパスを残す。
- 失敗後も「録画を開始」から再試行できる。制作ツールやEditorの操作には影響させない。

### 戻り先

- シーンヘッダーかパネルの「編集表示へ戻る」で録画ビューを閉じ、退避した編集中のカメラへ戻る。録画は続ける。
- 停止後は録画ビューを開いたまま次の録画を始められる。閉じると普段のパネル配置へ戻る。

制作前の質問はTab / Shift+Tabで全候補を移動し、Spaceで選択する。ページ変更時は最初の候補へフォーカスし、自由入力と送信ボタンにも移動できる。フォーカス移動だけでは回答を変更・送信しない。Blenderモデルの置き換えでは対象EntityとMesh Rendererを示し、TransformとほかのComponentを保つ。

Scene設定の生成操作はSkybox・環境光・Fog・カメラ・画面効果・風・物理・編集表示を部分更新し、変更内容の設定項目に値を示す。未指定の設定を保ち、戻す操作を共用する。画面と本体の形式が不一致なら推論前に再起動・更新を案内し、送信待ちの依頼を保持する。

参照: MI-127。制作チャットの「作業の記録」は現在・過去の依頼とも折りたたまず表示する。現在の進行状況と同じ末尾の案内は表示を一つにまとめ、思考中の案内だけで記録がない間は空の見出しを出さない。保存イベントは記録とAPIに保持する。追従中は新しい記録へスクロールし、上へ読み戻したときは利用者の位置を保つ。素材の確認質問は候補名の下に実カタログ・Assetsのサムネイルを置き、横幅に応じたカード一覧にする。追加・割り当て予定と保存済みの会話にも作業説明の下へサムネイルを表示し、クリックとTab / Spaceで選べるようにする。未回答ではSceneを変更せず、選択した候補IDを回答へ引き継ぐ。プレビューを取得できない場合は代わりの風景を作らず状態を表示する。

作業の記録では「Scene設定を調整」のような分類名だけを繰り返さず、画面にある項目名と変更前後の値を示す。変更中は予定値、保存後は実際に反映した値で記録する。画像なしIBLの無効化やグリッドの自動調整なども、適用後のSceneと照合する。Entityの調整には名前・位置・回転・大きさのどれを変えたかを示す。変更内容の行名も変更する項目から作り、汎用のScene設定ラベルを出さない。「Plan：作品名」の見出しと折りたたみは使わず、設定は項目名・値・変更前の値を並べる。有効・無効と色は読み取り表示にし、JSON本文と重複表示しない。詳細を保存していない旧版の連続ログは保存件数付きの1項目へまとめ、現在のSceneの値から過去の変更を推測しない。

ChatGPTの枠を開くと、入力欄下に「MCP接続」を常時表示する。狭い画面でも入力欄の近くに置く。ChatGPTの接続状態や生成中の状態にかかわらず、既存のMCP設定を直接開ける。閉じる・Escapeで元のボタンへフォーカスを戻し、入力・会話・認証・実行中の作業を保持する。

MaterialもAssetsから制作チャットへ添付できる。Entityとは種類を区別した名前付きチップを表示し、複数選択・解除・チャット別下書き・Queueの依頼ごとの対象を保持する。Materialは最大16件、送信時に利用できるものだけ扱う。添付したMaterialの現在値を優先してモデルへ渡し、material-updateは既存MCPのupdate_material_assetを通す。設定カードと具体的な前後値を表示し、取り消しは依頼単位で共用する。添付だけではSceneやAssetを変更せず、消失した対象は他素材へ置き換えず保留する。

完了したMaterialの変更結果には「現在のMaterialを調整」を表示する。対象は結果に保持した正確なAsset IDで照合し、現在のpropertiesをBase Colorの色・HEXとRoughness・Metallicの数値・スライダーに表示する。同じMaterialへの最後の変更結果に一つだけ置く。色変更はAlphaを保ち、未指定のShaderやテクスチャも維持する。操作は通常のMaterial編集、描画、Undo、自動保存へ通し、保存状態は既存の表示で確認する。過去のログと設定値は書き換えない。対象がない場合と未完了・確認待ち・取り消し済みでは非表示にし、Play・インポートなど編集できない状態では無効にする。

Skybox・Fogを変更した完了結果には「現在のScene設定を調整」を表示する。公開結果の`sceneSettingsSections`で実際に扱った節を識別し、それぞれ最後の結果に一度だけ操作欄を置く。現在のSceneから有効・無効、色、明るさ、距離を読み、通常のシーン設定と同じ検証・描画・Undo・自動保存へ渡す。空の画像・Shaderは保ち、その素材で調整できる項目だけを出す。IBLには利用可能な画像を必要とし、Fogの終了距離は開始距離より大きくする。過去の設定値やログを現在値に書き換えない。未完了・確認待ち・取り消し済みは非表示、Play・読み込み中は無効にする。
