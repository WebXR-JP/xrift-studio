## F-17 AI エディター連携・MCP の状態設計

### 制作チャットの実行・履歴分岐

参照: MI-03, MI-05, MI-09

- 制作は 1 つの内部セッション（Pi）で直接進める。管理役のセッションや通常の実装・検証ごとの承認工程は設けず、重要な未決定事項だけを確認する。画面文言には Pi などの内部実装名を出さない。
- 制作中は応答途中の文章、再試行、会話の要約、実行中の正式ツールと制作・配置・保存の進行状況を表示する。内部思考は表示しない。「この依頼の実行情報」で実際のモデル応答・ツール実行とトークン使用量を確認でき、表示回数を制作の停止上限には使わない。
- 制作中は「今の制作に反映」（現在の応答・操作の直後に追加）と「終了後に実行」（現在の制作終了後に同じ会話で継続）を選べる。
  - 追加指示には添付を保持し、対象シーン・チャット・依頼をネイティブ側で照合する。
  - 受信確認後にだけ入力欄を空にし、送信エラーや送信中の追記はそのまま残す。未反映の追加指示は会話に残し、入力欄へ戻せる。
- 通常の応答が終わっただけの場合は「応答済み」と表示し、保存・画像確認・完成条件の検証完了とは区別する。検証の呼び出しがないだけで失敗扱いにせず、モデルやツールの実際のエラーだけを残す。
- 成功後は実際のシーンと作業記録を残し、モデル配置の結果には作成済み ID と寸法を返す。失敗時は部分成果を保持し、現在のシーンへ戻って修正できるようにする。
- 制作途中に重要な確認が必要になった場合は現在のシーンを明示的に保存して回答を待ち、保存済み件数を表示する。回答後も件数・使用量・取り消し用の控えを引き継ぐ。「この依頼を終了」で追加の制作を止め、保存済みの結果を残せる。
- 「履歴ツリー」の完了した応答から「ここから分岐」で別案のチャットを作成できる。シーン自体は復元しないことを操作前に明記する。
- Studio はワールド内に制作目標を保存する。再接続後も MCP の `get_world_authoring` で設計図・画像・未確認条件・次の操作を取得できる。完了確認には最新の両画像と各条件の合格が必要で、編集後は画像を確認し直す。スクリプト実行に追加承認は求めず、ログインと公開の判断は共通ガイドに従う。外部の Node.js ランナーやリポジトリのクローンは不要とする。

### 操作前

- MCP 接続パネルでは、対応する AI クライアントを XRift Studio MCP へワンクリック登録できること、会話から現在のシーンを読み取り・編集できること、AI の変更も通常の「元に戻す」と自動保存の対象になることを登録前に読める位置へ明記する。
- パネルには Codex、Claude Code、Claude Desktop / Cowork、OpenCode、Cursor の検出結果、登録範囲、XRift Studio MCP サーバーの状態を表示する。
  - Codex は現在の `PATH` に加え、公式インストーラー、Codex アプリ付属 CLI、npm、pnpm、WinGet、Homebrew、単体インストーラーの標準配置から検出し、環境変数が古くても再起動せずに認識する。
  - ネイティブ API を利用できないブラウザでは「デスクトップ版で利用できます」と表示し、登録済みと誤表示しない。
  - Claude Desktop / Cowork はローカルセッションのみを対象とし、リモートの Cowork ではローカル MCP を起動できないことを登録前に示す。
- MCP の接続対象は現在開いているビジュアルプロジェクトに限定し、接続クライアントへプロジェクト ID・シーン ID・セッションのリビジョンを返す。接続だけで `SceneDocument`、`AssetManifest`、選択状態、履歴は変更しない。
- AI の書き込みは認可済みプロジェクトの編集と Play 中の差分同期に対応したツールだけに許可する。読み込み中・プロジェクト切替中・Play 中に使えない操作は理由を示して読み取り専用にする。
  - 公開を依頼された場合は `publish_project` を使う。
  - プロジェクト削除、形式を限定しない任意ファイル読み書き、任意シェル操作は提供しない。素材削除は参照検査付きの専用ツールに限る。
- ローカルの音声・テクスチャ・3D モデル・Skybox・シェーダーは専用取り込み操作で追加できる。対応形式、通常ファイルであること、symlink や reparse point を含まないこと、容量上限、シグネチャまたは UTF-8 を検査し、プロジェクト管理領域へのコピーに限定する。Entity 削除はシーン構造を変更して保存する操作として扱う。

### 操作中

- クライアント登録は安全な固定手順に限定する。
  - Codex と Claude Code は検出した実行ファイルを直接起動し、クライアントごとに固定した `mcp add` 引数だけを渡す。
  - Claude Desktop / Cowork と Cursor は既存設定をバックアップしたうえで `mcpServers.xrift-studio` だけを追加・更新する。
  - OpenCode も既存設定をバックアップし、`mcp.xrift-studio` へ公式のローカルサーバー形式で追加する。
  - 登録する MCP サーバーは内容ハッシュを付けてアプリのデータ領域へコピーし、Cargo の開発出力は直接起動しない。シェル文字列連結、任意コマンド実行、プロジェクト文書へのトークン保存は行わない。
- MCP からの書き込みでは入力のプロジェクト ID、シーン ID、`expectedRevision` を現在セッションと照合し、副作用のないエディターツールで全入力を検証してから 1 件の履歴として確定する。
- 主なツール境界は次のとおりとする。
  - `update_scene_settings`: Skybox、Fog、Ambient Light、Camera、エディター背景、grid・gizmo・snap の設定を部分更新する。Skybox 画像はプロジェクト内に元データがあるテクスチャだけを受け付け、Play 中も共有シーンへ即時反映する。
  - `import_audio_asset` / `import_texture_asset` / `import_model_asset` / `import_skybox_asset` / `import_shader_asset`: Edit 中だけ使用でき、検証済みのローカル素材をプロジェクト管理領域へ追加する。読み取り結果は管理下のメタデータに限り、外部パスや不要なバイナリを含めない。
  - `get_model_asset` / `update_model_asset`、`reimport_model_asset`、`get_shader_asset` / `update_shader_asset`: 既存素材の編集用元データと派生メタデータを同じリビジョン単位で扱う。
  - `create_prefab`: Entity 階層を再利用可能なプレハブ素材と文書として保存する。`set_project_thumbnail`: 既存テクスチャから保存用サムネイルを更新する。
  - 音声素材の `place_asset` は音源 Entity を作成し、`core.audio-source` の追加・更新・削除は既存 Entity へ保存する。`update_texture_asset` は Play 中も既存テクスチャの設定を保存する。Component・Entity の変更は影響する Entity だけ、マテリアル・テクスチャ・パーティクルの変更は参照する Entity だけを実行環境へ再同期する。
- 同じ MCP ブローカーへの書き込みは順に処理する。複数クライアントの同時操作で短いキューのタイムアウトを超えた場合は `EDITOR_BUSY` で終了し、最新状態の再取得と再試行を案内する。
  - エディターの準備状態は定期的なハートビートで更新し、WebView の再読み込みや異常終了後は自動失効させる。接続数・初回メッセージ読み込み時間・メッセージサイズも制限し、停止したクライアントが他クライアントを長時間待たせないようにする。
  - 成功結果には変更前後のリビジョン、対象 Entity・素材、コマンド概要、自動保存状態を含める。

### 成功時

- MCP 接続を開くたびにクライアントを再検出し、登録済みで更新が必要なサーバーだけを、現在のアプリに同梱された内容ハッシュ付き版へ自動更新する。
  - 検出から更新までの同時実行を共有し、設定の開閉や再表示で登録を重複させない。
  - 未登録クライアントや明示的に無効化した接続は自動登録・有効化しない。既存の他サーバー設定、XRift 項目の環境変数やタイムアウトも維持する。
  - 自動更新に失敗した場合は原因と手動の「更新」操作を残す。登録先の更新と実行中の接続を区別し、成功後も AI クライアントの再起動または MCP 再読み込みが必要であることを示す。
- 接続後はクライアント名、対象プロジェクトとシーン、最後の操作を表示する。
- シーン設定変更は全セクションを 1 件の更新としてまとめ、シーンとシーン設定パネルへ同期し、Play 中の変更も保存して Stop 後に残す。素材配置では新しい Entity を作り、Hierarchy・シーン・Inspector で同じ Entity を選択する。いずれも通常の「元に戻す」「やり直す」と自動保存を使う。
- AI の変更後は、対象 Entity、シーン設定、追加・更新した音声やテクスチャへすぐ移動できるようにし、パネルからも通常の「元に戻す」を実行できるようにする。トースト通知だけで終わらせない。

### 失敗時

- クライアント未検出、登録コマンド失敗、サーバー未起動、エディター未接続、未認可プロジェクト、シーン不一致、リビジョン不一致、処理中・読み込み中、Play 中に実行不可の操作、入力検証失敗では、文書と履歴を変更しない。
- 失敗時はクライアント再検出、登録再試行、エディターへ戻る操作、最新状態の再取得のいずれかを案内する。テクスチャ取り込み元を含む絶対パス、接続トークン、コマンド出力の原文は画面に表示しない。

### 戻り先

- パネルを閉じても、エディター・シーン・選択状態・接続状態・直近の操作を維持する。別プロジェクトを開いた場合は前プロジェクトへの書き込み認可を引き継がず、最新状態を取得するまで変更を拒否する。
- AI の変更は通常の「元に戻す」で取り消し、同じコマンド履歴からシーン・素材・両選択状態を復元する。登録解除ではクライアント側の設定だけを外し、プロジェクト文書とエディター履歴は変更しない。

### エディター内の ChatGPT ワールド生成

#### 継続制作（`/goal`）とプラン・確認

- 参照: MI-126。入力欄で `/goal 目標` を送信すると、同じ依頼の中で制作と見直しを継続する。入力中は継続制作になることを示し、空の目標は送信しない。
  - 実行中はゴール・見直し回数・進捗・保存件数と停止操作を表示する。未確定の達成率は表示せず、見直し回数と実際の保存件数を示す。
  - 変更保存後も最新シーンを確認し、必要な改善がなくなったら完了とする。判断が必要な質問は回答を待ち、回答後もゴールを継続する。停止やエラー時は保存済み成果を残し、後続の送信待ちキューも保留する。固定の継続回数や時間上限は設けず、内部セッションが完成条件を確認する。シーン移動や Studio 再起動後は自動で再開しない。
- 最初のプランで制作範囲・細かさ・焦点・完了条件・1〜6 回の上限を決め、同じ依頼の中で維持する。家 1 軒なら主役の構造、街全体なら区画・道・大きさ・配置と素材再利用を重視する。
  - 通常送信でも環境やワールド全体の制作は上限内で保存と継続を進める。個々の背景素材への細かな画像修正を繰り返さず、最後に全体を 2 方向から描画して確認する。
  - 未完了なら具体的な残項目だけを次の計画へ渡し、条件を満たせば完了する。上限到達時は残項目を表示して停止し、完了済みとは表示しない。質問待ちでは継続せず、回答後も上限はリセットしない。
- 会話と送信待ちキューを同じスクロール領域に置き、会話の高さを確保しつつ短いウィンドウではチャット全体もスクロールできるようにする。確認待ちや送信待ちが重なっても、プランの反映・破棄、入力、停止、キュー再開を操作できる状態を維持する。
- 公式 XRift Component は既存定義から設定項目を AI へ渡し、通常の追加・更新処理で保存する。Entity 削除では配下件数と対象名を変更内容に表示し、手動編集との競合を検査したうえで「変更を戻す」の対象に含める。

#### マテリアル比較・確認質問・キュー・制作方法

- 参照: MI-128, MI-129。全体一括の依頼では全体へ使う候補を一度だけ確認し、1 回の保存でシーン内の有効な `Mesh Renderer` の全スロットへ適用する。Entity ごとの選択は要求せず、32 件を超えても依頼を分割しない。形状・配置・元の共有マテリアルはそのまま残し、依頼単位で取り消せる。
  - マテリアル比較依頼では 6〜12 候補を対象の用途・色・照明に合う順で提示する。単体・明示した一部・依頼された全体を区別し、複数対象では別々の候補を選べる。回答までは変更せず、Entity への割り当てでは元の共有マテリアルを維持する。Assets のマテリアル自体を編集する場合は参照先にも反映される旨を説明し、範囲が不明なら対象の公開名で確認する。
- 参照: MI-03, MI-05, MI-09。重要な希望や対象を確認する必要がある場合は、文章のみなら各 3 択、素材なら最大 12 候補と「その他（自由入力）」を最大 3 ページで表示する。Skybox は十分な素材がある場合 6〜12 候補を依頼とシーンに合う順に並べる。
  - 前後ページへ移動しても回答を保持し、最後の「回答して進める」で送信する。回答がそろうまでシーンを変更せず、未回答での反映も拒否する。回答中にシーンや作品を移動した場合は元の対象でのみ再開できる。
  - 回答後は同じ依頼・モデル・添付を引き継いで編集を進め、MCP / API で反映前確認を指定した依頼は回答後も確認待ちとする。回答は会話とコピー可能な作業履歴に残す。
- 参照: MI-119, MI-120。Enter で送信、Shift+Enter で改行し、IME 変換の確定では送信しない。受け付けた依頼は入力欄から消し、処理中も次の入力を受け付ける。
  - 送信できない依頼は理由とともに送信待ちキューへ保持し、送信順と各依頼のモデル・思考量・添付・制作方法を維持する。チャットからの依頼は直接編集（build）に統一し、以前のプラン設定が残る送信待ちも送信時は build で実行する。未接続時にキューが増えても、接続操作が見える高さを確保する。
  - キューは現在の作品・シーン・チャットに限定し、送信直前に最新シーンを読み込む。質問回答や変更確認の待ち状態では次の送信を待機し、停止・失敗・変更破棄ではキューも保留する。「再開」「再試行」と依頼ごとの取消を表示する。チャットを閉じてもキューと下書きを保持し、作品・シーン・チャットを移った場合は元の対象へ戻って明示的に再開する。Studio 終了時に未送信キューは破棄する。
- 「制作方法」は「AIにおまかせ」「素材ストア中心」「Blenderで制作」から選べる。
  - 「AIにおまかせ」では既存 Assets、外部素材、コード、UIKit、Blender を用途に合わせて組み合わせ、Blender が未導入・確認中でも自動で制作できる。
  - 「素材ストア中心」は Assets と素材ストアを使い、静的な形状のコード組み立てと Blender 制作を行わない。Blender の状態と再確認操作は表示し、コード制作を妨げない。
  - R3F の原本を保存し、手動編集を保ったまま同じ Entity を更新する。複製・受け渡し後の原本もコピー先へ対応させる。制作後は実際のシーンを 2 方向から有限回見直す。
  - Blender の独立モデルは最大 2 件並行で制作し、完成順に実 GLB の取り込み・配置・保存へ進める。同じ対象への連続操作と他操作の順序は維持し、保存済み結果は Hierarchy・Inspector から編集できる。計画の公開説明を受信した段階で「制作予定」と表示し、未検証の計画を反映済みと扱わない。内部推論や形状 JSON は表示しない。
- モデル単体制作では、対応モデルの思考量を初期値「高（じっくり）」とし、利用者が選んだ値と「モデルの既定」を保持する。形状には安定したパーツ ID を付け、輪郭の押し出しと部品の繰り返しも利用できる。初回依頼・今回依頼・制作指示・形状原本は GLB と同じ処理で保存し、続きの依頼では現在の原本から対象部分を修正して各版の Asset を残す。Hierarchy の書き出しと追加でも原本とモデルの対応を維持する。
- モデル単体制作の反映・保存後は、Studio の実際の描画を 3 方向から取得して依頼と形状を照合する。「実際の形を3方向から確認」「輪郭・寸法・構造・材質を見直し」「修正して保存」を実工程に合わせて表示する。画像確認は最大 3 回、修正は最大 2 回とし、修正版も再確認する。
  - 上限到達、同じ修正の繰り返し、取得・推論失敗時は理由と最後の保存結果を残して停止する。原本や GLB が一致しない場合も古い形状で上書きせず、対象への手動編集を保持する。画像確認の成功を、実アカウントでの推論品質評価と混同しない。

#### 画面配置・状態遷移・履歴・添付・補完候補

- 参照: MI-03, MI-05。下部ステータスバーの ChatGPT から、Scene View・Script の隣に制作チャットタブを開く。初期状態では非表示とし、閉じる・切替・再表示でも入力と接続状態を保持する。Scene View の横・Inspector の上に表示し、チャットヘッダーにも「閉じる」を配置する（タブとヘッダーの閉じる操作は共通処理）。
  - 制作チャット入力欄下の「MCP接続」から外部クライアントを登録する。左下の歯車はシーン設定を開閉し、バージョン情報はプロジェクトライブラリの「設定」で確認する。ChatGPT タブや選択は変えず、設定を閉じた後に制作を続けられる。MCP 専用タブは作らない。タブレット・スマートフォンも同じ下部の ChatGPT 操作から開ける。
- 参照: MI-124。制作チャット上部の「Sceneを広く」「チャットを広く」で表示を即時切り替えられる。「チャットを広く」では Scene View を小さくし、Hierarchy と Inspector を隠して右側チャットを画面の高さまで広げる。Scene・チャット・Inspector は再マウントせず、入力・添付・会話・選択・制作中処理を維持する。戻すと Inspector と調整済みパネル幅を復元し、閉じて開き直しても表示を維持する。レイアウトのリセットでは「Sceneを広く」へ戻し、スマートフォン幅では既存の全面表示を使う。
- **操作前**: 未接続時は会話中央の接続カードに「ChatGPTに接続」を表示し、接続後はヘッダーのアカウントアイコンから詳細と解除へ進める。ChatGPT プランの利用許可、モデル、思考量、依頼入力、MCP 接続、送信操作を表示する。思考量はモデルの対応情報から候補を生成し、「モデルの既定」では明示指定を送らない。モデル変更で非対応になる選択は既定へ戻し、情報がないモデルへ推測値を付けない。外部素材は 3D モデル・マテリアル・音声を必要に応じて使い、種類ごとのチェックボックスは出さない。Node.js や外部 CLI の準備は求めない。
- **処理中**: ログインはブラウザでの完了を案内し、接続中・復元中・失敗・再接続を会話中央の同じ位置に示す。接続状態とエラーはネイティブ側で保持し、タブ切替で消さない。
  - 通常は変更内容の検証後に現在作品とコード下書きを保存し、現在のシーンで Entity を 1 つずつ調整・追加して保存する。推論中に手動編集が入った場合は最新シーンと素材から考え直す。反映中は無関係な Entity・設定・プレハブへの編集を保持し、同じ対象が変わった場合だけ再計画する（同一依頼で最大 2 回、状況をチャット表示）。
  - MCP / API から `mode=plan` を指定した場合はシーンとファイルを変更せず「変更を反映」または「変更を破棄」を待つ。確認済み対象が変わっていれば新しい変更内容を表示して再確認を待つ。
  - チャットには実行中工程、保存済み累計件数、直近結果を表示し、Scene View と Inspector で確認できる。二重実行を拒否し、Play 中と素材読み込み中は生成不可とする。停止操作は現在工程を安全に終えてから止まり、保存済み変更を残す。
- **成功時**: 現在のワールドに文書と素材が保存され、変更内容と結果をチャットで確認できる。Scene View、Hierarchy、Inspector から通常編集へ進み、Play で確認できる。
- **失敗時**: チャットと通知に工程と理由を残す。認証・推論・変更内容検証の失敗では現在作品を変更しない。途中失敗では配置済み Entity と取り込み済み素材を保持し、確認先と再試行を案内する。手動編集が続いて再計画上限に達した場合は変更を保持して停止し、編集が落ち着いたら次の依頼で最新シーンから再開できる旨を案内する。
- **戻り先**: 制作中に作品やシーンが切り替わった場合は適用を停止する。接続解除時はリフレッシュトークンを失効させて Studio と OS の保存先から接続情報を消し、作品は保持する（遠隔解除に失敗してもローカル接続は消し、確認先を表示）。更新用接続情報は OS の安全な保存先に保管して起動時に復元し、復元中は送信を保留、期限切れ等の失敗時は再接続を案内する。
- **MCP インターフェース**: 接続開始と生成開始は直ちに返す。接続状態は `get_chatgpt_connection`、プランと工程・進行件数・結果は `get_chatgpt_generation` で確認し、`list_chatgpt_models` は対応する思考量と既定値も返す。`generate_chatgpt_world` は既定で現在シーンへ反映し、`mode=plan` 指定時のみ反映前プランを作る（Studio チャットには制作モード切替を置かない）。`reasoningEffort` は選択モデルの対応値を任意指定でき、省略時は API 既定を使う。`apply_chatgpt_plan` は最新の `projectId`・`sceneId`・`revision` を要求する。`cancel_chatgpt_generation` はプラン破棄と制作停止に使う。`target=new` 指定時だけ元の下書きを保存して別ワールドを作る。開始済みを完了扱いしない。
- **外部素材の参照順序**: 制作チャットは現在プロジェクトの素材と内蔵カタログを優先し、外部素材が必要な場合だけ Poly Haven、ambientCG、AI LOWPOLY PROPS、音蔵の対応種別を検索する。既存 Entity の名前・配置を保ったモデル追加・差し替え、マテリアル・Skybox・Audio Source・Collider 設定に対応する。処理中は実際の取り込み・反映・保存を表示し、失敗時も保存済み結果を残す。
- **会話履歴と出力コピー**: 参照: MI-03, MI-05, MI-09。チャット上部に履歴選択と新規チャットを置き、詳細操作に名前変更・全文コピー・履歴削除をまとめる。制作中は会話切替と削除を無効にする。履歴削除はシーンを変更しない。履歴は端末に保存し、再起動で失われた確認待ちや実行中処理を再開済みと表示しない。保存失敗時はエラーとコピー案内を出す。
  - ヘッダーの「出力をコピー」は制作中も使え、会話・変更項目・作業記録・エラー・案内・操作名をまとめてコピーする（未送信入力とアカウント情報は除外）。成否は出力欄の外に表示し、失敗時も文字選択でコピーできる。出力欄内の Ctrl+A / Command+A はテキスト選択に限定し、Entity 選択や他シーン操作を実行しない。タッチ操作でも文字選択を許可する。
- **添付・取り消し**: 参照: MI-03, MI-05, MI-09。Hierarchy の複数選択を保ったまま Entity をチャットへドロップでき、入力欄の上に添付名と解除操作を表示する（互換用ドラッグ JSON は本文へ挿入しない）。添付のルートと配下を送信直前のシーンから優先して要約し、親子関係をモデルへ渡す（送信上限を維持し、大きな階層が一部参照になることを明示）。
  - 添付はチャットごとの下書き・キュー依頼・送信後会話に対応付け、送信後に入力欄の添付を空にしてキューと会話へ対象名を残す。削除済み添付は送信前に理由を示して保留し、他対象へ自動置換しない。「続ける」ボタンは出さず、次の依頼は入力欄から送る。
  - 取り消せる保存済み変更には保存件数の横に「この依頼の変更を戻す」を表示する（依頼内変更を一括で戻す操作であり、個別行取消に見せない）。実行時の控えがある場合だけ表示し、後の手動編集を上書きする場合は停止する。控えは起動中のみ有効とし、再起動後は表示しない。戻した後は保存件数と結果行を取り消し済み表示へ切り替える。
  - チャットには今回の変更と残作業を表示し、次の依頼では手動編集を含む現在シーンと会話を引き継いで完了済み作業を重ねない。過去の会話や未実行プランをシーンの基準データとして扱わず、内部の件数制限や JSON 修正を利用者に要求しない。
- **入力候補（Tab 補完）**: 参照: MI-03, MI-05, MI-125。接続済みで入力欄が空のとき、直前の完了結果と添付中の Entity・マテリアルから端末上で候補を 1 件だけ生成し、入力欄に表示する（追加の推論 API 通信は行わず、会話末尾に 3 択や長い操作説明を置かない）。処理中、送信待ちあり、未接続、質問・変更確認待ち、失敗・停止・取消後は表示しない。
  - 候補表示でフォーカスを動かさず、空欄で修飾キーなしの Tab を押すと 1 件の依頼文と対象添付 ID を入力欄へ挿入する（挿入だけでは送信せず、編集後に Enter で送信）。閉じるボタンまたは Escape で候補を閉じ、入力欄へフォーカスを戻す（同じ結果・添付のままなら再表示しない）。上下キー、Shift+Tab、IME 変換中、入力途中は通常操作を維持する。最大 3 ページの質問フォームでは独立して Tab 移動・Space 選択を維持する。

### Entity の右クリックから依頼する

F-17 の制作チャット導線。参照: MI-05、MI-09。

- **操作前**: Hierarchy と Scene View の Entity メニューに「チャットに送る」を表示し、モデル内の参照ノードを除き「AIで作り替える…」も表示する。Text や空の Entity も対象とし、複数選択・Play 中・取り込み中などの無効状態では理由を示す。
- **操作後**: 制作チャットを開いて対象を名前付きで添付し、入力欄へフォーカスする。作り替えでは用途に合った仕上げ依頼文を入れて「AIにおまかせ」を選び、「希望する仕上がり」の文を選択状態にしてすぐ書き換えられるようにする。既存の下書きと添付は維持し、この段階ではシーン変更や送信を行わない。
- **送信**: 依頼を送信すると既存キューで作品・シーン・添付・制作方法を固定する。「AIにおまかせ」は外部素材・コード・UIKit・Blender を用途に応じて選び、Blender 指定時だけ未導入時の導入・再確認を案内する。生成・置換・失敗復帰・変更を戻す操作は既存の制作チャットに従う。
- **戻り先**: チャットを閉じても入力と添付を保持する。「制作方法」は「AIにおまかせ」「素材ストア中心」「Blenderで制作」から変更でき、待機中依頼は送信時の選択を保持する。

### 開発画面デバッグ（標準 MCP）

参照: MI-03, MI-05, MI-09

#### 操作前

- デバッグ版 Tauri を起動し、標準 MCP の `tauri` サーバーを読み込む。Codex はリポジトリの `.mcp.json` を、その他の MCP クライアントは `pnpm mcp:debug-config` で生成した設定を使う。
- 現在の WebView を画像で確認する目的を明確にし、シーン編集用の `xrift-studio` MCP と画面調査用の `xrift-studio-debug` MCP を区別する。

#### 操作中

- UI を変更するたびに、`webview_screenshot`、`webview_dom_snapshot`、`read_logs` を必要な順に呼び出す。Tauri コマンドを変更した場合は `ipc_monitor` と `ipc_get_captured` も使う。処理中の画面はスクリーンショットを再取得し、二重操作や状態ラベルの不一致を確認する。
- 画面調査用 MCP は表示中 WebView の読み取りを基本とし、OS ネイティブダイアログ・連続動画・リリース版への接続は対象外とする。ログイン・アップロード・削除・リセットなどの書き込み操作には別途明示確認を求める。

#### 成功時

- 画像・DOM・コンソール・IPC の結果を同じ変更の検証記録として残し、次の修正でも参照できるようにする。スクリーンショットはリポジトリに入れず、クライアントの一時領域または一時作業領域へ保存する。

#### 失敗時

- Tauri アプリ未起動、MCP サーバー未接続、画面読み込み失敗、スクリーンショット取得失敗、コンソールエラーを区別して示し、原因に応じた復帰手順（アプリ起動、MCP 再読み込み、画面再読み込み、ログ確認）を案内する。画面調査だけでプロジェクト文書、`AssetManifest`、履歴は変更しない。

#### 戻り先

- MCP クライアントは最後に確認した画面・DOM・ログ・IPC の状態を保持し、修正後に同じ画面から再取得できる。開発用 Tauri Bridge はデバッグビルドにだけ含め、リリースビルドの MCP 機能には追加しない。

完了条件: 対応する AI クライアントへ XRift Studio MCP を 1 操作で登録し、認可済みビジュアルプロジェクトから現在のシーン・素材・選択・リビジョンを取得できる。Skybox、Fog、Ambient Light、Camera、エディター表示設定、素材配置、マテリアル編集、ノードグラフのマテリアルポインター設定、Poly Haven / ambientCG の検索・ダウンロードは通常のエディターコマンド、「元に戻す」、自動保存を使う。AI と手動操作が競合しても暗黙に上書きせず、登録後も接続状態・対象シーン・直近編集・復帰手段をエディターに残す。

## F-35 ビジュアル編集 QA 診断と短時間録画の状態設計

制作チャットの Blender 途中画像は F-17、MI-03・MI-05・MI-09 に従う。対象の制作依頼だけに実際の形状の撮影画像を追加し、直近 4 枚とパーツ数・撮影時刻を表示する。最初と最後、長い制作では約 10 秒経過後のパーツ完成時に更新する。停止後や別依頼に遅れて届いた画像は反映せず、会話の保存対象にもしない。撮影失敗時はモデル制作を継続しつつ状態を案内する。

参照: MI-03, MI-05, MI-14, MI-26, MI-80

### 操作前

- シーンのツールバーに「診断」を配置し、Edit と Play の両方で使えるようにする（Play 中は実行中レンダラーを計測）。短い診断動画は MCP の要求で取得する。
- 「診断」はオン・オフ切り替えとし、オンの間だけ右上に計測パネルを重ねる。パネルはポインターイベントを受けず、下にあるシーンの操作を妨げない。
- パネルには FPS、フレーム時間、draw calls、triangles、可視メッシュ数、総メッシュ数、geometry 数、texture 数、カメラ位置、Far（描画する最長距離）を表示する。計測中の `LIVE` と録画中の `REC` は同じ位置に表示する。
- 形状とテクスチャの VRAM 概算と合計値を MiB で表示する。
  - 実シーンが参照する頂点・インデックス・インスタンス属性、マテリアル / Uniform、背景・環境テクスチャを集計し、重複参照は除く。
  - テクスチャは実形式と mipmap を考慮し、GPU 圧縮済みと非圧縮に分けて算定済み件数と MiB を表示する（両者の合計をテクスチャ全体と一致させ、未算定件数は別に数える）。判定には実行中テクスチャの GPU 形式を使い、JPEG / WebP や KTX2 の RGBA 代替読み込みを GPU 圧縮済みとして扱わない。
  - 未読み込みや非対応形式は未算定件数として明示し、0 と断定しない。影、描画バッファ、内部生成領域は対象外と明記する。初回計測後に値を表示し、診断を閉じたら計測を止める。MCP の `capture_scene_debug` にも同じ値を返す。

### 操作中

- 0.5 秒ごとに Three.js レンダラーの実測値を取得して表示を更新する。React の状態から推定した値は使わない。
- MCP が診断動画を要求したら、シーンの Canvas を最大 15 秒の WebM として記録し、録画中であることと上限秒数を通知に表示する。上限到達時は自動停止して保存中表示へ切り替え、保存中は開始も停止も受け付けない。
- 診断表示と録画では、`SceneDocument`、`AssetManifest`、「元に戻す」履歴、コンパイル結果を変更しない。サムネイル撮影時はパネルを隠して写り込まないようにする。

### 成功時

- 停止または自動停止後、デスクトップ版では保存先を選んで WebM を保存してパスを通知に残し、ブラウザ版ではファイルをダウンロードする。
- MCP へは計測結果、または保存パスと録画時間を返す。計測処理は UI と共通化する。
- 保存後はシーンへ戻り、診断表示の状態を維持する。

### 失敗時

- WebView の Canvas 録画非対応、利用可能な WebM 形式なし、録画フレーム 0 件の場合はそれぞれの理由を通知し、録画状態を解除してシーンは変更しない。
- 保存を取り消した場合はその旨を表示し、保存失敗時は理由を残して診断表示と最後の計測値を維持する。
- 別の録画を保存中に要求が来た場合は完了後の再試行を案内し、二重保存を始めない。

### 戻り先

- もう一度「診断」を押すと表示を閉じる。録画の成否にかかわらず、シーンと Play の状態・選択・カメラを維持する。

完了条件: Edit と Play で実行中レンダラーの FPS、フレーム時間、draw calls、triangles、可視メッシュ数、カメラの Far を確認でき、最大 15 秒の WebM を保存して問題発生前後を検証できる。診断と録画は編集データや履歴を変更せず、停止・保存失敗・WebM 非対応後も同じシーンへ戻れる。

## F-42 ワールド制作の録画の状態設計

参照: MI-03, MI-05, MI-09, MI-122

### 操作前

- シーン右上の「録画」からパネルを開き、状態、フレームのアスペクト比・短辺・fps・画素数、録画ビュー設定、録画用カメラ、保存先を 1 画面にまとめる。開始前に保存内容と解像度を確認できるようにする。
- 「録画ビューを表示」で投稿先比率に合うフレームを先に表示する。編集画面の比率で撮影してから切り抜く手順にはしない。
- 録画用カメラは「全体」「斜め」「正面」「真上」から選べ、フレーム内のドラッグで調整できる。MCP の `set_recording_camera` でも同じ姿勢を設定できる。
- 保存済みワールドでは保存先に `<ワールド>/Recording` を表示して動画と JSON を保存し、外部フォルダー選択は出さない。未保存プレビューでは従来の既定先とフォルダーダイアログを使う。AI は保存先パスを指定できない。

### 処理中

- 「録画を開始」を押すと録画ビューを表示し、ボタンを「録画を停止」へ変える。開始中・停止中はボタンを無効にして二重操作を防ぐ（MI-03）。
- フレーム左上とシーンヘッダーに `REC` と経過時間を、パネルに経過時間と書き込み済み容量を表示する。`REC` 表示は動画に含めない。
- プロジェクト再読み込みや別タブ移動でシーンが表示されなくなった場合は「シーンが表示されていません」と表示し、最後のフレームで録画を継続する。
- プロファイルは録画中も変更でき、「次の録画から反映されます」と案内する。
- MCP から開始した録画は「<client名>が録画を開始しました」と通知し、利用者が開始を把握できるようにする。

### 成功時

- 停止後もパネルに「保存済み」、録画時間、容量、パスを残し、「フォルダーを開く」から保存先を開けるようにする（MI-05）。トーストにもパスを表示する。
- 動画の隣に付属 JSON ファイルを保存し、プロジェクト・シーン・クライアント・構図を記録して後から確認できるようにする。
- MCP へはパス、録画時間、バイト数、付属ファイルのパスを返す。

### 失敗時

- WebView の録画非対応、ファイル作成不可、書き込み失敗時は「失敗」と理由を 1 文で表示し（MI-09）、途中失敗時は部分ファイルのパスを残す。
- 失敗後も「録画を開始」から再試行でき、制作ツールやエディターの操作に影響を与えない。

### 戻り先

- シーンヘッダーまたはパネルの「編集表示へ戻る」で録画ビューを閉じ、退避していた編集カメラへ戻る（録画自体は継続する）。
- 停止後は録画ビューを開いたまま次の録画を始められ、閉じると通常のパネル配置へ戻る。

### 制作チャットの質問・作業記録・結果調整（F-17 補足）

- **質問フォームのキーボード操作とモデル置換**: 制作前の質問では Tab / Shift+Tab で全候補を移動し、Space で選択する。ページ切替時は先頭候補へフォーカスし、自由入力と送信ボタンにも移動できる（フォーカス移動だけでは回答を変更・送信しない）。Blender モデルの置き換えでは対象 Entity と `Mesh Renderer` を示し、`Transform` と他 Component を維持する。
- **シーン設定の生成操作**: Skybox・Ambient Light・Fog・カメラ・画面効果・風・物理・編集表示を部分更新し、変更内容の設定項目に値を表示する。未指定項目は維持し、取り消し操作を共用する。画面と本体で形式が一致しない場合は推論前に再起動・更新を案内し、送信待ち依頼を保持する。
- **作業の記録とサムネイル表示（MI-127）**: 制作チャットの「作業の記録」は現在・過去とも折りたたまず表示する。現在進行状況と重複する末尾案内は 1 つにまとめ、思考中案内だけで記録がない間は空見出しを出さない。保存イベントは記録と API に保持し、自動追従中は新しい記録へスクロールしつつ、上へ読み戻した場合は利用者の位置を維持する。
  - 素材確認質問では候補名の下に実カタログ・Assets のサムネイルを置き、横幅に応じたカード一覧で表示する。追加・割り当て予定や保存済み会話にも作業説明の下にサムネイルを表示し、クリックと Tab / Space で選択できるようにする。未回答ではシーンを変更せず、選択した候補 ID を回答へ引き継ぐ。プレビューを取得できない場合は架空の風景を作らず状態を表示する。
  - 作業の記録では「Scene設定を調整」のような分類名だけを繰り返さず、画面上の項目名と変更前後の値を示す（変更中は予定値、保存後は実際に反映した値）。画像なし IBL の無効化やグリッド自動調整も適用後のシーンと照合する。Entity 調整では名前・位置・回転・大きさのどれを変えたかを示し、変更内容の行名も対象項目から作る。「Plan：作品名」の見出しや折りたたみは使わず、項目名・値・変更前の値を並べる。有効・無効と色は読み取り表示とし、JSON 本文と重複表示しない。詳細を持たない旧版の連続ログは保存件数付きの 1 項目にまとめ、現在のシーン値から過去を推測しない。
- **MCP 接続ボタンの常設**: ChatGPT パネルを開くと、狭い画面でも入力欄の近くに「MCP接続」を常時表示する。ChatGPT の接続状態や生成中にかかわらず既存の MCP 設定を直接開け、閉じる・Escape で元のボタンへフォーカスを戻しつつ、入力・会話・認証・実行中作業を保持する。
- **マテリアルの添付**: Assets からマテリアルも制作チャットへ添付できる。Entity とは種類を区別した名前付きチップを表示し、複数選択・解除・チャット別下書き・キュー依頼ごとの対象を保持する（最大 16 件、送信時に利用できるもののみ）。添付マテリアルの現在値を優先してモデルへ渡し、`material-update` は既存 MCP の `update_material_asset` を通す。設定カードと具体的な前後値を表示し、取り消しは依頼単位で共用する。添付だけではシーンや素材を変更せず、消失した対象は他素材へ置き換えずに保留する。
- **完了結果からの直接調整**:
  - 完了したマテリアル変更結果には「現在のMaterialを調整」を配置する（同一マテリアルの最終変更結果に 1 つだけ表示）。結果に保持した正確な Asset ID で照合し、`Base Color` の色・HEX と `Roughness`・`Metallic` の数値・スライダーを表示する。色変更時は `Alpha` を保ち、未指定のシェーダーやテクスチャも維持する。操作は通常のマテリアル編集・描画・Undo・自動保存を通し、過去ログや過去設定値は書き換えない。対象不在・未完了・確認待ち・取消済みでは非表示とし、Play・インポートなど編集不可状態では無効にする。
  - Skybox・Fog を変更した完了結果には「現在のScene設定を調整」を配置する。公開結果の `sceneSettingsSections` で実際に扱った節を識別し、各節の最終結果に 1 つだけ操作欄を置く。現在シーンから有効・無効、色、明るさ、距離を読み、通常のシーン設定と同じ検証・描画・Undo・自動保存を通す。空の画像やシェーダーは維持し、その素材で調整可能な項目だけを表示する（IBL には利用可能な画像が必要、Fog の終了距離は開始距離より大きくする）。過去の設定値やログは書き換えず、未完了・確認待ち・取消済みでは非表示、Play・読み込み中は無効にする。
