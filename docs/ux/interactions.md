# 共通の動き（MI 一覧）

[機能一覧へ戻る](../UX_INTERACTIONS.md)

## 使い方

新しい画面や状態遷移を追加するときは既存の項目を再利用する。再利用できない場合は新しい `MI-xx` を追加する。項目には必ず、対象状態、開始条件、見た目の変化、操作可能な状態、終わり方を書く。動きは状態や結果を伝える場合だけ追加する。

機能仕様では、次の形式で参照する。

```text
F-06 アイテム検査
参照: MI-03, MI-05, MI-09
```

## 共通の動き

| ID | 状態と開始条件 | 見た目と時間 | 操作と終わり方 |
| --- | --- | --- | --- |
| MI-01 | 画面または一覧が初めて表示される | `fade-in`で450msかけて下から 6px動かす。画面の存在を示す。注目は奪わない。 | 表示中も操作を妨げない。完了後は静止する。 |
| MI-02 | カードや副操作にポインタを重ねる | 背景または境界線をわずかに変える。カードは最大 4px上へ動かす。200ms以内に終える。 | クリックできることを示す。意味のない常時アニメーションは付けない。 |
| MI-03 | 主操作を実行する | ラベルを「実行中」に変える。ボタンを無効化する。必要ならログまたは進捗を開く。 | 二重実行を防ぐ。成功、失敗、取消可能のいずれかが明らかになるまで通常状態へ戻さない。 |
| MI-04 | ダイアログを開く | 背景を薄く暗くする。内容は `scale-in`で350msかけて0.94 から 1.0 へ表示する。全ダイアログは共通の余白、角丸、影、背景濃度を使う。画面高を超える内容はheaderと画面の下部を保つ。body内でスクロールする。狭い画面では複数columnを縦へ並べる。主操作と閉じる操作を画面内に残す。 | 背景クリックと Escape の扱いを明示する。処理中で安全に閉じられない場合は閉じる操作を無効にする。`prefers-reduced-motion`では表示アニメーションを最小化する。 |
| MI-05 | 非同期処理が成功または失敗する | 成功・失敗のトーストを短く表示する。色だけでなく操作名と結果を文言で示す。 | トーストだけで終わらせず、作成物、URL、ログ、再試行のいずれかへ到達できる状態を残す。 |
| MI-06 | 一覧の項目が表示される | 一覧全体を 100ms遅らせる。各カードは 40msずつずらして `fade-in` する。 | 新規作成カードを先頭に固定する。空状態でも作成入口を表示する。 |
| MI-07 | アップロード前に公開情報を確認する | target、`xrift.json` 相当のタイトル・説明、サムネイル、既存 remote ID、保存 / compile freshness、診断を一つの review に示す。未編集項目だけを「テンプレートのままです」と表示する。 | blocker があればアップロードを止める。対象 field または Editor へ戻り、保存・compile 後に同じ review を再確認する。すべて整った時だけ明示的な最終操作を有効にする。 |
| MI-08 | ローカル実行、upload または審査結果を得る | local preview は実行中、upload 完了は ID / version / content hash、審査中は「処理中」、公開済みは「公開済み」と別 label で示す。公式 result に URL がある時だけ URL を表示する。 | URL を ID から推測して作らない。停止、status refresh、結果コピー、Editor へ戻るのうち現在可能な操作を残す。古い結果は input hash と version を添えて区別する。 |
| MI-09 | 読み込み失敗、設定不備、空の状態になる | 落ち着いたエラーまたは空状態の面を表示する。原因または状況を一文で示す。Viteの更新で遅延moduleが古くなった場合は一度だけ自動再読み込みする。短時間の再発では再読み込みを繰り返さない。エラー面へ移る。 | 必ず再試行、再読み込み、編集、作成、ログ確認のいずれか一つ以上を置く。 |
| MI-10 | オブジェクト一覧またはシーンでオブジェクトを選択する。文字入力外で `Ctrl / Cmd + A` を押す場合も同じ扱いにする | click は Pointer Down / Up 間の小さな移動を許容する。一つのシーン picker で解決する。表示中のメッシュを優先する。その後、ライト / 音声 / Empty等のオブジェクト原点付近を画面サイズ固定の補助領域として扱う。120ms 以内にオブジェクト一覧の選択背景、シーンの選択表示、設定の見出しと値を同じオブジェクト ID へ更新する。全選択では現在の主選択を維持する。選択表示は色だけに頼らない。 | cameraまたはgizmoのdragでは選択を変えない。短い空領域clickでは明示的に解除する。`Ctrl / Cmd + A` はシーン内の全オブジェクトを選ぶ。input、textarea、select、contenteditableでは文字選択を優先する。選択のためにシーンデータや元に戻す履歴は変更しない。別オブジェクトの選択または明示的な選択解除で終わる。 |
| MI-11 | user 素材をシーン / オブジェクト一覧へ drag する。「配置」を実行する場合も同じ扱いにする。オブジェクト一覧 / シーンの右クリックから primitive を作る場合も同じ扱いにする。外部ファイルをここに移動する場合も同じ扱いにする | drag 中に対象と結果を表示する。3Dモデル / プレハブ / パーティクル / 音声はシーンでは配置位置、オブジェクト一覧ではシーンの直下または親オブジェクトを明示してオブジェクトを配置する。音声は参照元音声素材を設定済みの音源オブジェクトとして作る。マテリアルは hover 中メッシュの割り当て枠へ binding する。テクスチャはマテリアル設定 slot を参照する。右クリック追加は click point / 選択親を示す。外部 file は読み込む Queue の全 stage を通す。 | Escape では変更せず終了する。領域外ここに移動でも変更せず終了する。drag と「配置」は同じ素材 placement を使う。Place / 追加 / Assign マテリアルの元に戻すは一つの履歴で document と前の `sceneSelection` / `assetSelection` を復元する。import 失敗では SceneDocument と AssetManifest を変えない。 |
| MI-12 | 移動、回転、拡大縮小ツールを切り替える、またはギズモを操作する | 選択ツールを押下状態と名称で示す。ギズモは待機中のRGB色と不透明度を抑える。hoverまたはdrag中の軸だけを明るくする。シーンより目立たせない。操作中はシーンと設定の数値を同期する。カメラ操作との競合を止める。pointer down から pointer up までを一つの Command Transaction とする。 | pointer up で一件の履歴として確定する。Escape では操作前へ戻す。不正値でも操作前へ戻す。どちらも履歴は追加しない。オブジェクトの選択は保つ。 |
| MI-13 | ビジュアル project を開く、保存する、または authoring document を変更する | ヘッダーには成果物種別、「ビジュアル」、保存状態だけを静かに表示する。stale compile は常時警告にしない。公開 review で自動保存・変換される事実と現在の診断を示す。 | commit marker が指すシーン / プレハブ / 素材 / folder を含む全 document set の保存に成功する。その後だけ対象 revision の「未保存」を解除する。未保存で戻る時は保存、破棄、取消を選べる。 |
| MI-14 | 編集で「動作確認」を実行する、動作確認中に選択オブジェクトの実行入力を変更する、または「停止」を実行する | project kind に応じた実行コピーを中央の`Play Window`へ開く。太い境界、専用header、「分離された実行コピー」の文言でシーンと区別する。停止は同じ位置に常時置く。オブジェクト一覧と設定は編集データを表示する。動作確認中もオブジェクト / コンポーネント構成、位置・回転・大きさ、衝突判定、Animation、既存マテリアル / パーティクルの許可されたpropertyとMCP経由のシーン settingsを調整できる。ワールドのinput / controller / gravity / collider physicsはアイテムへ適用しない。 | PlaySessionは開始時snapshotとオブジェクト別実行環境 revisionを持つ。許可した変更は通常のauthoring Commandとして保存する。シーン settingsは共有シーンへ即時反映する。変更オブジェクトまたは変更素材の参照オブジェクトだけを新revisionで先頭から再実行する。無関係なオブジェクト、player、camera、physics stateは維持する。テクスチャ / 3Dモデル設定、設定のマテリアル割り当て、シーンの位置・回転・大きさギズモ、素材ここに移動は停止まで無効にする。停止で全実行環境 resourceをdisposeする。最新の編集データ、両selection、設定 context、編集 cameraへ戻る。初期化失敗時は編集のまま原因と再試行を示す。 |
| MI-15 | 素材で素材を一回クリックする、またはオブジェクト設定の素材 reference を開く | 素材の選択背景と右設定の素材 context を同じ `assetSelection` へ更新する。`sceneSelection` は維持する。設定 header のオブジェクト / 素材 tab から双方へ戻れる。オブジェクトは追加しない。元に戻す履歴も増やさない。 | 別素材 / オブジェクトの選択で終わる。設定 context 切替でも終わる。マテリアルは参照オブジェクト数と「共有中」を表示する。テクスチャ / 3Dモデルは元データと derived status を表示する。 |
| MI-16 | 右設定でマテリアル / テクスチャを変更する | マテリアルは glTF core PBR、TextureInfo、emissive、normal、occlusion、alpha / double-sided、typed extension、テクスチャは元データ、色空間、resize、mipmap / sampler、compression、derived / diagnostics を section 分けする。同じマテリアル ID を参照する全オブジェクトと選択中のライブpreviewへ同期する。変更後はgenerated thumbnailをstaleにして一時rendererの更新queueへ送る。shadow はオブジェクトのメッシュ section に残す。 | 有効値の確定を `UpdateAssetCommand` 一件にする。AssetManifest を未保存にする。SceneDocument やオブジェクト固有値へ複製しない。不正値は確定しない。field 近くに形式、範囲、色空間、slot の意味を示す。動作確認中は既存マテリアルのpropertyだけ保存する。参照オブジェクトへ再反映できる。テクスチャ設定は読み取り専用にする。 |
| MI-17 | visual project で compile、check、upload を開始し、必要な toolchain がない | authoring 画面は閉じない。Node.js、XRift CLI、認証のうち不足している項目とセットアップ操作を表示する。通常の編集 / 保存は利用可能なままにする。 | セットアップ後は同じ操作へ戻れる。取消時は編集へ戻る。SceneDocument、AssetManifest、staging output、公開先を変更しない。 |
| MI-18 | 新規作成を開く | item classic、world classic、item visual、world visual の四カードを同じ階層で表示する。成果物、制作方法、正本、作成後の画面を一文で示す。hover だけに説明を隠さず、常に表示する。 | 一カードの選択で名前 / 保存先確認へ進む。戻ると四カードへ戻る。前の選択を保持する。取消では project を作らない。 |
| MI-19 | 素材の「作成 > マテリアル」を選ぶ | 名前、標準サーフェスまたは glTF 既定値プリセット、作成先 folder を compact dialog で示す。作成中も右オブジェクト設定を保つ。 | 成功時はマテリアルを一件追加する。`assetSelection` にする。オブジェクトへ binding しない。取消 / validation 失敗では AssetManifest、両 selection、history を変えない。 |
| MI-20 | GLB / GLTF / テクスチャ / HDRI / MP3 をここに移動または import する | Editor下部の素材 status barへ現在のstageと進捗を表示する。詳細を開くとActivity drawerでvalidate、copy、parse / decode、derive、dynamic thumbnail、commit、件数、bytes、診断を確認できる。完了項目を閉じなくても制作を続けられる。元データ保持、resize / mipmap / compression recipe、stale状態は右設定で確認できる。3Dモデル再importなど別の素材 transaction中は入口を理由付きで無効化する。同じ元データへのcommitを並行実行しない。HDR / EXRはシグネチャ検証後にequirectangular環境テクスチャとして保存する。同じ履歴で現在シーンの空の背景へ設定する。保存後はHDR / EXRソースからtone map済みの一覧用thumbnailを自動生成する。未生成・旧renderer版・上下を反転する変更を検出して再生成する。MP3はシグネチャ検証後に音声素材としてproject管理下へ原本を保存する。編集画面では自動再生しない。 | 全検証後だけAssetManifestへcommitする。成功時はstatus barとdrawerにマテリアル / テクスチャの展開件数、または空の背景への設定結果と「素材を表示」を残す。新素材を`assetSelection`にできる。HDRIのテクスチャ設定では上下を反転するを含む読み込み設定を編集できる。thumbnail生成失敗は永久な準備中表示にしない。再試行可能な通知として示す。HDRI以外の素材へのimportは明示的なシーンここに移動なしにシーンを変えない。失敗時はdrawerを開いて原因を示す。取消時はtemporaryを回収してlast-goodと両selectionを維持する。 |
| MI-21 | thumbnail を生成、再生成、または stale 判定する | card は pending / generating / ready / stale / failed を label と status icon で示す。3Dモデル / テクスチャ / マテリアルは ready な generated thumbnail を優先する。それ以外だけ kind icon を fallback にする。マテリアル cardはWebGL contextを保持しない。内容hashが変わった時だけ一つの一時rendererで順番に画像化する。 | 成功時は同じ素材 ID の thumbnail hash を更新する。生成画像をprojectへ保存する。一時rendererを解放する。失敗時も card と素材を残す。再生成と診断を置く。last-good が stale なら「古いプレビュー」と明示する。 |
| MI-22 | toolbar、menu、context menu、keyboard から Command を起動する | central Shortcut Registry の label、semantic Lucide icon、platform binding、enabled reason を全 surface で一致させる。active tool は icon、label、押下状態で示す。conflict は両 command を実行しない。設定へ案内する。 | Command の実行結果を成功 / 失敗として表示する。text input、contenteditable、数値入力、IME composition 中は editor shortcut を抑止する。override と既定へ戻す操作は Editor Preferences に保存する。 |
| MI-23 | Copy / Paste / 複製 / 削除を実行する | Copy は versioned buffer の対象数、Paste / 複製は生成予定数、素材削除は参照元件数を示す。document 変更を伴う操作だけを Command history に積む。 | Paste / 複製 / 削除の元に戻す / やり直すは同じ IDs と前後の `sceneSelection` / `assetSelection` を復元する。Copy 自体は document 元に戻すにしない。参照を壊す削除は置換、解除、取消のいずれかを同じ操作に含める。 |
| MI-24 | オブジェクト一覧のオブジェクト subtree を素材 / folder へここに移動してプレハブにする | ここに移動 target、プレハブ名、オブジェクト / 素材 dependency 件数、既存プレハブ / cycle conflict を表示する。成功前はシーン、素材、folder のどれも変更しない。 | 成功時はプレハブ / document と instance metadata を一 transaction で作る。`sceneSelection` は instance rootにする。`assetSelection` はプレハブにする。元に戻す / 失敗 / 取消では全 document と両 selection を元へ戻す。 |
| MI-25 | authoring操作を一件確定する、元に戻す / やり直すする、またはCtrl/Cmd+Sで即時保存を要求する | 確定したrevisionを短い待機時間後に自動保存する。headerを「自動保存待ち」「自動保存中」「自動保存済み」「自動保存エラー」で更新する。連続変更は最新revisionへまとめる。保存処理は必ず直列化する。一時失敗は最新revisionだけを短い間隔で最大3回再試行する。その間は「自動保存中」を維持する。Ctrl/Cmd+Sは主導線ではなく待機中の保存を即時flushする。 | commit markerと全hashが一致する。その後だけ対象revisionを保存済みにする。保存中の追加編集は次の自動保存へ引き継ぐ。古い保存完了で新しいrevisionを保存済みにしない。新しいrevisionが待機中なら古いrevisionの再試行を打ち切る。上限後の失敗ではlast committed setを維持する。編集を止めない。同じheaderから再試行できる。戻る操作は最新revisionの保存完了を待つ。失敗時はEditorに留まる。 |
| MI-26 | 動作確認、generated preview、compile または check を実行する | Editor direct 動作確認、generated staging preview、check/build を別 label にする。input fingerprint、target、stale、progress を示す。diagnostic は生成元の記録から元オブジェクト / 素材 / field へ link する。 | fresh hash の結果だけ成功にする。停止 / cancel は process と resource を cleanup する。編集へ戻る。公式に未記載の CLI / hosted / XFT preview は存在するように表示しない。 |
| MI-27 | Upload modal を開き、review から remote result まで進める | review、auth-check、saving、compiling、required thumbnail copy / SHA-256 verify、checking、uploading、processing、succeeded、failed を一つの modal 内で段階表示する。title、description、thumbnail、diagnostic、progress、cancel / retry を現在 state に合わせる。ワールド / アイテムとも公式CLIのbuild付きcheckをremote upload開始記録より前に完了させる。 | `public/thumbnail.png` のcopyまたはSHA一致確認、またはbuild付きcheckに失敗した場合はremote uploadを開始しない。検証成功後は「公開用ステージングへコピー済み」を残す。閉じると編集に戻る。結果 ID は保持する。remote commit 後を取消済みと断定しない。成功時は正式 result の ID / version / hashを示す。正式に返る時だけ URL を示す。test / 通常検証では実 upload をしない。 |
| MI-28 | 素材 folder または素材の context menu を開く | folder では作成 / import / 新規 folder / 素材をエクスプローラーで開く。素材では rename / duplicate / delete / references / reimport / thumbnail regeneration / 元データをエクスプローラーで表示する。kind と state に応じて出し分ける。project 元データを持たない document / builtin 素材と論理 folder は物理素材 root を開く。shortcut と icon は Registry と一致させる。 | 一つの操作選択で閉じる。Escape / 外側 click でも閉じる。実行不可項目は理由を tooltip で示す。menu を開いただけでは document や selection を変えない。Explorer 起動失敗では Editor と selection を維持する。素材 status に確認先を示す。 |
| MI-29 | panel splitter を動かす、panel header を dock zone へ drag する、または layout を reset する | drag 中は resize cursor、minimum size、dock preview、最終 order を表示する。シーン / 素材 data と authoring history は変更しない。 | ここに移動で normalized size / zone / order を Editor Preferences に保存する。Escape / 領域外ここに移動は開始前 layout へ戻す。reset は既定 layout へ戻す。保存失敗時も session layout を保つ。再試行を示す。 |

## 実装制約

- 動きは `opacity` と `transform` を中心にし、レイアウトを押し広げたり、操作対象を移動させたりしない。
- ブランド色、影、動きは主操作、状態変化、注目すべき結果を示すときだけに使う。
- テキスト、アイコン、色、動きのうち二つ以上で状態を伝える。アイコンや色だけに意味を預けない。
- `prefers-reduced-motion` を尊重する。新しいアニメーションを追加するときは、動きを減らしても状態が分かる表示を用意する。
- 操作の開始・処理中・成功・失敗・復帰先を揃える。待機中に主操作を再実行できるように見せない。
- Markdown、UI 文言、コミットメッセージには絵文字を使わない。

## 変更手順

1. 機能の目的と到達点を `F-xx` として書く。
2. 操作前、処理中、成功、失敗、復帰先を列挙する。
3. 各状態に対応する `MI-xx` を選び、足りなければこの文書へ項目を追加する。
4. 実装では、状態・文言・無効化・URL または成果物への導線を同時に作る。
5. 実機確認が必要な変更は、実行前にユーザーへ確認方法と副作用を伝え、許可を得てから確認する。
