# 共通の動き（MI一覧）

[機能一覧へ戻る](../UX_INTERACTIONS.md)

## 使い方

新しい画面や状態遷移を追加するときは既存の項目を再利用する。再利用できない場合は新しい`MI-xx`を追加する。項目には必ず、対象の状態、開始条件、見た目の変化、操作可能な状態、終わり方を書く。動きは状態や結果を伝える場合だけ追加する。

機能仕様では、次の形式で参照する。

```text
F-06 アイテム検査
参照: MI-03, MI-05, MI-09
```

## 共通の動き

| ID | 状態と開始条件 | 表示と所要時間 | 操作と終わり方 |
| --- | --- | --- | --- |
| MI-01 | 画面または一覧が初めて表示される | `fade-in`で450msかけて下から6px動かす。画面が表示されたことを控えめに示す。 | 表示中も操作を妨げない。完了後は静止する。 |
| MI-02 | カードや副操作にポインタを重ねる | 背景または境界線をわずかに変える。カードは最大4px上へ動かす。200ms以内に終える。 | クリックできることを示す。意味のない常時アニメーションは付けない。 |
| MI-03 | 主操作を実行する | ラベルを「実行中」に変える。ボタンを無効化する。必要ならログまたは進捗を開く。 | 二重実行を防ぐ。成功、失敗、取消可能のいずれかが明らかになるまで通常状態へ戻さない。 |
| MI-04 | ダイアログを開く | 背景を薄く暗くする。内容は`scale-in`で350msかけて0.94から1.0へ表示する。すべてのダイアログは共通の余白、角丸、影、背景濃度を使う。画面の高さを超える内容はヘッダーとフッターを保つ。本文内でスクロールする。狭い画面では複数列を縦へ並べる。主操作と閉じる操作を画面内に残す。 | 背景クリックとEscapeの扱いを明示する。処理中で安全に閉じられない場合は閉じる操作を無効にする。`prefers-reduced-motion`では表示アニメーションを最小化する。 |
| MI-05 | 非同期処理が成功または失敗する | 成功・失敗のトーストを短く表示する。色だけでなく操作名と結果を文言で示す。 | トーストだけで終わらせず、作成物、URL、ログ、再試行のいずれかへ到達できる状態を残す。 |
| MI-06 | 一覧の項目が表示される | 一覧全体を100ms遅らせる。各カードは40msずつずらして`fade-in`する。 | 新規作成カードを先頭に固定し、空の状態でも作成入口を表示する。 |
| MI-07 | アップロード前に公開情報を確認する | 対象、`xrift.json`相当のタイトル・説明、サムネイル、既存の公開先ID、保存状態とコンパイル結果の新旧、診断を一つの確認画面に示す。未編集項目だけを「テンプレートのままです」と表示する。 | 処理を止める問題があればアップロードを止める。対象入力項目またはエディターへ戻り、保存・コンパイル後に同じ確認画面を再確認する。すべて整った時だけ明示的な最終操作を有効にする。 |
| MI-08 | ローカル実行、送信または審査結果を得る | ローカルプレビューは実行中、送信完了はID / バージョン / 内容のハッシュ、審査中は「処理中」、公開済みは「公開済み」と別ラベルで示す。公式結果にURLがある時だけURLを表示する。 | URLをIDから推測して作らない。停止、状態の再確認、結果コピー、エディターへ戻るのうち現在可能な操作を残す。古い結果は入力内容のハッシュとバージョンを添えて区別する。 |
| MI-09 | 読み込み失敗、設定不備、空の状態になる | 落ち着いたエラーまたは空の状態を示す画面を表示する。原因または状況を一文で示す。Viteの更新で遅延モジュールが古くなった場合は一度だけ自動再読み込みする。短時間の再発では再読み込みを繰り返さない。エラー画面へ移る。 | 必ず再試行、再読み込み、編集、作成、ログ確認のいずれか一つ以上を置く。 |
| MI-10 | HierarchyまたはシーンでEntityを選択する。文字入力中以外に`Ctrl / Cmd + A`を押す場合も同じ扱いにする | クリックはポインタを押してから離すまでの間の小さな移動を許容する。共通のシーン選択処理で対象を決める。表示中のメッシュを優先する。その後、ライト / 音声 / Empty等のEntity原点付近を画面サイズ固定の補助領域として扱う。120ms以内にHierarchyの選択背景、シーンの選択表示、設定の見出しと値を同じEntityIDへ更新する。全選択では現在の主選択を維持する。選択表示は色だけに頼らない。 | カメラまたはギズモのドラッグでは選択を変えない。短い空領域クリックでは明示的に解除する。`Ctrl / Cmd + A`はシーン内のすべてのEntityを選ぶ。input、textarea、select、contenteditableでは文字選択を優先する。選択のためにシーンデータや元に戻す履歴は変更しない。別Entityの選択または明示的な選択解除で終わる。 |
| MI-11 | Assetsの素材をシーンやHierarchyへドラッグする。「配置」、右クリックでの基本形状作成、外部ファイルのドロップも対象とする | ドラッグ中は配置先と結果を示す。3Dモデル、Prefab、パーティクル、音声は、シーンでは配置位置、Hierarchyではシーン直下か親Entityを示す。音声は素材を参照するAudio Source付きのEntityとして作る。マテリアルはポインタ下のメッシュのスロットへ割り当てる。テクスチャはマテリアル設定のスロットを参照する。右クリックでの追加はクリック位置と選択中の親を示す。外部ファイルは取り込みキューの全工程を通す。 | Escapeや領域外へのドロップでは変更しない。ドラッグと「配置」は共通の配置処理を使う。配置、追加、マテリアル割り当てを元に戻すと、文書と操作前の`sceneSelection` / `assetSelection`を一つの履歴で復元する。取り込みに失敗してもSceneDocumentとAssetManifestは変更しない。 |
| MI-12 | 移動、回転、拡大縮小ツールを切り替える、またはギズモを操作する | 選択ツールを押下状態と名称で示す。ギズモは待機中のRGB色と不透明度を抑える。ポインタを重ねた軸やドラッグ中の軸だけを明るくする。シーンより目立ちすぎないようにする。操作中はシーンと設定の数値を同期する。カメラ操作との競合を止める。ポインタを押してから離すまでを一つのCommandのトランザクションとする。 | ポインタを離すと一件の履歴として確定する。Escapeでは操作前へ戻す。不正値でも操作前へ戻す。どちらも履歴は追加しない。Entityの選択は保つ。 |
| MI-13 | ビジュアルプロジェクトを開く、保存する、または編集用文書を変更する | ヘッダーには成果物種別、「ビジュアル」、保存状態だけを控えめに表示する。古いコンパイル結果は常時警告にしない。公開前の確認画面で編集内容の保存と公開データの作成、現在の診断を示す。テクスチャは使用中の画像をそのまま公開する。 | 保存完了マーカーが指すシーン / Prefab / 素材 / フォルダーを含む文書一式をすべて保存できた後だけ、対象revisionの「未保存」を解除する。未保存で戻る時は保存、破棄、取消を選べる。 |
| MI-14 | 編集で「Play」を実行する、Play中に選択Entityの実行入力を変更する、または「Stop」を実行する | プロジェクト種別に応じた実行コピーを中央の`Play Window`へ開く。太い境界、専用ヘッダー、「分離された実行コピー」の文言でシーンと区別する。停止は同じ位置に常時置く。Hierarchyと設定は編集データを表示する。Play中もEntity / Component構成、位置・回転・大きさ、衝突判定、アニメーション、既存マテリアル / パーティクルの許可されたプロパティとMCP経由のシーン設定を調整できる。ワールドの入力 / 操作コントローラー / 重力 / コライダーの物理演算はアイテムへ適用しない。 | PlaySessionは開始時スナップショットとEntity別実行環境revisionを持つ。許可した変更は通常の編集用Commandとして保存する。シーン設定は共有シーンへ即時反映する。変更Entityまたは変更素材の参照Entityだけを新revisionで先頭から再実行する。変更と無関係なEntity、プレイヤー、カメラ、物理演算状態は維持する。テクスチャ / 3Dモデル設定、Inspectorのマテリアル割り当て、シーンの位置・回転・大きさギズモ、素材ドロップは停止まで無効にする。停止で全実行環境リソースを解放する。最新の編集データ、両選択状態、Inspectorの編集対象、編集カメラへ戻る。初期化失敗時は編集のまま原因と再試行の操作を示す。 |
| MI-15 | Assetsで素材を一回クリックする、またはInspectorの素材参照を開く | 素材の選択背景とInspectorの素材編集対象を同じ`assetSelection`へ更新する。`sceneSelection`は維持する。設定ヘッダーのEntity / 素材タブから双方へ戻れる。Entityは追加しない。元に戻す履歴も増やさない。 | 別素材 / Entityの選択で終わる。Inspectorの編集対象切替でも終わる。マテリアルには参照するEntityの数と「共有中」を表示する。テクスチャ / 3Dモデルは元データと派生データの状態を表示する。 |
| MI-16 | Inspectorでマテリアルやテクスチャを変更する | マテリアルではglTF標準のPBR、TextureInfo、Emissive、Normal Map、Occlusion Map、Alpha / Double Sided、型の定義がある拡張を分ける。テクスチャでは元データ、色空間、サイズ変更、ミップマップ / サンプラー、圧縮、派生データ / 診断を分ける。同じマテリアルIDを参照するすべてのEntityと、選択中のライブプレビューへ反映する。変更後は生成済みサムネイルを古い結果として扱い、一時レンダラーの更新キューへ送る。影の設定はEntityのメッシュ設定に残す。 | 有効な値への変更を`UpdateAssetCommand`一件として記録し、AssetManifestを未保存にする。SceneDocumentやEntity固有の値へ複製しない。不正値は確定しない。入力欄の近くに形式、範囲、色空間、スロットの用途を示す。Play中は既存マテリアルのプロパティだけを保存し、参照Entityへ再反映できる。テクスチャ設定は読み取り専用にする。 |
| MI-17 | ビジュアルプロジェクトでコンパイル、検査、送信を開始し、必要な実行環境がない | 編集画面は閉じない。Node.js、XRift CLI、認証のうち不足している項目とセットアップ操作を表示する。通常の編集 / 保存は利用可能なままにする。 | セットアップ後は同じ操作へ戻れる。取消時は編集へ戻る。SceneDocument、AssetManifest、ステージング出力、公開先を変更しない。 |
| MI-18 | 新規作成を開く | アイテムのコード編集、ワールドのコード編集、アイテムのビジュアル編集、ワールドのビジュアル編集の4枚のカードを同じ階層で表示する。成果物、制作方法、編集するデータ、作成後の画面を一文で示す。ポインタを重ねた状態だけに説明を隠さず、常に表示する。 | カードを1枚選ぶと名前と保存先の確認へ進む。戻る操作では前の選択を保持し、4枚のカードを再表示する。取消ではプロジェクトを作らない。 |
| MI-19 | Assetsの「作成 > マテリアル」を選ぶ | 名前、標準サーフェスまたはglTF既定値プリセット、作成先フォルダーを小型のダイアログに表示する。作成中もInspectorを保つ。 | 成功時はマテリアルを一件追加し、`assetSelection`にする。Entityへは割り当てない。取消や入力検証の失敗では、AssetManifest、両方の選択状態、履歴を変更しない。 |
| MI-20 | GLB / GLTF / テクスチャ / HDRI / MP3をドロップまたは取り込む | エディター下部の素材ステータスバーへ現在の工程と進捗を表示する。詳細を開くと取り込み履歴パネルで検証、コピー、解析 / デコード、派生データの生成、動的なサムネイル生成、確定、件数、バイト数、診断を確認できる。完了項目を閉じなくても制作を続けられる。元データ保持、サイズ変更 / ミップマップ / 圧縮設定、更新前の状態はInspectorで確認できる。3Dモデル再取り込みなど別の素材のトランザクション中は入口を理由付きで無効化する。同じ元データへの確定を並行実行しない。HDR / EXRはシグネチャ検証後に正距円筒図法の環境テクスチャとして保存する。同じ履歴で現在シーンの空の背景へ設定する。保存後はHDR / EXRソースからトーンマッピング済みの一覧用サムネイルを自動生成する。未生成の画像、レンダラーの旧バージョンで作った画像、上下反転設定の変更を検出して再生成する。MP3はシグネチャ検証後に音声素材としてプロジェクト管理下へ原本を保存し、編集画面では自動再生しない。 | すべての検証が終わった後だけAssetManifestへ確定する。成功時はステータスバーと詳細パネルにマテリアル / テクスチャの展開件数、または空の背景への設定結果と「素材を表示」を残す。新素材を`assetSelection`にできる。HDRIのテクスチャ設定では、上下反転を含む読み込み設定を編集できる。サムネイルの生成に失敗したら、準備中の表示をやめ、再試行できる通知へ切り替える。HDRI以外の素材への取り込みは明示的なシーンドロップなしにシーンを変えない。失敗時は詳細パネルを開いて原因を示す。取消時は一時ファイルを回収して直前に正常だった状態と両選択状態を維持する。 |
| MI-21 | サムネイルの生成・再生成や、古い画像かどうかの判定を行う | カードには`pending / generating / ready / stale / failed`の状態をラベルとアイコンで示す。3Dモデル、テクスチャ、マテリアルは生成済みの使用可能なサムネイルを優先し、画像がない場合だけ種類アイコンを使う。マテリアルのカードごとにWebGLコンテキストを保持しない。内容のハッシュが変わったときだけ、一つの一時レンダラーで順に画像を作る。 | 成功時は同じ素材IDのサムネイルのハッシュを更新し、画像をプロジェクトへ保存する。一時レンダラーは解放する。失敗してもカードと素材を残し、再生成と診断を確認できるようにする。直前に正常だった画像が古い場合は「古いプレビュー」と示す。 |
| MI-22 | ツールバー、メニュー、右クリックメニュー、キーボードからCommandを実行する | 共通のShortcut Registryを使い、ラベル、操作に対応するLucideアイコン、OS別のキー割り当て、実行可否の理由を全画面で揃える。選択中のツールはアイコン、ラベル、押下状態で示す。ショートカットが競合した場合は両方のCommandを実行せず、設定へ案内する。 | Commandの成功・失敗を表示する。文字・数値入力、contenteditable、IME変換中はエディターのショートカットを抑止する。キー割り当ての変更と既定に戻す操作は、エディター設定へ保存する。 |
| MI-23 | Copy / Paste / 複製 / 削除を実行する | Copyはバージョン付きのコピーバッファの対象数、Paste / 複製は生成予定数、素材削除は参照元件数を示す。文書変更を伴う操作だけをCommandの履歴に記録する。 | Paste / 複製 / 削除の元に戻す / やり直すは同じIDと前後の`sceneSelection` / `assetSelection`を復元する。Copy自体は文書の編集履歴には記録しない。参照を壊す削除は置換、解除、取消のいずれかを同じ操作に含める。 |
| MI-24 | HierarchyのEntityとその配下を、AssetsやフォルダーへドロップしてPrefabにする | ドロップ先、Prefab名、Entityと素材の依存件数、既存Prefabとの競合や循環参照を示す。成功するまで、シーン、素材、フォルダーを変更しない。 | Prefab文書と配置インスタンスの情報を一つのトランザクションで作る。`sceneSelection`は配置インスタンスのルート、`assetSelection`はPrefabにする。元に戻す、失敗、取り消しでは、全文書と両方の選択状態を元に戻す。 |
| MI-25 | 編集操作を確定する、元に戻す・やり直すを実行する、またはCtrl/Cmd+Sで即時保存する | 確定したrevisionを短い待機時間後に自動保存する。ヘッダーは「自動保存待ち」「自動保存中」「自動保存済み」「自動保存エラー」で更新する。連続した変更は最新revisionへまとめ、保存処理は直列に行う。一時的な失敗は最新revisionだけを短い間隔で最大3回再試行し、その間は「自動保存中」を保つ。Ctrl/Cmd+Sは、待機中の保存をすぐ実行する補助操作にする。 | 保存完了マーカーとすべてのハッシュが一致した後だけ、対象revisionを保存済みにする。保存中の追加編集は次の自動保存へ引き継ぐ。古い保存の完了で新しいrevisionを保存済みにしない。新しいrevisionが待機中なら古いrevisionの再試行を打ち切る。再試行の上限後も、最後に保存が成功した文書一式を保ち、編集を続けられるようにする。同じヘッダーから再試行できる。戻る操作は最新revisionの保存完了を待ち、失敗したらエディターに留まる。 |

## 実装制約

- 動きは`opacity`と`transform`を中心にし、レイアウトを押し広げたり、操作対象を移動させたりしない。
- ブランド色、影、動きは主操作、状態変化、注目すべき結果を示すときだけに使う。
- テキスト、アイコン、色、動きのうち二つ以上で状態を伝える。アイコンや色だけに意味を預けない。
- `prefers-reduced-motion`を尊重する。新しいアニメーションを追加するときは、動きを減らしても状態が分かる表示を用意する。
- 操作の開始、処理中、成功、失敗と、復帰先を揃える。待機中は主操作を無効にし、再実行できないことを示す。
- Markdown、UI文言、コミットメッセージには絵文字を使わない。

## 変更手順

1. 機能の目的と到達点を`F-xx`として書く。
2. 操作前、処理中、成功、失敗、復帰先を列挙する。
3. 各状態に対応する`MI-xx`を選び、足りなければこの文書へ項目を追加する。
4. 実装では、状態・文言・無効化・URLまたは成果物への導線を同時に作る。
5. 実機確認が必要な変更は、確認方法と副作用を実行前に伝える。必要な許可を得たうえで確認し、すでに得た許可は取り直さない。
