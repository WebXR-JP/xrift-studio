# 共通の動き（MI 一覧）

[機能一覧へ戻る](../UX_INTERACTIONS.md)

## 使い方

新しい画面や状態遷移を追加するときは既存の項目を再利用する。再利用できない場合は新しい `MI-xx` を追加し、対象の状態・開始条件・見た目の変化・操作可能な状態・終わり方を必ず明記する。動きは状態や結果を伝える必要があるときだけ付ける。

機能仕様では次の形式で参照する。

```text
F-06 アイテム検査
参照: MI-03, MI-05, MI-09
```

## 共通の動き

| ID | 状態と開始条件 | 表示と所要時間 | 操作と終わり方 |
| --- | --- | --- | --- |
| MI-01 | 画面または一覧を初めて表示する | `fade-in` で 450ms かけて下から 6px 動かし、画面が表示されたことを控えめに示す。 | 表示中も操作を妨げず、完了後は静止する。 |
| MI-02 | カードや副操作にポインターを重ねる | 背景や境界線をわずかに変え、カードは最大 4px 上へ動かす（200ms 以内）。 | クリック可能であることを示す。意味のない常時アニメーションは付けない。 |
| MI-03 | 主操作を実行する | ラベルを「実行中」へ変えてボタンを無効化し、必要に応じてログや進捗を開く。 | 二重実行を防ぎ、成功・失敗・取消可能のいずれかが確定するまで通常状態へ戻さない。 |
| MI-04 | ダイアログを開く | 背景を薄く暗くし、内容を `scale-in` で 350ms かけて 0.94 から 1.0 へ表示する。全ダイアログで余白・角丸・影・背景濃度をそろえ、画面高を超える場合はヘッダーとフッターを固定して本文のみスクロールする。狭い画面では複数列を縦に並べ、主操作と閉じる操作を画面内に残す。 | 背景クリックと Escape の扱いを明示し、処理中で安全に閉じられない場合は閉じる操作を無効にする。`prefers-reduced-motion` ではアニメーションを最小化する。 |
| MI-05 | 非同期処理が成功または失敗する | 成功・失敗のトーストを短く表示し、色だけでなく操作名と結果を文言で伝える。 | トーストだけで終わらせず、作成物・URL・ログ・再試行のいずれかを確認・操作できる状態を残す。 |
| MI-06 | 一覧の項目を表示する | 一覧全体を 100ms 遅らせ、各カードを 40ms ずつずらして `fade-in` する。 | 新規作成カードを先頭に固定し、空の状態でも作成入口を表示する。 |
| MI-07 | アップロード前に公開情報を確認する | 対象、`xrift.json` 相当のタイトル・説明、サムネイル、既存公開先 ID、保存状態とコンパイル結果の新旧、診断を 1 つの確認画面に表示し、未編集項目だけを「テンプレートのままです」と示す。 | 公開を止める問題があれば送信を止め、対象入力欄やエディターへ戻って保存・コンパイル後に再確認する。すべて整ったときだけ最終操作を有効にする。 |
| MI-08 | ローカル実行・送信・審査の結果を得る | ローカルプレビューは実行中、送信完了は ID / バージョン / 内容ハッシュ、審査中は「処理中」、公開済みは「公開済み」と別ラベルで表示し、公式結果に URL がある場合だけ URL を出す。 | ID から URL を推測して作らない。停止・状態再確認・結果コピー・エディターへ戻るのうち現在可能な操作を残し、古い結果は入力ハッシュとバージョンで区別する。 |
| MI-09 | 読み込み失敗・設定不備・空の状態になる | 落ち着いたエラーまたは空状態の画面を表示し、原因や状況を 1 文で示す。Vite の更新で遅延モジュールが古くなった場合は一度だけ自動再読み込みし、短時間の再発では繰り返さずエラー画面へ移る。 | 再試行・再読み込み・編集・作成・ログ確認のいずれか 1 つ以上を必ず配置する。 |
| MI-10 | Hierarchy やシーンで Entity を選択する（文字入力中以外の `Ctrl / Cmd + A` を含む） | クリック時のわずかなポインター移動を許容し、共通のシーン選択処理で表示中メッシュを優先して対象を決める（ライト・音声・Empty 等の原点は画面サイズ固定の補助領域で判定）。120ms 以内に Hierarchy の選択背景、シーンの選択表示、Inspector の見出しと値を同じ Entity ID へ更新し、全選択では現在の主選択を維持する。色だけに頼らない。 | カメラやギズモのドラッグでは選択を変えず、短い空領域クリックで明示的に解除する。`Ctrl / Cmd + A` は全 Entity を選択する（`input`、`textarea`、`select`、`contenteditable` では文字選択を優先）。選択だけでシーンデータや履歴は変更しない。 |
| MI-11 | Assets の素材をシーンや Hierarchy へドラッグする（「配置」、右クリックの基本形状作成、外部ファイルドロップを含む） | ドラッグ中に配置先と結果を示す。3D モデル・プレハブ・パーティクル・音声はシーンでは配置位置、Hierarchy ではシーン直下か親 Entity を示す（音声は `Audio Source` 付き Entity として作成）。マテリアルはポインター下のメッシュスロットへ、テクスチャはマテリアル設定スロットへ割り当てる。右クリック追加はクリック位置と親を示し、外部ファイルは取り込みキュー全工程を通す。 | Escape や領域外ドロップでは変更しない。ドラッグと「配置」は共通処理を使い、元に戻すで文書と操作前の `sceneSelection` / `assetSelection` を 1 履歴で復元する。取り込み失敗時は `SceneDocument` と `AssetManifest` を変えない。 |
| MI-12 | 移動・回転・拡大縮小ツールを切り替える、またはギズモを操作する | 選択中ツールを押下状態と名称で示す。ギズモは待機中の色と不透明度を抑え、ホバー軸やドラッグ軸だけを明るくしてシーンより目立たせない。操作中はシーンと Inspector の数値を同期し、カメラ操作との競合を止める。ポインター押下から解放までを 1 コマンドのトランザクションとする。 | ポインターを離すと 1 件の履歴として確定する。Escape や不正値では操作前へ戻し履歴を追加しない。Entity の選択は維持する。 |
| MI-13 | ビジュアルプロジェクトを開く・保存する・編集文書を変更する | ヘッダーには成果物種別、「ビジュアル」、保存状態だけを控えめに表示する。古いコンパイル結果は常時警告にせず、公開前確認画面で保存・公開データ作成・診断を示す。テクスチャは使用中の画像をそのまま公開する。 | 保存完了マーカーが指すシーン・プレハブ・素材・フォルダー一式をすべて保存できた後だけ対象リビジョンの「未保存」を解除する。未保存で戻るときは保存・破棄・取消を選べる。 |
| MI-14 | 「Play」を実行する、Play 中に選択 Entity の設定を変える、または「Stop」を実行する | プロジェクト種別に応じた実行コピーを中央の `Play Window` へ開き、太い境界・専用ヘッダー・「分離された実行コピー」の文言で編集シーンと区別する。Stop は同じ位置に常設し、Hierarchy と Inspector は編集データを表示し続ける。Play 中も Entity / Component 構成、Transform、衝突判定、アニメーション、既存マテリアル・パーティクルの許可プロパティ、MCP 経由シーン設定を変更できる。ワールドの入力・物理演算はアイテムへ適用しない。 | `PlaySession` は開始時スナップショットと Entity 別リビジョンを持ち、許可変更を通常コマンドとして保存する。シーン設定は共有シーンへ即時反映し、変更 Entity または変更素材を参照する Entity だけ新リビジョンで先頭から再実行する（無関係な Entity・プレイヤー・カメラ・物理状態は維持）。テクスチャ / 3D モデル設定、Inspector のマテリアル割当、ギズモ、素材ドロップは Stop まで無効にする。Stop で全実行リソースを解放して最新編集データ・両選択・編集カメラへ戻り、初期化失敗時は編集のまま原因と再試行を示す。 |
| MI-15 | Assets で素材を 1 回クリックする、または Inspector の素材参照を開く | 素材の選択背景と Inspector の対象を同じ `assetSelection` へ更新し、`sceneSelection` は維持する。Inspector ヘッダーの Entity / 素材タブで双方を行き来できる。Entity 追加や履歴追加は行わない。 | 別素材・Entity の選択やタブ切替で終わる。マテリアルには参照 Entity 数と「共有中」、テクスチャ / 3D モデルには元データと派生データの状態を表示する。 |
| MI-16 | Inspector でマテリアルやテクスチャを変更する | マテリアルは glTF 標準 PBR、`TextureInfo`、`Emissive`、`Normal Map`、`Occlusion Map`、`Alpha` / `Double Sided`、型付き拡張に分け、テクスチャは元データ・色空間・サイズ変更・Mipmap / サンプラー・圧縮・派生データ / 診断に分けて表示する。同じマテリアル ID を参照する全 Entity とライブプレビューへ即時反映し、変更後はサムネイルを古い状態として更新キューへ送る（影設定は Entity のメッシュ設定に残す）。 | 有効値の変更を `UpdateAssetCommand` 1 件として記録して `AssetManifest` を未保存にし、`SceneDocument` や Entity 固有値へ複製しない。不正値は確定せず入力欄近くに条件を示す。Play 中は既存マテリアルプロパティだけ保存・再反映でき、テクスチャ設定は読み取り専用にする。 |
| MI-17 | ビジュアルプロジェクトでコンパイル・検査・送信を開始したが、必要な実行環境が不足している | 編集画面を閉じず、Node.js・XRift CLI・認証のうち不足項目とセットアップ操作を表示する。通常の編集と保存は利用可能なままにする。 | セットアップ後は元の操作へ戻れ、取消時は編集へ戻る。`SceneDocument`、`AssetManifest`、ステージング出力、公開先は変更しない。 |
| MI-18 | 新規作成を開く | アイテム / ワールドとコード編集 / ビジュアル編集の 4 カードを同じ階層に並べ、成果物・制作方法・編集データ・作成後画面を 1 文で常時表示する（ホバー時だけに隠さない）。 | カードを選ぶと名前と保存先の確認へ進み、戻る操作で前選択を保持したまま 4 カードへ戻れる。取消ではプロジェクトを作らない。 |
| MI-19 | Assets の「作成 > マテリアル」を選ぶ | 名前、標準サーフェスまたは glTF 既定値プリセット、作成先フォルダーを小型ダイアログに表示し、作成中も Inspector を維持する。 | 成功時はマテリアルを 1 件追加して `assetSelection` にする（Entity へは割り当てない）。取消や検証失敗では `AssetManifest`・両選択・履歴を変えない。 |
| MI-20 | GLB / glTF / テクスチャ / HDRI / MP3 をドロップまたは取り込む | 下部の素材ステータスバーへ現在工程と進捗を表示し、詳細パネルで検証・コピー・解析 / デコード・派生データ生成・サムネイル生成・確定・件数・バイト数・診断を確認できる（完了を閉じずに制作継続可能）。別素材トランザクション中は入口を理由付きで無効化し並行確定を防ぐ。HDR / EXR はシグネチャ検証後に正距円筒図法環境テクスチャとして保存し、同じ履歴で空の背景へ設定したうえでトーンマッピング済みサムネイルを自動生成・再生成する。MP3 はシグネチャ検証後に原本を保存し編集画面では自動再生しない。 | 全検証通過後にだけ `AssetManifest` へ確定し、展開件数や背景設定結果と「素材を表示」を残す。サムネイル生成失敗時は準備中表示を止めて再試行通知へ切り替える。HDRI 以外の取り込みは明示ドロップなしにシーンを変えない。失敗時は詳細パネルを開いて原因を示し、取消時は一時ファイルを回収して直前の正常状態と両選択を維持する。 |
| MI-21 | サムネイルを生成・再生成する、または鮮度を判定する | カードに `pending` / `generating` / `ready` / `stale` / `failed` をラベルとアイコンで示す。3D モデル・テクスチャ・マテリアルは使用可能な生成済みサムネイルを優先し、ない場合だけ種類アイコンを表示する。マテリアルカードごとに WebGL コンテキストを保持せず、内容ハッシュ変更時だけ 1 つの一時レンダラーで順に生成する。 | 成功時は同じ素材 ID のサムネイルハッシュを更新して保存し、一時レンダラーを解放する。失敗してもカードと素材を残して再生成・診断を確認でき、古い画像には「古いプレビュー」と示す。 |
| MI-22 | ツールバー・メニュー・右クリック・キーボードからコマンドを実行する | 共通のショートカットレジストリーを使い、ラベル、Lucide アイコン、OS 別キー割り当て、実行可否の理由を全画面で統一する。選択中ツールはアイコン・ラベル・押下状態で示し、競合するショートカットはどちらも実行せず設定へ案内する。 | 成否を表示する。文字・数値入力、`contenteditable`、IME 変換中はエディターショートカットを抑止する。キー割り当て変更と初期化はエディター設定へ保存する。 |
| MI-23 | Copy / Paste / 複製 / 削除を実行する | Copy はコピーバッファーの対象数、Paste / 複製は生成予定数、素材削除は参照元件数を表示し、文書変更を伴う操作だけを履歴に記録する。 | Paste / 複製 / 削除の元に戻す・やり直しは同じ ID と前後両選択を復元する（Copy は履歴へ積まない）。参照を壊す削除では置換・解除・取消を同じ操作に含める。 |
| MI-24 | Hierarchy の Entity と配下を Assets やフォルダーへドロップしてプレハブ化する | ドロップ先、プレハブ名、Entity と素材の依存件数、既存プレハブとの競合・循環参照を表示し、成功するまでシーン・素材・フォルダーを変更しない。 | プレハブ文書と配置インスタンス情報を 1 トランザクションで作成し、`sceneSelection` を配置ルート、`assetSelection` をプレハブにする。元に戻す・失敗・取消時は全文書と両選択を元へ戻す。 |
| MI-25 | 編集を確定する、元に戻す / やり直しを実行する、または `Ctrl/Cmd+S` で即時保存する | 確定したリビジョンを短い待機時間後に自動保存し、ヘッダーを「自動保存待ち」「自動保存中」「自動保存済み」「自動保存エラー」で更新する。連続変更は最新リビジョンへまとめて直列保存し、一時失敗は最新リビジョンだけを最大 3 回再試行する（再試行中も「自動保存中」を維持）。`Ctrl/Cmd+S` は待機中保存を即座に実行する補助操作とする。 | 保存完了マーカーと全ハッシュの一致確認後にだけ保存済みにし、保存中の追加編集は次の自動保存へ引き継ぐ。古い保存完了で新しいリビジョンを保存済みにせず、新リビジョン待機中は古い再試行を打ち切る。上限失敗後も最後の正常保存データを保ってヘッダーから再試行でき、戻る操作は最新保存完了を待って失敗時はエディターに留まる。 |
| MI-26 | Play・生成ステージングプレビュー・コンパイル・検査を実行する | エディター直接 Play、生成ステージングプレビュー、検査 / ビルドに別ラベルを付け、入力識別値・対象・鮮度・進捗を表示する。診断から対象 Entity・素材・入力欄を開けるようにする。 | 現在内容とハッシュが一致する結果だけを成功とする。停止・取消でリソース後処理を行い編集へ戻る。公式仕様にない CLI / hosted / XFT プレビューは利用可能に見せない。 |
| MI-27 | 公開ダイアログを開き事前確認から送信結果まで進める | 確認・認証・保存・コンパイル・必須サムネイルコピー / SHA-256 検証・検査・送信・処理中・成功・失敗を 1 ダイアログで表示する。ワールド・アイテムともに公式 CLI のビルド付き検査を送信開始記録より前に完了させる。 | `public/thumbnail.png` コピー、SHA 一致、ビルド付き検査のいずれかに失敗したら送信を始めない。検証後は「公開用ステージングへコピー済み」を残す。閉じると編集へ戻って結果 ID を保持し、XRift で確定した後に取消済みと断定しない。URL は正式返却時のみ表示し、通常テストでは実送信しない。 |
| MI-28 | 素材フォルダーまたは素材の右クリックメニューを開く | 右クリック位置起点で右下へ開き、画面端では実寸に応じて左・上へ切り替える（Assets パネル高に制限せず、収まらない項目はメニュー内スクロール）。作成・操作ボタンからは下辺起点で開く。フォルダーと素材の種類・状態に応じて項目を出し分け、元データを持たない文書素材・組み込み素材・論理フォルダーでは物理素材ルートを開く。ショートカットとアイコンはレジストリーに統一する。 | 1 項目選択、Escape、外側クリックで閉じる。実行不可項目は理由をツールチップに表示し、開いただけでは文書・選択を変えない。エクスプローラー起動失敗時はエディターと選択を維持して確認先を示す。 |
| MI-29 | パネル境界を動かす、ヘッダーを配置領域へドラッグする、または配置を初期化する | ドラッグ中はリサイズカーソル、最小サイズ、配置プレビュー、最終順序を表示し、シーン・素材データと編集履歴は変更しない。 | ドロップで正規化した配置をエディター設定へ保存する。Escape や領域外ドロップは開始前配置へ、初期化は既定配置へ戻す。保存失敗時も現在セッションの配置を維持して再試行を示す。 |

## 実装制約

- 動きは `opacity` と `transform` を中心にし、レイアウトを押し広げたり操作対象を移動させたりしない。
- ブランド色・影・動きは、主操作・状態変化・注目すべき結果を示すときだけに使う。
- テキスト・アイコン・色・動きのうち 2 つ以上で状態を伝え、アイコンや色だけに意味を預けない。
- `prefers-reduced-motion` を尊重し、新しいアニメーションを追加するときは動きを減らしても状態が分かる表示を用意する。
- 操作の開始・処理中・成功・失敗と戻り先をそろえ、待機中は主操作を無効化して再実行不可であることを示す。
- Markdown、画面文言、コミットメッセージに絵文字は使わない。

## 変更手順

1. 機能の目的と完了条件を `F-xx` として書く。
2. 操作前・処理中・成功・失敗・戻り先を列挙する。
3. 各状態に対応する `MI-xx` を選び、不足があればこの文書へ項目を追加する。
4. 実装では状態・文言・無効化・URL または成果物への導線を同時に整える。
5. 実機確認が必要な変更は、確認方法と副作用を実行前に伝えて許可を得たうえで確認し、すでに得た許可を再度求めない。
