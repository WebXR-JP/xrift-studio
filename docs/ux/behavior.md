## F-22 3D モデルの Animation 再生

参照: MI-11, MI-13, MI-14, MI-35, MI-36, MI-54, MI-56, MI-60。保存形式と再生の詳細は [KHR_interactivity](../KHR_INTERACTIVITY_EDITOR.md#animation-belongs-to-the-graph) に従う。

- **操作前**: 3D モデルに含まれるクリップ一覧を確認できる。キーフレームを新規作成する機能とは明確に区別する。
- **操作中**: クリップを持つ 3D モデルを配置した際、再生用の Node Graph と「Interaction Trigger」を作成する。再生順・待機・繰り返しは Node Graph で編集する。
- **成功時**: 動作確認（Play）と公開ワールドで同じ Node Graph を使って再生する。保存後に再読み込みしてもクリップ参照を維持する。
- **失敗時**: クリップの欠落や未対応の操作は診断に表示し、編集対象へ戻れるようにする。
- **戻り先**: Node Graph を閉じると 3D モデルの設定へ戻る。Stop 時は動作確認中の実行状態を破棄する。

## F-28 スクリプトと Script Component の状態設計

参照: MI-03, MI-05, MI-09, MI-14, MI-69, MI-70, MI-71, MI-72, MI-73

### 編集タブ・Graph 連携・編集プレビューの基本設計

- スクリプトはシーンや Node Graph と同じ領域のタブで編集する（MI-69、MI-72）。左の一覧には検索欄、ファイル名、パス、新規作成操作を置く。ファイルを開くと読み込み状態を表示し、失敗時は再読み込みできるようにする。
- シーンや Node Graph のタブへ切り替えても、編集中のコードと元に戻す履歴を保持する。別ファイルへの切り替え時や閉じる操作では、未保存の変更がある場合に確認する。保存中は切り替えと閉じる操作を無効にし、完了後も同じコードを表示する。動作確認中に保存した場合は、そのスクリプトを使う Entity へ反映する。
- Node Graph とスクリプトの連携には、明示的な `ctx.graph.on` / `ctx.graph.emit` を使う。同じシーン内の `event/send` / `event/receive` とイベント名をそろえると、双方向に処理を開始できる。
  - 連携は実行中だけの通知とし、値の受け渡し・イベントの再送・コードと Node Graph の相互変換は行わない。
  - 停止・再起動・失敗時にはイベント購読を解除する。
- 編集プレビューは F-28、MI-70、MI-72 に従う。Inspector の「スクリプトを表示する場面」で「編集中の表示と動作確認」を選ぶと、保存済みモジュールを変換し、名前付きエクスポートの `Render` を編集画面にも表示する。開始・更新処理は Play 中に実行する。UIKit Panel テンプレートはこの設定で作成する。Stop 後は編集プレビューへ戻り、変換や描画の失敗は対象スクリプトの診断に表示する。

### 操作前

- Assets のヘッダーから「新規スクリプト」を選べる。作成ダイアログには回転、追従、マテリアル、テクスチャ、パーティクル、3D モデル表示、音源制御、ライト点滅、近接イベント送信、イベントによるライト切替の組み込みテンプレートを並べ、用途に合うアイコンとソースプレビューを添える。
  - 組み込みテンプレートには XRift 公式ショートカットと競合するキー操作を含めない。
  - Entity を選択している場合は、スクリプト作成と Script Component の追加を一度に確定できる。作成だけを選んだ場合も、作成したスクリプトを Assets で選択してエディターを開く。スクリプトを選択した状態で Component を追加すると、そのスクリプトを参照する。
- Assets ではスクリプトにコードアイコンと TypeScript / TSX のラベルを表示する。AI エディター連携からも、ソースの取得・作成・更新、Script Component への明示参照、Play / Stop を実行でき、変更時は通常エディターと同じリビジョン検査を行う。
- スクリプトエディターの API ガイドでは、次の内容を確認できる。
  - プロパティ宣言、通常テクスチャと音声の読み込み、保存済み音源・ライト制御、ワールド座標の近接イベント
  - テクスチャから継承する繰り返し・補間・Mipmap 設定、`Render` での 3D モデル表示、マテリアルのテクスチャ Transform とパーティクルの上書き
  - 実行時だけの変更と永続編集の違い、KTX2 プレビューとスクリプト用型付きローダーの境界
- 1 つの Entity に複数の Script Component を追加できる。実行順は Entity の階層順と Component の並び順で決まり、その順序を Inspector にも表示する。
- スクリプトを選ぶと、宣言されたプロパティが型どおりに Inspector へ並ぶ。テクスチャなどの素材プロパティと Entity プロパティの選択結果は、`assetReferences` / `entityReferences` にも反映する。宣言を読み取れない場合は値を推測せず、「プロパティを読み取れません」と理由を表示する。
- MCP クライアントは `get_scripting_capabilities` を使って、利用可能な `ctx.assets` / `ctx.audioSources` / `ctx.lights` / `ctx.materials` / `ctx.particles`、実行時イベント、ワールド座標と編集データの Entity 参照の境界、テクスチャ・音声ローダー、各セレクター、実行時一時操作と永続編集ツールの区別、近接送信からライト受信までの設定手順を取得できる。`list_script_templates`、`create_script_asset(templateId)`、`apply_script_template` は UI と同じバージョン 5 のカタログを使う。
- アイテムプロジェクトでは重力と Rigid Body を実行しない。物理演算 API が未対応である旨をスクリプトのドキュメントと Inspector に明記する。

### 操作中

- Play 開始時にシーンで使用するスクリプトをまとめて変換する。変換中はボタンを「準備中」にして無効化し、編集画面を表示したまま待つ。追加のスクリプト承認ダイアログは挟まず、UI・MCP ともに保存済みソースを読み込んで変換に成功してから開始する（MI-70）。更新後も再承認は求めない。スクリプトの来歴とソースのハッシュは診断情報として保持する。
- Play 中の編集と差分同期の扱いは次のとおりとする。
  - Entity の追加・削除・複製・親変更・Component 追加は編集データへ保存し、実行中のシーンへ差分同期する。
  - 回転速度や色などの宣言済みプロパティはスクリプトを再起動せず、同じインスタンスの `ctx.props` へ次フレームから反映する。
  - ソース保存、スクリプト参照、素材・Entity 参照の許可リスト、Component 構成の変更は、変換に成功した対象 Entity だけを再起動する。
  - 既存マテリアル・パーティクルのプロパティは Inspector や MCP から保存し、参照する Entity だけへ再反映する。
  - MCP からのシーン設定変更は共有シーンへ即時反映し、`update_texture_asset` はそのテクスチャを直接またはマテリアル・パーティクル経由で参照する Entity だけを再起動する。
  - テクスチャ元データの新規インポート、Inspector からのテクスチャ設定変更、Inspector でのマテリアル割り当ては Stop まで無効にする。
- 実行時 API の適用範囲を次のように限定する。
  - テクスチャ・音声の読み込みは Script Component で明示した素材だけを対象にし、スクリプトインスタンス単位でキャッシュする。`loadTexture` で省略した色空間・繰り返し・補間・上下反転・Mipmap はテクスチャ設定から継承する。
  - `ctx.audioSources` と `ctx.lights` は Entity 自身の Component だけをセレクターで選び、音声再生やライトの点灯・色・強度・Point / Spot 距離をスクリプトの所有者（owner）単位で合成する。
  - マテリアル操作は Entity 自身のメッシュ複製、パーティクル操作は Entity 自身の Emitter に限定し、子 Entity・別スロット・別 Entity・共有素材を暗黙に変更しない。後から読み込まれた音源・ライト・メッシュ・Emitter にも同じ規則を適用する。
- 近接イベント（`proximity-event`）は明示した編集データの Entity を `getWorldPosition` で判定し、`xrift:proximity-state` へチャンネル、範囲内フラグ、元データ Entity、`enter | exit | sync` を送る。出入りの通知は遷移時に一度だけ送り、同期通知は稼働中チャンネル向けと後から起動した受信側向けに分ける。
  - `event-light` はチャンネルごとに範囲内の送信元を追跡する。
  - 実行時のプレイヤー・アバターは `ctx.find` へ公開しない。スクリプトイベントは同じルート内に限定し、`KHR_interactivity` や編集データへ暗黙には接続しない。
- コードを連続入力した場合は履歴の現在項目を更新する。保存時に書き込むのは対象スクリプトのソースファイルだけとする。

### 成功時

- 全スクリプトの変換に成功した場合だけ Play へ進む。実行結果はスクリプトエディターの Console で確認でき、新しい実行時エラーが発生した場合は Console を自動で開く。
- Play 中の保存では対象スクリプトを使う Entity だけを再生成する。反映した Entity 数を短く通知し、プレイヤー位置・カメラ・物理演算の状態は維持する。
- プロパティ値の変更は回転速度・ライト点滅速度・近接半径・チャンネルなどの実行状態を保ったまま即座に見た目へ反映する。`ctx.audioSources`、`ctx.lights`、`ctx.materials`、`ctx.particles` による変更は Play 中だけ有効で、編集データ自体は書き換えない。ライトの保存対象スカラー値は既存ランタイムへ直接反映し、ライト種別や Component 構成の変更時だけ対象 Entity を再起動する。
- 公開時は一時作業フォルダーへスクリプトソースとアダプターを出力し、生成した `src/World.tsx` または `src/Item.tsx` から静的インポートする。シーンのサブツリーを Play と同じ `XriftScriptRoot` で包み、同じ `XriftScriptHost` へプロパティ、実行順、素材・Entity 参照の解決処理、任意の `Render` エクスポートを渡す。出力先パスはコンパイル結果に記録する。

### 失敗時

- 変換に失敗した場合は Play を開始せず、ファイル名・行・列・原因を一覧に表示し、該当行へ移動できるようにする。
- スクリプト実行側が管理するライフサイクル、イベント、React 描画で発生した実行時例外は、そのスクリプトだけを停止する。Entity ID、スクリプト名、処理段階、例外メッセージを Console へ出力し、シーンと他の Entity は動かし続ける。
  - `ctx.lifecycle` を使わずに開始した Promise・タイマー・ポインターコールバックの例外発生元特定、ソースマップによる行・列表示、同一例外の件数集約は未対応として扱う。
- Play 中の保存で変換に失敗した場合は、直前に動作していたスクリプトを継続実行し、失敗内容を Console へ出力する。
- 未宣言または存在しない素材 ID では `ctx.assets.url` と `loadTexture` がともに `null` を返す。URL を解決できても通常画像としてデコードできない場合は `loadTexture` だけが `null` を返す。スクリプトは処理を続けるか `ctx.log` で理由を記録し、シーン全体を停止させない。
- `ctx.assets.loadTexture` で KTX2、HDR、EXR、マテリアルを直接読み込めるようには見せない。マテリアル・パーティクルプレビュー用の KTX2 はローカルの Basis トランスコーダー、OpenBrush の組み込みテクスチャは同梱 URL を使う別経路であり、スクリプト用の型付きローダーは今後の対応課題であることを明記する。
- stdio MCP エディターツールとサーバーの境界を次のように明確にする。
  - スクリプトの作成・読取・更新、Script Component 追加、Play 切替、プロパティと明示参照の更新に加え、Play 中の Entity・Component 変更も同じリビジョン検査と差分同期経路で実行する。
  - 近接ライト設定手順ではセンサー・対象・受信側を解決し、`proximity-event` に対象参照、受信側に `core.light.*` と `event-light`、両スクリプトに同じチャンネルを設定する。
  - 永続的なライト編集は `core.light.*` の追加・更新・削除、音声編集は `import_audio_asset`、`place_asset`、`core.audio-source` の追加・更新・削除、その他の素材編集も専用ツールへ分離する。
  - `pnpm tauri:dev` のデバッグビルドだけに登録する特権付き Tauri MCP 連携は、WebView での JavaScript 実行と Tauri コマンドの `invoke` を許可する開発者向け自動操作であり、上記 stdio エディターツールとは権限境界が異なる。リリースビルドには登録・搭載せず、公開された承認経路としても扱わない。
- `https://` で始まる外部モジュールを読み込むスクリプトや、Runtime JSON 出力を選択した場合は、公開を止める診断を対象スクリプトと理由つきで表示する。
- 取り込み由来のスクリプトも追加承認なしで変換・実行し、変換失敗時は Play を開始せず Console に対象と理由を表示する。

### 戻り先

- 変換失敗時は編集状態のままスクリプトエディターの該当行へ戻る。修正後、同じ Play 操作から再試行できる。
- 実行時例外が発生した場合は、該当行への移動、そのスクリプトの再開、または Stop を選べる。
- Stop を実行すると、生成したモジュール、blob URL、タイマー、リスナー、読み込んだテクスチャ、マテリアル枠所有のテクスチャ複製、独立音声プレイヤーをすべて破棄し、実行時の音源・ライト・マテリアル・パーティクル上書きを元に戻す。Play 中に Inspector や MCP で保存した編集データはそのまま残し、編集時の選択とカメラへ戻る。
- 公開を止める診断からは該当スクリプトまたはアップロード確認画面へ戻れ、修正後に同じ画面で再検査できる。

完了条件: TypeScript でスクリプトを作成し、共通テンプレート一覧からソースプレビュー付きで追加できる。Entity へ複数の Script Component を付け、宣言したプロパティと素材・Entity 参照を Inspector で設定できる。Play 中のプロパティ変更は再起動なしで次フレームに反映され、明示参照したテクスチャ・音声や Entity 自身の音源・ライト・マテリアル・パーティクルを所有者（owner）単位で制御できる。ワールド座標による近接イベントをチャンネル経由でライト等へ連携でき、永続変更は保存・差分同期される。実行時例外は該当スクリプトだけを停止し、公開ワールドにも同じスクリプト実行基盤と参照解決を静的インポートで出力できる。MCP からも同じテンプレート・参照契約・リビジョン検査で操作できる。

## F-38 操作のトリガーの状態設計

参照: MI-05, MI-09, MI-11, MI-14, MI-25, MI-60, MI-89

`Interactable` で包む GLB は、読み込み完了後やモデルの差し替え後も照準の判定対象へ追加する。編集・Play・公開出力で共通のレイヤー追従処理を使い、公式 `Interactable` の登録・`enabled`・コールバックを維持する。未読み込み中は反応せず、読み込み後は届く距離で照準が反応してクリックできる。無効化や取り外し後は反応を解除する。モデルの当たり判定は描画メッシュを使うため、インタラクトのためだけに Collider を追加する必要はない。

### 操作前

- Component 追加メニューの Interaction カテゴリに「Interaction Trigger」を配置する。Node Graph が 1 つもない場合は Component 追加と同時に新規作成し、「On Interact」だけを配置した状態でノードエディターを開く。
- Inspector のカードには対象 Graph の選択、Graph を開く操作、押したときの処理一覧を表示する。`Interactable` が付いていない Entity では、操作できない理由と追加操作を Play 前に示す。
- ノードエディターのパレットでは「On Interact」を Event、「Set Property」「Toggle Property」を Entity の Category に並べる。追加直後の処理ノードは対象未設定であることを診断に表示する。

### 処理中

- 処理ノードを選択すると、対象 Entity、Component、プロパティを現在のシーンから選べる。Component を切り替えると、プロパティは新しい対象で有効なものへ置き換え、値ポートの型も同時に更新する。
- 値はプロパティの型に合った UI で編集する（ON/OFF はチェックボックス、数値は範囲付き入力、色はカラーピッカー、再生状態は選択肢）。生の float 配列を直接編集させない。
- 未設定、対象不在、ON/OFF 以外へのトグル指定は保存を止めず警告として問題一覧に表示し、正規形式の JSON からは削除しない。

### 成功時

- ノードカードには「SpeakerのAudio Sourceを再生する」のように対象と結果を自然な文で表示する。Inspector の一覧にも同じ文を並べ、Node Graph を開かなくても動作を把握できるようにする。
- Play では公式 `Interactable` の登録対象へ Studio がレイキャストを行い、押したときの処理を音源・ライト・Entity 表示へ適用する。公開ワールドにも同じ実行環境モジュールと正規形式の Graph を出力する。
- Trigger で後から表示する Entity は、初期状態が無効（非表示）であっても公開ワールドへ出力する。

### 失敗時

- Graph 未設定、参照先素材の欠落、操作イベントなしの場合は公開時に診断を表示する。Runtime JSON 出力では実行できないため、公開を止める診断として扱う。
- Play 中の適用は実行時限定とし、Stop で元の値へ戻す。物理コライダーは Entity の表示切替とは別扱いとし、Trigger では変更しない。

### 戻り先

- ノードエディターを閉じると元の Entity の Inspector へ戻り、「開く」からいつでも同じ Graph を開き直せる。
- 変更は元に戻す履歴と自動保存の対象にする。Graph は素材として保存し、同じ Graph を参照する他の Entity にも変更を反映する。

完了条件: Entity へ「Interaction Trigger」を追加し、公式 `Interactable` を押したときに別 Entity やその Component のプロパティを変更できる。対象・Component・プロパティ・値をノードエディター上でシーンから選べ、Inspector に動作一覧が表示される。Play・公開ワールド・MCP が同じ正規形式の Graph と適用経路を使う。

### F-28 Vehicle / Seat の追加と確認（MI-69、MI-72）

- 「アセットストア」の「ギミック」にカスタム車を、XRift 公式 Component の一覧に `Vehicle` と `Seat` を配置する。`Vehicle` とカスタム車のどちらを追加しても同じ設定済みの階層を生成する。
  - 追加前に GLB の見た目を確認でき、作成中は二重操作を防ぐ。
  - 追加後は作成した Entity を選択し、編集画面に収める。速度などは Inspector で変更でき、Script Component を削除すれば機能を外せる。
  - 作成に失敗した場合はダイアログにエラーを表示し、名前と選択内容を保持したまま再試行できるようにする。
- カスタム車を追加すると、Hierarchy に車体・運転席・同乗席・タイヤ 4 個・排気煙の編集可能な Entity 階層を展開する。
  - 見た目は通常の Mesh / Model、動きは Script として分離し、子 Entity の Transform やマテリアルを自由に編集できる。
  - 編集中は Script を実行せず、Play と公開先で同じ子 Entity を `Vehicle` / `Seat` で包む。走行中のタイヤ回転と排気煙は、同期済み `Vehicle` の移動から各参加者側で更新する。
  - GLB の遅延読み込みや差し替え後もインタラクト判定を追加する。地面追従は既定でオンとし、Inspector から切り替えられる。旧式の専用プレビューは持たない。
- World Play では、座席をクリックして着席し、WASD で公式の運転操作を行い、Space で降車する。Stop 時は座席の占有状態と移動中の車体を破棄する。文字入力中やフォーカス喪失時は操縦を止める。テンプレートには独自キー割り当てを加えず、公式 `Seat` の入力を使う。
- 「ギミック」「3Dセット」「glTFマテリアル」の一覧は基本 4 列とし、ナビゲーションと詳細ペインを除いた幅が 520px 未満では 3 列、400px 未満では 2 列に切り替える。検索・カテゴリ絞り込み・選択カードの詳細表示は維持する。
