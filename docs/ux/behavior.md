## F-22 3Dモデルの Animation 再生

参照: MI-11, MI-13, MI-14, MI-35, MI-36, MI-54, MI-56, MI-60。保存形式と再生の詳細は [KHR_interactivity](../KHR_INTERACTIVITY_EDITOR.md#animation-belongs-to-the-graph) に従う。

- 操作前: 3Dモデルのクリップ一覧を確認する。キーフレームを新しく作る機能とは区別する。
- 操作中: クリップを持つ3Dモデルの配置に合わせて、再生用のGraphと「Interaction Trigger」を作る。再生順序・待機・繰り返しはグラフで編集する。
- 成功時: 動作確認と公開ワールドが同じグラフを使って再生する。保存後の再読み込みでもクリップの参照を保つ。
- 失敗時: クリップの欠落や未対応の操作を診断に表示し、編集対象へ戻れるようにする。
- 戻り先: グラフを閉じると3Dモデルの設定へ戻る。停止時は動作確認の実行状態を破棄する。

## F-28 スクリプトとスクリプトのコンポーネントの状態設計

スクリプトは、シーンやGraphと同じ領域のタブで編集する（MI-69、MI-72）。左の一覧には検索欄、ファイル名、パス、新規作成の操作を置く。ファイルを開くと読み込み状態を表示し、失敗した場合は再読み込みできるようにする。

シーンやGraphへ移っても、編集中のコードと元に戻す履歴は保持する。別ファイルへ切り替えるときや閉じるときは未保存の変更を確認する。保存中は切り替えと閉じる操作を無効にし、完了後は同じコードを表示する。動作確認中に保存した場合は、そのスクリプトを使うオブジェクトへ反映する。

Graphとスクリプトの連携には明示的な`ctx.graph.on` / `ctx.graph.emit`を使う。同じシーン内の`event/send` / `event/receive`とイベント名を合わせると、双方向に処理を開始できる。連携は実行中だけの通知で、値の受け渡し、イベントの再送、コードとGraphの相互変換は行わない。停止・再起動・失敗時にはイベントの購読を解除する。

参照: MI-03, MI-05, MI-09, MI-14, MI-69, MI-70, MI-71, MI-72, MI-73

### 操作前

- Assetsのヘッダーから「新規スクリプト」を選べる。作成ダイアログでは、回転、追従、マテリアル、テクスチャ、パーティクル、3Dモデル表示、音源制御、ライト点滅、近接イベント送信、イベントによるライト切替の組み込みテンプレートを確認できる。各テンプレートには用途に合うアイコンとソースのプレビューを付ける。オブジェクトを選択している場合は、スクリプトの作成とScript Componentの追加を一度に確定できる。組み込みテンプレートには、XRift公式ショートカットと競合するキー操作を含めない。作成だけを選んだ場合も、作成したスクリプトをAssetsで選択してエディターを開く。スクリプトを選択した状態でComponentを追加すると、そのスクリプトを参照する。
- Assetsでは、スクリプトにコードのアイコンとTypeScript / TSXのラベルを表示する。AIエディター連携からも、ソースの取得・作成・更新、Script Componentへの明示的な参照、動作確認と停止を実行できる。変更時には通常のエディターと同じリビジョン検査を行う。
- スクリプトエディターのAPIガイドで、プロパティ、通常のテクスチャと音声の読み込み、保存済み音源 / ライト制御、ワールド座標の近接イベント、テクスチャから継承する画像の繰り返しと補間 / Mipmap設定、`Render`での3Dモデル表示、マテリアルのテクスチャTransform / パーティクル上書き、実行時だけの変更と永続編集の違い、KTX2のプレビューとスクリプト型付きローダーの境界を確認できる。
- 1つのオブジェクトに複数のScript Componentを追加できる。実行順はオブジェクトの階層順とComponentの並び順で決まり、その順序をInspectorにも表示する。
- スクリプトを選ぶと、宣言したプロパティが設定へ型どおりに並ぶ。テクスチャなどの素材プロパティとオブジェクトプロパティは選択結果を`assetReferences` / `entityReferences`へも入れる。宣言を読み取れないスクリプトは値を推測せず「プロパティを読み取れません」と理由を示す。
- MCPクライアントは`get_scripting_capabilities`で利用可能な`ctx.assets` / `ctx.audioSources` / `ctx.lights` / `ctx.materials` / `ctx.particles`、実行環境イベント、ワールド座標と編集データのオブジェクト参照の境界、テクスチャ / 音声ローダー、各セレクター、実行環境一時操作と永続ライト / 音声 / テクスチャ / マテリアルのツールの区別、近接送信からライト受信までの設定手順を取得する。`list_script_templates`、`create_script_asset(templateId)`、`apply_script_template`はUIと同じバージョン5のカタログを使用する。
- アイテムプロジェクトでは重力とRigidBodyを実行しない。物理演算のAPIが未対応であることを、スクリプトの文書とInspectorに表示する。

### 操作中

- 動作確認の開始時に、シーンで使うスクリプトをまとめて変換する。変換中はボタンを「準備中」にして無効化し、編集画面を表示したまま処理を待つ。
- 動作確認中もオブジェクトの追加・削除・複製・親変更・コンポーネント追加を編集データへ保存して実行中のシーンへ差分同期する。回転速度、色などの宣言済みプロパティ値はスクリプトを再起動せず、同じインスタンスの`ctx.props`へ次のフレームから反映する。元データの保存、スクリプト参照、素材 / オブジェクト参照の許可リスト、コンポーネント構成の変更は、変換に成功した対象オブジェクトだけを再起動する。既存マテリアル / パーティクルのプロパティは設定とMCPから保存し、参照オブジェクトだけへ再反映する。MCPのシーン設定変更は共有シーンへ即時反映し、`update_texture_asset`はテクスチャを直接またはマテリアル / パーティクル経由で参照するオブジェクトだけを再起動する。テクスチャ元データの新規インポート、設定からのテクスチャ設定、設定でのマテリアル割り当ては停止まで無効にする。
- テクスチャ / 音声読み込みはScript Componentで明示した素材だけを対象にし、スクリプトインスタンス単位でキャッシュする。`loadTexture`で省略した色空間、繰り返し、補間、上下反転、Mipmapはテクスチャから継承する。`ctx.audioSources`と`ctx.lights`はオブジェクト自身のコンポーネントだけをセレクターで選び、音声再生とライトの点灯・色・強度・Point / Spot距離をスクリプトごとのowner単位で合成する。マテリアル操作はオブジェクト自身のメッシュ複製、パーティクル操作はオブジェクト自身のEmitterへ限定する。子オブジェクト、別スロット、別オブジェクト、共有素材を暗黙に変更しない。後から読み込まれた音源 / ライト / メッシュ / Emitterにも同じ対象規則を適用する。
- `proximity-event`は明示した編集データのオブジェクトを`getWorldPosition`で判定し、`xrift:proximity-state`のデータへチャンネル、範囲内かどうか、元データオブジェクト、`enter | exit | sync`を送る。境界への出入りの通知は遷移時に一度だけ送る。同期通知は、稼働中のチャンネル向けと後から起動した受信側向けに分ける。`event-light`はチャンネルごとの範囲内にある送信元を追跡する。実行環境プレイヤー / アバターは`ctx.find`へ公開せず、スクリプトイベントは同じルート内に限定し、KHR_interactivityや編集データへ暗黙には接続しない。
- 動作確認は追加のスクリプト承認ダイアログを挟まず、保存済みの元データを読み込み、変換に成功してから開始する（MI-70）。UIとMCPで同じ手順を使い、スクリプトの更新後も再承認は求めない。準備中は編集を保ち、失敗した場合はConsoleから原因と対象ファイルを確認できる。スクリプトの来歴と元データハッシュは診断情報として保持する。
- コードを続けて入力した場合は、履歴の現在の項目を更新する。保存時に書き込むのは、そのスクリプトのソースファイルだけとする。

### 成功時

- 全スクリプトを変換できた時だけ動作確認へ入る。スクリプトエディターのConsoleから実行結果を確認でき、新しい実行時エラーでは自動的にConsoleを開く。
- 動作確認中の保存では、そのスクリプトを使うオブジェクトだけが作り直される。反映したオブジェクト数を短く示し、プレイヤー位置、カメラ、物理演算は保持する。
- プロパティ値の変更は回転速度、ライト点滅速度、近接半径、チャンネルなどの実行状態を維持したまま即時に見た目へ反映する。`ctx.audioSources`、`ctx.lights`、`ctx.materials`、`ctx.particles`の変更は動作確認中に確認でき、編集データ自体は変更しない。ライトの保存対象のスカラー値の変更は既存実行環境へ反映し、ライト種別やコンポーネント構造だけ対象オブジェクトを再起動する。
- 公開では一時作業フォルダーへスクリプト元データとアダプターを出力し、生成した`src/World.tsx`または`src/Item.tsx`から静的インポートする。シーンサブツリーを動作確認と同じ`XriftScriptRoot`で包み、同じ`XriftScriptHost`へプロパティ、実行順、素材 / オブジェクト参照の解決処理、任意の`Render`エクスポートを渡す。出力先パスをコンパイル結果に残す。

### 失敗時

- 変換に失敗した場合は動作確認を開始しない。ファイル名、行、列、原因を一覧に表示し、該当行へ移動できるようにする。
- スクリプト実行側が管理するライフサイクル、イベント、Reactの描画で起きた実行時例外はそのスクリプトだけを停止し、オブジェクトID、スクリプト名、処理段階、例外メッセージをスクリプトConsoleへ残す。シーンとほかのオブジェクトは動かし続ける。`ctx.lifecycle`を使わずに開始したPromise / タイマー / ポインターのコールバックで起きた例外の発生元の特定、ソースマップによる行・列、同一例外の件数集約は未対応として扱う。
- 動作確認中の保存で変換に失敗した場合は、直前に動いていたスクリプトを走らせ続け、失敗をConsoleへ残す。
- 未宣言または存在しない素材IDでは`ctx.assets.url`が`null`になり、`loadTexture`も`null`を返す。URLを解決できても通常画像としてデコードできないテクスチャでは`loadTexture`だけが`null`になる。スクリプトは処理を続けるか`ctx.log`で理由を残し、シーン全体を停止しない。
- `ctx.assets.loadTexture`でKTX2、HDR、EXR、マテリアルを直接読み込めるようには見せない。マテリアル / パーティクルプレビューのプロジェクト内のKTX2はローカルのBasisトランスコーダー、OpenBrushの組み込みテクスチャは同梱URLを使う別経路であり、スクリプト用型付きローダーは今後必要であることを示す。
- XRift Studioのstdio MCPエディターツールとサーバーはスクリプトの作成・読取・更新、Script Component追加、動作確認切替、プロパティと明示参照の更新に加え、動作確認中のオブジェクト / コンポーネント変更を同じリビジョン検査と差分同期経路で実行する。近接ライト設定手順はセンサー / 対象 / 受信側を解決し、`proximity-event`へ対象参照、受信側へ`core.light.*`と`event-light`、両スクリプトへ同じチャンネルを設定する。動作確認は追加承認なしで保存済みスクリプトを変換し、変換失敗時には開始しない。永続ライト編集は`core.light.*`の追加 / 更新 / 削除、音声編集は`import_audio_asset`、`place_asset`、`core.audio-source`の追加 / 更新 / 削除、ほかの素材編集も専用ツールへ分離する。
- `pnpm tauri:dev`のデバッグビルドだけに登録する特権付きのTauri MCP連携は、webview JavaScript実行とTauriコマンドの`invoke`を許す開発者向けの自動操作であり、上記stdioエディターツールとは権限の境界が異なるものとする。リリースビルドには同じ連携機能を登録・搭載せず、公開された承認経路として扱わない。
- `https://`から始まるモジュールを読むスクリプトや、実行環境JSONへの出力を選んだ場合は、アップロードを止める診断を表示する。対象のスクリプトと理由を併記する。
- 取り込み由来のスクリプトも追加承認なく変換・実行する。変換失敗時はPlayを開始せず、Consoleに対象と理由を示す。

### 戻り先

- 変換失敗時は編集のままスクリプトエディターの該当行へ戻る。修正して同じ動作確認操作から再試行できる。
- 実行時例外では該当行への移動、そのスクリプトの再開、停止のいずれかへ到達できる。
- 停止は生成したモジュールとblob URL、タイマー、リスナー、読み込んだテクスチャ、マテリアル枠所有のテクスチャ複製、独立音声プレイヤーを破棄し、実行環境音源 / ライト / マテリアル / パーティクル上書きを元へ戻す。動作確認中に設定 / MCPで保存した編集データは残し、編集の選択とカメラへ戻る。
- 公開を止める診断からは、該当するスクリプトかUploadの確認画面へ戻れる。修正後は同じ画面で再検査できる。

完了条件: スクリプトをTypeScriptで書く。共通テンプレート一覧から元データプレビュー付きで作成する。オブジェクトへScript Componentとして複数付けられる。宣言したプロパティが設定へ自動で並ぶ。素材参照とオブジェクト参照を選べる。動作確認中のプロパティは再起動なしで次のフレームへ反映する。明示参照した基本テクスチャ / 音声、オブジェクト自身の音源 / ライト / マテリアル / パーティクルをスクリプトごとのowner単位で操作できる。明示参照オブジェクトのワールド座標近接を実行環境イベントへつなぐ。ライト等の視覚効果をチャンネルで接続できる。オブジェクト / コンポーネント構成と対応する保存対象のプロパティは永続化する。ライトのスカラー値は既存実行環境へ反映する。それ以外は影響オブジェクトだけを再同期する。実行時例外は該当スクリプトだけを停止する。同じスクリプト実行側、ルート、音声 / ライト / パーティクル実行環境、参照の解決処理を公開ワールドへ静的インポートとして出力する。MCPも同じテンプレート、参照契約、リビジョン検査で作成・編集・適用・実行できる。

## F-38 操作のトリガーの状態設計

Interactableで包むGLBは、読み込み後やモデルの差し替え後も照準の判定対象へ追加する。Edit・Play・公開用出力は共通のレイヤー追従処理を使い、公式Interactableの登録・enabled・コールバックを保つ。未読み込み中は反応せず、読み込み後は届く距離で照準が反応してクリックできる。無効化・取り外し後は反応を解除する。モデルの当たり判定は描画メッシュを使うため、インタラクトのためだけにColliderを追加する必要はない。

参照: MI-05, MI-09, MI-11, MI-14, MI-25, MI-60, MI-89

### 操作前

- Componentを追加する画面のInteractionカテゴリに「Interaction Trigger」を置く。Graphが一つもない場合は、Componentの追加と同時に作成する。作成したGraphには「On Interact」だけを置き、ノードエディターで開く。
- Inspectorのカードには、対象Graphの選択、Graphを開く操作、押したときの処理一覧を表示する。Interactableがないオブジェクトでは、操作できない理由と追加の操作を動作確認前に示す。
- ノードエディターのパレットは「On Interact」をEvent、「Set Property」「Toggle Property」をEntityのCategoryに並べる。追加直後の処理は対象が未設定であることを診断に出す。

### 処理中

- 処理ノードを選ぶと、オブジェクト、コンポーネント、プロパティを現在のシーンから選ぶ。コンポーネントを変えるとプロパティは新しい対象で有効なものへ置き換え、値接続口の型も一緒に書き換える。
- 値はプロパティの型で編集する。ON/OFFはチェックボックス、数値は範囲付きの入力、色はカラー選択欄、再生状態は選択肢で示し、生のfloat配列を直接編集させない。
- 未設定、対象が見つからない、ON/OFF以外への切り替えは、保存を止めずに警告として問題の一覧へ出す。正規形式のJSONからは削除しない。

### 成功時

- ノードカードには「SpeakerのAudio Sourceを再生する」のように対象と結果を書く。設定の一覧も同じ文で、Graphを開かずに何が起きるか分かる状態にする。
- 動作確認では、公式Interactableの登録対象へStudioがレイキャストする。押したときの処理を音源、ライト、オブジェクトの表示へ適用し、公開ワールドにも同じ実行環境モジュールと正規形式のGraphを出力する。
- Triggerが表示を戻すオブジェクトは、無効なままでも非表示の状態で公開ワールドへ出力する。

### 失敗時

- Graphが未設定の場合、参照先の素材がない場合、操作イベントがない場合は、公開時に診断を表示する。Runtime JSONへの出力では実行できないため、公開を止める診断として扱う。
- 動作確認中の適用は実行時のみで、停止すると元の値へ戻る。物理コライダーはオブジェクトの表示と別で、Triggerでは変えない。

### 戻り先

- ノードエディターを閉じると同じオブジェクトの設定へ戻る。設定の「開く」から同じGraphへ再び到達できる。
- 変更は元に戻す操作とAutosaveの対象にする。Graphは素材として保存し、同じGraphを使うほかのオブジェクトにも変更を反映する。

完了条件: オブジェクトへ「Interaction Trigger」を追加する。公式Interactableを押したときに別オブジェクトやそのコンポーネントのプロパティを変えられる。対象、コンポーネント、プロパティ、値はノードエディターのシーンから選ぶ。設定には押したときの動きが一覧で残る。動作確認、公開ワールド、MCPは同じ正規形式のGraphと同じ適用経路を使う。

### F-28 Vehicle / Seat の追加と確認（MI-69、MI-72）

「外部から追加」のギミックにカスタム車を、XRift公式Componentの一覧にVehicleとSeatを置く。Vehicleとカスタム車を追加すると、同じ設定済みの階層を作成する。選択前にGLBの見た目を確認でき、作成中は二重操作を防ぐ。成功後は追加したEntityを選択し、編集画面に収める。速度などはInspectorで変更でき、Script Componentを削除すると機能を外せる。作成に失敗した場合はダイアログにエラーを残し、名前と選択内容を保って再試行する。

World Playでは、座席をクリックすると着席し、WASDで公式の運転操作へ入力する。Spaceで降車し、Stopで座席の占有状態と移動中の車体を破棄する。文字入力中やフォーカスを失ったときは操縦を止める。テンプレートには独自のキー割り当てを加えず、公式Seatの入力を使う。

カスタム車追加時はHierarchyに車体・運転席・同乗席・タイヤ4個・排気煙を展開する。見た目は通常のMesh/Model、動きはScriptとして分け、子EntityのTransformやMaterialを編集できる。EditでScriptを実行せず、Playと公開先では同じ子EntityをVehicle/Seatで包む。GLBの遅延読み込み・差し替え後にもインタラクト判定を追加する。地面追従は標準オンで、Inspectorから変更できる。レガシーの専用プレビューは持たない。

カスタム車は「外部から追加」の「ギミック」に表示する。追加時に車体・座席・タイヤ・排気煙の編集可能なEntityを展開する。走行中の回転と煙は同期済みVehicleの移動から各参加者側で更新する。

ギミック・3Dセット・glTFマテリアルの一覧は基本4列。ナビゲーションと詳細ペインを除いた一覧の内容幅が520px未満では3列、400px未満では2列にする。検索・カテゴリの絞り込みと選択したカードの詳細表示は維持する。
