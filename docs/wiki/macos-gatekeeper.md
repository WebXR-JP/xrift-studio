# macOS で開けないとき

macOS で `.dmg` を入れたあと、初回起動が **「開発元を確認できないため開けません」** という主旨の表示でブロックされることがあります。ダウンロードしたファイルが壊れているわけではなく、GitHub Releases の `.dmg` はそのまま使えます。macOS の Gatekeeper を一度だけ通す操作が必要です。

## なぜブロックされるのか

XRift Studio は有志製のため、Apple Developer Program（年額 99 USD）の署名と公証（notarization）を付けずに配布しています。ブラウザからダウンロードしたファイルには macOS が隔離属性を付けるため、公証のないアプリは初回起動時に止められます。

一度許可すれば、次回以降は通常どおり起動できます。

## 開くまでの手順（macOS 13 Ventura 以降）

1. `.dmg` を開き、**XRift Studio** を **アプリケーション** フォルダへドラッグします。
2. アプリケーションフォルダの **XRift Studio** を開こうとします。ここではまだ開けませんが、**この 1 回目の試行が必要です**。試さないと、次の手順の「このまま開く」ボタンが出ません。
3. **システム設定** → **プライバシーとセキュリティ** を開きます。
4. **「ダウンロードしたアプリケーションの実行許可」** が **App Store と確認済みの開発元**（macOS の版によっては「App Store と既知のデベロッパ」）になっていることを確認します。**App Store** だけになっていると、次のボタンが出ません。
5. 同じ画面を下へスクロールすると、「"XRift Studio" は開発元を確認できないため、使用がブロックされました」といった行と **このまま開く** ボタンが出ています。**このまま開く** を押します。
6. Touch ID かパスワードで認証します。
7. **もう一度、警告のダイアログが出ます。ここで「開く」を押します。** ここを閉じてしまうと開けないままなので、最後まで進めてください。
8. XRift Studio が起動します。次回以降は Launchpad や Dock から通常どおり開けます。

> **注意**: 手順 2 と手順 7 が抜けやすい箇所です。「一度開こうとして、設定で許可して、最後の確認でもう一度開く」という 3 段構えになっています。

## macOS 12 Monterey の場合

**システム環境設定** → **セキュリティとプライバシー** → **一般** タブを開きます。一度開こうとしたあとであれば、この画面の下部に **このまま開く** が表示されます。

## Control キーを押しながら開く方法について

以前は、アプリを Control キーを押しながらクリック（右クリック）して **開く** を選ぶと、Gatekeeper を通せました。

**macOS 15 Sequoia 以降では、この方法は使えません。** Apple が、公証のないアプリを Control クリックで許可する経路を廃止し、システム設定から許可する形に変更したためです。効かなくても操作を間違えているわけではないので、上の手順に進んでください。

## 「壊れているため開けません」と出る場合

**「"XRift Studio" は壊れているため開けません。ゴミ箱に入れる必要があります。」** と表示され、システム設定にも **このまま開く** が出ない場合があります。これは隔離属性が付いたまま署名を検証できなかったときの表示で、ファイルが実際に壊れているとは限りません。

アプリケーションフォルダへ入れたうえで、ターミナルから隔離属性を外します。

```bash
xattr -dr com.apple.quarantine "/Applications/XRift Studio.app"
```

実行後、アプリを通常どおり開きます。

> **注意**: この操作は macOS の確認を外すものです。[XRift Studio の GitHub Releases](https://github.com/WebXR-JP/xrift-studio/releases/latest) から自分でダウンロードしたファイルにだけ実行してください。

## どのファイルを選ぶか

macOS 用の `.dmg` は 1 つだけで、Apple Silicon と Intel の両方に対応した universal ビルドです。CPU に合わせて選び分ける必要はありません。

## 次に更新するとき

- **アプリ内の更新**（設定の **更新を確認**、または起動時の通知）で入れ替えた場合、ブラウザ経由のダウンロードではないため隔離属性が付かず、この手順は不要です。
- 新しい `.dmg` をブラウザからダウンロードして入れ直した場合は、同じ手順をもう一度行います。
