# XRift への公開（アップロード）

制作したワールドやアイテムを XRift に公開します。公開はエディターの中で完結し、途中の状態と結果はその場で確認できます。

## 公開の流れ

**XRiftへ公開**を押すと、確認画面から順に進みます。

| 段階 | 何が起きるか |
| --- | --- |
| 内容の確認 | 種別、タイトル、説明、サムネイル、既存の公開先、保存と変換の新しさ、診断件数を表示します。 |
| ログイン確認 | 未ログインなら、同じ画面からログインへ進めます。 |
| 保存 | 未保存の編集を確定します。 |
| 変換 | ビジュアル制作データを XRift 向けのコードへ変換します。 |
| 検査 | ビルドを含む検査を実行します。結果は APPROVE / REVIEW / REJECT で表示します。 |
| アップロード | ファイル数、容量、送信中のファイルを表示します。 |
| 審査 | 送信後の自動審査です。まだ公開されていない場合があります。 |
| 完了 | worldId / itemId、versionId、versionNumber、content hash を表示します。 |

各段階で、取り消せるかどうかと、失敗したときの戻り先が画面に出ます。審査中を公開済みとしては表示しません。公式の結果が公開 URL を返した場合だけ、そのページを開く導線が出ます。

## 公開前の確認

アップロードの直前に、`xrift.json` のタイトル・説明とサムネイルが**テンプレートのままではない**ことを確認します。未編集のままなら公開を開始せず、編集画面へ案内します。編集して保存すると、残りの項目を確認したうえでアップロードへ続けられます。

サムネイルは、現在のシーンの見た目からアップロード確認画面で保存できます。新規公開でも既存ワールドの更新でも、送信前に見直せます。

## 容量とパフォーマンスの見積り

公開前に、初回ロードの容量と回線別の推定時間、素材と実行時 VRAM の目安、容量と負荷の大きい順の内訳を確認できます。

最適化の候補（解像度の縮小、KTX2 圧縮、Draco 圧縮）は個別に選んで適用できます。適用後は変換結果と再計算された見積りを確認してから、同じ確認画面へ戻れます。

公開用のテクスチャ設定を編集画面にも使う場合は、**編集にもこの設定を適用**を押します。元画像は残り、変換した画像を使うようになります。

## 再公開する

一度公開したワールドやアイテムを更新すると、同じ公開先を更新します。公開先の ID はプロジェクト内に保存され、変換のたびに作り直される一時プロジェクトへ引き継がれます。

送信結果が不明な場合は、二重公開を防ぐため送信を保留します。XRiftで公開状況を確認し、すでに公開されていれば編集に戻ってください。公開されていないことを確認できた場合に限り、**未公開を確認して送信保留を解除**からやり直します。

## 検査で止まる場合

- **REJECT**: アップロードへ進めません。ログから対象を確認して修正します。
- **未編集のタイトル・説明・サムネイル**: 編集画面へ戻って更新します。
- **保存または変換が古い**: 保存し直すか、再変換してから進みます。

アイテムでは、ビルドを含むセキュリティチェックの結果と、修正に必要なログを同じ画面で確認できます。
