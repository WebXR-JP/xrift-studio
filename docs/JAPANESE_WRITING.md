# XRift Studioの画面名と専門用語

この文書では、画面・利用ガイドで使う名前と、機能の違いを確認できます。

## 残す表記

画面名は「ビジュアルエディター」「コードエディター」です。操作は「素材を配置する」「コードを編集する」、データは「コードプロジェクト」と書いてください。画面名と操作名を分けて案内します。

ワールドの実行・終了ボタンは「Play」「Stop」です。案内でも同じ名前を使い、機能は「動作を確認する」と説明します。録画や音声の停止操作と混同しないようにしてください。

| 名前 | 用途 |
|---|---|
| Entity | シーンに配置するもの |
| Inspector | 選択したものを編集するパネル |
| Hierarchy | Entityの階層を表示するパネル |
| Assets | モデル、画像、音声などを管理するパネル |
| Components | Entityに追加する機能の一覧・追加メニュー |

個別の機能には「Component」、データ一般には「素材」を使います。パネルを案内するときはAssetsやInspectorなど、画面に表示される名前で説明してください。マテリアル、テクスチャ、ノードも制作に必要な用語です。定義は利用ガイドで説明します。

Component名はAdd Componentのレジストリに合わせます。Mesh Renderer、Rigid Body、Box Collider、Mesh Collider、Transform、公式XRift Componentの名前は、Inspector、操作メニュー、通知でも同じ英語名を使ってください。効果や操作は日本語で説明します。

## 専門用語と日本語の使い分け

ほかの制作ツールや仕様書で使われる名前は、画面の主ラベルに残します。英語名をツールチップだけに隠さないでください。初めて使う人にも効果が分かるよう、必要な場所に短い日本語の説明を付けます。

| 名前 | 効果・用途 |
|---|---|
| Normal Map | 陰影で細かな凹凸を表す。メッシュの形や輪郭は変わらない |
| Skybox / Skybox Texture / Skybox Shader | 背景、背景画像、背景の色や動きを描くマテリアル |
| IBL | 画像を照明や反射に使う |
| Bloom | 明るい部分の光をにじませる |
| SSAO | 接地部分や隙間に陰影を加える |
| Fog | 遠景をかすませる |
| Ambient Light | 全体を均一に照らす |
| Color Grading | 明暗差や色味を調整する |

項目名にはSkyboxやBloomを使い、効果は日本語で説明します。「上空の色」「地平線の色」などの色名、「追加」「削除」などの操作名は日本語を使ってください。一般語まで機械的に英語へ置き換えないようにします。

SkyboxとIBL、Normal Mapと形状の変形、Occlusion MapとSSAO、EmissiveとBloomは、それぞれ別の設定です。見た目が似ていても説明を分けてください。ライトを含まない発光プリセットは、周囲を照らすライトとして案内しません。

Inspector、シーン設定、カタログ、ノードの選択肢、通知、利用ガイドで名前を揃えます。効果の説明に加え、入力形式・単位・条件が必要な項目では、それぞれを短く示してください。

Node Graphでは、Node、Category、Port、型の名前を英語で表示します。On Start、Branch、Sequenceなど、ほかのNode Graphや仕様書でも使われる名前を保ち、動作と接続方法は日本語で説明してください。番号付きのPortは、入力・出力とも1から始まる数字で表示します。追加、削除、整列などの操作ボタンも日本語で案内します。

新しく作るGraphの既定名は、MainやAnimationなどの英語名に揃えます。利用者が付けたGraph名は、保存済みの`graph.name`をそのまま使ってください。用途を説明するレシピ名と操作ボタンは日本語で表示します。表示名の変更でNodeの`op`、PortのID、型の識別子、保存形式は変えません。

## マテリアルの表記

項目名はglTFの英語名を基準にします。Base Color、Metallic、Roughness、Clearcoat、Iridescence、Transmissionは、その名前を表示してください。BlenderやUnityも参照できますが、シェーダーによる意味の違いを確認します。

見出しは英語名を主にし、必要なら意味が分かる短い日本語を添えます。MToonやBloomには読み方や日本語の補足を付けません。子項目では数値の方向、単位、必要条件を説明してください。ボタン、案内文、エラーは日本語で書きます。

Clearcoatには「透明な上塗り」、Iridescenceには「薄膜の虹色反射」など、効果を伝える説明を添えられます。英語の項目名は保ってください。Base ColorとDiffuse Color、RoughnessとSmoothness、AlphaとTransmissionは同じ値として扱いません。Volumeの材質の厚みと、Iridescenceの膜厚も別です。膜厚の単位はnmです。

標準マテリアルのAlphaと、動作中のマテリアルのOpacityは、編集する値が違います。APIの識別子を保ち、それぞれの用途を説明してください。音声のvolumeは「音量」で、マテリアルのVolumeとは区別します。

拡張の見出しと説明は`material-extension-registry.ts`に合わせます。単独編集、複数選択、ノードのマテリアル項目、利用ガイドでも同じ名前を使ってください。拡張IDは見出しのツールチップに残します。

## 操作と条件の確認

案内に書く名前は、現在の画面のラベルに合わせてください。プレハブの更新は「プレハブに反映」、調整する場所は「Inspector」と書きます。ノードの旧名を別名表や検索互換として追加しません。検索対象には現在の表示名、説明、操作IDを使います。

ファイルをプロジェクトへ入れる操作は「追加」「取り込み」、XRiftへ送る操作は「公開」です。GitリポジトリからのコピーはGitHubのforkと区別します。一般的な案内では「AIクライアント」「インストール」「プロジェクト」と書き、進捗IDの`npm-install`などは表示だけを日本語にしてください。

ノードでは、実行するタイミングと接続先を説明します。Set Delayの待機後の処理はDoneへ接続します。Outは待機の開始直後に進みます。Sequenceも各処理の完了を待ちません。英語名と日本語の説明を、実装と比較して確認してください。

入力条件、単位、数値の方向、共有素材への影響、未保存の変更が失われる操作、利用条件は保ちます。必要な入力条件は入力前から見える場所に表示してください。エラーでは分かっている原因と次の操作を案内し、原因が不明な場合は断定しません。送信結果が不明な場合も、確認先と二重送信を避ける手順を残します。

API名、ノードの`op`、接続口のID、JSONキー、保存済みID、URL、コマンドは変更しません。表示文の改稿では保存形式を保ち、第三者のライセンス原文と過去の検証結果も維持します。

## 確認する

画面文言を変えたら、README、利用ガイド、`docs/guide/manifest.json`の案内も確認してください。起動、新規作成、取り込み、編集、Play、保存、公開、終了の各操作と、未選択・処理中・成功・失敗・取り消しの表示を対象にします。

`node --test scripts/japanese-copy.test.mjs scripts/ui-flow-copy.test.mjs`で、用語、検索、説明、保存形式、文書参照を確認できます。画面のソースを変えた場合は`pnpm typecheck`も実行してください。実画面では文字切れ、改行、空の枠、エラー時の案内を確かめます。実施した検証と未検証の範囲は、PRの説明に記載してください。
