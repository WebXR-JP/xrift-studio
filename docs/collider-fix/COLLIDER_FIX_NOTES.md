# 当たり判定の修正

対象: `xrift-studio-authoring-workflow-no-diagnostics(1).zip` のソース。
修正版のソース一式と回帰テストをまとめたもので、Windows 向け実行ファイルではありません。

## 修正内容

### モデルが表示されても当たり判定ができない

自動コライダーの初回走査より後にモデルが読み込まれると、空の形状や読み込み中の仮の箱を使ったままになってしまう経路がありました。

- 読み込み後の Three.js オブジェクトの追加・削除を監視し、衝突形状を生成し直します。
- モデル読み込み中の仮の箱は衝突対象から除外します。
- 衝突形状の更新時に、モデル・スクリプト・Rigid Body 全体を再マウントしません。
- 描画距離や描画用インスタンシングで見た目が非表示になっても、床の衝突判定を消さないようにしています。
- Play、Classic JSX 出力、ランタイムのソースで同じ生成処理を使います。

### 既存の Mesh Collider を使う場合

「当たり判定に追加」では、既存の Component を再利用して、固定の Rigid Body・Trimesh・Trigger なしの状態にそろえます。無効な Component の再有効化、重複した Rigid Body の整理、Collider 固有の摩擦・反発・Trigger 設定の反映も修正しました。

明示的な Mesh Collider と親の自動生成が二重に適用されないようにしています。Collider の設定は削除せず、無効化して残します。

### 親・子・共有モデル

共有モデルの一部を外す場合は、親側の広い判定を解除し、残すノードごとに判定を分けます。共有モデル全体を外す場合は、子ノードに残っている判定も解除します。子に独立した Rigid Body があっても、表示モデルの親に残る自動生成を確認します。

「これだけを歩けるようにする」は、編集データ内のほかの Collider と自動生成を解除します。Script や公式ギミックの内部で独自に生成する Collider は対象外です。

### 形状・座標・読み込み待ち

- 頂点配列を直接コピーせず、アクセサーを通して読み取ります。glTF の `InterleavedBufferAttribute` にも対応しています。
- インデックスの範囲、有限な頂点値、三角形を検証し、面積のない三角形を除外します。
- 子の Transform を頂点に反映し、衝突形状は所有する Rigid Body の座標系に配置します。階層の Scale が位置に重複適用される経路を避けています。
- 反転した形状の面の向きと、`InstancedMesh` の個別 Transform を正しく扱います。
- 共有ノードや衝突用モデルの読み込みも Play の準備待ちに含めました。
- 読み込み途中でも 15 秒で歩行を強制開始してしまう処理を取り除きました。準備中は既存の表示を出し、途中で Play を停止できます。
- Trigger のみの場合は、通り抜ける設定であることを Inspector に表示します。

### この環境で実行できなかった確認

依存パッケージを取得できず、アプリ全体の型チェックは `three`、`react` などの未導入エラーで失敗しました。コンパイラー全体のフィクスチャも `three` 不足で起動できていません。Tauri / Web エディターの起動、実際のワールドを歩く操作、公開先での実機確認は未実施であり、成功扱いにはしていません。

単体テストと構文検査には Node 22.16.0 と環境内の TypeScript 5.8.3 を使用しました。プロジェクト指定の TypeScript 7.0.2 による検証ではありません。依存定義とロックファイルは変更していません。

`public/xrift-runtime-shell` は添付時の既存ファイルをそのまま残しており、再ビルドしていません。ブラウザから直接公開するための事前ビルド済みシェルに反映するには、依存導入後に以下を実行してください。

```sh
pnpm runtime:build
node scripts/build-world-runtime-shell.mjs
```

## テストの再実行

依存パッケージを導入したプロジェクトのルートで実行します。

```sh
node scripts/run-authoring-fixtures.cjs
node scripts/test-mesh-collider-physics.cjs
node scripts/check-mesh-collider-sources.cjs
node scripts/check-fixture-coverage.mjs
pnpm typecheck
pnpm cli:test
```

`run-authoring-fixtures.cjs` には Node 22.15 以降が必要です。TypeScript を別の場所に導入している場合は、`XRIFT_TYPESCRIPT_PATH` でパスを指定できます。

## 残る仕様上の注意

- 親の自動 Cuboid / Ball を、一部の子だけ除外するために自動で Trimesh に変換することはしません。形状を保ったまま分割できない場合は操作を止め、親の自動生成を解除する案内を表示します。子を持たない Entity 自身の自動 Cuboid / Ball は、追加・解除操作で置き換えられます。
- 動く Rigid Body の Trimesh を Convex Hull にする既存方針は維持しています。「当たり判定に追加」では歩行面向けの固定 Trimesh を設定します。
- Shader 変形や Skinned Mesh の毎フレームの変形に追従する衝突判定は追加していません。
- モデルの欠損や不正な形状を、仮の床で成功したように見せる処理は入れていません。

既存プロジェクトで確認するときは、一度 Play を停止してから対象メッシュを選び、「当たり判定に追加」を押して Play を再開してください。既存の Mesh Collider を手動で削除して作り直す必要はありません。
