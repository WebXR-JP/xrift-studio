## 実施した確認

`validate_assets.py` を使い、32 点すべてについて GLB ヘッダー・長さ・JSON / BIN アライメント・BufferView / Accessor の範囲・頂点属性数・三角形インデックス・座標の有限性・法線と接線の長さおよび直交性・画像の読み出し・PBR 係数・参照の整合性を検査しました。大きく裏返った法線がないことも確認しています。スムーズ法線の局所的なずれの件数は `after.json` に記録しています。

既存 29 点のバウンディングボックスは、元データと各軸 0.15mm 以内で一致します。ただし、配置位置が自動で移行されることや、形状が元モデルと同一であることを保証するものではありません。

すべての GLB は外部バッファや外部画像 URL を持たず、配布用に 1 ノード・1 メッシュにまとめています。複数の材質を持つモデルは複数プリミティブの構成です。収録スタジオの透明材質は不透明材質と混ぜずに残し、元から範囲外だった `roughnessFactor` を 0〜1 に補正しました。

Node 回帰テスト 8 件では、ハッシュ、モデル参照、焚き火・噴水・井戸のレシピ設定、リソース破棄の重複防止、非 ImageBitmap 環境への対応、読み込み待ち・遅延完了処理がコード上に存在することを確認しています。React の画面操作を再現したテストではありません。

変更した TS / TSX の構文チェック結果は `typescript-syntax.json`、回帰テスト結果は `node-tests.tap`、構造検査の集計は `validation.json` に保存しています。

## 比較から分かること・分からないこと

GLB の合計容量は約 72.5% 減り、描画プリミティブ数の合計も 189 から 110 に減りました。一方で、三角形数は 55,100 から 76,272 に増えています。実際の描画負荷は、同時に配置するモデル数、透明パーティクルの重なり、照明、端末性能によって変わるため、容量削減率をそのまま FPS 改善率とは見なしていません。

すべての画像を RGBA8 として個別に展開し、完全なミップマップ列を持つと仮定した単純計算では、旧モデル群が約 36.01 MiB、新モデル群が約 34.58 MiB です。これは画像寸法だけからの推定値であり、ブラウザや GPU での実測メモリではありません。CPU 側の画像データ、ジオメトリ、共有リソース、描画ターゲットは計算に含めていません。

## 未実施

実行環境に Blender 本体を導入できず、ネイティブな `.blend` の保存と同梱の再構築スクリプトの実行は未実施です。公式 Khronos glTF Validator も実行していません。`pnpm typecheck` は `pnpm: command not found` で開始できず、Vite / Tauri / XR 端末 / 公開先での検証も行えていません。本番ビルド、インストーラー生成、GitHub への反映も実施していません。
