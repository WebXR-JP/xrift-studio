# 3D セット用モデルの差し替え版

添付された `xrift-studio-main.zip` をもとに、XRift Studio の 3D セット用 GLB とカタログの参照を更新しました。配布物は Studio 本体のソース ZIP であり、ワールドプロジェクトやインストーラーは含みません。

## main 取り込み時の検証（2026-09-07）

海 21 種類・Skybox 33 種類を含む `main` に、モデル関連の変更だけを統合しました。以下は提供元の検証に加えて、取り込み時に実行した結果です。

- モデル変更だけを適用したチェックアウトで、本体と E2E の TypeScript 型チェックが通過しました。
- 32 点の GLB 構造・画像・ハッシュ・参照・既存 29 点の配置範囲の検査と、8 件の Node 回帰テストが通過しました。
- Three.js の `GLTFLoader` で 32 点すべてを読み込んで描画し、既存のレシピ整合性フィクスチャを実行しました。
- 実際の R3F プレビューで焚き火・噴水・井戸を確認しました。読み込みを遅らせても未完成の画像を保存しないこと、失敗表示、通常終了時および終了後に届いたモデルのジオメトリ解放を含む 4 件のブラウザテストが通過しました。

Windows でも検査・再生成スクリプトを使えるよう、テキストの読み書きを UTF-8 に統一しました。また、モデルの実際の境界サイズをカタログに記録し、井戸のように床を原点とするモデルでも全体がプレビューに収まるよう補正しています。

Blender での再構築、Tauri での実際のファイル追加・保存・再読み込み、公開先での動作、FPS・VR 実機性能は未検証です。以下に記載する提供元の未検証事項と、取り込み時の検証結果を区別して参照してください。

## 更新した範囲

`public/visual-editor/recipe-assets/` の既存 29 点を対象に、28 点を新しく造形し、収録スタジオ 1 点は元の造形を残して最適化しました。さらに焚き火の炉・噴水・井戸の石囲いを加え、配布用 GLB は合計 32 点になりました。

焚き火には、不揃いな炉石・灰・焦げた薪・切り口・熾火を作り込んでいます。噴水は、二段の石の受け皿・中央の支柱・ノズル・水面・6 本の水筋で構成しました。井戸は、内側が空いた石積みと水面を専用 GLB とし、木製の屋根・巻き上げ軸と組み合わせています。

ベンチの板と金具、松明の柄と火皿、石灯籠の開いた火袋と屋根、枝と葉が分かれた木など、ほかのモデルも形状と質感を見直しました。新規造形とテクスチャはすべて同梱の生成コードから作成したもので、写真素材や新たな第三者モデルのダウンロードは使っていません。収録スタジオに元から入っていたテクスチャの出所は `THIRD_PARTY_ASSETS.md` に残しています。リポジトリ全体のライセンスは変更していません。

公式・第三者のサンプルを収めた `starter-assets/`、Open Brush、公式 Component、音源は変更していません。利用者のインストール済みアプリ、公開サイト、GitHub リポジトリへの書き込みも行っていません。

## Blender について

今回の実行環境には Blender 本体がなく、Blender での生成・編集・再書き出しは実行できていません。完成済みの `.blend` ファイルは含みません。

配布用 GLB は Python の造形・書き出し処理で生成しています。31 点分の名前付きメッシュ、UV、法線、マテリアル定義を `tools/recipe-models/sources/*.json.gz` に保存し、それを Blender のネイティブな編集用オブジェクトに戻す `rebuild_blender.py` を同梱しました。このスクリプトは Python の構文確認まで済ませており、Blender 上での実行確認は未実施です。GLB 自体は Blender の通常の glTF インポートでも開ける形式です。

収録スタジオについては、部品名を残した元の GLB を `tools/recipe-models/sources/recording-studio.original.glb` に保存しています。これは編集用の元ファイルであり、アプリが配布する軽量版とは別です。

## 軽量化の結果

| 指標 | 元の 29 点 | 更新後の 32 点 |
| --- | ---: | ---: |
| GLB の合計容量 | 20,882,492 bytes（20.88MB） | 5,752,128 bytes（5.75MB） |
| glTF の描画プリミティブ数の合計 | 189 | 110 |
| 三角形の合計 | 55,100 | 76,272 |

GLB 容量は約 72.5% 削減しました。材質ごとにメッシュをまとめ、不要な重複頂点をインデックス化しています。テクスチャ解像度は新規モデルが 128〜256px、収録スタジオが最大 512px です。圧縮用の追加デコーダーは導入していません。

一方で、三角形の合計数は増えています。新しい 3 点を追加したほか、元が数十〜数百ポリゴンだった小物にも面取りや金具を加えたためです。すべてのモデルでファイルサイズや描画負荷が一律に減るわけではありません。プリミティブ数は GLB 内部の集計値であり、実際のフレームにおけるドローコール数とは異なります。FPS、実機の GPU メモリ、発熱は測定していません。

焚き火のパーティクル上限は合計 410 から 152 に、噴水は 520 から 80 に変更しました。これは上限値の比較であり、常時描画されるパーティクル数や FPS の実測値ではありません。

全 32 点の個別比較は [検証レポート](REPORT.ja.md) と `before.json` / `after.json` にまとめています。

## アプリ側の差し替え

`builtin-recipe-models.ts` の 32 点すべてについて、ファイルサイズ・SHA-256・内容から決まる Asset ID を更新しました。焚き火・噴水・井戸のレシピも新しい GLB を配置するように変更しています。既存 29 点のバウンディングボックスと原点の位置関係は維持しているため、松明・ベンチ・木にある配置側の高さ補正はそのまま機能します。

プレビューでは、モデルの読み込み完了を待ってから静止画を保存するようにしました。モデル更新時のキャッシュキーも変更し、プレビューを閉じたときにはジオメトリ・マテリアル・テクスチャ・ImageBitmap を解放します。画面を閉じた後に読み込みが完了したモデルも解放する処理を加えました。これらの UI 変更は実機では未確認です。

このソースで起動した Studio から新しく追加する 3D セットには、新しいモデルが使われます。既存ワールドに取り込み済みの旧モデルは自動で上書きされず、別の内容ハッシュを持つ Asset として残ります。既存ワールドに反映したい場合はバックアップを取ったうえで、新しいセットの追加と入れ替えを行ってください。

## 動きの範囲

GLB 単体は静的モデルです。焚き火の炎・煙・火の粉と噴水中央の飛沫は、Studio のレシピ側の Particle Component で動かしています。噴水の水面と 6 本の水筋は静的な形状であり、流体シミュレーション、屈折・透過の水シェーダー、アニメーションする水面は実装していません。単体 GLB に炎のアニメーションが入っているわけではありません。

既存レシピの方針に合わせ、今回追加した GLB に音や Collider は自動追加していません。

## 開発環境での確認

展開したフォルダーを既存の XRift Studio 開発環境で開いてください。`package.json`、ロックファイル、レジストリ設定は変更していません。

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm tauri:dev
```

上記は開発環境で確認するための手順です。ZIP 提供元の実行環境には `pnpm` とプロジェクトの依存パッケージがなく、`pnpm typecheck`、Vite、Tauri、実機での動作確認は実行できていません。インストーラーや本番ビルドも作成していません。

## モデルを作り直す

モデルを使うだけなら、次の手順は不要です。配布用 GLB はすでに含まれています。

```bash
python -m pip install -r tools/recipe-models/requirements-authoring.txt
python tools/recipe-models/build.py
```

このコマンドは、造形・GLB 出力・収録スタジオの最適化・カタログのハッシュ更新・構造検査までを一括で実行します。編集対象は `models.py`、`textures.py`、`geometry.py` です。テクスチャ生成を変更した場合は全点を再生成してください。形状だけを変更するときは `--only fountain` のように個別指定できます。

Blender の編集用ファイルを作成する手順（Blender 4.2 以降を想定、未実行）は次のとおりです。

```bash
blender --background --python tools/recipe-models/rebuild_blender.py
blender --background --python tools/recipe-models/rebuild_blender.py -- --only fountain campfire-base
```

`blender/` に各モデルの `.blend` を保存する設計です。`--export` を付けると `blender/exports/` にも GLB を書き出しますが、配布用の `public/` は自動で上書きしません。Blender で編集した GLB を採用する場合は、サイズ・原点・材質分割を再確認し、ファイルを差し替えたうえでハッシュ更新とアプリ側の検証を行ってください。

```bash
python tools/recipe-models/sync_catalog.py
python tools/recipe-models/validate_assets.py
node --experimental-strip-types --test scripts/recipe-models.test.mjs
pnpm exec playwright test e2e/recipe-models.spec.ts
```

構造検査には「静的・1 ノード・材質ごとにまとめた 1 メッシュ」という今回の配布条件も含めています。Blender から編集部品をそのまま書き出した場合は、この条件に合うようにまとめ直す必要があります。

## 収録物と検証結果

配布用 GLB は `public/visual-editor/recipe-assets/`、造形ソースと Blender 再構築用データは `tools/recipe-models/`、比較表・チェック結果・プレビュー画像は `docs/asset-refresh/` にあります。

32 点の GLB 構造・参照・画像の読み出し、既存 29 点の配置サイズ、ハッシュの一致を検査しました。依存パッケージなしで動く 8 件の回帰テストも通過しています。変更した TypeScript / TSX の 5 ファイルに構文エラーはなく、Python スクリプトの構文確認も通っています。ただし、これはプロジェクト全体の型チェックが通ったという意味ではありません。

同梱している提供元プレビュー画像は、生成した GLB を VTK に読み込み直してレンダリングしたものです。XRift Studio や Blender の実際の画面ではなく、動的パーティクルも写っていません。公式 Khronos glTF Validator、Blender での再構築、XRift Studio の実機起動、公開先での動作は未検証です。
