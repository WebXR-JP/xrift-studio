# 3Dセット用モデルの差し替え版

添付された `xrift-studio-main.zip` を基に、XRift Studioの3Dセット用GLBとカタログの参照を更新したソースプロジェクトです。**Studio本体のソースZIPであり、ワールドプロジェクトやインストーラではありません。**

## main取り込み時の検証（2026-09-07）

海21種類・Skybox33種類を含むmainへ、モデル関連の変更だけを統合しました。以下は提供元の検証に加えて取り込み時に実行した結果です。

- モデル変更だけを置いたチェックアウトで、本体とE2EのTypeScript型チェックが通過しました。
- 32点のGLB構造・画像・ハッシュ・参照・既存29点の配置範囲の検査と、8件のNode回帰テストが通過しました。
- Three.jsのGLTFLoaderで32点すべてを読み込み・描画し、既存のレシピ整合性fixtureを実行しました。
- R3Fの実プレビューで焚き火・噴水・井戸を確認しました。読み込みを遅らせても未完成の画像を保存しないこと、失敗表示、通常終了と終了後に届いたモデルのジオメトリ解放を含む4件のブラウザテストが通過しました。

Windowsでも検査・再生成スクリプトを使えるよう、テキストの読み書きをUTF-8に統一しました。モデルの実際の境界をカタログに保持し、井戸など床を原点とするモデルの全体がプレビューに入るよう補正しました。

Blenderの再構築、Tauriでの実ファイル追加・保存・再読込、公開先、FPS・VR実機性能は未検証です。以下にある提供元の未検証事項と、今回の検証結果を区別してください。

## 更新した範囲

`public/visual-editor/recipe-assets/` の既存29点を対象に、28点を新しく造形し、収録スタジオ1点は元の造形を残して最適化しました。さらに焚き火の炉・噴水・井戸の石囲いを加え、配布用GLBは32点になりました。

焚き火には、不揃いな炉石、灰、焦げた薪、切り口、熾火を作りました。噴水は、二段の石の受け皿、中央の支柱、ノズル、水面、6本の水筋で構成しています。井戸は、内側が空いた石積みと水面を専用GLBにし、木製の屋根・巻き上げ軸と組み合わせました。

ベンチの板と金具、松明の柄と火皿、石灯籠の開いた火袋と屋根、枝と葉が分かれた木など、他のモデルも形状と材質を見直しています。新規造形とテクスチャは同梱の生成コードから作ったもので、写真素材や新たな第三者モデルのダウンロードは使っていません。収録スタジオに元から入っていたテクスチャの出所は `THIRD_PARTY_ASSETS.md` に残しています。リポジトリ全体のライセンスは変更していません。

公式・第三者のサンプルがある `starter-assets/`、OpenBrush、公式Component、音源は変更していません。ユーザーのインストール済みアプリ、公開サイト、GitHubリポジトリにも書き込んでいません。

## Blenderについて

**今回の実行環境にはBlender本体がなく、Blenderでの生成・編集・再書き出しは実行できていません。完成済みの `.blend` ファイルは含みません。**

配布用GLBはPythonの造形・書き出し処理で実際に生成しています。31点分の名前付きメッシュ、UV、法線、マテリアル定義を `tools/recipe-models/sources/*.json.gz` に保存し、それをBlenderのネイティブな編集用オブジェクトへ戻す `rebuild_blender.py` を同梱しました。このスクリプトはPythonの構文確認までで、Blender上の実行確認は未実施です。GLB自体はBlenderの通常のglTFインポートでも開ける形式です。

収録スタジオは、部品名を残した元のGLBを `tools/recipe-models/sources/recording-studio.original.glb` に保存しています。これは編集用原本であり、アプリが配布する軽量版とは別です。

## 軽量化の結果

| 指標 | 元の29点 | 更新後の32点 |
| --- | ---: | ---: |
| GLBの合計容量 | 20,882,492 bytes（20.88MB） | 5,752,128 bytes（5.75MB） |
| glTFの描画プリミティブ数の合計 | 189 | 110 |
| 三角形の合計 | 55,100 | 76,272 |

GLB容量は約72.5%減りました。材質ごとにメッシュをまとめ、不要な重複頂点を索引化しています。テクスチャは新規モデルが128〜256px、収録スタジオが最大512pxです。圧縮用の追加デコーダーは導入していません。

ただし、三角形の合計は増えています。新しい3点を加えたほか、元が数十〜数百ポリゴンだった小物にも面取りや金具を加えたためです。全モデルのファイルサイズや描画負荷が一律に減るわけではありません。プリミティブ数はGLB内部の集計であり、実際のフレームのドローコール数ではありません。FPS・実機のGPUメモリ・発熱は測定していません。

焚き火のパーティクル上限は合計410から152へ、噴水は520から80へ変更しました。上限値の比較であり、常時描かれる粒子数やFPSの実測値ではありません。

全32点の個別比較は [検証レポート](REPORT.ja.md) と `before.json` / `after.json` にあります。

## アプリ側の差し替え

`builtin-recipe-models.ts` の32点すべてで、ファイルサイズ・SHA-256・内容から決まるAsset IDを更新しました。焚き火・噴水・井戸のレシピも新しいGLBを配置するように変更しています。既存29点のバウンディングボックスと原点の位置関係は維持しているので、松明・ベンチ・木にある配置側の高さ補正はそのまま使います。

プレビューはモデルの読み込み完了を待ってから静止画を保存します。モデル更新時のキャッシュキーも変え、プレビューを閉じた際にはジオメトリ・マテリアル・テクスチャ・ImageBitmapを解放します。画面を閉じた後に読み込みが完了したモデルも解放する処理を加えました。これらのUI変更は実機では未確認です。

**既存ワールドにすでに取り込んだ旧モデルを、自動で上書きする変更ではありません。** このソースで起動したStudioから、新しく追加する3Dセットが新しいモデルを使います。以前に取り込んだモデルは別の内容ハッシュを持つAssetとして残ります。既存ワールドへ反映する場合はバックアップを取り、新しいセットの追加と入れ替えを行ってください。

## 動きの範囲

GLB単体は静的モデルです。焚き火の炎・煙・火の粉と噴水中央の飛沫は、Studioのレシピ側のParticle Componentで動きます。噴水の水面と6本の水筋は静的な形状で、流体シミュレーション、屈折・透過の水シェーダー、アニメーションする水面は実装していません。単体GLBに炎のアニメーションが入っているわけではありません。

既存レシピの方針に合わせ、今回追加したGLBに音やColliderは自動追加していません。

## 開発環境での確認

展開したフォルダーを既存のXRift Studio開発環境で開いてください。`package.json`、ロックファイル、レジストリ設定は変更していません。

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm tauri:dev
```

上記は開発環境での確認手順です。ZIP提供元の実行環境では `pnpm` とプロジェクト依存パッケージがなく、`pnpm typecheck`、Vite、Tauri、実機での動作確認は実行できていません。インストーラや本番ビルドも作っていません。

## モデルを作り直す

モデルを使うだけなら、次の処理は不要です。配布用GLBはすでに入っています。

```bash
python -m pip install -r tools/recipe-models/requirements-authoring.txt
python tools/recipe-models/build.py
```

この処理は造形・GLB出力・収録スタジオの最適化・カタログのハッシュ更新・構造検査まで行います。編集対象は `models.py`、`textures.py`、`geometry.py` です。テクスチャ生成を変えた場合は全点を再生成してください。`--only fountain` などは形状だけを変更するときに使えます。

Blenderの編集用ファイルを作る手順（Blender 4.2以降を想定、未実行）は次のとおりです。

```bash
blender --background --python tools/recipe-models/rebuild_blender.py
blender --background --python tools/recipe-models/rebuild_blender.py -- --only fountain campfire-base
```

`blender/` に各モデルの `.blend` を保存する設計です。`--export` を付けると `blender/exports/` にもGLBを書き出します。配布用の `public/` は自動で上書きしません。Blenderで編集したGLBを採用する場合は、サイズ・原点・材質分割を再確認し、ファイルを差し替えた後にハッシュ更新とアプリ側の検証を行ってください。

```bash
python tools/recipe-models/sync_catalog.py
python tools/recipe-models/validate_assets.py
node --experimental-strip-types --test scripts/recipe-models.test.mjs
pnpm exec playwright test e2e/recipe-models.spec.ts
```

構造検査には「静的・1ノード・材質ごとにまとめた1メッシュ」という今回の配布条件も含めています。Blenderから編集部品をそのまま書き出した場合は、この配布条件へまとめ直す必要があります。

## 収録物と検証結果

配布用GLBは `public/visual-editor/recipe-assets/`、造形ソースとBlender再構築用データは `tools/recipe-models/`、比較表・チェック結果・プレビュー画像は `docs/asset-refresh/` にあります。

32点のGLB構造・参照・画像の読み出し、既存29点の配置サイズ、ハッシュの一致を検査しています。依存パッケージなしで動く8件の回帰テストも通過しました。変更したTypeScript / TSXは5ファイルで構文エラーがありません。Pythonスクリプトの構文確認も通っています。これはプロジェクト全体の型チェックが通ったという意味ではありません。

同梱の提供元プレビュー画像は、生成したGLBをVTKへ読み込み直してレンダリングしたものです。架空の完成イメージではありませんが、XRift StudioやBlenderの実画面ではなく、動的パーティクルも写していません。公式Khronos glTF Validator、Blenderの再構築、XRift Studioの実機起動、公開先での動作は未検証です。
