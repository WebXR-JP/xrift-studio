# 使い方ガイドの管理

利用者向けの原稿は `docs/guide/*.md`、目次・検索語・関連記事は `docs/guide/manifest.json` を正本とします。公開URLは従来の `/wiki/` を維持しますが、GitHub Wikiやエディター本体のSPAを表示エンジンとして使いません。

## 読み手と最初の体験

中心となる読み手は、配布アプリを使ってワールドを作る人です。主導線は「インストール → ビジュアルエディターで配置 → マテリアルで色と質感 → 保存 → Play → 公開」。AI接続、コード制作、Blenderの詳しい操作は前提にしません。

旧Wiki原稿は別フォルダーにも残さず削除しました。開発・ビルド・配布手順は `DEVELOPMENT.md` と分野別の開発文書で管理します。制作機能そのものを削除したわけではありません。

## 表示と組み込み

公開版は既存の `react-markdown` と `remark-gfm` をビルド時だけ使い、各記事を静的HTMLへ変換します。本文、見出し、目次、次のページはJavaScriptが無効でも読めます。ブラウザーへ送るJavaScriptは検索などに限定しています。本文検索は同じ原稿から生成した同一配信元の索引を使い、検索語を外部サービスへ送信しません。

`src/index.css`、3D表示、Monaco、アプリのReact起動処理を公開ガイドに読み込みません。追加のパッケージや外部検索アカウントは必要ありません。Markdownを独自の正規表現でHTML化するエンジンは作らず、既存の標準レンダラーを使い続けます。

アプリ内は `GuideHost` を一つだけ置き、`GuideLink` からページを指定します。開いたときに本文とMarkdownレンダラーを読み込むため、初回起動時に全記事を処理しません。非モーダルのヘルプパネルは編集内容を変更しません。閉じる操作と元のボタンへのフォーカス復帰を用意しています。検索機能は公開ガイドにあり、アプリ内ではページ選択・ページ内目次・関連記事を使います。

公開・問い合わせなど既存のモーダル内からは `GuideExternalLink` でブラウザーを開きます。公開フォームを閉じず、送信状態や入力値を保持し、モーダルを重ねません。ブラウザーを開けない場合は既存のToastでエラーを示します。

## ページを更新する

1. 実際の画面名・配置・入力・保存後の状態をソースとアプリで確認します。
2. 一つの目的に対して「何ができるか → 始める前に → 操作 → 成功の見分け方 → うまくいかない場合」を書きます。重要な警告は操作の前に置きます。
3. 新しい記事はmanifestへ登録し、日本語・英語・読み方を検索語に加えます。`next` は明確な次の操作がある場合だけ指定します。全記事を機械的に連結しません。
4. 初心者向けの原稿に開発手順を追加しないでください。詳細な数値一覧や特殊な用途は別記事へ分けます。
5. 原稿の先頭のh1とmanifestのtitleを一致させます。見出し付きリンクは `./materials.md#作って割り当てる` の形式で書きます。見出しIDは `guide-utils.mjs` で公開版とアプリ内版を共通化しています。
6. `reviewedVersion` / `reviewedOn` は、対象バージョンで検証した範囲に合わせて更新します。ソース確認だけなら実機確認済みと書かないでください。

Entity / Hierarchy / Inspector / Assets / Components、Base Color / Roughness / Clearcoat / Iridescenceなどの語は画面と揃え、説明を自然な日本語にします。AlphaとTransmission、SkyboxとIBL、Normal Mapと形状変形、EmissiveとBloomを同じ意味にしないでください。

## 検証コマンド

依存パッケージ導入後の通常の開発環境で実行します。既存のレジストリとlockfileを使用し、ガイドのためにそれらを切り替える必要はありません。

```sh
pnpm run test:guide
node --test scripts/japanese-copy.test.mjs scripts/ui-flow-copy.test.mjs
pnpm run typecheck
pnpm run e2e:typecheck
pnpm run build:preview
pnpm run e2e:test -- e2e/guide.spec.ts
```

`build:preview` は紹介ページに加えて `preview-dist/wiki/` を生成し、全HTMLのローカルリンク・見出し・アセットを検査します。GitHub Pagesのルート用 `404.html` も出力します。`build:wiki` はガイドのみを再生成します。開発中は `pnpm run preview:wiki` の `/wiki/` で確認できます。アプリ側の開発サーバーにも `/wiki/` のプレビュー経路があります。

公開先は従来のGitHub Pagesです。旧URLの移行ページや互換処理は用意しません。通常の `#見出し` はページを切り替えません。

## リリース前に見ること

幅320 / 390 / 768 / 1440 CSS pxで全記事の横はみ出し、本文16px以上、見出しの折り返しを確認します。本文200%拡大、キーボードでの検索・Escape・フォーカス復帰、直接URL・再読み込み・戻る、画像の代替テキスト、検索失敗・該当なしも確認します。数値表が必要な記事では表の内部だけをスクロール可能にします。

新規利用者に説明せず「導入 → 色を変えた物の保存 → Play」を試してもらいます。迷った場所、誤操作、説明に戻った場所を記録し、ページ追加より先に導線を直します。アクセス解析や外部サービスへのログ送信は今回追加していません。

実機では、初期画面からセットアップなしで編集を開始できること、保存と再開、文脈ヘルプを開いても編集内容が変わらないこと、ヘルプを閉じて作業へ戻れること、公開フォームを保持したままブラウザーへ移れることを確認してください。

## 検証記録

ZIP作成時のレビューとログは `docs/guide-review/` にあります。取り込み後の検証は[統合確認](./guide-review/INTEGRATION.md)へ記録します。添付版の検証用HTMLと、通常の依存関係・開発サーバーで実施した確認を区別してください。

`editor-layout.webp` は添付プロジェクトにあった参考画像です。今回の変更後の実機スクリーンショットではありません。公開前に現行画面を撮り直し、初回起動・マテリアル作成と割り当て・保存・Playの操作画像を追加してください。
