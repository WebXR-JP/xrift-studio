# 使い方ガイドの管理

原稿は`docs/guide/*.md`、目次・検索語・関連記事は`docs/guide/manifest.json`で管理します。公開先は`/guide/`です。

## 更新方法

実際の画面に合わせて、操作と結果を短く説明します。記事の先頭見出しとmanifestのタイトルを揃え、新しい記事はmanifestへ登録します。記事間のリンクは`./materials.md#作って割り当てる`の形式で書きます。

Entity / Hierarchy / Inspector / Assets / Componentsやマテリアル名は画面の表記に揃えます。開発手順は`DEVELOPMENT.md`と分野別の開発文書で管理します。

## 表示と公開

`pnpm run build:preview`は紹介ページと`preview-dist/guide/`の静的HTML、検索索引、404ページを生成します。ガイド専用の検査は公開条件に含めません。

ガイドだけを生成するときは`pnpm run build:guide`、開発中の確認には`pnpm run preview:guide`を使います。開発サーバーの`/guide/`から開けます。

アプリ内のヘルプは同じ原稿を使います。`GuideLink`で記事を指定し、公開フォームなどのモーダルからは`GuideExternalLink`で開きます。

## 変更の確認

必要に応じて`pnpm run test:guide`で記事のリンクを確認し、`pnpm run e2e:test -- e2e/guide.spec.ts`で表示や検索を確認できます。変更した記事はブラウザでも読み、リンク先と画面の説明が合っているか確認してください。

## 画像の撮影

2026-09-08の画像29枚の判定と撮り直し条件は、[画像の目視レビュー](./GUIDE_IMAGE_REVIEW.md)にあります。`capture-plan.json`の`review.status`が`retake-required`の画像は掲載保留です。ファイルが存在しても、そのまま記事へ戻さず、指摘を解消した実画面を撮って確認してください。

記事の画像は`docs/guide/media/`に置き、本文から`![何が写っているか](./media/<slug>.png)`の形式で参照します。画像の直後には、どこを見るかを一文のキャプション（`*...*`）で添えます。必要な撮影の一覧は`scripts/guide/capture-plan.json`で管理します。

撮影にはTauri MCPのデバッグ機能（`webview_screenshot`）を使い、現在のデスクトップ版の画面を写します。OSのファイル選択ダイアログなどネイティブUIは写らないため、撮影対象に含めません。個人情報やトークンが映らないサンプルプロジェクトで撮影します。

```bash
pnpm tauri:dev
node scripts/guide/capture-guide.mjs list     # 必要な画像と不足の一覧
node scripts/guide/capture-guide.mjs capture  # 計画の手順どおり画面を用意して順に撮影
node scripts/guide/capture-guide.mjs capture --shot first-world.png  # 1枚だけ撮り直す
pnpm run test:guide   # 画像の参照切れを確認
pnpm run build:guide  # 公開用の HTML を生成
```

`capture`は各ショットの用意ができてからEnterで撮影します。`--yes`を付けると確認なしで連続撮影します。撮影時はアプリのウィンドウを1440x900にし、画像は幅1280px以下で保存します。画像を差し替えた記事は、本文の操作名とキャプションが今の画面と合っているか読み直します。

撮影中は`docs/guide/`へ書き込みません。開発サーバーが変更を検知して再読み込みすると、開いていたプロジェクトが一覧へ戻ります。撮影した画像は一時場所に置き、確認が終わってから`media/`へまとめて配置します。初回セットアップは未セットアップ環境で撮影し、インストール先の詳細を閉じて個人のパスを写さないようにします。OS側の画面が中心の記事（インストールで困ったときなど）には画像を付けず、その理由を`capture-plan.json`の`omitted`に残します。

### 設定欄の拡大表示

1280×800の実画面は、Markdown画像のタイトルに`"セットアップ"`、`"Transform"`、`"Base Color"`、`"Metallic / Roughness"`、`"マテリアルの割り当て"`、`"Ambient Light"`、`"追加メニュー"`を指定すると、その欄を拡大表示できます。表示範囲は`src/lib/guide-image-framing.mjs`で管理し、静的ガイドとアプリ内ガイドで共有します。タイトルを省くと全体を表示します。

拡大範囲は現在の撮影構図に合わせて定めています。撮り直したら、同じ表示範囲に対象が収まることを静的ガイドとアプリ内ガイドの両方で目視確認してください。元画像は変えずに残し、ブラウザー版の画像リンクから開けます。

## 動画教材

入口は`docs/guide/video-tutorials.md`、各教材は`lesson-<章>-<番号>.md`です。各教材は動画を先に置き、その下に短い操作の要点と通常ガイドへのリンクを付けます。完成した教材だけを`manifest.json`と`tutorials.json`へ登録してください。

MP4と実動画から切り出したJPEGは`docs/guide/media/tutorials/`で管理します。MP4はH.264/AAC、1920×1080、faststartで、各ファイルと教材全体を100 MB未満に保ちます。文字の読める解像度を優先し、容量だけのために画面を読めなくしないでください。公開動画の音声・画面内素材の利用条件は`video-credits.md`で案内します。元の録音、認証情報、非公開ストレージの識別子は置きません。

本文で`[動画を再生する：題名](./media/tutorials/lesson-01-01.mp4)`を独立した段落に書くと、静的ガイドでは操作ボタン付きの動画になります。自動再生はせず、各教材ページでメタデータだけ先読みします。一覧は遅延読み込みのサムネイルのみです。JavaScriptが無効でも再生とリンクを使えます。GitHub上のMarkdownでは、同じMP4へのリンクになります。

アプリ内ヘルプにはMP4をバンドルせず、公開ガイド上の同じMP4をブラウザーで開きます。動画には通信が必要なことをリンクに明記しています。通常の手順は従来どおりアプリ内で読めます。

更新時は実ファイルの再生時間を`tutorials.json`へ反映し、全動画のデコード、音声と映像の長さ、字幕と設定欄の読みやすさを確認してください。逐語録を用意していない場合、本文を「字幕」「書き起こし」と呼ばず「操作の要点」として区別します。`pnpm test:guide`は全教材の参照、容量、プレイヤー、一覧と安全なパスを検査します。ブラウザーでも320 px幅とデスクトップ幅、再生・一時停止・シーク、検索から教材への移動、MP4を開く代替導線を確認してください。

## 制作から公開までのコース

`learning-course.md`を入口に、`curriculum.json`で章と受講順を管理します。既存の動画教材を参照する場合は`format: video`、文章だけで進める教材は`format: article`です。文章教材には「動画：未収録（文章で進められます）」を明記し、未完成の動画や仮のURLを登録しません。

各レッスンに、できるようになること、前提、具体的な手順、成功の確認、詰まりやすい点、次のレッスンを用意します。`manifest.json`の`next`は受講順に合わせます。動画を増やすだけでなく、保存・復元・送信結果不明・審査中など、途中で止まる場面の次の行動も書いてください。

公開の案内は、ブラウザ版とデスクトップ版、アップロード完了と審査通過、一覧掲載とインスタンスの参加範囲を区別します。認証情報の発行や入力、ワールドの送信、公開範囲の変更を教材作成の検証として実行しないでください。公開済みの画面名とソースを照合し、実機未確認の部分はPRに記録します。

ナレーション原稿の用意と、音声生成・映像への組み込み・聴感確認の完了は別々に管理します。音声原稿だけで「音声あり」に変更しません。原録音、声の参照先、制作環境の秘密情報はリポジトリへ含めません。
