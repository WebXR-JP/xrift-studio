# 使い方ガイドの管理

原稿は `docs/guide/*.md`、目次・検索語・関連記事は `docs/guide/manifest.json` で管理します。公開先のパスは `/guide/` です。

## 更新方法

実際の画面に合わせて、操作と結果を簡潔に説明します。記事の先頭見出しと `manifest.json` のタイトルを揃え、新しい記事を追加したら `manifest.json` へ登録します。記事間のリンクは `./materials.md#作って割り当てる` の形式で書いてください。

`Entity` / `Hierarchy` / `Inspector` / `Assets` / `Components` やマテリアル名は画面の表記に揃えます。開発手順は `DEVELOPMENT.md` と分野別の開発ドキュメントで管理します。

## 表示と公開

`pnpm run build:preview` を実行すると、紹介ページと `preview-dist/guide/` 配下の静的 HTML、検索索引、404 ページが生成されます。ガイド専用の検査は公開条件に含めていません。

ガイドだけを生成したいときは `pnpm run build:guide`、開発中の確認には `pnpm run preview:guide` を使います。開発サーバーの `/guide/` から確認できます。

アプリ内ヘルプも同じ原稿を使います。画面内からは `GuideLink` で記事を指定し、公開フォームなどのモーダルからは `GuideExternalLink` で開きます。

## 変更の確認

必要に応じて `pnpm run test:guide` で記事のリンク切れを確認し、`pnpm run e2e:test -- e2e/guide.spec.ts` で表示や検索の動作を確認できます。変更した記事はブラウザでも開き、リンク先と画面の説明が一致しているか確認してください。

## 画像の撮影

2026-09-08 に実施した画像 29 枚の判定と撮り直し条件は、[画像の目視レビュー](./GUIDE_IMAGE_REVIEW.md) にまとめています。`capture-plan.json` の `review.status` が `retake-required` の画像は掲載保留です。ファイルが残っていてもそのまま記事へ戻さず、指摘を解消した実際の画面を撮り直して確認してください。

記事の画像は `docs/guide/media/` に配置し、本文から `![何が写っているか](./media/<slug>.png)` の形式で参照します。画像の直後には、どこを見ればよいかを 1 文のキャプション（`*...*`）で添えます。必要な撮影項目の一覧は `scripts/guide/capture-plan.json` で管理します。

撮影には Tauri MCP のデバッグ機能（`webview_screenshot`）を使い、現在のデスクトップ版の画面をそのまま撮ります。OS のファイル選択ダイアログなどネイティブ UI は写らないため、撮影対象に含めません。個人情報やトークンが映り込まないサンプルプロジェクトで撮影してください。

```bash
pnpm tauri:dev
node scripts/guide/capture-guide.mjs list     # 必要な画像と不足の一覧
node scripts/guide/capture-guide.mjs capture  # 計画の手順どおり画面を用意して順に撮影
node scripts/guide/capture-guide.mjs capture --shot first-world.png  # 1枚だけ撮り直す
pnpm run test:guide   # 画像の参照切れを確認
pnpm run build:guide  # 公開用の HTML を生成
```

`capture` は各ショットの準備ができてから Enter を押して撮影します。`--yes` を付けると確認なしで連続撮影します。撮影時はアプリのウィンドウサイズを 1440×900 にし、画像は幅 1280px 以下で保存します。画像を差し替えた記事は、本文の操作名とキャプションが現在の画面と合っているか読み直してください。

撮影中の注意事項は次のとおりです。

- 撮影中は `docs/guide/` へ直接書き込まないでください。開発サーバーが変更を検知して再読み込みすると、開いていたプロジェクトが一覧へ戻ります。撮影した画像はいったん一時フォルダーへ置き、確認後に `media/` へまとめて配置します。
- 初回セットアップは未セットアップ環境で撮影し、インストール先の詳細欄を閉じて個人のパスが写らないようにします。
- OS 側の画面が中心の記事（インストールで困ったときなど）には画像を付けず、その理由を `capture-plan.json` の `omitted` に記録します。

### 設定欄の拡大表示

1280×800 の画面キャプチャは、Markdown 画像のタイトルに `"セットアップ"`、`"Transform"`、`"Base Color"`、`"Metallic / Roughness"`、`"マテリアルの割り当て"`、`"Ambient Light"`、`"追加メニュー"` を指定すると、該当する欄を拡大表示できます。表示範囲は `src/lib/guide-image-framing.mjs` で管理し、静的ガイドとアプリ内ガイドで共有します。タイトルを省略すると全体を表示します。

拡大範囲は現在の撮影構図に合わせて調整しています。画像を撮り直したときは、対象が同じ表示範囲に収まることを静的ガイドとアプリ内ガイドの両方で目視確認してください。元画像は加工せずに残しており、ブラウザ版では画像リンクから全体を開けます。

## 動画教材

入口は `docs/guide/video-tutorials.md`、各教材は `lesson-<章>-<番号>.md` とします。各教材では動画を先頭に置き、その下に短い操作の要点と通常ガイドへのリンクを添えます。完成した教材だけを `manifest.json` と `tutorials.json` に登録してください。

MP4 と実動画から切り出した JPEG は `docs/guide/media/tutorials/` で管理します。MP4 は H.264 / AAC、1920×1080、faststart 形式で作成し、各ファイルおよび教材全体の容量を 100 MB 未満に収めます。容量削減のために画面の文字が読めなくならないよう、可読性を優先してください。公開動画の音声や画面内素材の利用条件は `video-credits.md` で案内します。元の録音データ、認証情報、非公開ストレージの識別子はリポジトリに置かないでください。

本文で `[動画を再生する：題名](./media/tutorials/lesson-01-01.mp4)` を独立した段落に書くと、静的ガイドでは操作ボタン付きの動画プレイヤーとして表示されます。自動再生は行わず、各教材ページではメタデータだけを先読みします。一覧ページでは遅延読み込みのサムネイルだけを表示します。JavaScript が無効な環境でも再生とリンクを利用でき、GitHub 上の Markdown では同じ MP4 へのリンクとして機能します。

アプリ内ヘルプには MP4 を同梱せず、公開ガイド上の同じ MP4 をブラウザで開く形にします。動画再生に通信が必要であることはリンク文言に明記しており、通常の手順解説は従来どおりアプリ内で読めます。

動画教材を更新するときは、次の点を確認してください。

- 実ファイルの再生時間を `tutorials.json` に反映し、全動画のデコード、音声と映像の長さ、字幕や設定欄の読みやすさを確認する。
- 文字起こしを用意していない場合、本文を「字幕」や「書き起こし」とは呼ばず、「操作の要点」として区別する。
- `pnpm test:guide` で全教材の参照、容量、プレイヤー、一覧、パスの安全性を検証する。
- ブラウザでも 320px 幅とデスクトップ幅の表示、再生・一時停止・シーク、検索からの移動、MP4 を直接開く代替導線を確認する。

## 制作から公開までのコース

第 0 章の `course-introduction.md` では、XRift と XRift Studio の関係、ワールドとアイテムの違い、各制作方法でできることを説明します。初めて触れる人が操作やコードの学習前に読めるよう、ガイドの最初の案内とコースの先頭からリンクします。

`learning-course.md` を入口とし、`curriculum.json` で章立てと受講順を管理します。既存の動画教材を参照する場合は `format: video`、文章だけで進める教材は `format: article` を指定します。文章教材には「動画：未収録（文章で進められます）」と明記し、未完成の動画や仮の URL は登録しません。

各レッスンには、できるようになること、前提、具体的な手順、成功の確認、詰まりやすい点、次のレッスンを用意し、`manifest.json` の `next` を受講順に合わせます。動画の本数を増やすだけでなく、保存・復元・送信結果不明・審査中など、制作や公開の途中で立ち止まりやすい場面の対処法も記載してください。

公開に関する案内では、ブラウザ版とデスクトップ版の違い、アップロード完了と審査通過の違い、一覧掲載とインスタンスの参加範囲の違いを明確に区別します。教材作成の検証として、認証情報の発行・入力、ワールドの送信、公開範囲の変更は実行しないでください。公開済みの画面名とソースコードを照合し、実機で未確認の部分は PR に明記します。

ナレーション原稿の作成と、音声生成・映像への組み込み・聴感確認の完了は分けて管理します。原稿ができただけで「音声あり」には変更しません。原録音データ、音声の参照先、制作環境の秘密情報はリポジトリに含めないでください。
