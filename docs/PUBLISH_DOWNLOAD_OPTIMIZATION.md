# 公開時のダウンロード容量削減

XRift へ渡す公開用コピーから、使われていない素材と、Studio のマテリアルで置き換え済みの GLB 内蔵画像を除外する。編集用の原本データと通常の Play 動作には影響を与えない。

## 処理のタイミング

公開準備の段階で参照関係を調べ、GLB の変換結果を内容と変換条件ごとにキャッシュする。配置位置やタイトルだけの変更であればキャッシュを再利用し、初回の圧縮処理を Play 開始時に挟まない。デスクトップ版の公開、ブラウザ版アップロード、コードプロジェクトへの書き出し、CLI 変換のすべてで同じ GLB 処理を使う。

初版では画質や形状を変える再圧縮や UV の切り出しは行わない。GLB のノード、メッシュ、マテリアル、アクセサの番号とデータはそのまま維持し、不要な画像とその格納領域だけを整理する。Draco のバイト列も再圧縮しない。未知の拡張や解析できないデータを含む場合や、変換後に容量が増える場合は原本を使う。

マテリアルを除外できるのは、同じ 3D モデルを使うすべてのメッシュで該当スロットが置き換えられている場合に限る。スクリプトなど、マテリアル差し替えを経由せず 3D モデルを利用する可能性がある参照は変換対象から外す。無効化された Entity や Component、スクリプトとノードグラフの `assetReferences`、マテリアルのテクスチャ、シェーダーのユニフォームなどの依存素材は公開対象として残す。`importedFromModel` や `optimizedFrom` は編集時の由来情報であり、公開依存には含めない。

## 状態と確認（F-27、MI-04、MI-07）

- 操作前: 既存の公開前確認からそのまま進む。独立した編集操作は増やさない。
- 処理中: 公開の進捗表示に対象の 3D モデルと処理内容を示す。既存の二重実行防止と中断処理に従う。
- 成功: ログに GLB の変換前後の容量とキャッシュ再利用の有無を記録し、既存の公開結果 URL へ進む。
- 失敗: 最適化できない GLB は理由をログに残したうえで原本を使って続行する。元ファイルの読み込みに失敗した場合は公開エラーとし、再試行へ戻す。
- 検証: GLB だけでなく外部テクスチャも含めた公開ファイル全体の合計容量を確認する。公開前の容量表示は原本に基づく概算であり、変換後の実測値とは区別する。

この処理は既存の公開・書き出し操作へ自動的に組み込むため、専用の MCP 操作は追加しない。

## ブラウザ版の配布

ランタイム JSON でもマテリアルスロットの既定割り当てを出力し、読み込み時はメッシュ内の配列位置より glTF のマテリアル番号を優先する。古いランタイムで内蔵画像を除くと一部メッシュで差し替え先を見失うため、ランタイム契約を `2026-09-06-model-instancing-v1` に更新する。

ブラウザ版を配布する前に `node scripts/build-world-runtime-shell.mjs` でシェルを再生成し、`pnpm runtime:shell:check` で一致を確認する。古いシェルでの公開は拒否する。デスクトップ版の JSX 公開は、この事前生成シェルに依存しない。
