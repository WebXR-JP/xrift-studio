# 公開時のダウンロード容量削減

XRiftへ渡す公開用コピーから、使わない素材と、Studioのマテリアルで置き換え済みのGLB内蔵画像を除く。編集用原本と通常の動作確認は変更しない。

## 処理のタイミング

公開準備で参照を調べ、GLBの変換結果を内容と変換条件でキャッシュする。配置位置やタイトルだけの変更では変換結果を再利用する。初回の圧縮処理を動作確認開始へ追加しない。公開、ブラウザアップロード、コード編集書き出し、CLI変換で同じGLB処理を使う。

初版では画質・形状を変える再圧縮やUVの切り出しを追加しない。GLBのNode、メッシュ、マテリアル、Accessorの番号とデータは保持し、不要画像とその格納領域だけを整理する。Dracoのバイト列も再圧縮しない。未知の拡張や解析できないデータは原本を使う。変換後に容量が増える場合も原本を使う。

マテリアルを外せるのは、同じ3Dモデルを使う全メッシュでそのSlotが置き換わる場合だけ。スクリプトなど、マテリアルの差し替えを通らずに3Dモデルを使う可能性がある参照は変換対象から外す。無効なオブジェクト・コンポーネント、スクリプトとGraphのassetReferences、マテリアルのテクスチャ、シェーダーのuniformなどの依存も公開対象へ残す。importedFromModelやoptimizedFromは編集用の由来であり公開依存にしない。

## 状態と確認（F-27、MI-04、MI-07）

- 操作前: 既存の公開前確認から進む。独立した編集操作を増やさない。
- 処理中: 公開の進捗に対象3Dモデルと処理内容を表示する。既存の二重実行防止と中断処理に従う。
- 成功: ログにGLBの変換前後の容量とキャッシュ再利用を記録し、既存の公開結果URLへ進む。
- 失敗: 最適化できないGLBは理由をログへ残し、原本で続行する。元ファイルの読み込み失敗は公開エラーとして再試行へ戻す。
- 検証: GLBだけでなく外部テクスチャを含む公開ファイルの合計を確認する。公開前の容量表示は原本を基にした概算であり、この変換後の実測値とは区別する。

この処理は既存の公開・書き出し操作に自動適用するため、専用のMCP操作は追加しない。

## ブラウザ版の配布

Runtime JSONでもマテリアル Slotの既定割当を出力し、読み込み時はglTFのマテリアル番号をメッシュ内の配列位置より優先する。古いランタイムで内蔵画像を除くと、一部のメッシュで差し替え先を見失うため、ランタイム契約を`2026-09-06-model-instancing-v1`へ更新する。ブラウザ版を配布する前に`node scripts/build-world-runtime-shell.mjs`でシェルを再生成し、`pnpm runtime:shell:check`で一致を確認する。古いシェルでの公開は拒否する。デスクトップのJSX公開はこの事前生成シェルに依存しない。
