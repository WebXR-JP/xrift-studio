# ワールド制作用ハーネス

ここでいうハーネスは、LLM がワールドを制作するための実行環境と制御の仕組みを指す。プロンプトやスキルに加え、MCP ツール、状態の取得、実行権限、画像による検証、失敗時の復帰を含む。特定の LLM の文体を指す言葉ではない。

MCP の説明文とツールは、依頼に合ったワールドを制作し、画像で結果を確認できるように整える。具体的な工程と設計図の書式は [ワールド制作スキル](../.agents/skills/xrift-world-direction/SKILL.md) にまとめる。

## 各文書と実装の役割

| 場所 | 残す内容 |
| --- | --- |
| `src-tauri/src/mcp.rs` の instructions | MCP クライアントが最初に読む制作手順と権限 |
| tool の description | 操作の目的、選ぶ基準、操作後の確認、失敗しやすい条件 |
| tool の戻り値 | 現在の状態、診断、次に確認する内容 |
| ワールド制作スキル | 設計図、作業の順序、素材の選び方、完了報告 |
| この文書 | ツールとスキルを変更するときの設計判断 |

外部の制作プロジェクトから接続するクライアントには、このリポジトリのスキルや文書が届くとは限らない。必要な操作説明は MCP の instructions と description にも含める。

## 設計判断

- 床の種類、品質、主役、予算は依頼と設計図に基づいて決める。カタログやツールの数が多いという理由で Terrain や草を選ばせない。
- 素材の入手先に一律の順位を付けない。モデルの形状・容量・ライセンスと、依頼に合うかを確認する。
- 空・環境光・フォグをまとめて確認する。ポストエフェクトは有効にする前後の画像を比較する。
- 回数、三角形数、ライト数などの制作予算は、依頼と公開先に応じて設計図で決める。固定の上限や過去の作例をスキルへ追加して選択肢を狭めない。
- 動きや繰り返しには Script も検討する。Script の承認、ログイン、公開の権限は既存の境界を守る。
- 完了の判断にはスポーン位置と俯瞰からの画像を使う。metrics と document だけで見た目を判断しない。

## 実装による支援

`src/lib/visual-editor/mcp-harness-guard.ts` は、画像を確認せず同じ種類の編集を繰り返したときに警告を返す。Terrain、草、同じ Entity の Transform、同じ Material、Scene 設定の書き込みが、`capture_scene_view` を挟まず 3 回続くと `harness` を付ける。書き込みは拒否しない。カウンターはセッション内だけに持ち、project に保存しない。

外部モデルの検索結果には `polycount` と `dimensionsMm` を含め、取り込む前に予算と比較できるようにする。配置後は接地と Material を画像で確認する。

同じ失敗が続く場合は、説明文、戻り値、制作手順、カタログの構成を調べて直す。過去の失敗談やモデルへの評価を追加する代わりに、判断に必要な情報を返す。

追加機能の候補は [ロードマップ](./VISUAL_EDITOR_ROADMAP.md#今後検討する項目)、ツールの権限と一覧は [MCP ツール](./MCP_EDITOR_TOOLS.md) を参照する。

## 参考にする設計

独自の実行ループを試す実装は [ワールド制作ハーネスの試作](../dev/world-harness/README.md) にある。モデル接続、通常の stdio MCP 接続、履歴からの再開、画像と完成条件による判定を分離している。現時点ではアプリ本体へ組み込まず、CLI で検証する。

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) は、モデル接続、ツール、セッション記録、実行ループをプラグインとして構成する。[アーキテクチャ資料](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)では、ツール実行の前後に介入する仕組みと、モデルに渡した情報をセッションログから再構成する設計も説明している。

XRift Studio では、この設計を次の検討に役立てる。以下は今後の設計の観点であり、DeepSeek Harness を導入済みという意味ではない。

- モデルやクライアントを変更しても、制作ツールの入出力・権限・検証方法を共通に保つ。
- 操作前の revision 確認と、操作後の結果・画像の確認を、説明文だけでなく実行経路で支える。
- 制作の再開に必要な設計図、操作結果、検証結果を記録する。セッション内の一時的な警告カウンターとは保存目的を分ける。
- 素材の取得や検証方法を追加するときは、役割ごとに交換・拡張できる構成を検討する。
