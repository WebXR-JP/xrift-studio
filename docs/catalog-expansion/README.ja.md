# 外部カタログ拡充 — glTFマテリアル50種類・ギミック50種類

更新日: 2026年9月8日。添付された `xrift-studio-main (3).zip` を元にしたソースコードの更新です。公開サイト・GitHub・既存のインストール先は変更していません。

## 追加した内容

| 対象 | 更新後 | 主な変更 |
| --- | ---: | --- |
| glTFマテリアル | 50種類 | Emissive、拡張マテリアル、Normal Map・ORM・UV・Alphaの比較 |
| ギミック | 50種類 | 扉・動き、照明、音、パーティクル、状態表示、組み合わせ |
| 専用モデル | 新規12個 | 花器、ボトル、布、宝石、溝付きの質感見本、パネル、操作ボタンなど |
| テクスチャ | 新規46枚 | 512×512 PNG。基本色・Normal・ORM・発光マスク・Alpha |

マテリアルにはテクスチャ付きの見本が32種類あり、Emissiveは7種類です。そのうち6種類は画像によって発光箇所を分ける見本です。新規のGLBとPNGは合計約4.51 MiBです。既存の3Dセットと保存済みのレシピIDは保持しています。

色だけを変えた一覧ではなく、比較する機能・表面・形状・操作が分かるセットとして追加しました。マテリアルは同じ形状の左右比較に統一し、ギミックには操作と編集の手順を付けています。

## 利用する場所

「外部から追加」から「マテリアル表現 > glTFマテリアル」または「ワールド機能 > ギミック」を開きます。マテリアルはワールドとアイテムの両方で50種類、ギミックはワールド向けです。

検索・分類から候補を選び、右側の詳細で比較条件や操作手順を確認します。Emissiveには専用の絞り込みボタンがあります。「テクスチャ付き」では、実際に画像を参照する見本だけを表示します。条件に合う候補がない場合は「条件をリセット」で戻れます。

詳細の見本はドラッグで回転し、ホイールで拡大できます。カタログ内のボタンはギミックを実行するものではありません。「シーンに追加」した後、棚を閉じてPlayで確認してください。追加後は通常のEntity、Material、テクスチャ、Component、Interactivity Graphとして編集できます。

## 見本の変更

比較の形状・向き・大きさを揃え、左右の台座、背景ライン、比較条件を用意しました。文字は3D内だけでなく詳細ペインにも表示します。透過の見本では背景ライン、反射の見本ではスタジオ環境光を使って違いを確認できます。布は折り目、宝石は平らなカット面、金属は溝のあるモデルで見比べます。

GLBにはUVとTANGENTを保存しています。Normal Mapで凹凸を、ORMのR・G・BでそれぞれAO・Roughness・Metallicを指定します。色と発光マップはsRGB、NormalとORMは線形データとして取り込みます。Alpha見本には本当の透明部分を持つPNGを使っています。

一覧は静止画を順番に生成し、選択した詳細だけをライブ表示します。GLBとテクスチャの読み込み完了を待ってからサムネイルを保存し、失敗時は欠落した見本を完成扱いにしません。50個のライブWebGL画面を同時に増やす実装にはしていません。

## 追加処理とMCP

モデルのMaterialは実際に読み込んだスロットへ割り当てます。必要なPNGはバイト数とSHA-256を確認し、既存のAsset取り込み処理でプロジェクトへ保存します。同じ画像を取り込み済みなら再利用します。シーンへ追加した後も、カタログの配信場所を参照し続ける仕組みではありません。

追加中は重複操作を止め、途中で別のプロジェクトや編集内容へ切り替わった場合は古い状態を上書きしません。SceneとAssetManifestの確定は取り込み後にまとめて行います。途中失敗した場合、使用されていない取り込みファイルがディスクに残る可能性はありますが、欠けたセットをSceneへ確定しません。

MCPの `list_scene_recipes` は分類・検索語・比較ラベルを返します。`apply_scene_recipe` で同じ見本一式を追加できます。`list_material_presets` は必要なテクスチャIDも返し、`create_material_from_preset` は画像を取り込んでからMaterialを確定します。表示だけの絞り込み・回転操作用に新しいtoolは増やしていません。

## 見え方・動作の前提

見本のスタジオ照明は比較用であり、配置先へは追加しません。配置先のSkyboxや環境光によって見え方は変わります。Emissiveは表面の発光で、周囲の照明にはLightが必要です。Bloomによるにじみは配置先のPost-processing設定に依存します。

新規ギミックは既存のグラフとComponentを使用します。Collider、通行制御、ネットワーク同期をすべての見本へ自動設定する更新ではありません。必要に応じて配置後に追加してください。複数ボタンの競合や連打、端末ごとの見え方・音・負荷は、実機での確認項目として残しています。

## 開発環境での確認

リポジトリのTakumi Guard設定を保ったまま依存パッケージをインストールし、次を実行してください。

```sh
pnpm typecheck
node tools/catalog-expansion/check-catalog.cjs
node scripts/check-fixture-coverage.mjs
pnpm e2e:typecheck
pnpm e2e:test e2e/external-store.spec.ts
```

通常の開発手順でアプリを起動し、Emissive・布・透過ガラス・Normal Mapをそれぞれ追加してください。保存、再読込、Undo、Playを確認します。音、扉、文字、パーティクルは異なる操作経路なので、それぞれ確認します。最後にテクスチャ付きMaterialをMCPから作成し、Assetsと書き出し結果に画像が含まれることを確認してください。

GLB・PNGの再生成と構造検査は次のコマンドです。Python、NumPy、Pillow、SciPyは制作スクリプト用で、アプリの実行依存には追加していません。

```sh
python tools/catalog-expansion/generate_assets.py
python tools/catalog-expansion/author_materials.py
python tools/catalog-expansion/validate_assets.py
```

新規モデルとテクスチャはこのプロジェクト向けに作成し、生成スクリプトを同梱しています。外部写真や有償素材の転載は含みません。配布条件はプロジェクトのMITライセンスに従います。
