# 外部カタログ拡充 — glTF マテリアル 50 種類・ギミック 50 種類

更新日: 2026年9月8日。添付された `xrift-studio-main (3).zip` をもとにしたソースコードの更新記録です。公開サイト・GitHub・既存のインストール先は変更していません。

## 追加した内容

| 対象 | 更新後 | 主な変更 |
| --- | ---: | --- |
| glTF マテリアル | 50 種類 | Emissive、拡張マテリアル、Normal Map・ORM・UV・Alpha の比較 |
| ギミック | 50 種類 | 扉・動き、照明、音、パーティクル、状態表示、組み合わせ |
| 専用モデル | 新規 12 個 | 花器、ボトル、布、宝石、溝付きの質感見本、パネル、操作ボタンなど |
| テクスチャ | 新規 46 枚 | 512×512 PNG。基本色・Normal・ORM・発光マスク・Alpha |

マテリアルにはテクスチャ付きの見本が 32 種類あり、Emissive は 7 種類です。そのうち 6 種類は画像によって発光箇所を分ける見本になっています。新規の GLB と PNG は合計約 4.51 MiB です。既存の 3D セットと保存済みのレシピ ID はそのまま維持しています。

比較する機能・表面・形状・操作が分かりやすいセットとして追加しました。マテリアルは同じ形状の左右比較に統一し、ギミックには操作と編集の手順を付けています。

## 利用する場所

「アセットストア」から「マテリアル表現 > glTFマテリアル」または「ワールド機能 > ギミック」を開きます。マテリアルはワールドとアイテムの両方で 50 種類、ギミックはワールド向けです。

検索や分類から候補を選び、右側の詳細で比較条件や操作手順を確認します。Emissive には専用の絞り込みボタンがあり、「テクスチャ付き」を選ぶと実際に画像を参照する見本だけを表示します。条件に合う候補がない場合は「条件をリセット」で元に戻せます。

詳細の見本はドラッグで回転し、ホイールで拡大できます。カタログ内のボタンはギミックを実行するためのものではありません。「シーンに追加」した後、ストアを閉じて Play で動作を確認してください。追加後は通常のオブジェクト、マテリアル、テクスチャ、コンポーネント、ノードグラフとして編集できます。

## 見本の変更

比較する形状・向き・大きさをそろえ、左右の台座、背景ライン、比較条件を用意しました。説明文は 3D 内だけでなく詳細ペインにも表示します。透過の見本では背景ライン、反射の見本ではスタジオ環境光を使って違いを確認できます。布は折り目、宝石は平らなカット面、金属は溝のあるモデルで見比べます。

GLB には UV と TANGENT を保存しています。Normal Map で凹凸を、ORM の R・G・B でそれぞれ AO・Roughness・Metallic を指定します。色と発光マップは sRGB、Normal と ORM は線形データとして取り込みます。Alpha 見本には透過部分を持つ PNG を使っています。

一覧では静止画を順番に生成し、選択した詳細だけをライブ表示します。GLB とテクスチャの読み込み完了を待ってからサムネイルを保存し、失敗した場合は欠落した見本を完成扱いにしません。50 個のライブ WebGL 画面を同時に動かさない構成です。

## 追加処理と MCP

モデルの Material は実際に読み込んだスロットに割り当てます。必要な PNG はバイト数と SHA-256 を確認し、既存の Asset 取り込み処理でプロジェクトに保存します。同じ画像を取り込み済みであれば再利用します。シーンに追加した後も、カタログの配信場所を参照し続ける仕組みではありません。

追加処理中は重複操作を止め、途中で別のプロジェクトや編集内容に切り替わった場合は古い状態で上書きしません。Scene と AssetManifest の確定は取り込み後にまとめて行います。途中で失敗した場合、未使用の取り込みファイルがディスクに残る可能性はありますが、欠けたセットが Scene に確定されることはありません。

MCP の `list_scene_recipes` は分類・検索語・比較ラベルを返します。`apply_scene_recipe` で同じ見本一式を追加できます。`list_material_presets` は必要なテクスチャ ID も返し、`create_material_from_preset` は画像を取り込んでから Material を確定します。表示だけの絞り込みや回転操作のために新しいツールは増やしていません。

## 見え方・動作の前提

見本のスタジオ照明は比較用であり、配置先には追加しません。配置先の Skybox や環境光によって見え方は変わります。Emissive は表面の発光表現であり、周囲を照らすには Light が必要です。Bloom による光のにじみは、配置先の Post Processing 設定に依存します。

新規ギミックは既存のノードグラフと Component を使用します。Collider、通行制御、ネットワーク同期をすべての見本に自動設定するものではありません。必要に応じて配置後に追加してください。複数ボタンの競合や連打、端末ごとの見え方・音・負荷は、実機での確認項目として残しています。

## 開発環境での確認

リポジトリの Takumi Guard 設定を維持したまま依存パッケージをインストールし、以下を実行してください。

```sh
pnpm typecheck
node tools/catalog-expansion/check-catalog.cjs
node scripts/check-fixture-coverage.mjs
pnpm e2e:typecheck
pnpm e2e:test e2e/external-store.spec.ts
```

通常の開発手順でアプリを起動し、Emissive・布・透過ガラス・Normal Map をそれぞれ追加してください。保存、再読み込み、Undo、Play を確認します。音、扉、文字、パーティクルはそれぞれ異なる操作経路を通るため、個別に確認します。最後にテクスチャ付き Material を MCP から作成し、Assets と書き出し結果に画像が含まれることを確かめてください。

GLB・PNG の再生成と構造検査は次のコマンドで行います。Python、NumPy、Pillow、SciPy は制作スクリプト用であり、アプリの実行依存には追加していません。

```sh
python tools/catalog-expansion/generate_assets.py
python tools/catalog-expansion/author_materials.py
python tools/catalog-expansion/validate_assets.py
```

新規モデルとテクスチャはこのプロジェクト向けに作成し、生成スクリプトを同梱しています。外部写真や有償素材の転載は含みません。配布条件はプロジェクトの MIT ライセンスに従います。
