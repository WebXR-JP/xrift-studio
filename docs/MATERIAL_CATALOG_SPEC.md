# マテリアルカタログ仕様

Sky シェーダーと同じ仕組みを使い、プリセット付きのカスタムシェーダーを水面と地形の草にも適用するための仕様をまとめる。

この文書は実装前の設計を記録したものである。既存機能は実物を確認したうえで記載し、新規部分は未実装の提案として区別している。

| --- | --- | --- |
| Skyシェーダー | `src/lib/visual-editor/sky-shader.ts` | 実装済み |
| Skyプリセット | `src/lib/visual-editor/sky-shader-catalog.ts` | 33件・11カテゴリ。自然・天候・宇宙・幻想・抽象・水中を含む。軽量・標準・高精細のdefinesをマテリアルに保持する。詳細は[空の背景シェーダー](./SKY_SHADERS.md) |
| Skyプレビュー | `src/components/visual-editor/SkyShaderCatalogPreview.tsx` | 実装済み |

Sky シェーダーが備えている仕組みのうち、そのまま流用できるものは次の 4 点である。

- `resolveSkyShaderMaterial`: 素材から Uniform 値を解決する
- `SKY_SHADER_DRIVEN_UNIFORMS` / `skyShaderDrivenUniforms`: 時間などランタイムが供給する Uniform の宣言
- `skyShaderTextureUniformNames`: テクスチャ Uniform の列挙
- `isSkyShaderMaterialAsset`: 素材種別の判定

水面マテリアルも同じ 4 点を用意すれば、設定画面・プレビュー・公開の各経路を作り直さずに済む。

## 共通方針

### 1. プリセットはコードで持ち、値は素材で持つ

シェーダー本体の GLSL はカタログ側に置き、制作者は Uniform の値を調整する（Sky と同じ形式である）。これにより、プリセット側の改善を既存ワールドへ反映でき、素材データに GLSL を含めないため公開時の審査対象も増えない。Uniform の数値だけであれば、`classic-runtime` 出力の `runtime.json` にもそのまま保存できる。

任意の GLSL を直接書きたい場合は、既存のカスタムシェーダー機能を使う。このカタログ機構には GLSL の編集機能を追加せず、公開経路の前提が異なる両者の操作を混在させない。

### 2. 重い設定は既定で軽い側に倒す

カタログから配置した直後の負荷を抑えるため、既定値は最軽量とし、品質は制作者が必要に応じて引き上げる形にする。各プリセットに `quality` を持たせ、`low` / `medium` / `high` で反復回数やレイヤー数を切り替える。

### 3. 風は共通の入力として扱う

水面の波と草の揺れには、既存の風コンポーネントを共通の入力として渡す。水面や草ごとに個別の風速を持たせず、同じシーン内で風の向きが揃うようにする。

## 風契約

既存の風コンポーネントの値を、シェーダーが読みやすい形式に正規化して供給する。

```
uWindDirection : vec2   水平方向の単位ベクトル
uWindSpeed     : float  m/s 相当
uWindTurbulence: float  0..1 乱れの強さ
uTime          : float  秒（既存の SKY_SHADER_DRIVEN_UNIFORMS と同じ供給元）
```

- オブジェクト個別の風設定がない場合は、グローバル設定の値を使う。
- どちらも設定されていない場合は `uWindSpeed = 0` とし、波と草は静止させる（既定で勝手に動かさない）。
- `uTime` は Sky と同じ供給経路を使い、別の時間軸を作らない。

将来的にマルチプレイヤー環境で見え方を揃える必要が出たときに `useServerClock` へ切り替えられるよう、時間の供給元は 1 箇所に集約しておく。

## 水面マテリアル

### プリセット

| id | 用途 | 想定負荷 |
| --- | --- | --- |
| `calm-lake` | 静かな湖面。反射弱め、波小さめ | 低 |
| `ocean-waves` | 海。うねりと白波 | 中 |
| `stylized-toon` | セルルック。段階的な色と輪郭 | 低 |

### uniform

共通の Uniform は次のとおりである。

```
uShallowColor  : vec3   浅い部分の色
uDeepColor     : vec3   深い部分の色
uOpacity       : float  0..1
uWaveHeight    : float  波の高さ
uWaveScale     : float  波の細かさ
uWaveLayers    : float  1..4  重ねる波の数（負荷に直結）
uFresnelPower  : float  縁の反射の強さ
uReflectivity  : float  0..1
```

`ocean-waves` のみ次の Uniform を持つ。

```
uFoamAmount    : float  0..1 白波の量
uFoamSharpness : float  白波の輪郭
```

`stylized-toon` のみ次の Uniform を持つ。

```
uBandCount     : float  2..8 色の段数
```

星の数の設定と同じく、`uWaveLayers` には 0.0〜1.0 の割合ではなく実際に重ねる波の数を指定する。数を増やしても既存の波の位相がずれないよう、レイヤーごとに固定のシードを使う（Sky の `42.0` / `78.0` / `134.0` と同じ方式である）。

### 軽量化

- `uWaveLayers` の既定値は `calm-lake` で 2、`ocean-waves` で 3 とする。
- メッシュ分割数を上げずに済むよう、法線は頂点ではなくフラグメントシェーダーで計算する。
- 反射は環境色の近似にとどめ、追加のレンダーパスによる実反射は入れない。鏡と違って水面は面積が広く、実反射では描画負荷を見積もりにくいためである。
- カメラが水中に入る場面で破綻しないよう、画面上の水平線より下だけを描画する最適化は行わない。

### 適用先

地形と同じくマテリアルスロットとして扱い、任意のメッシュに割り当てられるようにする。水面専用のプリミティブは追加せず、板ポリゴンを配置してマテリアルを割り当てることで、池も海も同じ仕組みで作れるようにする。

## 地形の草

全体のなかで最も作業量が多い領域であるため、3 つのフェーズに分けて進める。

### フェーズ1: 散布データ

シーンドキュメントに地形ごとの散布情報を持たせる。

```
grassLayers: [
  {
    id: string
    typeId: string      草の種類（カタログの id）
    density: number     1平方メートルあたりの本数
    mask: number[]      Terrain 解像度に合わせた 0..1 の配列
    heightRange: [min, max]
    slopeLimit: number  この傾斜より急な面には生えない
  }
]
```

- `mask` は高さフィールドと同じ解像度に揃える。解像度が異なると、編集時に各サンプルを正しく対応付けられない。
- スキーマに項目を追加するときは、`serialization.ts` の許可キーにも必ず追加する。未知キーはブロッキングエラーとして弾かれるため、追加し忘れると保存した時点でシーンを読み込めなくなる（物理設定を追加した際に実際に発生した）。

### フェーズ2: 描画

- `InstancedMesh` を使い、1 レイヤーを 1 ドローコールで描画する。
- 配置は `mask` と地形の高さから決定的に生成する。乱数結果は保存せず、シードと `mask` から毎回同じ配置を再現することで、シーンドキュメントの肥大化を防ぐ。
- 距離カリングは既定 40m とし、それより遠いレイヤーは描画しない。
- LOD は近距離を交差板 3 枚、遠距離を 1 枚とする。
- インスタンス数の上限は 1 レイヤーあたり 50,000 件とする。上限を超える `density` は上限値に丸め、黙って切り捨てずに設定画面へその旨を表示する。

### フェーズ3: 揺れ

風契約の Uniform を頂点シェーダーで受け取り、根元を固定したまま先端ほど大きく揺れるようにする。

- 全体が同じ位相で揺れると単調な板に見えるため、位相はインスタンスのワールド座標から導出する。
- 静止画撮影などの用途で意図しない動きが出ないよう、`uWindSpeed = 0` のときは微小な揺れも入れず完全に静止させる。

### 草の種類

| id | 見た目 |
| --- | --- |
| `short-grass` | 短い芝 |
| `tall-grass` | 背の高い草 |
| `wildflower` | 花付き |
| `dry-grass` | 枯れ草 |

種類ごとにテクスチャと既定の高さ・幅を持つ。制作者は種類を選び、`density` と `mask` をペイントして調整する。

### 公開への反映

`classic-runtime` 出力の `runtime.json` には、種類 ID、`density`、`mask`、シードだけを散布情報として保存し、GLSL やインスタンス座標は含めない。ランタイム側で同じ配置を再生成するため、公開物のサイズが `density` に比例して増えることはない。

これに伴い、ランタイム側（`packages/xrift-studio-runtime`）にも対応する生成コードが必要になる。Studio 側とランタイム側で生成アルゴリズムが一致していないと、動作確認時と公開後で草の位置がずれてしまうため、一致をフィクスチャテストで固定する。

## 実装順

1. 風契約を正規化し、既存の風設定から上記 4 つの Uniform を生成する。水面と草の両方で使うため最初に着手する。
2. Sky のカタログ構造を流用して、水面マテリアルを実装する。
3. 地形の草をフェーズ 1〜3 の順で実装する。

## 注意（この設計を実装する人へ）

- 単一のファイルだけを見て「機能が存在しない」と判断せず、着手前にコードベース全体を広く検索する。実際にこの文書を作成する過程でも、`component-registry.ts` だけを見て定義本体の `editor-session.ts` を見落とし、風コンポーネントが存在しないと誤認した経緯がある。
- シーンドキュメントのスキーマを変更するときは、`serialization.ts` の許可キーと MCP の `update_scene_settings` を同時に更新する。
- 並行して別セッションが `sky-shader-catalog.ts`、`InspectorPanel.tsx`、`SceneSettingsPanel.tsx` を編集している場合があるため、着手前に `git status` を確認する。
