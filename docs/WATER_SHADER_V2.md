# 水面シェーダー v2 — 海・水面カタログの拡充

## 変更の概要

既存の水面シェーダーを 3 種類から 21 種類・8 カテゴリへ拡充しました。従来の 3 種類の ID はそのまま維持し、新規 18 種類を追加しています。GLSL は共通コアと演出用の定義に分かれており、波の形や泡などを組み合わせた 16 通りの演出構成を備えています。

その後、川のプリセット 3 種類と「川・小川」カテゴリを追加し、現在は 24 種類・9 カテゴリ・17 通りの演出構成となっています。川だけは風ではなく流れで動きます。詳細は「[流れる水面（川のプリセット）](#流れる水面川のプリセット)」を参照してください。

Assets の「アセットストア → 水面シェーダー」および既存 MCP の `list_material_presets` / `install_material_preset` から利用できます。インストール後は従来どおり、GLSL と Uniform を持つ独立したマテリアルとして追加されます。新しいネットワーク取得先や依存パッケージは追加していません。

## 使い方

1. 本変更を取り込んだ XRift Studio を、元のプロジェクトと同じ依存関係を導入して起動します。
2. Assets → アセットストア → 水面シェーダーを開き、検索またはカテゴリからプリセットを選びます。
3. 詳細プレビューを確認しながら、波・さざ波、反射・透明感、泡、演出、色を調整し、「マテリアルへ追加」を押します。
4. 水平の水面メッシュを作成してマテリアルを割り当てます。追加後も素材の設定からパラメーターを調整できます。
5. 水面が動かない場合はシーンの風設定を確認してください。詳細パネルの「プレビューに風を適用」はプレビューだけに効き、シーン自体は変更しません。川のプリセットは風が止まっていても流れます。

通常の Plane では `uWaveDisplacement` を 0 のまま使えます。水面の輪郭ごと動かしたい場合は、`dev/water-shaders/meshes` または別添シェーダーパックの分割メッシュを取り込んで使ってください。

## 品質面の変更

- うねりは最大 4 層の Gerstner 波、細かなさざ波は解析勾配を持つノイズで計算します。波の接線から法線と圧縮度を求め、泡は波頭の圧縮・塊・ちぎれた縁・小さな穴を組み合わせて表現しています。波の急峻さの合計には上限を設けています。
- 空の反射方向、視線角度による反射、主光源のきらめき、波頭の疑似散乱を調整できます。遠方の細かな模様や鋭い反射は画面上の微分を使って弱めます。画面屈折、反射カメラ、追加のテクスチャ読み込みは行いません。
- 演出設定に応じて、寄せ波、風に流れる泡筋、集光模様、雨の円形波紋、発光、セルルック、水彩のむら、インクの線、偏光色、発光格子、流氷風の模様を切り替えます。セルルックやインク調など、結果に影響しない物理寄りの操作項目は非表示にしています。
- 風の速度または `uWaveSpeed` のどちらかが 0 であれば、水面の波・泡・雨の波紋・夜光の動きが止まります。これは既存の共通風仕様に合わせるための動作です。川のプリセットではこの規則は風による成分だけに適用され、流れ自体は `uFlowSpeed` で進み続けるため、風が止まっても停止しません。

## 流れる水面（川のプリセット）

川は風のない日でも流れます。そのため演出 `FLOW`（define `WATER_FLOW`）を共通コアへ追加し、流れの速さを風とは独立した値として持たせました。対象は `clear-stream`、`mountain-rapids`、`slow-river` の 3 種類で、カテゴリは「川・小川」です。画像は使わず、他のプリセットと同じノイズで描画します。

### 描くもの

- 流れに乗って下るさざ波。同じ模様を半周期ずらした 2 枚で交互に入れ替えながら運ぶため、1 枚を滑らせたときのようなベルト状の見え方にならず、流れながら形が変わります。周期ごとに別の模様から始めるため、同じさざ波が繰り返されることもありません。
- 流れの向きへ長く伸びたゆるやかなうねり。
- 流れに沿って伸びる白い筋。量は `uRapids`（早瀬の強さ）と `uFoamAmount`（白波の量）の積で決まります。
- 岸へ向かって浅くなる川底の近似。浅い場所ほど透け、斜めから見るほど透けにくくなります。水ぎわは `uBankSoftness` の幅で消え、境界線も同じ幅でゆらぎます。
- 反射・きらめき・Fog は他のプリセットと同じ処理です。

### 風と流れの分担

| 動くもの | 進め方 | 止まる条件 |
| --- | --- | --- |
| 流れに乗るさざ波・うねり・白い筋 | `uTime × uFlowSpeed` | `uFlowSpeed`が0 |
| 風で立つさざ波・うねり、映り込む雲模様 | `uTime × uWindSpeed × uWaveSpeed`（従来と同じ） | シーンの風、または`uWaveSpeed`が0 |

風が止まると、風で立つさざ波は動きを止めるだけでなく振幅も 0 になります。動いている水面の上に静止した風の模様を残さないためです。`uFlowSpeed` と風の両方を 0 にすると、水面は完全に静止します。

流れの進み方は時間に対して一次です。時間変化する値を掛けるとワールドを開いている時間が長いほど流れが速くなってしまうため、この形にしています。模様の座標は周期ごとに折り返すため、時間経過で座標が大きくなって模様が粗くなることはありません。

### 向きと位置

流れの向きと中心線は、割り当てたメッシュの配置から決まります。向きはメッシュのローカル X 軸をワールドの水平面へ投影した方向で、`uFlowAngle` で回転させられます。中心線はメッシュの原点を通ります。

Entity を移動・回転させると川も一緒に動くため、1 つのマテリアルを複数の区間で使い回せます。模様の座標はワールド基準で計算されるため、同じ向きで一直線に並べた区間同士は継ぎ目で模様がつながります。

川幅は `uChannelWidth` で指定します。メッシュがそれより広い部分は透明になります。Studio の Plane に割り当てる場合は、X 方向を長さ、もう一方を幅として拡大してください。

### 操作項目

共通の項目に加えて、`uFlowSpeed`（流れの速さ）、`uFlowAngle`（流れる向き）、`uRapids`（早瀬の強さ）、`uChannelWidth`（川幅）、`uChannelDepth`（中央の深さ）、`uBankSoftness`（水ぎわのぼかし）、`uClarity`（水の澄み具合）を追加しています。

川には逆光で透ける波頭がないため、`uScatterStrength` は表示しません。また、`uWaveSpeed`、`uWaveHeight`、`uDetailStrength`、`uFoamAmount`、`uOpacity` の説明文は川での用途に合わせて差し替えています。

### 川の制約

- 流れは直線です。曲がった川を作る場合は短い直線区間をつないで配置しますが、向きの異なる区間の継ぎ目では模様がつながりません。UV や頂点属性に沿って曲がる流れは今回の対象外です。
- 川底は放物線の近似であり、地形の高さ・水深・岩の位置は読み取りません。岩の上流での盛り上がりや後流の波は描きません。
- 水面はメッシュの端で切れるため、上流と下流の端は地形や岩などで隠してください。
- 落差、滝、水しぶきは描きません。

## 表現上の制約

- 反射は指定した天頂色・水平線色と水専用の雲模様による近似です。シーン内の建物やアバターを鏡のように映す機能ではなく、空の背景画像や雲とも自動同期しません。夕景や月明かりのサンプル照明がそのままシーンに追加されることもなく、実際の主光源と環境光はシーン設定から供給されます。
- 寄せ波は `uShoreAngle`、`uShoreOffset`、`uShoreWidth` で指定する直線の岸を前提としています。地形や岩との接触検出、地形に沿った泡、波の衝突シミュレーションはありません。
- 水深による吸収、画面屈折、水底へのコースティクス投影、影の受け取り、浮力・衝突判定、水中用ポストエフェクトは実装していません。流氷も水面上の模様であり、歩ける氷のメッシュではありません。
- 不透明度は基本の透過率です。浅い角度の反射や泡の部分は不透明に近づきますが、0 にすると完全に非表示になります。透過メッシュ同士を重ねたときの描画順は既存ランタイムの制約を受けます。
- 川のプリセットは直線の流れだけを描きます。曲がった川、地形や岩への接触、落差は対象外です。詳しくは「[川の制約](#川の制約)」を参照してください。

## 水面メッシュ

| ファイル | 大きさ | 頂点 | 三角形 | 用途 |
| --- | --- | ---: | ---: | --- |
| ocean-grid-64m-64.glb | 64m × 64m | 4,225 | 8,192 | 控えめなうねり、3層程度から調整 |
| ocean-grid-64m-128.glb | 64m × 64m | 16,641 | 32,768 | 頂点変位を使う標準的な試作 |

どちらも XZ 平面、上向き法線、原点中心、テクスチャなしです。最初は `uWaveDisplacement=0.3` 程度から少しずつ上げてください。メッシュを大きく拡大したり波を極端に細かくしたりすると頂点が足りなくなるため、その場合は分割数を増やすか、頂点変位や波の重ね数を下げてください。

GLSL は頂点位置を動かすだけで、CPU 側のバウンディングボックスや物理形状は更新しません。大きな変位を与えた際に画面端でカリングが起きないかも確認してください。

## 負荷とプレビュー

- 品質は `uDetailQuality` の 0（軽量）、1（標準）、2（高精細）で切り替えます。細かいノイズの層数を変え、0 では雲模様と雨の波紋を省略します（すべての演出が省かれるわけではありません）。「負荷目安」は実装上の相対的な目安であり、FPS や Quest 実機での測定値ではありません。
- 一覧カードは共有の `WebGLRenderer` で順番に描いた静止画です。可視領域付近だけを描画し、最大 64 件までキャッシュします。詳細プレビューだけが R3F Canvas で動作するため、追加されるコンテキストは共有サムネイル用 1 個と詳細用 1 個だけで、21 個の Canvas を同時に動かすことはありません。ストアを閉じると共有レンダラーを破棄します。非表示タブ、表示範囲外、一時停止、動きを減らす設定では詳細アニメーションを停止します。
- 海の見本は水面を上から見下ろす構図ですが、川は幅が数 m しかないため同じ視点では細い線になってしまいます。そのため川のプリセットでは、川幅に合わせた距離の岸から見下ろす構図で描き、見本の水底を水面のすぐ下に配置しています（`water-preview-renderer.ts` の `waterPreviewView`）。カードと詳細プレビューは同じ構図です。
- 検索によって選択中の項目が隠れた場合は検索結果の先頭を選択し、該当 0 件の場合は説明を表示します。追加処理中は再追加とプリセット切り替えを抑止し、成功・失敗の結果をパネルに表示します。プレビューを描画できない場合も失敗を明示し、CSS による仮プレビューには置き換えません。

## 保存済みマテリアルと並行改修

既存マテリアルの GLSL は保存データに埋め込まれているため、ソースコードを更新しただけでは自動で切り替わりません。同じプリセットをカタログから追加し直すと、従来の ID のマテリアルが現在のパラメーターで更新されます。以前の見た目を残したい場合は、先にプロジェクトを保存して別名バックアップを取っておいてください。

この成果物は共有された `xrift-studio-main(1).zip` を基準にした海用の改修であり、別作業の空の背景や 3D モデル改修を取り込んだものではありません。それらと組み合わせる場合は、プロジェクト丸ごとの上書きではなく差分パッチを確認して適用してください。

`water-shader-pack/preview.html` はインターネット接続なしで開ける WebGL2 確認ページですが、Three.js の標準入力と一部チャンクを最小のアダプターで置き換えているため、Studio の統合テストにはなりません。

任意の Linux 参照描画では EGL / Mesa、Python、NumPy、Pillow を使います。これらはアプリ本体の依存関係には追加していません。
