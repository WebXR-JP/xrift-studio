# ライトベイクの仕組み

動かないメッシュに当たる光をエディター内で計算し、ライトマップとして保存する機能の設計である。利用手順は [利用ガイド](./guide/light-bake.md)、操作と状態遷移は [F-48](./ux/editor.md#f-48) を参照する。

## 基本方針

- ベイクはエディター上で作者が実行したタイミングで行う。公開時に焼き直すことはしない。
- 結果は `lightmap` 種別のアセットとしてプロジェクトに保存する。Scene View、Play、公開ワールドのすべてで、同じ 2 つのファイルを同じコードで適用する。
- 元のモデルや共有マテリアルは書き換えない。ベイク対象外の Entity が同じモデルやマテリアルを使っている場合があるためである。
- 適用できないメッシュや読み込めないファイルがあっても、別の陰影で代替せず、適用しない理由を記録する。

## データ構造

| 場所 | 内容 |
| --- | --- |
| `MeshComponent.lightBake` | 対象かどうかと細かさの倍率。省略時は対象外 |
| `LightComponent.bakeMode` | `realtime`（省略時）または `baked` |
| `SceneSettings.lightBake` | 画像サイズの上限、品質、影のやわらかさ、使用中の `lightmapAssetId` |
| `LightmapAsset` | 画像（EXR）のパス、UV2 データのパス、焼いた Entity と Light、ベイク時点のシーン署名 |

ファイルは `assets/imported/lightmaps/<画像のSHA-256の先頭16桁>/` に 2 つ保存する。中身のハッシュをディレクトリ名にしているため、焼き直しても前のファイルが残り、「元に戻す」で直前のライトマップへ復帰できる。使われなくなったファイルの自動削除はまだ実装していない。

- `lightmap.exr`: 半精度 RGBA の正方形画像。1 辺は 64 以上の 2 のべき乗とする。放射照度をそのまま保持するため、負の値や 1 を超える値も含む。
- `lightmap-uv.bin`: メッシュごとの UV2 データ。バイナリ形式の仕様は `packages/xrift-studio-runtime/src/lightmap-data.ts` に準拠する。

### UV2 データ

メッシュは「Entity ID」と「Entity 内で何番目のメッシュか」で特定する。番号は、`xriftLightmapScope` の印が付いた親の配下を深さ優先で数えた順とし、ベイク時・適用時ともに `collectXriftLightmapMeshes` で数える。編集補助（`editorHelper`）、MToon の輪郭線、スキニングやモーフターゲットを持つメッシュは対象から除外する。

メッシュごとに次の情報を持つ。

- 元の頂点数とインデックス数。読み込んだジオメトリと一致しなければ適用しない。
- 追加する頂点の複製元。チャートの境界では同じ頂点が画像の異なる座標を参照するため、頂点を増やす。
- 差し替えるインデックス（位置と新しい頂点番号の組）。
- 頂点ごとの UV（画像全体に対する 16bit 固定小数）。

追加頂点とインデックス差し替えの内容が一致するメッシュは、1 組のデータを共有して書き出す。

## ベイクの流れ

実装は `src/lib/visual-editor/light-bake/` に置き、Three.js や DOM に依存しない部分はフィクスチャで検証する。

1. **収集（`collect-scene.ts`）**: Scene View の Three.js シーンから、印の付いたメッシュのワールド座標形状、マテリアル、ライト、環境を取得する。保存済みドキュメントから組み立て直さないため、モデルの読み込み結果や割り当てたマテリアルがそのまま反映される。テクスチャは縮小描画して GPU から読み戻し、IBL は背景として 6 方向へ描画して読み戻す。
2. **UV2 の生成（`unwrap.ts`）**: 面の向きが基準面から 45 度以内の連続した面を 1 チャートにまとめる。チャートを正面から平面へ投影し、最も長い外周の辺を横軸に揃える。ワールド座標で計算するため、画像上の面積が実寸に比例する。
3. **配置（`unwrap.ts`）**: 全チャートを高さ順に段詰めする。解像度は上限（1 m あたり 40 px）から開始し、収まる最小の画像サイズを選ぶ。上限サイズに収まらなければ、解像度を二分探索で下げる。チャートの周囲には 1 px の余白を空ける。
4. **テクセルの割り当て（`raster.ts`）**: テクセルの中心が三角形の内側にあればその座標を、縁から 1 px 以内なら縁の座標を担当させる。
5. **光の計算（`tracer.ts`、`bvh.ts`）**: 自前の BVH（ビン分割 SAH）へレイを飛ばしてパストレースを行う。Web Worker を論理コア数 - 1（最大 8）起動し、2048 テクセル単位で分散処理する。
6. **仕上げ（`bake.ts`）**: 無効なテクセルを同じチャートの隣接値で補完し、ばらつきに応じて輪郭を残すぼかし（à-trous 3 回）をかけたうえで、余白を周囲の色で埋める。
7. **保存**: EXR と UV2 データをプロジェクトへ書き込み、Lightmap アセットを更新し、シーンの `lightmapAssetId` を 1 件の操作履歴として反映する。

## 焼く光の種類

ライトマップの値は Three.js の `lightMap` と同じ放射照度であり、描画時に Albedo / π が乗算される。ライトの減衰も Three.js の物理ベースの式に合わせている。

| 光 | ライトマップへ入れる量 |
| --- | --- |
| `baked` ライトの直接光 | すべて（描画時はライトを消す） |
| `realtime` ライトの直接光 | 入れない（描画時に照らす） |
| すべてのライトの間接光 | すべて |
| Emissive の面が周囲を照らす光 | すべて |
| Ambient Light、Hemisphere Light、IBL | 遮られて届かない分を負の値で記録 |

環境光は描画時に「遮蔽物がない」前提で加算されるため、最初のレイが何かに衝突した方向だけ、その方向の環境輝度を差し引いて記録する。何も遮られなければ差分は 0 となり、開けた場所では誤差が生じない。Three.js の `aoMap` を使わないのは、モデルが元々持つ AO Map の枠を奪わないためである。

`baked` に設定した Ambient Light と Hemisphere Light については、遮られずに届く分をそのまま焼き込み、描画時は無効化する。

### テクセルの扱い

- 1 テクセル内でレイの出発点をわずかにずらし、影の縁に格子状のギザギザが出ないようにする。ずらした地点がテクセル中心から見通せない場合（壁の向こう側など）は採用しない。
- 最初のレイの 40% 超が裏面に当たったテクセルは、閉じた形状の内側にあるとみなして無効化し、隣接する有効値で補完する。
- 半透明（blend）のマテリアルは光を遮らず反射もしない。抜き（mask）のマテリアルは、テクスチャのアルファが閾値以上の部分だけを遮蔽物として扱う。

## 適用

`packages/xrift-studio-runtime/src/lightmap-apply.ts` をエディターと公開物の両方で共有する。

- 印の付いた親配下のメッシュを数え、保存データと照合する。0.5 秒ごとに再確認するため、遅れて読み込まれたモデルにも適用される。
- ジオメトリは元の属性配列を共有したまま、空いている UV スロット（`uv1`〜`uv3`）に UV2 を追加した複製へ差し替える。頂点追加が必要なメッシュだけ配列を作り直す。
- マテリアルは `lightMap` を設定した複製へ差し替える。複製は「元のマテリアルと UV スロット番号」の組ごとに 1 つ作り、同じマテリアルを使うメッシュ同士で共有する。
- 作者の編集やトリガーによる書き換えに追従するため、元のマテリアルの変更は毎フレーム複製へ反映する。
- ライトマップを表示できるのは Standard / Physical / Lambert / Phong / Toon マテリアルである。Unlit、MToon、カスタムシェーダーには適用しない。
- 取り外すときは、元のジオメトリとマテリアルへ戻す。

公開物では、コンパイラが対象メッシュを `<group userData={{ xriftLightmapScope: true }}>` で包み、シーンに `XriftSceneLightmap` を 1 つ配置する。`baked` のライトには `baked` を渡す。ライトマップの 2 ファイルは `assetCopyPlan` に入り、`public/` 直下へコピーされる。ワールド側のコードから通信 API を直接呼べないため、ファイル読み込みには Three.js の `FileLoader` を使う。

## 焼き直しが必要かの判定

`computeLightBakeSignature` によって、対象メッシュとその祖先の Transform、割り当てたマテリアルの値、モデルのハッシュとスケール、有効なライト、Ambient Light、IBL、ベイク設定を 1 つのハッシュにまとめる。ベイク時点のハッシュを Lightmap アセットに保存しておき、現在値と異なれば「Sceneが変わりました」と表示する。対象から外したメッシュや `realtime` に戻したライトは、焼き直しを待たずにすぐ反映する。

## 未対応の項目

- ランタイム JSON での公開（ブラウザ版からの公開）。コンパイラはライトマップを使うシーンを `lightmap-unsupported-runtime-output` で停止する。対応には `react-three-fiber/index.tsx` と `three/index.ts` への組み込み、およびランタイムシェルの再生成が必要。
- 動く物体への光（ライトプローブ）。`baked` ライトは対象外メッシュやアバターを照らさない。
- チャート境界をまたぐ色の連続化。なめらかな曲面では境界に薄い筋が見えることがある。
- 鏡面反射と Normal Map の方向。ライトマップが保持するのは拡散光のみである。
- Spot Light の投影画像（`map`）と、ライトごとの影のやわらかさ。
- プレハブ内のメッシュをインスタンス単位でベイク対象にする操作。プレハブ元の Entity を対象にすると、全インスタンスが対象になる。
- 使われなくなったライトマップファイルの削除と、複数枚への分割。

## 検証

- `pnpm cli:test` の「light bake」: BVH と総当たりの一致、UV2 の重なりと実寸、テクセル割り当て、UV2 データの往復変換、焼いた影と間接光の量、環境光の差分、Emissive、閉じた形状の内側判定、適用と復元、マテリアルの共有と追従、コンパイラ出力、ランタイム JSON の拒否。
- `pnpm cli:test` の「staged world typecheck」: ライトマップを含むワールドの生成コードを、公開テンプレートと同じ設定の `tsc` で型検査する。
- `e2e/light-bake.spec.ts`: 検証用ページ（`e2e.html`）上で、パネルからのベイク実行、Lightmap アセットの保存、Scene View への適用、配置変更後の表示と再ベイク、Play、取り外しを検証する（CI の実行対象外）。

検証用ページのモック（`src/release-e2e/mock-tauri.ts`）では、ベイク直後に書いたファイルを読み戻すため、ライトマップ関連ファイルだけをメモリ上で保持して返す。その他のファイル読み込みは、既存テストの前提に合わせて失敗する挙動のまま維持している。
