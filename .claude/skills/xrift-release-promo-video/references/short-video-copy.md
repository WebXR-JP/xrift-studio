# ショート動画の台本とコピー

30秒の紹介動画では、XRift Studioを使っている人や使い始めた人に、更新でできる操作を伝えます。何ができるかを、短く具体的な日本語で書いてください。リリースノートや実装メモは、画面に載せる短い案内へ書き直します。

## 台本の承認用テンプレート

```markdown
# <更新名>の30秒台本

- 状態: `pending` / `approved`
- リリース状態: `published` / `upcoming`
- 対象: XRift Studio を使っている、または使い始めた制作者
- 形式: 1920×1080 / 30fps / 30秒 / 無音でも理解可能
- 紹介する変更: <利用者にとっての変化を一文で>
- 根拠: <差分>、<実画面素材>

| 秒数 | 画面内テキスト | 実画面・演出 | 主張の根拠 |
|---|---|---|---|
| 0〜2 | XRift Studio アップデート情報 | シリーズ見出し | リリース情報 |
| 2〜6 | <変更内容>\n<利用者にとっての変化> | 見出し | 差分と収録素材 |
| 6〜22 | <短い補足> | 実画面で主操作を1つ。ポインターと最大2回のズーム | 収録素材 |
| 22〜27 | <結果を短い丁寧語で> | 操作後の実画面 | 収録素材 |
| 27〜30 | XRift Studio アップデート公開中 | 締め | `published` の場合 |

## コピー監査

- 無音で理解できる: はい / いいえ
- 各行を声に出して自然: はい / いいえ
- UI内部語・名詞の並びを除去: はい / いいえ
- 台本の全文をユーザーが確認済み: はい / いいえ
```

## 書き方

- 0〜2秒は必ず`XRift Studio アップデート情報`にする。英語のシリーズ名や「RELEASE PREVIEW」は使わない。
- 2〜6秒は2行だけにする。1行目で変化、2行目で利用者にとっての結果を伝える。
- 説明文は「〜できるようになりました」「〜を確認できます」のような、短い丁寧語の文にする。句読点がなくても自然に読める長さへ削る。
- 利用者が行う操作と、その結果を具体的に書いてください。画面の名前は、操作を案内するために必要なものを残します。処理名やログ名を並べた説明は避けます。
- 1シーンでは一つの変化だけを書く。テロップは、画面の見出しと下部キャプションを合わせても同じことを繰り返さない。
- 効果を大きく見せる言い切り、確認できない比較、公開前に「公開中」と書くことを避ける。

## 言い換え

| 避ける表現 | 推奨する表現 |
|---|---|
| 公開処理の診断 | 公開に失敗した理由を確認できます |
| stderrとstdoutを保持 | 原因を確認しやすくなりました |
| 公開エラーの次の一手まで、見えるように | 原因と対処方法が分かるようになりました |
| 安全に再試行 | 確認してから、もう一度公開できます |
| 差分から見える改善 | 今回のアップデート |

## 承認基準

- タイトル、操作中の案内、結果、締めまで、台本の全文をまとめて提示してください。
- 各文を声に出して確認し、不自然なら動詞のある短い文へ書き直す。
- 画面内のすべての主張を、差分または収録済み実画面へ対応付ける。
- `pending`の台本をRemotionのレンダリング対象にしない。
