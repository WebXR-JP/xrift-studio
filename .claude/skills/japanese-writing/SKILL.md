# 日本語の作成と推敲

仕様、数値、条件、例外、承認、禁止事項、対応状況を保ち、操作と結果が伝わる文章にする。文章の書き手やモデル名で文体を分類しない。

## 推敲

- 抽象的な比喩は具体的な操作・対象にする。重複説明を削り、条件が変わる箇所で文を分ける。理由と結果の関係は残す。
- 文体は周囲に合わせる。正確さに必要な技術語は残し、読み手に必要な説明だけ添える。
- コード、コマンド、API、正式ラベル、保存済みID、JSONキー、パス、URLは変えない。見出し変更時は参照アンカーも直す。
- 仕様が不明なら実装を確認する。不確かな説明を断定に変えない。過去の記録は当時の日付・事実・結論を保持する。
- 同じ説明がある関連文書を必要な範囲で確認し、一括置換で意味を変えない。誤字修正だけなら対象文と差分の確認でよい。

## 用語

[文章と用語のルール](../../../docs/JAPANESE_WRITING.md) に従う。

- 画面名は「ビジュアルエディター」「コードエディター」。操作や形式の名前と区別する。
- `Entity / Inspector / Hierarchy / Assets / Components` は英語のまま使う。ノードの旧名を検索用の別名として残さない。
- glTFのマテリアル名は英語を主ラベルにして読み方を添え、数値の方向・単位・条件を短い日本語で説明する。
- Normal Map、Skybox、IBL、Bloomなど定着した用語も英語を保つ。一般的な操作や色名まで英語化しない。
- AlphaとTransmission、Volumeの厚みとIridescenceの膜厚、SkyboxとIBL、Normal Mapと形状変形、EmissiveとBloomを区別する。
- Component名はAdd Componentの英語表記に揃える。照合箇所は [UXスキル](../xrift-studio-ux/SKILL.md#コンポーネント名の表記) を参照する。
- ファイル追加とXRiftへの公開を区別し、進捗IDは表示だけ翻訳する。音声のvolumeとマテリアルのVolumeを取り違えない。

差分で意味の欠落、条件の逆転、リンク切れを確認する。画面説明は実際のボタン名・接続先・状態と照合し、確認範囲を報告する。スキルの互換コピーは共通ガイドの同期手順に従う。
