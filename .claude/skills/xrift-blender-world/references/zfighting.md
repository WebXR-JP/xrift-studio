# Z-fighting — 原因と設計ルール

**制作を始める前に読む。** 後から直すと全パーツの座標を触ることになる。

## 何が起きたか（実例）

Podcast スタジオを Blender で作り、EEVEE のレンダーでは完璧に見えていた。
XRIFT に持ち込んだ瞬間、壁の吸音パネル・腰壁・見切り・ルーバーの下地が
ちらついた（カメラを動かすと面が入れ替わる）。

原因は**取り付け物の裏面を、ホスト面とぴったり同一平面に置いていた**こと。

```python
X0 = -1.8                       # 左壁の内面
# ダメな書き方 — パネルの裏面が x=X0 で壁の内面と完全に一致する
box("AcousticPanel_01", X0, X0 + 0.035, y0, y1, z0, z1)
```

同一平面の 2 面はデプス値が数値的に同じになる。どちらが手前かは丸め誤差で決まるので、
カメラが動くたびに勝敗が入れ替わってちらつく。

## なぜ Blender では見えず XRIFT で出るのか

デプスバッファの精度は `near` と `far` の比で決まる。**`near` が小さく `far` が大きいほど精度が落ちる。**

| | near | far | 精度 |
|---|---|---|---|
| Blender ビューポート（既定） | 0.1 | 100 | 比 1:1,000 |
| XRIFT の既定カメラ | 0.1 | **2000** | 比 1:20,000 — **20 倍粗い** |

さらに Blender は室内をアップで見ていることが多く、実質的な深度レンジが狭いので余計に出にくい。
**「Blender で出ていない」は「XRIFT で出ない」の保証にならない。**

## ルール1 — 不透明マテリアルは backface culling を有効にする

**これが最初に効く。** Blender のマテリアルは `use_backface_culling` が既定 False で、
glTF エクスポータはそれを **`doubleSided: true`** として書き出す。両面描画だと
背中合わせに重なった面が両方描かれるので、深度が競ってちらつく。

実測：対策前のスタジオは **15 マテリアル全部が `doubleSided: true`** だった。

```python
for mat in bpy.data.materials:
    mat.use_backface_culling = True      # ガラスなど裏から見せたいものだけ False
```

ソリッドの箱で組んだ部屋は、部屋に面した側の法線が必ず部屋を向くので、
片面にしても見た目は変わらない。描画負荷はむしろ下がる。

書き出した GLB で確認すること：

```python
sum(1 for m in js["materials"] if m.get("doubleSided"))   # 0 が理想
```

## ルール2 — 取り付け物はホストへ食い込ませる

面を合わせるのではなく、**必ず数 mm 重ねる**。重なっていれば深度差が生まれ、勝敗が確定する。

```python
EMBED = 0.004      # 4mm。1mm 未満だと精度によっては足りない。10mm 超は見た目に響く

# 良い書き方 — 裏面を壁の内側 4mm へ沈める
box("AcousticPanel_01", X0 - EMBED, X0 + 0.035, y0, y1, z0, z1)
```

`room_lib.py` の `attach_span()` / `rest_on()` がこれを自動でやる。手で座標を書かず、必ず使う。

```python
from room_lib import attach_span, rest_on

# 左壁(x=X0)に厚み 35mm のパネルを貼る。inward=+1 は「部屋が X0 より大きい側にある」の意
x_lo, x_hi = attach_span(X0, +1, 0.035)      # -> (X0-0.004, X0+0.035)

# 右壁(x=X1)なら部屋は X1 より小さい側なので inward=-1
x_lo, x_hi = attach_span(X1, -1, 0.035)      # -> (X1-0.035, X1+0.004)

# 床に置く脚（底面を 2mm 沈める）
z_lo, z_hi = rest_on(0.0, 0.72)              # -> (-0.002, 0.72)
```

### 具体例 — 天井のダウンライト

実際に XRIFT でちらついた箇所。筐体の上面が天井の下面とちょうど一致していた。

```python
RH = 2.5                                   # 天井の下面
# ダメ — cyl は中心+高さ指定なので、上面がちょうど 2.5 に乗る
cyl("Light_Downlight_01", 0.066, 0.034, (dx, dy, RH - 0.017))
#   -> z 2.466 〜 2.500、天井の下面と同一平面

# 良い — hang_under で上端を天井へ 4mm 突き抜けさせる
lo, hi = hang_under(RH, 0.034)             # -> (2.466, 2.504)
cyl("Light_Downlight_01", 0.066, hi - lo, (dx, dy, (lo + hi) / 2))
```

`attach_span` / `rest_on` / `hang_under` はいずれも **(lo, hi) を返す**。
`box()` はそのまま渡せるが、`cyl()` / `cone()` は中心と高さを取るので
`hi - lo`（高さ）と `(lo + hi) / 2`（中心）に変換して渡す。

## 見落としやすい箇所チェックリスト

実際に踏んだものを全部挙げる。室内を作るとほぼ全部出てくる。

| 取り付け物 | ホスト | 対策 |
|---|---|---|
| 吸音パネル・化粧パネル | 壁の内面 | `attach_span(壁面, inward, 厚み)` |
| 腰壁・幅木の薄い皮 | 壁の内面 | 同上 |
| 見切り・笠木・回り縁 | 壁の内面 | 同上 |
| ルーバーの下地板 | 壁の内面 | 同上 |
| 天井コーブ・折り上げの見切り | 壁の内面 / 天井 | 同上 |
| ダウンライト筐体の上面 | 天井の下面 | 天井へ 4mm 突き抜けさせる |
| 壁付け照明の取付プレート | 壁の内面 | `attach_span` |
| テーブル・椅子の脚の底面 | 床の天面 | `rest_on(0.0, 高さ)` |
| 卓上機材の底面 | 天板の上面 | `rest_on(天板高, 高さ)` |
| サイン・時計の筐体 | 壁 or ルーバー前面 | `attach_span` |
| 窓・ドア枠 | 壁の内面 | 枠は壁厚を貫通させて重ねる |
| 窓ガラス | 枠の内側 | 枠と重ねる（面一にしない） |
| **XRIFT の `starter-floor`** | 自作の床の天面 | **エンティティを無効化する** |

## ルール3 — join したオブジェクトの「中」も同じ

**ここで 2 回刺された。** `join()` で 1 オブジェクトにまとめた部品どうしも、
面が重なれば当然ちらつく。オブジェクトが 1 個になったからといって安全にはならない。

実例：天井ダウンライトは「筒 + レンズ」を join して 1 個にしていた。

```python
can  = hang_under(RH, 0.034)          # (2.466, 2.504)
lens = hang_under(RH - 0.026, 0.008)  # (2.466, 2.478)  ← 底面が筒と同じ 2.466
```

どちらも下向きの面が z=2.466 に重なる。**同じ向きなのでカリングでも消えない。**
XRIFT で天井だけちらつき続けた原因がこれだった。

```python
can_span = hang_under(RH, 0.034)
lens_lo  = can_span[0] + 0.005        # レンズは筒の中へ引っ込める
lens     = (lens_lo, lens_lo + 0.008)
```

同じ形の間違いが出やすい組み合わせ：

| join するもの | 一致しがちな面 |
|---|---|
| 照明の筒 + レンズ | 底面 |
| 椅子の座面 + 背もたれ支柱 | 座面の下端 |
| テーブルの貫と幕板 | 交差部の上下面 |
| ドア枠の縦枠 + まぐさ | 上端・端面 |
| 四周に回すトリム（腰壁・笠木・コーブ・間接照明） | コーナーで直交する部材どうし |

四周トリムは、直交する 2 本の厚み（Z 範囲）を 1mm ずらすと、片方が完全に埋まって解決する。

## 例外 — 突き合わせは問題ない

同じメッシュ内で辺を共有する突き合わせ（壁を分割して `join` したときの継ぎ目）は Z-fighting しない。
**面が重なっているのではなく、隣り合っているだけ**だから。開口部まわりの壁分割は安心して使ってよい。

同様に、離れている面（隙間がある）も問題ない。危ないのは**同一平面に 2 枚ある**ときだけ。

## XRIFT 側でできる緩和

設計で潰すのが本筋だが、こちらも効く。

- **カメラの `far` を下げる。** 屋内ワールドに 2000m は要らない。`update_scene_settings` で
  `camera.far` を 200 程度にすると深度精度が一気に上がる（`near` を 0.1 → 0.2 に上げるのも効く）
- **`starter-floor` を無効化する。** 自作の床と必ず衝突する

## 書き出し前のセルフチェック

`scripts/find_coplanar.py` を `exec` する。同一平面**かつ実際に重なっている**面のペアだけを返す。

```
suspect    … 取り付け物が構造面と同一平面。attach_span / rest_on で直す
structural … 床と壁のように本来接している構造どうし。放置してよい
```

素朴に「平面座標が一致する面」を集めるだけだと使いものにならない。左右の壁に貼った
パネルどうしが、3m 離れているのに同じ y 座標を共有しているというだけで引っかかる。
`find_coplanar.py` は残り 2 軸の矩形の重なり面積まで見るので、この誤検知が出ない。

### 実測値

対策前の Podcast スタジオ（48 オブジェクト / 5,576 tris）で走らせた結果：

```
suspect_count: 78
```

内訳は、目視で挙げていたもの（吸音パネル × 壁、腰壁 × 壁、笠木 × 壁、コーブ見切り × 壁、
間接照明ストリップ × 壁、壁付け照明 × 壁、ルーバー下地 × 壁、ダウンライト × 天井、
椅子/テーブル × 床、マイク/ミキサー × 天板）に加えて、**見落としていたもの**も出た：

- 窓枠 × 壁（開口部の 4 辺すべて）
- ドア枠 × 壁 / 腰壁 / 笠木
- ON AIR サインの筐体 × 発光面（自分の中の部品どうし）
- 時計の筐体 × 表示面
- ルーバーのスリット × 下地板
- ブース奥の箱 × 壁

**目視では取りこぼす。** 書き出し前に必ず機械的に走らせること。
対策後の同じ手順で組んだシーンでは `suspect_count: 0` になる。

### 検出器の限界

これは知った上で使うこと。

- **オクルージョンを見ない。** 他のソリッドの内部に埋まっていて見えない面も報告する。
  四周トリムのコーナー端面などが該当し、これは直さなくてよい
- **面の当たり判定が bounding box。** 三角形分割された文字メッシュなどで、
  実際には重なっていないのに bbox が重なって誤検知する
- **数を 0 にするのが目的ではない。** 「見える場所で同じ向きの面が重なっていないか」を見る。
  `Light_*` `Chair_*` `Table` `Door_*` のような**視界に入る部品**を優先して潰す

### 直し方

`suspects` に出たペアのうち、**後から付けた方**を `attach_span` / `rest_on` に通す。
どちらが「後から付けた方」か迷ったら、構造（床・壁・天井・テーブル天板）ではない側。

自分の中の部品どうし（サイン筐体 × 発光面など）も同じ。発光面は筐体から数 mm 浮かせるか、
逆に筐体へ沈める。
