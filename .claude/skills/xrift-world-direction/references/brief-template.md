# ブリーフの書式と完成チェックリスト

ブリーフは、最初のツール呼び出しの前に書き、最初の報告と完了報告に同じものを置く。案は 1 つ。
途中で変えたときは、変えた項目と理由を追記する。ユーザーが読んで違えばその場で直せることが
目的なので、短く書く。数値の上限や予算は、この書式が決めるのではなく、作るモデルがワールドの
規模と公開先を考えて自分で決めて書く。

## 書式

```text
ワールドブリーフ
- 場所と用途: <誰が来て、何をする、どんな場所>
- 雰囲気: <時間帯、天気、色の印象>
- 床: <床の種類と大きさ。Terrain を使うなら、起伏が体験にどう効くか>
- 主役: <訪問者が写真を撮る 1 つの物>
- 動きと反応: <何が動き、何に応えるか。無ければ「無し」>
- 入れないもの: <ユーザーの依頼と噛み合わないもの>
- 予算: <自分で決めた三角形、draw call、容量と、各要素にかける手間の上限>
```

## 完成チェックリスト

完了報告の前に通す。通らない項目は直すか、通らない理由を報告に書く。

- [ ] 主役が、スポーン位置・目の高さのキャプチャに写っている
- [ ] 「入れないもの」がシーンに無い
- [ ] 灰色 (既定 Material) のプリミティブが残っていない
- [ ] 空・環境光・フォグ・露出が同じ時間帯と天気を指している
- [ ] ライトの役割 (key、fill、accent) が整理され、影を落とすものが決まっている
- [ ] 大・中・小の尺度の物がそれぞれある
- [ ] 同じ Model の複製は角度と倍率が違う
- [ ] 浮いている物、沈んでいる物が無い
- [ ] スポーンが床の上にあり、主役を向いている
- [ ] 落下できる縁に Collider か手すりがある
- [ ] 触れる仕掛けがあり、Play で動く
- [ ] 音がある
- [ ] 場所の名前の看板がある
- [ ] `capture_scene_debug` の三角形・draw call・VRAM がブリーフの予算内
- [ ] 完了報告に、ブリーフ、2 枚のキャプチャのパス、metrics が書いてある
