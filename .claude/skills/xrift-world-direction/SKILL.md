# XRift ワールドの制作工程

依頼内容と現在のSceneを確認して制作・調整してください。完成条件は画像と動作で確かめます。依頼されていない要素は追加しません。日本語の説明では、配置の意図、操作、検証した結果を明確にしてください。

## 作業範囲と進め方

実行できる操作は`AGENT.md`に従って判断してください。依頼済みの制作と検証は、許可を取り直さず進めます。認証、対象作品の不一致、接続不能で作業を続けられない場合は、状況を報告してください。その条件に影響されない作業は先に終えます。公開の依頼がなければ、保存と検証まで行って完了です。

`get_editor_context`と`list_entities`などのツールで、現在のSceneと利用できる機能を確認してください。既存作品を開く場合は、依頼された作品か確かめます。対象が分からないまま別の作品を変更しません。

## 設計図

新規制作や大きな変更では、現状を確認し、書き込み前に`references/blueprint-template.md`で設計図を作ってください。配置・色・雰囲気の小さな調整は、変更対象と完成条件を短く記録します。制作セッションを使う場合は、begin/update/finishツールの契約に従います。

制作手段は依頼内容と必要な品質に合わせて選んでください。ツールの数や過去の作例を基準にせず、依頼されていない体験や設備を必須にしません。前提を変えた場合は理由を記録します。

### 体験と設備

体験の設計を依頼された場合は、訪問者が行うことを決めてください。景観や配置の調整だけなら、新しい体験は追加しません。交流・共同作業・発表のワールドでは画面共有を先に検討し、採用するか省くか、その理由を設計図に書きます。ミラーはアバターの確認や交流、TagBoardはイベントでのタグ選択など、用途に合わせて選びます。すべてのワールドに付ける必要はありません。

`list_component_definitions`または`get_world_authoring`の`worldComponents`に、用途、配置の手順、公式のプロパティ定義、既存設備が返る。既存設備を調べてから追加・調整する。現行のタグ選択部品は`TagBoard`であり、別の`TagMarker` APIがあると推測しない。詳しい判断は`references/world-components.md`にある。

## 工程

新規制作では、次の工程を目安にしてください。既存Sceneの状態と依頼内容に合わせて、工程と順序を選びます。小さな変更では、対象と影響する箇所を確認し、全体を作り直す必要はありません。

### 1. 床と構造物

`get_editor_context`と`list_entities`で、スターターの床・太陽・スポーン位置を確認する。設計図の床と違うものが置かれていたら、削除するか差し替える。そのうえで、床と大きな構造物を設計図に合わせて作る。プリミティブの初期の灰色Materialのまま残さない。置いた物は`get_entity_bounds` / `sample_terrain_point`で地面への接地を確かめる。

### 2. 主な設備と景観

設計図の体験に必要な設備と、中心となる景観を先に作ってください。画面共有を使う場合はスクリーンと客席・操作位置、イベントでは受付と待機場所を確保します。素材は`references/asset-sourcing.md`から、設計図の品質に合うものを選んでください。画面共有、ミラー、タグ選択には公式Componentを使います。自作の板やScriptで見た目だけを再現しません。ほかの動き、繰り返し配置、反応は`references/scripting-patterns.md`に従ってScriptで作ります。

### 3. 光と空

空、環境光、フォグは`update_scene_settings`でまとめて設定してください。時間帯に合わせて調整し、夕方の空に昼の照明を組み合わせるような不一致を避けます。

ポストエフェクトを使うかどうかは、設計図の「品質の水準」に合わせて決める。使う場合は、有効にする前後で`capture_scene_view`を撮って見比べる。見た目に差がなければ無効にする。

### 4. 設計図の残り

設計図に記載した小物、音、仕掛け、動きなど、残りの要素を作ってください。

### 5. 検証

1. `set_scene_view_camera`でカメラをスポーン位置・目の高さに置き、主役のほうへ向けて`capture_scene_view`を撮る。
2. `set_scene_view_camera { preset: "iso" }`で俯瞰に切り替え、`capture_scene_view`を撮る。
3. `capture_scene_debug { action: "metrics" }`の値を、設計図の「予算」と照合する。
4. 2枚の画像を設計図の「完成の条件」と見比べて、合否を判定する。判定の根拠は完了報告に書く。
5. 設備がある場合は、観客席の前列・後列・端、操作位置、受付など必要な利用視点からも撮影する。表示面の向き、読みやすさ、遮蔽物、通路、壁や枠との収まりを確認する。追加画像には`authoringView`を付けず、スポーン・俯瞰の証拠を上書きしない。
6. 配置と機能の確認を分ける。画面共有の開始・表示・停止、タグ選択、ミラーでのアバター確認は対応する実行環境で確認し、参加者間の共有・同期は複数クライアントで確かめる。Editの待機画面だけで動作確認済みにしない。確認できない項目は未検証として報告し、その条件を合格にしない。

見た目は画像、負荷はmetrics、機能は実行結果で確認してください。それぞれの確認結果を報告します。

## 完了報告と復旧

完了報告には、設計図か変更記録、画像の保存先、metricsと予算の比較、完成条件の判定を記載してください。前提、未検証・未完了の項目と、その理由も示します。

- `harness`が同種の書き込み反復を警告したら画像を撮り、確認できた欠点を修正する。欠点がなければ次へ進む。
- 外部モデルは`search_external_assets`の`polycount`と予算を比較してから取り込む。
- Scriptの失敗は`get_editor_context.scriptRuntime`の変換・実行エラーを直してPlayで再確認する。
