# XRift Studioで制作する

最初に`list_projects`と現在のSceneを確認する。接続中のStudioから`get_world_authoring_guide`で最新の制作ガイドを取得できる。`topic: "overview"`で利用できる制作方法を確認し、`r3f`、`assets`、`blender`のうち、実際に使う方法の詳細だけを読む。

- ツールを選ぶ前に、依頼された完成形と範囲を読み取る。対象が一部分の修正、モデル1点、周辺を含む配置、ワールド全体のどれかを判断し、役割と見る距離に合う細かさで作る。近くで見る家には構造の細部が必要でも、街全体では道路や建物の種類に統一感を持たせ、すべての建物に内装を作る必要はない。

- 作者の意図と今回の修正内容から、具体的な完成条件を数件決める。構図、人の大きさとの比率、動線、主役、周辺の要素、素材の配色、照明をまとめて設計する。最初の保存時点で全体がまとまった状態にする。床や小物1点だけでは、場所全体を作り終えたことにはならない。

- ワールド全体を作るときは、背景・照明と空間内の案内を一緒に設計する。依頼された作風に合うSkybox、照明、情報の優先順位を選ぶ。展示・教材・メニュー・サインにはtopic: spatial-ui、新しい背景や環境の変更にはtopic: environmentを読む。読みやすいカード、目的の伝わるまとまり、実物の見本で体験を構成し、同じ掲示板に長文を並べるだけにしない。作者が求めた簡素な構成や暗い演出は保つ。

- 現在のSceneを確認し、編集する対象と既に作られている内容を特定する。ワールド全体の依頼を、現在選択されているEntityだけの修正に狭めない。新しいワールドのstarterEntityIdsは、接続先が確認した任意の足場として使える。役立つ場合は置き換え、初期形状を残すためだけに新しい機能を作らない。依頼の範囲外の制作物と作者の手動編集は保つ。

- 完成形と利用できる機能に合わせて制作方法を選ぶ。自動制作では、モデルや表面に適した作品内・外部の素材、建築などに再利用できる静的ソース、空間UIに実際のUIKit Script Render、独自の形状に必要なBlenderを組み合わせる。Blenderは選択肢の一つであり、必須ではない。作者が制作方法を指定した場合はそれに従う。一部分を作り替えるときは、所有するEntityの配置、既存の動作、手動で追加された子を保ち、ルートや描画処理を重ねずに依頼された見た目を置き換える。詳細ガイドは使う制作方法の分だけ読む。

- 見える建築や小物は、用途と見る距離に合う形に仕上げる。輪郭、比率、縁の処理、厚み、継ぎ目、光の反射、床への接地を、一つの構成として設計する。教材の見本や意図した作風に役立つ単純な形状は残す。家具・主役・建築には構造が分かる形を与え、単色の箱を置いた段階で完成としない。適した外部素材を選び、曲面・面取り・独自の構造で仕上がりが良くなる場合はBlenderも使う。改善は実際の撮影画像で評価する。使ったツールの多さ自体を品質の基準にしない。

- 依頼の範囲内で通常の設計判断を行い、利用できる機能で全体の制作を始める。外部素材は、足りない形状や表面を補うことで完成形が良くなる場合に、その用途に絞って探す。カタログ全体の調査や、繰り返し使うものを1点ずつ別々に生成することを、ワールド全体の制作の前提にしない。

- 安定した部品や完成済みのものを再利用し、設計に役立つ違いを付ける。形状や制作の手間は、見える構造と主役に配分し、隠れる部分や用途に関係しない細部は省く。依頼された体験に必要な設備を選び、その利用場所を確保してから周囲を飾る。

- 全体がまとまった状態で保存し、想定する距離から実際に描画されたSceneを確認して、最初に決めた完成条件と比べる。条件を満たしていない具体的な箇所を直し、全体を作り直したり、依頼されていない装飾を増やしたりしない。Sceneのデータや件数だけでは、見た目の品質や動作を確認したことにはならない。

- 接続先が定めた実行上限と、現在の完成確認の記録に従う。完成条件を満たしたら作業を終える。追加の書き込みが認められない場合は、保存済みの結果と具体的な残作業を報告して止める。作者が依頼を変更しない限り、続きの作業にも同じ上限と完成条件を引き継ぐ。未確認の動作は正直に報告し、公開は依頼された場合だけ行う。

設計のtopicは必要なものだけを取得する。`spatial-ui`: VR・WebGLで読みやすい案内空間を作る。情報の優先順位、余白、人に合うカードの大きさ、対応する文字設定と、再利用できる静的ソースの例を扱う。 `environment`: 依頼に関係しない制作物を保ち、Skybox・IBL・照明を揃える。VR・WebGLの負荷の目安と対象端末での確認も扱う。

静的ソースを保存して制作する場合は、`apply_r3f_scene`で原本を所有するルートを作成・更新する。修正前に`get_entity_components`でそのルートを読み、完全な`r3fAuthoring.source`を使う。一般のComponentコード取り込みでは、保存された原本を更新できない。対応する操作と制限は、ツールのスキーマと返された機能情報で確認する。

ワールド全体の制作では、`get_world_authoring`で作業を再開するか、`begin_world_authoring`で設計内容と完成条件を保存する。書き込みには現在のrevisionを使う。保存した結果をスポーン視点（spawn）と斜め上からの俯瞰（iso）で撮影し、`review_world_authoring`で完成条件を一つずつ確認・記録して、`complete_world_authoring`で終える。小さな直接編集では、ワールド全体の制作手順を始める必要はない。

[共通ガイド](../../../src/lib/visual-editor/world-authoring-guide.json)から、Studio ChatGPT・MCP・このスキルへ同じ基本方針を渡す。制作方法の詳細は必要に応じて取得し、作業前にすべての方法を読まない。
