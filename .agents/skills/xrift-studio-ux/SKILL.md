# XRift Studioの画面設計

操作の流れを変える場合は[UX原則](../../../docs/UX_PRINCIPLES.md)、動きや状態遷移を変える場合は[UX_INTERACTIONS](../../../docs/UX_INTERACTIONS.md)の該当箇所を読んでください。文言の修正では、画面全体を再設計する必要はありません。UpdateDialog、ProjectLibrary、ProjectCard、EditorViewを実装例として参照できます。日本語の作成・推敲では、`AGENT.md`の文章と用語の方針に従ってください。

## 導線

操作前、処理中、成功後、失敗後に何を表示するか決めてください。主な操作と、次に開く対象を示します。成功後は、通知に加えて作成物・URL・更新結果を開けるようにします。

一覧には変更結果と選択状態を反映し、新規作成の操作を先頭に残してください。更新が見つかった場合は、現在の版との違い、更新の実行、延期の操作をまとめて示します。

公開前のタイトル・説明・サムネイルが初期値のままなら、編集する場所を案内します。保存後に内容を再確認してください。処理中はボタンのラベルと無効化で二重操作を防ぎ、中断できない処理を中断可能に見せないようにします。

白とニュートラルカラーを基調にしてください。ブランド色、影、動きは、状態や操作を伝える強調に使います。主要な操作にはラベルか`title`を付けます。動き、無効化、文言、復帰先は対応する`MI-xx`に記録し、新しい動きはWikiへ追記してください。

## コンポーネント名の表記

Component名はAdd Componentのレジストリに合わせます。Inspector、削除・有効化の操作、通知、Hierarchy、カタログでも同じ英語名を使ってください。公式Componentも正式名を保ち、画面ごとに別の翻訳を付けません。

LightとAudio Sourceの種類は、選択した内容とラベルが一致することを確認します。効果、操作、単位は短い日本語で説明し、保存済みIDとAPI名は保ってください。

## Entity作成とComponent追加

Entity作成は、選択中のEntityがあっても新規作成の操作として扱います。既存EntityへのComponent追加はInspectorから行ってください。SceneとHierarchyのEntity上で右クリックすると、対象の編集と受け渡し操作を表示します。Hierarchyの空白で右クリックすると、共通カタログから新規作成できます。

候補、順序、重複、依存条件は共通定義を使います。必須のTransform、旧追加メニューの項目、単独で成立しない項目はEntity作成の候補から除いてください。追加できない理由は、選択前に表示します。

Entity、基本形状、ワールド、ライト、UI、音声、エフェクト、XRiftの分類は折りたためるようにし、名前や用途でも検索できるようにします。Project Kindで使えない候補には理由を表示し、操作時も拒否してください。空Entityは先頭、CubeとPlaneはPrimitive、SpawnPointはWorldに置きます。

形状はCubeやPlaneなどの名前を保ち、「床」などの用途名に変えません。Rigid Bodyなど既存Entityに追加する機能は、新規配置の候補から分けます。同じXRiftの機能をPrefabとComponentの両方で重複表示しません。分類名には利用者が分かる名前を使い、内部構成の名前を避けてください。

複数選択中の右クリックでは、名前変更・削除などを上に表示します。追加候補は表示せず、選択状態を保ってください。

## Assetsとヘルプ

Assetsではフォルダー階層の下に種類フィルターを置きます。Modelsなどの種類をフォルダーとして表示せず、選択した種類の素材を表示してください。

空ワールドには、使う素材だけを生成します。テスト用Material、サンプルPrefab、空のStarter Libraryは作りません。PrimitiveのMaterialは配置時に追加してください。

素材のカードは、名前とプレビューを一覧で確認できる大きさにします。プレビュー未生成、読み込み中、失敗の状態は、中央の種類アイコンで示してください。同じ代替文をカードごとに繰り返しません。素材の欠損や解析失敗の警告は残します。

リストでは素材名を中心に表示します。各行にdocument、パス、通常時のready表示は出しません。サイズはKB・MBなどの単位を付け、名前の右に読みやすい文字で右揃えにしてください。

配置は右クリックの「シーンへ配置」から行います。カードや行には配置ボタンを置かず、配置できるかどうかでカードの高さや名前の幅を変えません。

利用ガイドとアプリ内ヘルプはdocs/guideの原稿を使います。作業に合うヘルプを開き、閉じたらフォーカスを元の操作へ戻してください。旧Wikiや旧URLへの移行ページは残しません。操作名を変えたら、ガイドの案内も揃えます。

操作と条件が伝わる日本語に整え、画面名と専門用語は[用語表](../../../docs/JAPANESE_WRITING.md)で確認してください。変更した表示、操作、状態は、xrift-studio-verifyから必要なTierを選んで検証します。実行できる範囲は`AGENT.md`に従います。
