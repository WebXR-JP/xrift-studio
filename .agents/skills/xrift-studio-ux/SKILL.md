# XRift Studio UX

導線の変更では [UX原則](../../../docs/UX_PRINCIPLES.md)、動き・状態遷移の変更では [UX_INTERACTIONS](../../../docs/UX_INTERACTIONS.md) の該当箇所を読む。文言修正だけで全体を再設計しない。既存の UpdateDialog、ProjectLibrary、ProjectCard、EditorView を実装例に使う。

## 導線

- 操作前・処理中・成功・失敗・復帰先を定め、主操作と次に開ける対象を示す。成功トーストだけで終えず、作成物・URL・更新結果へ到達できるようにする。
- 一覧の結果と選択状態を更新し、新規作成を先頭に残す。更新検知では現在との差分、実行、延期を同じ導線に置く。
- 公開前のタイトル・説明・サムネイルが初期値なら編集へ案内し、保存後に再確認する。
- 処理中のラベルと無効化で二重操作を防ぐ。安全でない中断を可能に見せない。
- 白・ニュートラルカラーを基調に、ブランド色・影・動きは意味のある強調に限定する。主要操作にはラベルか `title` を付ける。
- 動き・無効化・文言・復帰先を対応する `MI-xx` として記録し、新しい動きはWikiへ追記する。

## コンポーネント名の表記

Add Componentのレジストリを正とし、Inspector、削除・有効化、通知、Hierarchy、カタログで同じ英語名を使う。画面別の翻訳表を作らず、公式Componentも正式名を保つ。Light・Audio Sourceの種類を選択内容と照合する。効果・操作・単位は短い日本語で説明し、保存済みID・API名は変えない。

## Entity作成とComponent追加

- Entity作成は新規作成のままにし、選択状態で既存EntityへのComponent追加に切り替えない。Component追加はInspectorか対象の右クリックから行う。
- 候補・順序・重複・依存条件は共通定義から選ぶ。必須Transform、旧追加口、単独で成立しない項目はEntity作成候補に出さず、追加不可の理由を選択前に示す。
- Entity、Primitive、World、Light、UI、Audio、Effect、XRiftの折りたたみで選ぶ。検索欄は置かない。空Entityを先頭、Cube・PlaneはPrimitive、SpawnPointはWorldに置く。
- 形状名を「床」などの用途名に変えない。Rigid Bodyなど既存Entityへの機能は新規配置候補に混ぜない。XRiftのPrefabとComponentは同じ機能を二重に並べない。分類名に内部構成を使わない。
- 複数選択の右クリックでは名前変更・削除などを上に出し、追加候補を混ぜない。選択状態を保持する。

## Assetsとヘルプ

- Assets直下にフォルダー階層、その下に種類フィルターを置く。Modelsなどの種類をフォルダーとして並べず、選択した種類の素材だけを表示する。
- 空ワールドには使用素材だけを生成する。テストMaterial・サンプルPrefab・空Starter Libraryは作らず、PrimitiveのMaterialは配置時に追加する。
- カードは素材名とプレビューを見渡せる密度にする。プレビュー未生成・読込中・失敗は中央の種類アイコンで示し、同じ代替文を並べない。素材の欠損・解析失敗の警告は残す。
- リストは素材名を中心にし、document・パス・通常時のreadyを各行に出さない。サイズは読める文字とKB・MB等の単位で名前の右に右揃えする。
- カード・行に配置ボタンを置かず、右クリックの「シーンへ配置」を使う。配置可否でカードの高さ・名前の幅を変えない。
- ガイドはdocs/guideを公開版・アプリ内で共有する。作業に対応するヘルプを開き、閉じたらフォーカスを戻す。旧Wiki・旧URL移行ページは残さない。操作名の変更とガイド更新を揃える。

変更した表示・操作・状態を xrift-studio-verify の該当Tierで確認する。実行判断は `AGENT.md` に従う。
