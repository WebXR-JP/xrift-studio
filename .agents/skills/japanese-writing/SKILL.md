# 日本語の作成と推敲

文章の書き手や使用した LLM によらず、読み手が操作・条件・結果を理解できる文章にする。特定の製品や人の名前で文体を分類したり、書き手の能力を評価したりしない。

## 意味を保つ

- 仕様、数値、条件、例外、承認、禁止事項、対応状況を変えない。重複をまとめる場合も、必要な情報が残ることを確認する。
- コード、コマンド、API 名、UI の正式なラベル、パス、URL は保持する。本文の見出しを変える場合は、参照リンクのアンカーも確認する。
- 誰が操作するかが重要な場面では、利用者・アプリ・AI などの主語を残す。「人」を機械的に消さない。
- 不確かな説明を断定に変えない。文章だけでは仕様を判断できない場合は実装を確認し、仕様変更と推敲を分ける。

## 表現を整える

- 比喩や抽象語で済ませず、何をどう操作し、何が起きるかを書く。「生きた画面」は「現在表示中の画面」、「着地先」は「コピー先」など、文脈に合う具体語にする。
- README や利用者向けガイドでは、内部用語を説明する。「dependency plan」は「依存パッケージの変更予定」のように書く。正式名称が操作の手掛かりになる場合は併記する。
- 条件や話題が切り替わるところで文を分ける。読点の数だけで分割しない。短文が続いて関係が分かりにくくなった場合は、理由と結果をつなぐ。
- 「このため」「同じ扱いにする」などの繰り返しを整理する。削ると意味が欠ける説明は、具体的な対象を書いて残す。
- 利用者向けにはですます調、設計書には常体など、周囲の文体に合わせる。表や短いラベルの体言止めは、読みやすければ残す。
- 「責務」「境界」「正規化」などの技術語は、一律に置き換えない。正確さが必要な箇所では残し、読み手にとって不明瞭な箇所だけ説明する。
- 「ハーネス」はエージェントの実行環境や制御を表す技術用語として使う。初出で範囲を説明し、曖昧な比喩と同じ理由で削除しない。

## 関連文書と確認

依頼された範囲を読み、同じ説明がある README、docs、スキルも検索する。検索に一致した単語を一括置換せず、前後の文と読み手に合わせて直す。過去の記録は日付・当時の事実・結論を保持する。

差分で意味の欠落、条件の逆転、リンク切れ、コード例の変更を確認する。`.agents/skills/` と `.claude/skills/` の対応するコピーは同期する。確認した範囲と検証結果を報告し、単語検索だけで全文の推敲が完了したとはしない。

## このプロジェクトの用語

画面・制作方式の名前は「ビジュアルエディター」「コードエディター」とする。「ビジュアル編集」「コード編集」を画面名として使わず、操作やプロジェクト形式とは区別する。

画面と利用者向けガイドの表記は、[文章と用語のルール](../../../docs/JAPANESE_WRITING.md)に揃える。表示名を変えても、API名・保存済みID・JSONキー・ノードの操作名と接続口の識別子は変更しない。

XRift Studioでは `Entity / Inspector / Hierarchy / Assets / Components` の表記を残す。説明を増やす前に、見出しと重複する案内や内部実装の説明を削れるか確認する。ノードの旧名を検索用の別名として残さない。

マテリアルはglTFの英語名を主ラベルにし、読み方を見出しに添える。Roughness、Clearcoat、Iridescenceなどを独自の日本語名へ置き換えない。説明は数値の方向・単位・条件を日本語で短く書く。AlphaとTransmission、Volumeの厚みとIridescenceの膜厚を区別する。

Normal Map、Skybox、IBL、Bloom、SSAO、Fog、Color Gradingなど、制作ツールで定着した名前も主ラベルに残す。名前は英語、効果と操作の説明は短い日本語にする。「上空の色」のような実際の色名や一般的な操作まで機械的に英語にしない。SkyboxとIBL、Normal Mapと形状の変形、EmissiveとBloomの違いを保つ。

起動から保存・公開・終了まで、未選択・処理中・成功・失敗の案内も確認する。説明に出すボタン名を実際の表示と照合する。ファイルの追加とXRiftへの公開を区別し、進捗IDは表示だけ日本語にする。ラベルは接続先の値を確認し、音声のvolumeをマテリアルのVolumeと取り違えない。

コンポーネント名はすべて英語で、Add Componentと同じ表記にする。Mesh Renderer、Rigid Body、Colliderなどを日本語の機能説明へ置き換えない。詳しい照合手順は[UXスキル](../xrift-studio-ux/SKILL.md#コンポーネント名の表記)に従う。
