# XRift Studioのリリース紹介動画

対象バージョンの差分と実画面を使い、利用者が新しくできる操作を紹介します。通常は1本で1つの更新を扱い、16:9、1920×1080、30fps、約30秒で作ります。ユーザーの指定があれば、その内容に従ってください。

## 制作と承認

`scripts/extract-release-diff.mjs --from <ref> --to <ref> --output <path>`で差分を取得してください。未コミットの変更を含める場合は`--worktree`を付けます。ファイルの差分を読み、未確認の機能・性能・公開日を紹介しません。

台本には時間配分、画面内の文、操作、ポインター、ズーム、差分と素材の根拠を記載します。全文をまとめて提示してください。`scriptApproval.status`は、ユーザーが明示的に承認するまで`pending`です。承認後に`approved`へ変え、Remotionでの実装とレンダリングへ進みます。台本を変えたら全文を再提示して承認を得てください。承認済み台本に沿った映像・音の調整は、その範囲で進めます。

通常の構成は、0〜2秒で「XRift Studio アップデート情報」、2〜6秒で変更と利点、6〜22秒で実画面の主な操作を1つ、22〜27秒で結果、27〜30秒で公開状況を示します。楽曲の小節に合わせる場合は、実際の長さを台本に書いてください。

公開済みの更新は「XRift Studioアップデート公開中」で締めます。公開前は`releaseStatus: upcoming`にし、公開済みと誤認する表示を避けてください。

実装されていない画面を架空のUIで補いません。必要な素材がなければ、収録する操作を示してください。表示イメージを使う場合は、画面内にその旨を記載します。字幕は無音でも理解できる文にします。ナレーションは、明示的な依頼と承認済み台本がある場合だけ追加してください。

## 完了条件

承認済み台本と実画面で示す内容を一致させ、字幕、操作対象、最後の案内を読めるようにしてください。ポインター、クリック波紋、ズームは同じ対象に合わせます。主な操作は1つ、ズームは最大2回を基本とします。

指定された縦横の形式で静止画と通し再生を確認し、黒画面、ちらつき、音ずれ、字幕切れを調べます。成果物、storyboard、差分の根拠、素材の出典、未検証の内容を報告してください。

Gitへ追加するのは、明示的に依頼されたソース、台本、根拠だけです。生成動画、連番画像、音素材、依存ディレクトリは追加しません。対象パスを指定してステージしてください。公開と外部送信は`AGENT.md`に従って判断します。
