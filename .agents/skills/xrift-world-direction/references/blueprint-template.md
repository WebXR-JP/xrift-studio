# 設計図の書式

設計図は、最初のツール呼び出しの前に書き、最初の報告と完了報告に同じものを置く。案は 1 つ。
途中で変えたときは、変えた項目と理由を追記する。ユーザーが読んで違えばその場で直せることが
目的なので、短く書く。数値の上限や予算、完成の条件は、この書式が決めるのではなく、作るモデルが
依頼とワールドの規模と公開先を考えて自分で決めて書く。項目は目安で、依頼に合わせて増減してよい。

```text
設計図
- 品質の水準: <軽さ優先 | 標準 | 高品質。依頼の言葉から読み取る>
- 場所と用途: <誰が来て、何をする、どんな場所>
- 雰囲気: <時間帯、天気、色の印象>
- 床: <床の種類と大きさ。Terrain を使うなら、起伏が体験にどう効くか>
- 主役: <訪問者が写真を撮る 1 つの物>
- 動きと反応: <何が動き、何に応えるか。無ければ「無し」>
- 入れないもの: <依頼と噛み合わないもの>
- 予算: <自分で決めた三角形、draw call、容量と、各要素にかける手間の上限>
- 完成の条件: <この設計図が満たされたと言える状態を、自分の言葉で 2〜3 行>
- 前提: <聞かずに決めたこと>
```

## 完了報告

完了報告は 1 通にまとめる。設計図、スポーン位置と俯瞰の 2 枚のキャプチャのパス、
`capture_scene_debug` の metrics と予算の照合、聞かずに決めた前提、やり残しと理由。
「完成の条件」を満たしたかどうかは、キャプチャを見て自分で判定し、その根拠を書く。
