# XRift ワールドの制作工程

XRift Studio の MCP でワールドを作るときの、ツールより先に決めることと、決めた順番に作る手順。
Studio の使い方 (revision、承認、Play) は MCP の instructions と `docs/MCP_EDITOR_TOOLS.md` に
ある。ここにあるのは順番と確認の仕方だけで、テーマ、床の種類、素材、数値の上限は決めない。
それらはユーザーの依頼と、作るモデル自身が決める。

## なぜこのスキルがあるか

MCP のツール一覧は Terrain と草に 14 本、床や壁を作るプリミティブに 1 本という偏りがあり、
スターターの床は屋外の板である。何も指示しないと、作業は「草原の Terrain を置く、木のレシピを
複製する、草の密度と色を往復する」へ収束する。ツールの数がワールドの形を決めてはいけない。
このスキルは、依頼の狙いから手順を決め、見ずに往復するのを止めるための手すりである。

## 守ること

1. **最初の書き込みの前にブリーフを書く。** 書式は `references/brief-template.md`。案は 1 つ。
   候補を並べてユーザーに選ばせない。最初の報告にブリーフを入れ、違えば途中で直せるようにする。
   予算 (三角形、draw call、容量) と、各要素にかける手間の上限も、ブリーフの中で自分で決めて書く。
2. **Terrain と草を既定にしない。** 床は依頼から決める。Terrain を選ぶのは、屋外の風景で地面の
   起伏そのものが体験に効くとブリーフに書いたときだけ。草は背景であり、主役ではない。
3. **見てから直す。** 同じ要素を続けて調整するときは、`capture_scene_view` のフレームに写った
   欠陥を 1 つ直し、また撮る。撮らずに往復しない。Studio 側も、同じ分類の書き込みが撮影を
   挟まずに続くと tool の戻り値に `harness` の警告を付ける。警告が出たら撮り、欠陥が無ければ
   その要素は確定として次の工程へ進む。
4. **主役を 1 つ決めて、土台の直後に作る。** スポーンから見た最初の 1 枚に主役が写る位置と向きに
   スポーンを置く。
5. **完了は撮って確かめる。** スポーン位置・目の高さから主役を向いた 1 枚と、俯瞰の 1 枚。
   数値と document は「何が映るはずか」しか言わない。何が映っているかを言うのはフレームだけ。
6. **過去のワールドは参照しない。** 判断材料は今の依頼、今の Scene、今のフレームだけ。

## 工程 (この順番で)

### 0. ブリーフ (ツール呼び出し 0 回)

場所と用途、雰囲気、床の種類と大きさ、主役、動きと反応、入れないもの、自分で決めた予算。
テーマの指定が無ければ、依頼の文脈 (用途、人数、雰囲気の言葉) から最も合うものを 1 つ決めて書く。

### 1. 土台とブロックアウト

`get_editor_context` と `list_entities` でスターターの床、太陽、スポーンを確認し、ブリーフの床と
違うなら消すか差し替える。床、壁、段、台をブリーフの床の種類に合わせて作り、材質を最初から入れる。
灰色の既定 Material のまま次の工程へ進まない。スポーンを主役が見える位置へ動かす。

### 2. 主役

調達順は `references/asset-sourcing.md`。主役は部品の「関係」で作る (台座、本体、光、音、Particle)。
Model を 1 つ置いて終わりにしない。動くもの、繰り返すもの、反応するものは Script で作る
(`references/scripting-patterns.md`)。触れる仕掛けを 1 つ、場所の名前の看板を 1 つ入れる。

### 3. 光・空・空気

空、環境光、フォグは `update_scene_settings` で同時に決める。空だけ夕方にして昼の白い光を
残さない。ライトは役割 (key、fill、accent) で置き、影を落とすものを決める。ポストエフェクト
(Bloom、AO、色味、露出) は既定で使わない。WebGL で見る全員の描画に効き、無くても成立する
ワールドがほとんどなので、依頼にその見た目の理由があるときだけ、撮って比べてから有効にする。

### 4. 小物と密度

大・中・小の尺度を揃える。直線グリッドにしない。同じ Model の複製は角度と倍率を変える。
高さは `sample_terrain_point` か `get_entity_bounds` で床面に合わせる。音を 1 つ。

### 5. 検証と仕上げ

1. `set_scene_view_camera` でスポーン位置・目の高さから主役を向き、`capture_scene_view`。
2. `set_scene_view_camera { preset: "iso" }` で俯瞰し、`capture_scene_view`。
3. `capture_scene_debug { action: "metrics" }` の三角形、draw call、VRAM をブリーフの予算と照らす。
4. `references/brief-template.md` のチェックリストを通す。
5. 完了報告には、ブリーフ、2 枚のキャプチャのパス、metrics を書く。

## やらないこと

- ブリーフを書かずに `create_terrain_from_preset` を最初に呼ぶ
- 「木」レシピを複製して森にする
- 草の色・密度・高さを、キャプチャを撮らずに往復する
- 灰色のプリミティブが最終成果物に残る
- 全部が y = 0、全部が scale 1、全部が yaw 0
- 空だけ変えて光を変えない
- スポーンが主役に背を向けている
- キャプチャのパスが無い完了報告
